# v3.3.0 Sprint 2: Legacy PDB Read-Only Dispatch Layer

## Sprint Goal and Scope

Replace the Sprint 1 no-op PDB dispatch layer (`src/pdbfile.c`) with a real
read-only parser for legacy PDB (`.pdb`) files, exposing atom coordinates
and key structural metadata as netCDF-4 dimensions, variables, and
attributes through the existing UDF7 dispatch table (`src/pdbdispatch.c`,
unchanged from Sprint 1).

In scope:
- Fixed-column parsing of `HEADER`, `TITLE`, `COMPND`, `SOURCE`, `CRYST1`,
  `MODEL`/`ENDMDL`, `ATOM`, and `HETATM` records.
- A `model` x `atom` netCDF schema (see below).
- Rejecting files with no `ATOM`/`HETATM` records at all.

Out of scope (deferred to Sprint 3):
- `SEQRES`-derived sequence data (`sequence` group / `mon_id` variable).
- Hybrid-36 encoded serial/residue numbers (documented known limitation).
- Additional real-world test files beyond `test/data/PDB/1J7W.pdb` and
  `test/data/PDB/4HHB.pdb`.

## NetCDF Schema

**Dimensions:**
- `model`: number of `MODEL`...`ENDMDL` blocks in the file, or `1` if none
  are present (both current test files have no `MODEL` records).
- `atom`: total number of `ATOM`+`HETATM` records per model, in file
  order (assumed constant across models within a file).

**Coordinate variable:**
- `atom_site_Cartn_x`, `atom_site_Cartn_y`, `atom_site_Cartn_z`:
  `NC_FLOAT`, shape `[model][atom]`, from columns 31-38/39-46/47-54.

**Per-atom variables** (dimension `[atom]`, constant across models):
- `atom_site_id` (`NC_INT`, serial, cols 7-11)
- `atom_site_label_atom_id` (`NC_CHAR`/string, name, cols 13-16)
- `atom_site_label_comp_id` (`NC_CHAR`/string, resName, cols 18-20)
- `atom_site_auth_asym_id` (`NC_CHAR`/string, chainID, col 22)
- `atom_site_auth_seq_id` (`NC_INT`, resSeq, cols 23-26)
- `atom_site_occupancy` (`NC_FLOAT`, cols 55-60)
- `atom_site_B_iso_or_equiv` (`NC_FLOAT`, tempFactor, cols 61-66)
- `atom_site_type_symbol` (`NC_CHAR`/string, element, cols 77-78; inferred
  from `atom_site_label_atom_id` if blank)
- `atom_site_group_PDB` (`NC_CHAR`/string, `"ATOM"` or `"HETATM"`)

**Global attributes** (`NC_CHAR`):
- `idCode` (`HEADER` cols 63-66)
- `classification` (`HEADER` cols 11-50)
- `depDate` (`HEADER` cols 51-59)
- `title` (concatenated `TITLE` continuation lines)
- `compnd` (concatenated `COMPND` continuation lines)
- `source` (concatenated `SOURCE` continuation lines)
- `cell_length_a`/`b`/`c`, `cell_angle_alpha`/`beta`/`gamma`,
  `space_group_name_H-M`, `symmetry_Z` (all from `CRYST1`, only if
  present)

## Major Tasks (dependency order)

1. Add a fixed-column line reader/tokenizer to `src/pdbfile.c` (or a new
   `src/pdbparse.c` helper) that reads the whole file into memory (PDB
   files are small; no streaming needed) and classifies each line by its
   6-character record name.
2. First pass: count `MODEL` blocks (→ `model` dimension) and count
   `ATOM`/`HETATM` lines within the first (or only) model (→ `atom`
   dimension). Reject with `NC_EINVAL` if the atom count is zero.
3. Second pass: allocate per-atom arrays, populate identity fields from
   the first model's `ATOM`/`HETATM` lines, and populate the
   `[model][atom]` coordinate arrays across all models.
4. Parse `HEADER`/`TITLE`/`COMPND`/`SOURCE`/`CRYST1` into global attribute
   values (only define attributes for records that are actually present).
5. Replace `NC_PDB_open()`'s no-op body: after building the netCDF-4
   skeleton (unchanged from Sprint 1), call `nc4_def_dim`/`nc4_def_var`
   equivalents (following the `fitsfile.c`/`dicomfile.c` pattern of
   populating `NC_GRP_INFO_T`/`NC_VAR_INFO_T` directly) to create the
   dimensions, variables, and attributes above.
6. Implement `NC_PDB_get_vara()` to serve reads from the in-memory arrays
   built at open time (mirrors `NC_FITS_get_vara()`'s in-memory-buffer
   pattern, no re-parsing on every read).
7. Flip `NEP_ENABLE_PDB` default in `ci-pdb.yml` from proving-only to a
   real read/verify job (already ON in that workflow; no CMake option
   default change needed — `NEP_ENABLE_PDB` stays OFF by default in
   `CMakeLists.txt` per the FITS precedent, ON only in CI).
8. Expand `test/tst_pdb_udf.c` with the assertions in Testing Requirements
   below, replacing the Sprint 1 open/close-only checks.

## Acceptance Criteria

- `nc_open()` on `test/data/PDB/1J7W.pdb` and `4HHB.pdb` succeeds and
  exposes the schema above.
- `atom` dimension length matches the file's `ATOM`+`HETATM` line count
  (4HHB: 4384 + 395 = 4779; 1J7W: 4391 + 418 = 4809).
- `model` dimension is `1` for both files (neither has `MODEL` records).
- `nc_get_vara()` on `atom_site_Cartn_x/y/z` for a known atom index
  matches the columns-31-54 values read directly from the file.
- `CRYST1`-derived global attributes match the file's `CRYST1` record
  values for both files.
- A synthetic file with no `ATOM`/`HETATM` records is rejected with
  `NC_EINVAL`.
- Full test suite remains green with `NEP_ENABLE_PDB` both ON and OFF.

## Testing Requirements

- Extend `test/tst_pdb_udf.c`:
  - Verify `atom` and `model` dimension lengths for both test files.
  - Verify `atom_site_Cartn_x/y/z` for at least one specific atom in each
    file against hand-computed expected values from the raw file.
  - Verify `atom_site_group_PDB` correctly distinguishes an `ATOM` row
    from a `HETATM` row.
  - Verify `CRYST1`-derived global attributes (`cell_length_a`, etc.).
  - Verify `idCode` and `classification` global attributes.
  - Add a small malformed-input fixture (e.g. a text file with only a
    `HEADER` line and no `ATOM`/`HETATM`) and assert `NC_EINVAL`.
- Run via `ctest -R tst_pdb_udf --output-on-failure` with
  `-DNEP_ENABLE_PDB=ON`.
- Confirm `ci-pdb.yml` passes with the expanded test.
