## Compatibility Matrix and Migration Checklist

| Surface | Existing NEP | Decision for nep-compress / NEP v4.2.0 | Verification gate |
| --- | --- | --- | --- |
| Disk format | Filter IDs `32004` (LZ4), `307` (BZIP2). `nc_def_var_filter` receives one unsigned parameter: LZ4 acceleration or BZIP2 level. LZ4 chunk layout is documented in `hdf5_plugins/LZ4/LZ4_HDF5_format.md`. | Retain the IDs and single-parameter API; no old-NEP/new-project file interchange guarantee is required. | For each filter, verify nep-compress write/reopen/read on populated files, including filter ID, parameter and values. |
| C API | `<nep.h>` + `-lnep`: `nc_def_var_lz4`, `nc_inq_var_lz4`, `nc_def_var_bzip2`, `nc_inq_var_bzip2`. | Use `<nep_compress.h>` + `-lnepcompress` (new names). Preserve names, signatures and return semantics; link both libraries only if the application also uses NEP formats. No promise of binary ABI compatibility with the old `libnep`. | Compile a former NEP client against the new header; test enabled/disabled filter inquiries and failures. |
| Fortran API | `use nep` + `-lnepf -lnep`, producing `nep.mod`. | Use `use nep_compress` + `-lnepcompressf -lnepcompress`, producing `nep_compress.mod` in a dedicated module install directory. Keep `nf90_def_var_*` / `nf90_inq_var_*` names and 1-based varid adjustment. No second `nep.mod` in a shared prefix. | Build migrated Fortran clients with `-I` for the new module; verify both filters and no module-name collision alongside NEP. |
| Build flags | `NEP_BUILD_LZ4=ON`, `NEP_BUILD_BZIP2=OFF`, `NEP_ENABLE_FORTRAN=ON`; `NEP_HAS_LZ4/BZIP2` in generated `nep_meta.h`. | New options: `NEPCOMPRESS_BUILD_LZ4=ON`, `NEPCOMPRESS_BUILD_BZIP2=OFF`, `NEPCOMPRESS_ENABLE_FORTRAN=ON`. Remove obsolete NEP flags/feature macros in Sprint 4 and document the upgrade; CMake should warn about obsolete NEP flags instead of silently ignoring them. Keep NEP's own `NEP_ENABLE_FORTRAN` only if needed for retained format examples/tests. | CMake configure with new options; NEP format-only configure without liblz4/libbz2. |
| Plugin discovery | NEP builds `libh5lz4.so` under `${CMAKE_INSTALL_LIBDIR}/plugin`; BZIP2 comes from the environment, not NEP. | nep-compress installs `libh5lz4.so` to its plugin directory; require an external compatible BZIP2 plugin for BZIP2 mode. Set `HDF5_PLUGIN_PATH` to directories containing the selected plugin(s), colon-separated on Linux, without installing duplicate ID 307 providers into the same path. | `H5Zfilter_avail(32004/307)`, plus encoder/decoder capability and write/reopen/read tests with selected HDF5. |
| Logging / format backend | NEP owns `nep_logging.h`, `nep_log` and `nep_set_log_level`; NEXTCDF-4 links `nep` and implements generic HDF5 filter handling. | nep-compress has no NEP logging dependency. Comment out compression logging calls if found; preserve error codes. NEP keeps logging, UDF/NEXTCDF-4 APIs and generic filter support. | Build/link nep-compress without NEP; build/log-test NEP with both logging ON and OFF and exercise NEXTCDF-4 filters. |

Current C API accepts levels 1-9; invalid levels return `NC_EINVAL`, missing filter returns `NC_EFILTER`. Inquiry allows NULL output pointers. Record existing multi-filter behavior as a baseline before porting: LZ4 inquiry uses `nc_inq_var_filter` (single-filter query), while BZIP2 inquiry enumerates filter IDs. Do not assert behavior for multiple filters is identical until tested.

## BZIP2 Provider Decision

Use an **external HDF5 BZIP2 plugin** for Sprint 2, as NEP does today. There is no BZIP2 plugin source to move. The installed local provider is `libh5bz2.so` in `/usr/local/netcdf-c/hdf5/lib/plugin` (alongside `lib__nch5bzip2.so`); neither file is NEP source. Do not copy either binary or claim its license without upstream source/provenance. For CI, acquire a compatible source/package with an identified license, then install its plugin into a known path; do not equate installing `libbz2` with installing an HDF5 plugin. If that CI provider cannot be secured and tested, BZIP2 support and the Sprint 2 acceptance gate remain blocked. Update docs/Spack's incorrect claim that NEP itself installs `libh5bzip2.so`.

When BZIP2 is enabled, configure or a test preflight must fail clearly if ID 307 is absent or lacks both encoding and decoding capability; never skip the BZIP2 tests silently. When disabled, make the optional dependency explicit. Confirm the external plugin works with nep-compress's one-parameter create/reopen path; no old-file interoperability claim is required.

## Baseline Verification (Local, 2026-10-17)

- Local tools exist: `/usr/local/netcdf-c/bin/nc-config` reports `4.10.2-development`, `/usr/local/netcdf-fortran/bin/nf-config` reports `4.6.2`, and `/usr/local/hdf5-2.1.1/bin/h5cc -showconfig` reports HDF5 `2.1.1`.
- A read-only Python `ctypes` probe loading `/usr/local/hdf5-2.1.1/lib/libhdf5.so` and calling `H5open()` / `H5Zfilter_avail(307)` and `(32004)` returned `1` for both with `HDF5_PLUGIN_PATH=/usr/local/netcdf-c/hdf5/lib/plugin`, and `0` for both with `HDF5_PLUGIN_PATH=/nonexistent`. This proves discovery in this environment, not correctness of encoding/decoding, plugin origin or NetCDF interoperability. The BZIP2 shared object depends on `libbz2.so.1.0`.
- The pre-existing `build/CMakeCache.txt` points at HDF5 1.14.6, LZ4 ON and BZIP2 OFF, but the tree is incomplete: `ctest --test-dir build -N` reports **0 tests**. It cannot serve as the required HDF5 2.1.1 regression baseline. No build directory was deleted or reconfigured.
- No C/Fortran round trips were run in Sprint 1; the independent nep-compress implementation did not yet exist. Old-NEP/new-project interchange tests are no longer required.

**Open at the time:** The BZIP2 binary's upstream license/provenance had not been established; the LZ4 plugin's referenced upstream `COPYING` needed checking. The incomplete NEP `build` directory did not provide a usable old-NEP test baseline; that baseline is no longer a cutover requirement.

For NEP's later format-only regression build, inspect and obtain approval before replacing its existing `build` directory per `AGENTS.md`. Pin `PATH`, `PKG_CONFIG_PATH`, `CMAKE_PREFIX_PATH`/`HDF5_ROOT`, and runtime library paths to the local installations. An old-NEP compression build is not required for cutover.

## Sprint 2 Independent Test Procedure

1. Create deterministic multichunk files with nep-compress, one per filter (LZ4 level 3, BZIP2 level 8); reopen with its plugin setup and compare dimensions, chunk sizes, IDs, parameters and values.
2. Exercise its C and Fortran inquiries where enabled. Test with plugins present and missing, including encoder/decoder capability. Inspect `ldd`/RPATH and `nc-config`/`nf-config` to avoid accidentally mixing HDF5 installations or resolving symbols from `libnep`.
3. Test nep-compress alongside NEP format libraries for plugin/module collisions. Keep the old NEP path intact until the new project builds independently and CI covers both filters. Old-NEP/new-project file interchange is not a blocker.
