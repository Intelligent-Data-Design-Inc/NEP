# v4.2.0 Sprint 2: Standalone nep-compress Build and Tests

## Goal

Make `/fast/ed/nep-compress/` build, install, and test the LZ4/BZIP2 compression APIs independently of NEP, while NEP's current implementation remains intact. Follow the [Sprint 1 inventory and decisions](v4.2.0-sprint1-results.md) and the [v4.2.0 roadmap](../roadmap.md). CI, full user documentation, and removal of compression from NEP are Sprints 3 and 4.

## Prerequisites and Boundaries

- Resolve the Sprint 1 open gates before claiming success: identify redistribution terms for `hdf5_plugins/LZ4/src/H5Zlz4.c` and a reproducible source/package for the external BZIP2 plugin. Do not copy the installed BZIP2 binary into the new repository.
- Establish a baseline for the *old* writer before extraction. NEP's existing `build` directory is incomplete (`ctest -N` found zero tests) and points at HDF5 1.14.6. Inspect it and obtain approval before deleting it for a fresh `build` per `AGENTS.md`; never treat a partial build as a passing baseline.
- Use `/usr/local/netcdf-c`, `/usr/local/netcdf-fortran`, and `/usr/local/hdf5-2.1.1` consistently for configure, link, and runtime. The BZIP2 plugin is currently found in `/usr/local/netcdf-c/hdf5/lib/plugin`; prove compatibility with the selected HDF5 rather than relying on its location alone.
- Keep NEP source, targets, headers, CTest, logging, UDF readers, NEXTCDF-4, and package recipes unchanged in this sprint. Port only the compression portions into the separate repository. Do not introduce an NEP dependency or copy `nep_logging.h`, `nep_log()`, or `nep_set_log_level()`. Comment out any logging statements encountered in extracted compression code, but preserve error handling.

## Implementation Sequence

### 1. Capture the old behavior

1. Configure a clean NEP `build` with both filters on, Fortran on, docs off, and the three local dependency prefixes pinned. Set `HDF5_PLUGIN_PATH` to include both NEP's locally built LZ4 plugin and the external BZIP2 provider. Confirm the correct `libnetcdf` and `libhdf5` with `nc-config`, `nf-config`, CMake cache, and `ldd`; run registered C, Fortran, and HDF5 compression tests. Record each result, including failures or skips.
2. With the old NEP API, generate small persistent LZ4 and BZIP2 NetCDF-4 fixtures (levels 3 and 8) containing deterministic data over multiple chunks. Record their SHA-256 hashes, filter IDs, one-element parameter arrays, dimensions, and expected values. Keep fixtures in the *test output* unless committing small, stable files is justified.
3. Record current missing-plugin behavior and single- vs multi-filter inquiry behavior as baseline observations. Do not silently "fix" unrelated legacy behavior while moving code.

### 2. Create standalone build targets

1. Add a CMake-only root project in nep-compress with options `NEPCOMPRESS_BUILD_LZ4=ON`, `NEPCOMPRESS_BUILD_BZIP2=OFF`, `NEPCOMPRESS_ENABLE_FORTRAN=ON` and `BUILD_TESTING`. Discover NetCDF-C, HDF5 and, when enabled, NetCDF-Fortran; find liblz4 only for the built LZ4 plugin. Match the NetCDF-C/HDF5 installation pair used by the executable; fail clearly on incompatible or missing required dependencies.
2. Extract the four C functions and `LZ4_ID=32004` / `BZIP2_ID=307` into `include/nep_compress.h` and a shared `libnepcompress`. Keep names, C signatures, level range (1-9), NULL inquiry outputs, `NC_EINVAL` for invalid levels and `NC_EFILTER` for unavailable plugins. Depend on NetCDF/HDF5 directly, not `libnep` or its logging API. Avoid copying UDF slot constants and NEXTCDF-4 code.
3. Extract the four `nf90_*` wrappers into `module nep_compress`, built as `libnepcompressf` with `nep_compress.mod` in a dedicated install location. Preserve the 1-based to 0-based varid adjustment. Do not install `nep.mod` or alter NEP's existing module in this sprint.
4. Build `libh5lz4.so` from the verified LZ4 source and install it under `${CMAKE_INSTALL_LIBDIR}/plugin`. Stage the build-tree plugin in one predictable path used by CTest. Preserve ID, parameter usage and on-disk chunk encoding; do not rebuild the entire copied upstream `hdf5_plugins` superproject if the direct source target suffices.
5. BZIP2 remains externally provided. When enabled, accept `NEPCOMPRESS_BZIP2_PLUGIN_DIR` pointing to the directory containing a compatible HDF5 plugin; verify in a probe using the selected HDF5 that ID 307 has both encoder and decoder before registering tests. Fail clearly if absent; libbz2 by itself is insufficient. Do not falsely claim to install `libh5bzip2.so`. When disabled, do not require that plugin.
6. Install the public header, libraries, module, plugin, and useful CMake exports. Validate installation to a private staging prefix without touching `/usr/local`; compile a C and a Fortran client using only the staged nep-compress artifacts and the selected NetCDF/HDF5 dependencies.

### 3. Port and extend tests

1. Port `test/tst_lz4.c`, `test/tst_bzip2.c`, `test_h5/tst_h_lz4.c`, `test_h5/tst_lz4_size.c`, `test_h5/tst_h_bzip2.c`, and `ftest/ftst_nep_lz4.F90` / `ftest/ftst_nep_bzip2.F90`. Replace includes, module imports and links; register each in CTest instead of relying only on a shell runner. Existing tests that write a file must run in separate working directories or use distinct output names to permit parallel CTest.
2. Test invalid levels, absent filter, enabled filter inquiry including NULL outputs, round-trip writes/reopen/read, and raw HDF5 filter discovery. Use explicit test environment paths for the built LZ4 plugin and *external* BZIP2 plugin; the old `test_h5` BZIP2 environment points only to the LZ4 directory and must not be replicated.
3. Add compatibility checks for old-NEP fixtures read by nep-compress and new-nep-compress fixtures read in the unchanged NEP setup. Compare values, filter IDs, parameters, and chunk metadata; use separate processes/paths so one loaded filter provider cannot mask a missing plugin. Test both directions for both algorithms; do not substitute `H5Zfilter_avail` alone for a data test.
4. Test the build matrix: LZ4 only (default), BZIP2 only with the plugin, both with Fortran on/off, and a missing BZIP2 plugin failure. Check disabled features do not leave unresolved symbols. Run a consumer with NEP format libraries installed alongside nep-compress to detect duplicate plugin IDs, library or module collisions; NEP still ships compression in Sprint 2, so isolate plugin paths and do not load two implementations for ID 32004 in one process.

## Local Verification Recipe

After handling any existing `build` directory safely, configure nep-compress from its root with:

```sh
export PATH="/usr/local/hdf5-2.1.1/bin:/usr/local/netcdf-c/bin:/usr/local/netcdf-fortran/bin:$PATH"
export PKG_CONFIG_PATH="/usr/local/netcdf-c/lib/pkgconfig:/usr/local/netcdf-fortran/lib/pkgconfig:$PKG_CONFIG_PATH"
cmake -S . -B build \
  -DCMAKE_PREFIX_PATH="/usr/local/hdf5-2.1.1;/usr/local/netcdf-c;/usr/local/netcdf-fortran" \
  -DHDF5_ROOT=/usr/local/hdf5-2.1.1 \
  -DNEPCOMPRESS_BUILD_LZ4=ON -DNEPCOMPRESS_BUILD_BZIP2=ON \
  -DNEPCOMPRESS_BZIP2_PLUGIN_DIR=/usr/local/netcdf-c/hdf5/lib/plugin \
  -DNEPCOMPRESS_ENABLE_FORTRAN=ON -DBUILD_TESTING=ON
cmake --build build
ctest --test-dir build --output-on-failure
cmake --install build --prefix "$PWD/build/stage"
```

The implementation must define/document `NEPCOMPRESS_BZIP2_PLUGIN_DIR` and set the CTest environment to include the built LZ4 plugin and the configured BZIP2 plugin directory; passing the CMake variable alone does not set `HDF5_PLUGIN_PATH` at test time. Confirm `ldd` resolves the selected installations and that `ctest -N` lists the enabled tests before claiming a pass. Use a separate clean `build` configuration for each matrix entry; do not run these commands against NEP's incomplete build.

## Acceptance Criteria and Handoff

- Standalone CMake build and private install work without any NEP checkout, `libnep`, or NEP logging symbols. The installed header and Fortran module use the migration names from Sprint 1 and do not collide with NEP's files.
- All enabled C, HDF5, and Fortran tests are registered and pass against the three pinned local prefixes; BZIP2 enabled with no working plugin fails visibly. Fortran-off and per-filter configurations build and test as specified.
- Old/new files are readable in both directions for both filters; data and filter metadata match, and plugin discovery is demonstrated in isolated processes. No new dependency on compression is introduced into NEP format readers or NEXTCDF-4.
- Record build commands, tool/library versions, CTest results, missing-plugin results, and unresolved provenance/licensing issues for Sprint 3. Do not begin Sprint 4 cleanup until standalone CI and documentation (Sprint 3) also pass.
