# V4.3.0 Sprint 1V4: SWMR Writer Support

Source: docs/roadmap.md, "V4.3.0 - NEXTCDF4 Development / Sprint 1V4".

## Goal

A native NEXTCDF-4 file can publish updates from one serial writer to independently running HDF5 SWMR readers without closing the writer. Applications can request the writer session at create/open time or explicitly start it after defining the schema. Fixed-size atomic data, unlimited-dimension growth, filters, frozen metadata and whole-file publication have a documented, tested contract; ordinary serial and MPI sessions remain unchanged. NEP reader refresh support remains Sprint 1V5.

## Decisions

| Topic | Decision |
|---|---|
| Ed's answers | `1c 2a 3a 4a 5a`. |
| Activation (1c) | Both `NC_SWMR_WRITE` on create/open and `int nc_start_swmr_write(int ncid)`. Creates defer activation to successful enddef; writable opens activate after loading/validating metadata. Explicit start commits pending definitions first. |
| Compatibility (2a) | Native NEXTCDF-4 only. Reject classic-model, NetCDF-4-model and MPI-IO sessions; do not silently change their on-disk bounds or model markers. |
| Types/schema (3a) | Fixed-size atomic variables, including small floats, complex and bitfields. Reject string/reference/user-defined variable types at activation. Freeze schema and attributes once active. No user-defined datatype lifecycle expansion. |
| Publication (4a) | `int nc_swmr_flush(int ncid)` publishes the entire file. Active-writer `nc_sync` uses the same path. No atomic multi-variable record, rollback, crash-recovery or power-loss durability promise. |
| Tests (5a) | A separately executed raw-HDF5 SWMR reader verifies the NEP writer in existing normal and ASan/UBSan full suites. No NEP reader API is pulled into 1V4. |
| Packaging | Always available with existing NEXTCDF-4 support: no new build option, dependency floor, library, header file, plugin path or install-layout change. Link the new functions from `libncnextcdf4`, not `libnep`. No Spack/conda recipe change. |
| Release | Sprint 2 owns release notes, tag and packaging publication. No implementation, commit or push during refinement. |

## Current state (2026-11-25)

- `docs/roadmap.md` assigns writer support here, NEP readers/refresh and the expanded usage guide to 1V5, and VDS/image/mmap/direct-chunk features to v4.4.0. This sprint references no GitHub issue. Earlier parallel plans (`v4.3.0-sprint1V1-*`, `1V2-*`, `1V3-*`) explicitly hand SWMR here; preserve their MPI and fixed-size transfer contracts. Earlier session-control/string/provenance deferrals are historical, not reasons to expand this sprint to dynamic data or Fortran.
- `src/nextcdf4/nxt4create.c` uses `H5F_LIBVER_LATEST` bounds for native files and `H5F_LIBVER_V110` for model files. It creates markers and root handles immediately. `nxt4open.c` loads all metadata after ordinary `H5Fopen`; neither path activates SWMR. Native format bounds do not make an ordinary write session a SWMR session.
- `nxt4file.c:NEXTCDF4__enddef` commits types, rebuilds dirty variable datasets, flushes pending attributes and writes provenance before leaving define mode. `NEXTCDF4_redef` and `nxt4meta.c:NEXTCDF4_check_write_define` permit re-entry. They need active-writer guards. `NEXTCDF4_sync` currently writes provenance then calls `H5Fflush`; close also writes provenance.
- `nxt4internal.h:NEXTCDF4_FILE_INFO_T` has no SWMR state. Variable datasets and dimension-scale datasets may have separate handles referring to one object; cache changes already reopen aliases (`nxt4meta.c:nx4_reopen_var_cache`). Do not introduce stale identifiers or reopen the file to activate SWMR.
- `nxt4io.c:var_io` extends a variable and its unlimited scales before `H5Dwrite`; logical lengths live in `NC_DIM_INFO_T.len`. Extent changes can therefore become observable before a complete multi-variable timestep. Publication is not a transaction.
- Installed `/home/ed/local/hdf5-2.1.1_mpi/include/H5Fpublic.h` declares `herr_t H5Fstart_swmr_write(hid_t file_id)`. Its contract requires writable/latest-format state and no open attributes or committed datatypes. Groups and datasets may remain open. The same header defines `H5F_ACC_SWMR_READ`; it does not declare `H5Fstart_swmr_read`. `H5Dpublic.h` declares `H5Dflush` and `H5Drefresh` and distinguishes flush from reader-side cache reload. Flush does not guarantee physical persistence under power loss.
- Local HDF5 source `H5Fint.c` checks actual superblock v3 and a SWMR-capable VFD. Existing old-format files must not be upgraded implicitly. The installed skill's model-mode/superblock descriptions are partly stale relative to current code; use code and installed HDF5 contracts, not the skill's historical compatibility claims.

Local upstream `libdispatch/dinfermodel.c:NC_omodeinfer` extracts the UDF slot with a mask; registration must still pass bare `NC_NEXTCDF4`, not the combined mode. End-to-end forwarding of the new bit needs the regression specified below; it has not been experimentally verified.

## Work items

### 1. Define public interfaces and private session state

Files: `include/nep.h`, `src/nextcdf4/nxt4internal.h`, `src/nextcdf4/nxt4file.c`.

- Add `#define NC_SWMR_WRITE 0x08000000`, explicitly a NEP native NEXTCDF-4 create/open flag, not an upstream NetCDF constant. Do not change UDF registration or reuse `NC_SHARE`/deprecated MPI bits.
- Declare and implement `int nc_start_swmr_write(int ncid);` and `int nc_swmr_flush(int ncid);` in the existing installed header and `nxt4file.c`, respectively. Both are exported by `libncnextcdf4`; consumers link that library. Declarations remain safe for C++ consumers and require no private headers. Availability follows `NEP_HAS_NEXTCDF4`; no new feature macro or fallback symbols in `libnep`.
- Add session-only `int swmr_requested; int swmr_active;` to file state, zero-initialized. Requested is set by the flag; active changes only after successful HDF5 activation. Never persist a new NEP marker or infer session activation merely from historical file contents.
- New private helpers: `int nx4_swmr_validate(NC_FILE_INFO_T *h5, NEXTCDF4_FILE_INFO_T *file);`, `int nx4_swmr_activate(NC_FILE_INFO_T *h5, NEXTCDF4_FILE_INFO_T *file);`, `int nx4_swmr_flush(NC_FILE_INFO_T *h5, NEXTCDF4_FILE_INFO_T *file);`. Activation helper requires committed data-mode metadata and must not call enddef recursively.
- Validate public ncids through NetCDF's dispatch identity before casting private state: invalid/closed IDs return `NC_EBADID`; valid non-NEXTCDF-4 IDs return `NC_ENOTNC4`. Subgroup IDs operate on their owning file. No new error constants.
- Installed-header Doxygen blocks fully describe arguments, linkage, deferred create semantics, frozen schema, allowed types, flush limits, failure behavior and every return code. Use `@author Edward Hartnett, Intelligent Data Design, Inc.`.

### 2. Integrate flag and explicit activation into create/open/enddef

Files: `nxt4create.c`, `nxt4open.c`, `nxt4file.c`, `nxt4internal.h`.

- Flagged create rejects compatibility flags, MPI parameters and existing unsupported flags before unlink/create or communicator duplication (`NC_EINVAL`). It returns an ordinary writable define-mode file with `swmr_requested=1`, not an already active writer. The application may define its schema until the first successful enddef or automatic enddef on write.
- Flagged open requires `NC_WRITE`, a serial session and native model; invalid combinations return `NC_EINVAL`. Validate restored model markers after metadata load as well as caller flags, so omitting a compatibility bit cannot bypass the native-only restriction. Open with ordinary read/write HDF5 access, load/validate schema, then activate before returning success. Cleanup all handles on failure; never unlink an existing opened file.
- Explicit start rejects read-only (`NC_EPERM`), compatibility/MPI (`NC_EINVAL`), unsupported schema (`NC_ENOTBUILT`) and invalid file format (`NC_EINVAL`) before committing anything. If already active, return `NC_NOERR` without another HDF5 activation. Set requested temporarily, enddef if needed, then activate once; enddef itself uses the same helper after successful metadata commitment. Avoid a second activation when enddef already performed it.
- Preflight the complete metadata tree. Permit standard fixed-size atomic variables, small floats, complex and bitfield variables; reject `NC_STRING`, `NC_STD_REF` and all user-defined variable types with `NC_ENOTBUILT`. Also reject declared user types (including unused/attribute-only types) rather than adding committed-type close/reopen machinery. This conservative schema restriction must be explicit in docs/tests. Pre-existing atomic attributes may remain, but none may be modified after activation.
- Perform type/schema preflight before a flagged create's enddef commits deferred user types. A validation failure leaves an explicit-start/create session inactive, usable and closable; caller may close/reopen without the flag for ordinary work. Do not repeatedly force failed activation during close: close finalizes inactive requested files as ordinary files and never starts SWMR just to close. A failed flagged open closes its internal state and returns no ncid.
- Query actual superblock via `H5Fget_info2` and require version 3; reject old files without upgrade. Query the file's actual VFD feature flags using its access property list/driver and `H5FDdriver_query`, requiring `H5FD_FEAT_SUPPORTS_SWMR_IO`. Do not equate a parallel-built library with an MPI-IO session: serial SWMR must work with the parallel dependency build too.
- After validating an opened file's actual superblock/model, set its session bounds with `H5Fset_libver_bounds(file->hdfid, H5F_LIBVER_LATEST, H5F_LIBVER_LATEST)` before activation; ordinary open currently does not set latest bounds. This is not permission to convert an old-superblock file. Finish pending types/datasets/scales/attributes/provenance and flush before `H5Fstart_swmr_write`. Existing open groups/datasets stay owned. No attributes or committed datatypes may be open. Schema validation excludes declared committed user types; ensure transient attribute handles have been released by existing writers/loaders. HDF5 activation errors return `NC_EHDFERR`; active stays false. Failed start does not promise rollback of already committed ordinary definitions.
- On success set active/requested and the effective `NC_SWMR_WRITE` mode bit for format inquiry. Explicit activation and flagged activation produce the same state. Reopening without the flag creates an ordinary session; activation is not persistent API state.

### 3. Freeze schema and preserve ordinary operations

Files: `nxt4file.c`, `nxt4meta.c`, `nxt4group.c`, `nxt4type.c`, `nxt4filter.c`, `nxt4ref.c`, `nxt4io.c`, `nxt4provenance.c`.

- Add the active-writer rejection to `NEXTCDF4_check_write_define` and `NEXTCDF4_redef`, and audit every mutator that bypasses this common guard. Return `NC_EPERM` before modifying memory or HDF5 for define/insert type, define dimension/variable/group, group/dimension/variable rename, attribute create/replace/rename/delete and file-default fill changes. An active writer cannot re-enter define mode, explicitly or implicitly.
- Storage/filter/fill/endian/quantize setters on committed variables retain their existing `NC_ELATEDEF` behavior; preserve argument-validation precedence where already tested. They must never rebuild/create datasets in active SWMR. Cover setters whose implementation does not use the common define guard.
- Existing attributes, schema inquiries and data reads remain allowed. Chunk-cache tuning remains session-only and allowed: preserve existing alias/token ownership and validate it after SWMR activation. No dataset creation, scale reattachment or attribute rewrite may occur as a side effect of cache tuning or data writes.
- Reject reference-creation helpers on active files with `NC_EPERM`; reference variable schemas are already excluded. Preserve serial reference behavior elsewhere.
- Leave fixed-size atomic write/conversion/quantization behavior intact, including completed-I/O `NC_ERANGE`, empty selections, striding and zero-count no-growth. Do not invent append-only enforcement: existing in-bounds writes are permitted and documented as potentially observable updates.
- Preserve current grow-variable/grow-scale/write semantics and shared-dimension maximum lengths. Do not claim a dimension length is a record-completion indicator. Readers must use an application completion protocol if several variables comprise one logical record. No promise that unflushed writes are invisible: HDF5 may flush opportunistically.
- Materialize provenance before activation; active sync/close must skip provenance/attribute rewrites. Close flushes, releases all aliases and clears HDF5 SWMR session status through normal close. Abort retains the existing close-style semantics and is not a transaction rollback. Ordinary inactive serial/MPI files retain current behavior.

### 4. Implement whole-file publication

Files: `nxt4file.c`, `nxt4internal.h`.

- `nc_swmr_flush` requires an active writable SWMR session; read-only returns `NC_EPERM`, inactive sessions return `NC_EINVAL`. It does not implicitly request/start SWMR or enter define mode.
- Walk the entire root/subgroup tree deterministically, calling `H5Dflush` for every variable dataset, then for dimension-scale datasets. Coordinate dataset aliases may be deduplicated by HDF5 object token using existing alias conventions; flushing an alias twice is also safe, but never close an alias as part of flushing. Finish with `H5Fflush(file->hdfid, H5F_SCOPE_GLOBAL)`.
- Active `NEXTCDF4_sync` uses exactly that helper; active close invokes it before releasing objects. Attempt normal cleanup even when close-time flushing fails, returning the flush error in preference to a later cleanup error. Inactive `nc_sync` remains unchanged.
- Return `NC_EHDFERR` for HDF5 flush failures; a partial flush is not rolled back. Never call `H5Drefresh` on writer datasets: refresh belongs to readers. Do not add `fsync`, filesystem cache manipulation or benchmark timing code to this API.
