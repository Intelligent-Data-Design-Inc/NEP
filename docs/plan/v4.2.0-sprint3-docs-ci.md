# v4.2.0 Sprint 3: nep-compress Documentation and CI

## Goal

Make `/fast/ed/nep-compress/` independently understandable, buildable, and testable from its GitHub checkout. Use the [Sprint 1 ownership contract](v4.2.0-sprint1-results.md) and [Sprint 2 status](v4.2.0-sprint2-results.md). Do not remove compression from NEP: that is Sprint 4, after the old-writer compatibility gate passes.

## Work in dependency order

1. **Reconcile documentation with the implementation.** Transfer `docs/compression.md` concepts into nep-compress, correcting NEP-era claims: LZ4 defaults ON, BZIP2 defaults OFF and needs an *external* HDF5 plugin for filter 307; Fortran is optional; CMake is the only supported build. Document the actual `NEPCOMPRESS_*` options, header, libraries, module and plugin path from the current code. Link the local LZ4 on-disk format specification. Keep historical performance claims labeled as historical or drop figures without a reproducible generator.
2. **Make the README a standalone entry point.** Explain the split from NEP as a way to simplify compression installation for users, link back to NEP for UDF formats/NEXTCDF-4, and provide clean configure/build/CTest/private install instructions and C/Fortran examples. Show how to obtain an external filter 307 plugin, how to set `HDF5_PLUGIN_PATH` for writing *and* reading, and how to migrate `<nep.h>`/`use nep` and link targets. Note NEP still bundles its old APIs until Sprint 4.
3. **Keep benchmark outputs with their sources.** Transfer LZ4/BZIP2-specific benchmark source, corresponding CSV/plot scripts, and metadata together if documenting their results. Do not drag in unrelated general NetCDF performance programs or make large benchmarks part of normal CI.
4. **Add independent GitHub Actions.** Use a single compatible dependency stack (NetCDF-C >=4.10.1, HDF5 >=1.14, NetCDF-Fortran when enabled, liblz4), and an *identified* external BZIP2 HDF5 plugin built for that HDF5. Configure LZ4-only and both-filter jobs with explicit options. Fail visibly if enabled filter 307 is missing or lacks encode/decode. Check CTest registration and execute C/HDF5/Fortran round trips; test install and a downstream CMake consumer. Do not silently skip BZIP2 or claim CI success based only on plugin discovery.
5. **Verify and record.** Run local docs link/command checks, CTest, and YAML validation when available. Review exact CI dependency package names/plugin ID before publishing. Leave Github Actions run status unverified until a workflow executes on GitHub; never claim a local YAML check is a successful GitHub run.

## Acceptance and deferrals

- A user can follow the README without a NEP checkout. The compression guide and README agree with build defaults and plugin provisioning; moved benchmark artifacts do not depend on dead NEP links.
- The independent workflow has a runnable path for LZ4 and BZIP2 and treats missing required coverage as failure. Record its real GitHub run URL/status separately; the workflow cannot be validated fully by local inspection.
- NEP's existing `build` directory and source remain untouched without approval. Old-NEP-writer/new-reader and reciprocal API tests from Sprint 2 remain an explicit blocker for Sprint 4; plugin-to-plugin LZ4 tests are not a substitute.
