# v4.2.0 Sprint 3: Documentation and CI Status

The separate `/fast/ed/nep-compress/` repository now has a standalone
README, `docs/compression.md`, optional LZ4/BZIP2 performance examples
with their historical CSV files, plot scripts and metadata, and
`.github/workflows/ci.yml`. NEP's active compression documentation
remains in place until the Sprint 4 cutover, so existing NEP users are
not sent to an unverified replacement prematurely.

## Local verification (2026-10-17)

- Local README/guide/performance links resolve. The guide reflects
  CMake defaults (LZ4 ON, BZIP2 OFF), the independent C/Fortran
  header/module names, and the *external* BZIP2 HDF5 plugin requirement.
- Optional benchmark targets compile with both filters enabled;
  they were not run (the datasets are large). The moved CSV files
  are historical, not new performance measurements.
- The existing local `build` was reconfigured after adding the
  benchmark option: standalone CMake build and 13/13 CTest tests
  passed against the pinned NetCDF-C/Fortran and HDF5 2.1.1
  installations. The benchmark option was then restored to OFF.
- The Conda environment and workflow YAML parse locally. CI checks
  filter 307 with a compatible external `hdf5plugin` package from the
  same Conda stack as HDF5; the CMake preflight rejects unavailable
  or decode-only providers. CI has LZ4-only, BZIP2-only and
  both-filter jobs, runs CTest and builds an installed consumer.

## Remaining gates

- The workflow has not been pushed or executed on GitHub. The
  Conda package combination, BZIP2 provider behavior, and GitHub
  Action versions have **not** been validated in a hosted run.
  Its presence is not evidence that GitHub CI passes.
- The Sprint 2 old-NEP-writer vs new-reader and reciprocal API/file
  tests remain blocked by NEP's incomplete `build` directory;
  no user approval to delete it has been granted. Do not begin
  the Sprint 4 removal on the basis of plugin-to-plugin tests.
- LZ4 plugin source provenance/redistribution notice is still
  unresolved; investigate it before publishing/releasing the
  new repository. No external BZIP2 plugin binary was copied into
  nep-compress.
