# v3.3.0 Sprint 3: More Testing of PDB Reading

## Sprint Goal and Scope

Expand regression coverage for the legacy PDB UDF reader (UDF7) beyond the
single-model X-ray files used in Sprint 2, enable the reader by default, and
add a Fortran smoke check. The work is strictly test/data/CI coverage; no new
PDB record parsing is introduced.

In scope:
- Acquire and redistribute one multi-model NMR ensemble from RCSB and one
  single-model synthetic PDB file without a `CRYST1` record (AlphaFold DB direct
  download returned 404 for multiple UniProt IDs during data acquisition).
- Extend `test/tst_pdb_udf.c` to verify multi-model coordinate reads and
  optional-record handling (e.g., files without `CRYST1`).
- Flip `NEP_ENABLE_PDB` from OFF to default ON in `CMakeLists.txt`.
- Add `ftest/ftst_pdb_udf.F90` as an open/close smoke check on one real PDB file.
- Update `.github/workflows/ci-pdb.yml` to validate the default-ON configuration.

Out of scope (deferred to Sprint 4 or later):
- `SEQRES`-derived sequence data.
- Hybrid-36 encoded serial/residue numbers.
- Multi-character chain IDs.
- Visualization examples or user-facing documentation (Sprint 4).

## Major Tasks (dependency order)

1. **Acquire test data**
   - Download one small multi-model NMR ensemble from https://www.rcsb.org
     (public domain). Selected: `1GAB.pdb` (56-residue B1 domain of
     streptococcal protein G, 20 models, public domain).
   - Generate one single-model synthetic PDB file without a `CRYST1` record
     (`no_cryst1.pdb`) because AlphaFold DB direct download returned 404 for
     multiple UniProt IDs.
   - Place both files in `test/data/PDB/`.
   - Document provenance, download URL, file size, PDB ID, and license in this
     sprint plan (under "Test Data Provenance" below) and in a short
     `test/data/PDB/README.md`.

2. **Update build defaults and test data copying**
   - Change `option(NEP_ENABLE_PDB "Enable legacy PDB reader support" OFF)` to
     `ON` in `/home/ed/NEP/CMakeLists.txt`.
   - Add `configure_file()` entries in `test/CMakeLists.txt` for the two new
     PDB files so they are copied into `data/PDB/` in the build tree.

3. **Extend C test coverage in `test/tst_pdb_udf.c`**
   - Add a helper that opens a file, verifies the `model` dimension length,
     and reads `atom_site_Cartn_x/y/z` for a fixed atom index from two different
     models, asserting the values differ.
   - Add a helper that opens a file known to lack `CRYST1` and confirms the
     file opens while the `cell_*` and `space_group_name_H-M` attributes are
     absent (or simply not required in the existing per-file test table).
   - Keep the existing `1J7W.pdb` and `4HHB.pdb` checks for regression.

4. **Add Fortran smoke check `ftest/ftst_pdb_udf.F90`**
   - Model after `ftest/ftst_fits_udf.F90`.
   - Bind to `NC_PDB_initialize()` via `iso_c_binding`.
   - Open one real PDB file from `../test/data/PDB/` read-only and close it.
   - Add the build/test block in `ftest/CMakeLists.txt` when `HAVE_PDB` is set,
     linking `ncpdb`, `nepf`, and `nep`.

5. **Update CI**
   - In `.github/workflows/ci-pdb.yml`, remove any explicit
     `-DNEP_ENABLE_PDB=ON` so the workflow exercises the new default.
   - Ensure `NEP_ENABLE_FORTRAN=ON` is present so `ftst_pdb_udf` is built and
     run.

6. **Run tests and fix regressions**
   - Configure a clean build with default options (PDB should be ON).
   - Run `ctest --test-dir build -R pdb --output-on-failure`.
   - Run the full CTest suite with PDB enabled and with PDB explicitly
     disabled (`-DNEP_ENABLE_PDB=OFF`) to confirm no regressions.
   - Confirm the updated `ci-pdb.yml` job passes.

## Acceptance Criteria

  tree by `test/CMakeLists.txt`.
