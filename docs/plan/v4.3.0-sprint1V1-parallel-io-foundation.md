# v4.3.0 Sprint 1V1: Parallel I/O Foundation (MPI-IO File Access)

Source: docs/roadmap.md, "V4.3.0 - NEXTCDF4 Development / Sprint 1V1".

## Goal

NEXTCDF-4 files can be created and opened collectively from MPI
programs through the upstream parallel entry points
`nc_create_par()`/`nc_open_par()`. The communicator and info handle
arrive in the dispatch `parameters` pointer, are duplicated into file
state, and configure the MPI-IO virtual file driver plus collective
metadata operations on the FAPL — matching upstream netCDF-4/HDF5
semantics. `var_par_access` and collective/independent data transfers
stay with Sprint 1V2; this sprint delivers file-level parallel access
(HDF5's default independent transfer mode) with a tested MPI stack.

## Decisions

| Topic | Decision |
|-------|----------|
| Create API flags | Users call `nc_create_par(path, NC_NEXTCDF4\|NC_NETCDF4, comm, info, &ncid)`. Upstream `nc_create_par` (netcdf-c built without PnetCDF) returns `NC_ENOTBUILT` unless `cmode & NC_NETCDF4` *before* dispatch — the extra bit is mandatory and documented. `nc_open_par` has no gate; bare `NC_NEXTCDF4` works there. |
| Build gating | New option `NEP_ENABLE_NEXTCDF4_PARALLEL` (default OFF). ON requires `NEP_ENABLE_NEXTCDF4` + MPI C + `HDF5_IS_PARALLEL` + `NC_HAS_PARALLEL4`; missing pieces are `FATAL_ERROR`. Emits `NEP_HAS_NEXTCDF4_PARALLEL` in `nep_meta.h`. |
| MPI linkage | `find_package(MPI REQUIRED C)` when the option is ON; `ncnextcdf4` links `MPI::MPI_C`. MPI code lives in existing `nxt4create.c`/`nxt4open.c`/`nxt4file.c`/`nxt4internal.h` under `#ifdef HAVE_NEXTCDF4_PARALLEL`. |
| MPI_INFO struct | Private `NX4_MPI_INFO {MPI_Comm comm; MPI_Info info;}` in `nxt4internal.h` — ABI-identical to upstream's internal `NC_MPI_INFO` (`include/ncdispatch.h`), which is not installed. |
| parameters handling | After `NEXTCDF4_check_mode` (which already rejects `NC_INMEMORY`), `parameters != NULL` means a parallel request. Without `HAVE_NEXTCDF4_PARALLEL` → `NC_ENOPAR`; with it → `H5Pset_fapl_mpio` on the FAPL. `NC_MPIIO`/`NC_MPIPOSIX`/`NC_PNETCDF` mode flags and `NC_PAR` stay rejected/unused; `var_par_access` stays `NC_NOTNC4_var_par_access` (Sprint 1V2). |
| Metadata collectivity | `H5Pset_all_coll_metadata_ops(fapl, 1)` and `H5Pset_coll_metadata_write(fapl, 1)` are set on the FAPL in parallel mode (both exist in HDF5 2.1.1; upstream guards them with `HDF5_HAS_COLL_METADATA_OPS`, unnecessary at 2.1.1). All ranks must make the same define-mode calls — documented. |
| Comm/info ownership | `MPI_Comm_dup` and `MPI_Info_dup` (skipped for `MPI_INFO_NULL`) into `NEXTCDF4_FILE_INFO_T`; freed in `NEXTCDF4_free_file` after `H5Fclose`. `MPI_Comm_free`/`MPI_Info_free` failure → `NC_EMPI` on close. |
| CI | `ci-parallel.yml` updated: netcdf-c built from `main` (64-slot UDF scheme, `--enable-parallel-netcdf4`), NEP configured with `-DNEP_ENABLE_NEXTCDF4=ON -DNEP_ENABLE_NEXTCDF4_PARALLEL=ON -DNEP_ENABLE_PARALLEL_TESTS=ON`; new dependency cache keys. |
| Tests | One MPI program `tst_nextcdf4_parallel` run via `${MPIEXEC_EXECUTABLE} -n 4` under the new ctest label `nextcdf4_parallel`, gated on `NEP_ENABLE_PARALLEL_TESTS` + `HAVE_NEXTCDF4_PARALLEL`. |
| Spack | No new variant: `+nextcdf4+parallel @4.3.0:` implies the feature. `cmake_args` passes `NEP_ENABLE_NEXTCDF4_PARALLEL` for `@4.3.0:`/`@main` only (version-gated so 4.2.0 still builds). Upstream copy ships with Sprint 2's version-bump PR. |

## Current state (2026-11-24)

- Dispatch table: `NEXTCDF4_create`/`NEXTCDF4_open` receive and ignore
  `void *parameters` (`src/nextcdf4/nxt4create.c:68,86`,
  `src/nextcdf4/nxt4open.c:41,51`). `var_par_access` is
  `NC_NOTNC4_var_par_access` (`src/nextcdf4/nxt4dispatch.c:69`).
- Mode rejection: `NEXTCDF4_check_mode` (`src/nextcdf4/nxt4file.c:722`)
  returns `NC_EINVAL` for `NC_DISKLESS|NC_INMEMORY|NC_MPIIO|NC_SHARE|
  NC_PERSIST|NC_MMAP`; `NC_MPIPOSIX`/`NC_PNETCDF` are `NC_MPIIO`
  aliases. It does **not** reject the `NC_NETCDF4` bit, so
  `NC_NEXTCDF4|NC_NETCDF4` passes validation unchanged.
- Upstream plumbing (verified in `/fast/ed/netcdf-c` main):
  `nc_create_par`/`nc_open_par` pack `{comm, info}` into `NC_MPI_INFO`
  and call `NC_create`/`NC_open` with `useparallel=1`
  (`libdispatch/dparallel.c:100-133,207-226`); `NC_create` forwards
  `parameters` to `dispatcher->create` including UDF dispatchers
  (`libdispatch/dfile.c:1966`), likewise `NC_open`
  (`dfile.c:2218`). `NC_infermodel` resolves `NC_UDF_FLAG` before any
  other flag, so `NC_NEXTCDF4|NC_NETCDF4` selects the UDF9 dispatcher.
- `NC_MPI_INFO` is defined only in netcdf-c's *internal*
  `include/ncdispatch.h:93` — it is not installed; NEP must declare an
  ABI-identical struct.
- Upstream reference implementation: `libhdf5/hdf5create.c:91-149`
  (`H5Pset_fapl_mpio` → `NC_EPARINIT`, `MPI_Comm_dup`/`MPI_Info_dup` →
  `NC_EMPI`, `H5Pset_all_coll_metadata_ops`/`H5Pset_coll_metadata_write`
  under `HDF5_HAS_COLL_METADATA_OPS`); `libhdf5/hdf5open.c:713,776,796`
  does the same on open.
- Local MPI stack (AGENTS.md): HDF5 2.1.1 parallel at
  `/home/ed/local/hdf5-2.1.1_mpi`, netcdf-c `main` parallel at
  `/home/ed/local/netcdf-c_mpi` (`NC_HAS_PARALLEL4=1`,
  `NC_HAS_PNETCDF=0`), MPI = `/usr/bin/mpicc` (Open MPI);
  `OMPI_MCA_rmaps_base_oversubscribe=1` needed past 4 ranks;
  `NCRCENV_RC=/dev/null` for isolated runs.
- Configure already detects both prerequisites:
  `HDF5_IS_PARALLEL` → `HDF5_PARALLEL` (`CMakeLists.txt:68-70`) and
  `nc-config --has-parallel4` → `USE_PARALLEL`/`NEP_HAS_PARALLEL`
  (`CMakeLists.txt:107-116,530-533`). `NEP_ENABLE_PARALLEL_TESTS`
  checks `NC_HAS_PARALLEL4` and finds `MPIEXEC_EXECUTABLE`
  (`CMakeLists.txt:176-177,357-380`, `config.h.cmake.in:12`).
  `test_parallel/` is a placeholder with no programs.
- `ci-parallel.yml` installs OpenMPI and builds parallel HDF5 2.1.1 +
  netcdf-c **4.10.1** (10-slot UDF scheme — NEXTCDF-4's 64-slot
  configure check would FATAL_ERROR) + netcdf-fortran, with
  `NEP_ENABLE_PARALLEL_TESTS=ON`, and runs the full ctest under
  `OMPI_ALLOW_RUN_AS_ROOT=1`.
- `test/nextcdf4/CMakeLists.txt` pattern: executable +
  `add_test` + `ENVIRONMENT "NCRCENV_RC=...;NETCDF_RC=...;LD_LIBRARY_PATH=..."`
  and per-test labels.
- Spack: `variant("parallel")` exists and maps to
  `NEP_ENABLE_PARALLEL_TESTS` with `^hdf5+mpi ^netcdf-c+mpi`
  (`spack/repos/spack_repo/nep/packages/nep/package.py:52-56,66-68,82,107`).
- Docs that currently deny parallel support and must change:
  `docs/prfaq.md:214` ("does **not** support parallel I/O"),
  `docs/prd.md:321-322,340`, `docs/design.md:840-841,851`,
  `README.md:190,231`, `docs/nextcdf4.md`, and
  `docs/nextcdf4_status_v4_3_0.md`.

## Work items

### 1. Build option and MPI detection (`CMakeLists.txt`, `config.h.cmake.in`, `include/nep_meta.h.in`)

- Add `option(NEP_ENABLE_NEXTCDF4_PARALLEL "Enable NEXTCDF-4 parallel
  I/O via MPI-IO" OFF)` next to `NEP_ENABLE_NEXTCDF4`
  (root `CMakeLists.txt`, ~line 168).
- When ON, inside the `NEP_ENABLE_NEXTCDF4` block:
  - `find_package(MPI REQUIRED C)`.
  - `if(NOT HDF5_PARALLEL) FATAL_ERROR` — MPI-enabled HDF5 required.
  - Reuse the `check_symbol_exists(NC_HAS_PARALLEL4 "netcdf_meta.h")`
    pattern (lines 359-366) to require parallel netcdf-c;
    `FATAL_ERROR` when absent.
  - `set(HAVE_NEXTCDF4_PARALLEL 1)`, `#cmakedefine` it in
    `config.h.cmake.in`, and set `NEP_HAS_NEXTCDF4_PARALLEL 1` in
    `nep_meta.h.in` (0 otherwise), matching the `NEP_HAS_PARALLEL`
    pattern.
- In `src/nextcdf4/CMakeLists.txt`: when `HAVE_NEXTCDF4_PARALLEL`,
  `target_link_libraries(ncnextcdf4 PRIVATE MPI::MPI_C)`.
- Tests gate: the new parallel ctest is added only when
  `NEP_ENABLE_PARALLEL_TESTS AND HAVE_NEXTCDF4_PARALLEL` — the option
  controls the feature, `NEP_ENABLE_PARALLEL_TESTS` controls whether
  mpiexec tests run.

### 2. File state and MPI plumbing (`src/nextcdf4/nxt4internal.h`, `nxt4file.c`)

- In `nxt4internal.h`, under `#ifdef HAVE_NEXTCDF4_PARALLEL`:
  `#include <mpi.h>`, define `NX4_MPI_INFO {MPI_Comm comm; MPI_Info
  info;}` (ABI twin of upstream `NC_MPI_INFO`), and extend
  `NEXTCDF4_FILE_INFO_T` with `int parallel;`, `MPI_Comm comm;`,
  `MPI_Info info;`, `int comm_duped;`, `int info_duped;`.
- `NEXTCDF4_free_file` (`nxt4file.c:169`): after `H5Fclose`, when
  `file->parallel`, `MPI_Comm_free`/`MPI_Info_free` the duplicated
  handles (each only when duped); failure → `NC_EMPI` folded into
  `ret`.
- Document in the struct comment that `comm`/`info` are owned copies
  valid until close.

### 3. Create path (`src/nextcdf4/nxt4create.c`)

- Remove `(void)parameters;`. After `NEXTCDF4_check_mode` and
  `valid_create_mode`:
  - `#ifdef HAVE_NEXTCDF4_PARALLEL`: if `parameters`,
    cast to `NX4_MPI_INFO *`, `H5Pset_fapl_mpio(fapl, mpi->comm,
    mpi->info)` → `NC_EPARINIT` on failure; then
    `H5Pset_all_coll_metadata_ops(fapl, 1)` and
    `H5Pset_coll_metadata_write(fapl, 1)` → `NC_EHDFERR`;
    `MPI_Comm_dup`/`MPI_Info_dup` (skip dup when `MPI_INFO_NULL`) into
    `file`; `file->parallel = 1`.
  - `#else`: `if (parameters) EBAIL(NC_ENOPAR);` — placed *after*
    `check_mode` so `NC_INMEMORY` still returns `NC_EINVAL`.
- Note in the `@param parameters` doc: non-NULL means
  `nc_create_par`/`nc_open_par` MPI info; `NC_NEXTCDF4|NC_NETCDF4` is
  required at `nc_create_par` because upstream rejects non-`NC_NETCDF4`
  create modes without PnetCDF.

### 4. Open path (`src/nextcdf4/nxt4open.c`)

- Same treatment: non-NULL `parameters` → parallel branch on the FAPL
  before `H5Fopen`; comm/info dup'd into file state; `file->parallel`
  set. Without parallel support → `NC_ENOPAR`.
- `nc_open_par` takes bare `NC_NEXTCDF4` (no upstream flag gate); the
  existing `H5Fis_hdf5` + marker checks are unchanged. `NC_NOWRITE`
  opens get the same mpio FAPL (read-only collective open).

### 5. Tests (`test/nextcdf4/tst_nextcdf4_parallel.c`, `test/nextcdf4/CMakeLists.txt`)

- New MPI program, plain comments only, `Author:` line per convention.
  Flow (all ranks, `MPI_COMM_WORLD`, `MPI_INFO_NULL`):
  `nc_create_par(path, NC_NEXTCDF4|NC_NETCDF4, ...)` → define dim
  `d`=4 and var `v`(`NC_INT`, dim `d`) → `nc_enddef` → each rank
  `nc_put_vara_int` its own 1-element hyperslab → `nc_close` →
  `nc_open_par(path, NC_NEXTCDF4, ...)` → all ranks read all 4 values
  and verify → `nc_close`. Also a second file exercising
  `NC_WRITE` reopen + append-style write, and `nc_sync` mid-run.
- Include `<mpi.h>` + `netcdf_par.h`; `MPI_Init`/`MPI_Finalize`;
  `ERR`-style macros on the shared `nc_tests.h` shim pattern used by
  `nc_test4/` ports, or the simpler local `ERR` convention from sibling
  tests — match whichever `tst_nextcdf4_*` uses.
- CMake: built only when `NEP_ENABLE_PARALLEL_TESTS AND
  HAVE_NEXTCDF4_PARALLEL`; link `ncnextcdf4` + MPI::MPI_C +
  `${NETCDF_LIBRARIES}`; `add_test(NAME tst_nextcdf4_parallel COMMAND
  ${MPIEXEC_EXECUTABLE} -n 4 $<TARGET_FILE:tst_nextcdf4_parallel>)`
  with `LABELS nextcdf4_parallel`, a `parallel/` working subdirectory,
  and the standard `NCRCENV_RC`/`NETCDF_RC`/`LD_LIBRARY_PATH`
  environment.

## Out of scope

- `nc_var_par_access` (`NC_COLLECTIVE`/`NC_INDEPENDENT`), the
  `H5Pset_dxpl_mpio` transfer property, and `var->chunkcache`-style
  per-var parallel state — Sprint 1V2.
- Upstream `tst_parallel*` ports, interchange tests, and parallel
  benchmarks — Sprint 1V3.
- SWMR (`H5Fstart_swmr_write`/`_read`) — Sprints 1V4–1V5.
- A runtime test of the `NC_ENOPAR` path (needs a parallel netcdf-c +
  serial-NEXTCDF-4 build combo not present in CI); the branch is
  compile-time trivial.
- Virtual datasets, `NC_DISKLESS`/`NC_INMEMORY`/`NC_MMAP` — v4.4.0;
  they stay rejected and are incompatible with `nc_*_par` anyway.
- Fortran parallel wrappers, pnetcdf, `NC_PNETCDF` classic-file
  parallel I/O.
- Tag, release notes, conda — Sprint 2.
