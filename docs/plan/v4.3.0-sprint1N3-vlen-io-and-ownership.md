# v4.3.0 Sprint 1N3: Vlen I/O and Ownership

Source: docs/roadmap.md, "V4.3.0 / Sprint 1N3".

## Goal

Vlen variables and attributes, vlens of supported user types, and compounds containing vlens work end to end with predictable ownership and recursive reclamation. Native and NetCDF-4-model files preserve those values and their complete type graphs across reopen and upstream interchange. A dedicated sanitizer CI job guards these dynamic-memory paths.

## Decisions

| Topic | Decision |
|-------|----------|
| Prerequisites | 1N1 fixed-size plumbing and 1N2 recursive member/layout support must pass first. |
| Modes | Native and `NC_NETCDF4_MODEL`; classic model continues rejecting user types (Ed, 1a). |
| Nesting | Full non-string nesting here, including vlens of user types, nested vlens and compounds/arrays containing vlens (Ed, 2a). Reject reference-containing graphs; strings stay with 1P. |
| Tests | Focused ownership/round-trip tests now, selected upstream regression ports in 1N4 (Ed, 3b). |
| Sanitizers | Add a dedicated AddressSanitizer/UndefinedBehaviorSanitizer CI job with leak detection, not just a local gate (Ed, 4b). |
| Element helpers | Put borrows the supplied payload; get copies `len * base_memory_size` bytes into caller storage. Do not reproduce upstream's hard-coded four-byte get size. |
| Public surface | Implement existing netCDF APIs only; no new allocator API, installed file, CMake option or dependency minimum. |

## Current state (2026-11-22)

- `src/nextcdf4/nxt4type.c:NEXTCDF4_def_vlen` uses `sizeof(hvl_t)` and an atomic-only base lookup, then commits immediately. `NEXTCDF4_put_vlen_element(int ncid, int typeid, void *vlen_element, size_t len, const void *data)` and `NEXTCDF4_get_vlen_element(int ncid, int typeid, const void *vlen_element, size_t *lenp, void *data)` both return `NC_ENOTBUILT`.
- Upstream `/fast/ed/netcdf-c/libhdf5/hdf5type.c:NC4_put_vlen_element` assigns `nc_vlen_t.len/p` without allocation. Its get helper copies with a literal `type_size=4`; copying that implementation would break double, byte and compound bases.
- Installed `/usr/local/netcdf-c/include/netcdf.h` defines `nc_vlen_t` as element count plus payload pointer, and exposes `nc_copy_data`, `nc_reclaim_data`, `nc_reclaim_data_all`, and legacy `nc_free_vlen(s)`. `nc_reclaim_data` does not free the outer buffer and must have valid file/type context.
- `nxt4meta.c:add_att` and same-type `NEXTCDF4_get_att` shallow-copy every non-string value; `read_hdf5_att` frees only the top-level read buffer. These paths cannot safely support dynamic payloads. The fixed-size helper signatures/lifetime rules in 1N1 and recursive type graph in 1N2 are planned prerequisites, not present code today.
- `nxt4io.c:var_io` has atomic-only size/memory resolution and conversion assumptions. Vlen I/O must bypass numeric conversion and retain HDF5-allocated payloads for the caller rather than reclaim them before return.
- Sprint 1M already requires the 64-slot netcdf-c scheme to avoid `NC_reclaim_data` aborts on UDF9. Keep that configure-time check; do not revive a 10-slot compatibility path.
- Baseline is 30 passing CTest tests. Local GCC 13.3.0 supports ASan/UBSan; actual sanitized execution of these new paths is not yet verified. CMake 3.28.3 and Doxygen 1.9.8 are installed; local libraries are HDF5 2.1.1 and netcdf-c 4.10.2-development.
- `.github/workflows/nextcdf4.yml` has one `nextcdf4` job using `ubuntu-latest`, pinned netcdf-c `5baa62e6966d3e505b895574dafbd531a4aed360` and HDF5 2.1.1; it builds dependencies, runs all CTest and warning-free docs. It has no sanitizer job. GCC sanitizer runtime availability on CI must be confirmed by the new smoke test, not assumed from an unpinned runner tool version.
- Spack review (`spack/repos/spack_repo/nep/packages/nep/package.py`, `spack/ci/spack.yaml`, `.github/workflows/spack.yml`, `docs/spack.md`): this sprint changes nothing the recipe depends on—no options/cache paths, dependencies/minima, installed layout/files or plugin directories. Sanitizer flags are job-local, not a package variant. No overlay/upstream recipe changes. Conda remains unaffected.
- Parent Sprint 1N cites no GitHub issue; document gaps 1–2 supply the problem statement.

## Work items

### 1. Generalize vlen definitions and the recursive type graph

Files: `src/nextcdf4/nxt4type.c`, `nxt4internal.h`, `nxt4meta.c`.

Resolve vlen bases through the 1N1 context-aware helpers. Use `sizeof(nc_vlen_t)` for the public memory representation, and verify its size/field offsets against `hvl_t` at compile time before relying on direct HDF5 transfer. Extend dependency-ordered commit and reload to vlen bases and compound members containing dynamic values. Do not commit a vlen immediately while a dependency remains mutable; follow the staged type commit from 1N1/1N2. Record the dynamic-content metadata used by netcdf-c's shared copy/reclaim logic, and reconstruct it identically on reopen. Reject cyclic type graphs before recursion.

Native mode accepts supported non-string types recursively; compatibility mode accepts standard enhanced-model types only. Reject `NC_STRING` and `NC_STD_REF` anywhere inside a newly supported graph with `NC_EBADTYPE`; do not silently permit borrowed pointers through fixed-size paths. Ordinary standalone string behavior remains unchanged for 1P.

### 2. Implement both element helpers

File: `nxt4type.c`; signatures stay unchanged.

Validate ncid, vlen type class, element pointer and element-count multiplication. `NEXTCDF4_put_vlen_element` sets the descriptor's count and borrowed payload pointer without copying or taking ownership; require a non-NULL payload only for nonzero length. `NEXTCDF4_get_vlen_element` reports the count and copies the descriptor payload into the caller's supplied storage using the resolved base memory size, never four-byte arithmetic. Require non-NULL `lenp`, and non-NULL output/payload for nonempty data. Zero length permits NULL payload/output. For a dynamic base, this helper copies descriptors only, not recursively owned subtrees: returned inner pointers remain aliases of the source element. Document that these helper aliases must not be independently reclaimed; callers wanting ownership use `nc_copy_data`. Test byte, short, double and compound bases, including empty/overflow/error cases.

### 3. Vlen variable transfer, fills, and attribute ownership

Files: `nxt4io.c`, `nxt4meta.c`, `nxt4file.c`, `nxt4type.c`, `nxt4internal.h`.

Extend `nx4_file_type`, `nx4_memory_type` and size resolution to recursive vlen graphs. Untyped/matching-type var/var1/vara/vars calls transfer `nc_vlen_t` descriptors with matching HDF5 memory types, no `nx4_convert_type`. Preserve unlimited-dimension growth, strided selections, empty selections and existing mode/error checks. Use malloc/free-compatible HDF5 vlen allocation on read so public recursive reclamation is valid. Caller-provided write payloads remain caller-owned; read payload ownership transfers only after successful I/O. On failed reads, reclaim any partial payloads and clear descriptors before returning the structural/I/O error.

Deep-copy dynamic attribute values on put and again on get using `nc_copy_data` and the complete type metadata. A caller may mutate/free input immediately after put, and may reclaim a get result without changing the cached attribute. Extend cached attribute replacement, deletion, `_FillValue`, rewrite-after-rename, pending-attribute flush, close and partial-open cleanup to reclaim recursively exactly once. Audit all `free(att->data)`, fill buffers and shared netcdf metadata deletion so none double-free or leak nested payloads. Before discarding type metadata, use `nc_reclaim_data` on owned dynamic values; do not reclaim borrowed write buffers. HDF5 temporary reads must either transfer ownership into the cache or be deeply copied and reclaimed, not shallow copied and freed. Empty vlen default fills/custom fills must survive the DCPL path and reopen; this is per-variable behavior, not 1O's file-level fill-mode API.

### 4. Focused ownership and interoperability tests

Files: new `test/nextcdf4/tst_nextcdf4_vlen.c`, `test/nextcdf4/CMakeLists.txt`; extend `tst_nextcdf4_user_types.c`/`tst_nextcdf4_compound_arrays.c` for dynamic interaction regressions.

Register enabled `tst_nextcdf4_vlen`. Exercise all four type classes as vlen bases where legal, nested vlens, compounds containing vlens and arrays of vlen fields; no strings/references. Cover native and compatibility modes, variable and global/subgroup/variable attributes, var/var1/vara/vars, differing lengths including zero, unlimited append, fill values, enddef/redefine and reopen. Generate upstream fixtures at runtime and verify both interchange directions for standard types. Compare recursive values and complete type inquiries, not pointer addresses.

Pin helper aliasing separately from owned results. Test mutation/free of source attribute payloads immediately after put; independent duplicate gets; attribute replace/delete/rename; same-type `nc_copy_att`; reclaim with `nc_reclaim_data` before close; legacy `nc_free_vlen(s)` for flat non-nested payloads only. Repeat create/write/read/replace/reclaim/close cycles to expose leaks. Inject invalid arguments and failed-open/type-resolution paths without relying on nondeterministic allocation failure. Newly allocated test data must be released even when assertions fail. Author strings in tests are plain `Author: Edward Hartnett, Intelligent Data Design, Inc.` comments, not Doxygen.

### 5. Dedicated sanitizer CI

File: `.github/workflows/nextcdf4.yml`.

Add a separate job with id/name `nextcdf4-sanitizers`, `runs-on: ubuntu-latest`, using the same HDF5 release and netcdf-c SHA as `nextcdf4`. Install the same build tools, relying on apt's selected GCC package to bring matching sanitizer runtimes. Compile/run a trivial program with `-fsanitize=address,undefined` to verify those runtimes rather than hard-coding versioned runtime packages or a new project dependency. Fail if sanitizer support is unavailable.

Build both dependencies and NEP with `-O1 -g -fno-omit-frame-pointer -fsanitize=address,undefined`, passing `CMAKE_C_FLAGS` and both executable/shared linker flags. Keep NEP `NEP_ENABLE_FORTRAN=OFF`, examples/benchmarks OFF and documentation ON. Use a separate dependency prefix `deps-sanitizers` and cache key beginning `nextcdf4-sanitizers-`, including runner/compiler, HDF5 version, netcdf SHA and sanitizer-flag revision; never reuse ordinary dependency binaries. Each fresh CI checkout builds NEP in `build`.

Set `ASAN_OPTIONS=detect_leaks=1:halt_on_error=1` and `UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1`. Run focused `tst_nextcdf4_(user_types|compound_arrays|vlen)` and then the full CTest suite, serially. Do not disable failing tests, leak detection, or add blanket suppressions. A proven external-library sanitizer defect is reported with a reproducer and remains an explicit blocker for Ed, not silently hidden. Retain ordinary `nextcdf4` docs enforcement; upload sanitizer configure/cache/test logs on failure using artifact name `nextcdf4-sanitizers-logs`. No change to the Spack workflow is needed.

### 6. User and developer documentation

Files: `docs/nextcdf4.md`, `docs/nextcdf4_architecture.md`, `docs/nextcdf4_status_v4_3_0.md`, `docs/plan/NEXTCDF4_plan.md`, relevant user-type claims in `docs/design.md`, `docs/prd.md`, `docs/prfaq.md`.

Document descriptor layout, helper aliasing versus deep copy, owned read buffers, reclaim-before-close, flat-only legacy free functions, nesting restrictions, and sanitizer job requirements. Remove the element-helper stub entries and mark user-type gaps complete only for the supported non-string graphs; preserve the distinct 1P string gaps. Source Doxygen uses `@author Edward Hartnett, Intelligent Data Design, Inc.`. No new public functions; any public addition requires full installed-header Doxygen.

## Verification

Run functional verification using the normal `build` first:

```sh
export LD_LIBRARY_PATH=/usr/local/netcdf-c/lib:/usr/local/hdf5-2.1.1/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}
cmake --build build --parallel 8
ctest --test-dir build -R '^tst_nextcdf4_(user_types|compound_arrays|vlen)$' --output-on-failure
ctest --test-dir build --output-on-failure
cmake --build build --target docs
```

For a local sanitizer build, first obtain specific approval to remove the existing `build` directory (do not run deletion without approval), then configure using dependencies built with the same sanitizer flags, with `SAN_DEPS` set to their absolute prefix:

```sh
export PKG_CONFIG_PATH="$SAN_DEPS/lib/pkgconfig"
export LD_LIBRARY_PATH="$SAN_DEPS/lib"
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug -DCMAKE_PREFIX_PATH="$SAN_DEPS" -DHDF5_ROOT="$SAN_DEPS" -DCMAKE_C_FLAGS='-O1 -g -fno-omit-frame-pointer -fsanitize=address,undefined' -DCMAKE_EXE_LINKER_FLAGS='-fsanitize=address,undefined' -DCMAKE_SHARED_LINKER_FLAGS='-fsanitize=address,undefined' -DNEP_ENABLE_NEXTCDF4=ON -DNEP_ENABLE_FORTRAN=OFF -DNEP_BUILD_EXAMPLES=OFF -DNEP_ENABLE_BENCHMARKS=OFF -DNEP_BUILD_DOCUMENTATION=ON
cmake --build build --parallel 8
ASAN_OPTIONS=detect_leaks=1:halt_on_error=1 UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1 ctest --test-dir build -R '^tst_nextcdf4_(user_types|compound_arrays|vlen)$' --output-on-failure
ASAN_OPTIONS=detect_leaks=1:halt_on_error=1 UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1 ctest --test-dir build --output-on-failure
cmake --build build --target docs
```

First add failing vlen regressions. Normal and sanitized tests must pass with zero ASan/LSan/UBSan findings. Both `nextcdf4` and `nextcdf4-sanitizers` CI jobs must pass, docs remain warning-free, and existing Spack `style`/`spack` jobs remain green. CI sanitizer execution is required even if local dependency instrumentation is unavailable; report that local limitation explicitly.
