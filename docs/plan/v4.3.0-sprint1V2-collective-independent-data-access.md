# v4.3.0 Sprint 1V2: Collective and Independent Data Access

Source: docs/roadmap.md, "V4.3.0 - NEXTCDF4 Development / Sprint 1V2".

## Goal

NEXTCDF-4 applications can select independent or collective transfers per variable through the existing NetCDF parallel API, with correct multi-rank fixed-size data I/O, empty selections, collectively negotiated unlimited-dimension growth, filters and fill regions. Serial behavior and on-disk compatibility remain unchanged. Focused correctness tests run in the existing Open MPI CI job; wider upstream coverage, cross-backend interchange and performance measurement remain Sprint 1V3 work.

## Decisions

| Topic | Decision |
|---|---|
| Ed's answers | All recommendations accepted: 1a, 2a, 3a, 4a. |
| API | Implement `nc_var_par_access` through private dispatch entry `NEXTCDF4_var_par_access(int ncid, int varid, int par_access)`. No new public API, installed header dependency or build option. |
| State | Store session-only `int parallel_access` in `NEXTCDF4_VAR_INFO_T`; initialize explicitly to `NC_INDEPENDENT` on definition and loading. Filters defined in a parallel session force collective mode. Reopen resets access preferences; filtered transfers require explicit collective selection if a loaded variable still has its independent default. |
| Filters (1a) | Integrate all existing filter setters with access selection. Any nonempty filter pipeline forbids setting independent mode; parallel data I/O on such a variable requires collective mode. Mandatory tests use built-in deflate/shuffle/fletcher32, not external plugins. |
| Types (2a) | Support fixed-size standard atomic types, small floats with existing conversion restrictions, complex/bitfield types, enums, opaque types and recursively fixed-size compounds. Parallel variable data I/O for `NC_STRING`, recursively variable-sized user types and `NC_STD_REF` returns `NC_ENOTBUILT` before transfer or extent mutation. Their serial support is unchanged; this sprint does not claim parallel reference-helper or dynamic-payload support. |
| Extension | Collective writes negotiate maxima across the file communicator and extend all affected datasets/scales consistently. Independent writes that need extension return `NC_ECANTEXTEND` before mutation; independent writes inside the existing physical extent remain supported. |
| Empty selections | Collective calls always enter HDF5, including zero-count and entirely fill-only reads; use none-selected memory/file dataspaces and an internal dummy buffer for zero-element calls. No buffer dereference, conversion or extent contribution from zero-element ranks. |
| CI (3a) | Extend `.github/workflows/ci-parallel.yml`, retaining Open MPI and its pinned netcdf-c SHA. Four-rank tests have CTest timeouts and isolated working directories. No new MPI matrix, sanitizer job or dependency build. |
| Failure contract (4a) | Match upstream's caller responsibility: identical collective call order, consistent mode selection and valid participating arguments. No general error-consensus protocol for rank-local validation/allocation failures. `NC_ERANGE` remains a completed-I/O warning local to each rank, not a reason to skip a collective transfer. |
| Packaging | Reuse `NEP_ENABLE_NEXTCDF4_PARALLEL` and existing Spack `+nextcdf4+parallel`. No new dependency floor, plugin directory, installed file or package variant. Conda remains unaffected. |

## Work items

### 1. Wire the access selector and session state

Files: `src/nextcdf4/nxt4dispatch.c`, `src/nextcdf4/nxt4internal.h`, `src/nextcdf4/nxt4io.c`, `src/nextcdf4/nxt4meta.c`.

- Add `int parallel_access` to `NEXTCDF4_VAR_INFO_T`, documented as an ephemeral transfer preference. Explicitly initialize it to `NC_INDEPENDENT` in `NEXTCDF4_def_var` and `load_one_var`; never serialize it or reset it during deferred DCPL rebuild/cache-handle reopen.
- Declare privately and implement in `nxt4io.c`: `int NEXTCDF4_var_par_access(int ncid, int varid, int par_access);`. Replace the positional dispatch entry, leaving all other entries in order. Do not expose internal dispatch declarations in installed `include/nextcdf4dispatch.h`.
- Without `HAVE_NEXTCDF4_PARALLEL`, return `NC_ENOPAR`. With the feature: reject values other than `NC_COLLECTIVE`/`NC_INDEPENDENT` with `NC_EINVAL`; resolve the file, require `file->parallel` (`NC_ENOPAR` otherwise), resolve the group-local variable (`NC_ENOTVAR`), and reject independent mode for any nonempty `var->filters` (`NC_EINVAL`). Invalid file IDs propagate `NC_EBADID` from normal dispatch/state validation.
- Accept changes in define/data mode and read-only parallel sessions. Change only this variable's preference, not storage, define mode, access preferences of sibling variables or the file communicator. Identical calls on all ranks are the caller's responsibility, as upstream documents.

### 2. Use a real transfer property list and preserve empty participation

Files: `src/nextcdf4/nxt4io.c`.

- In `var_io`, create an owned `H5P_DATASET_XFER` for parallel file transfers; set it using `H5Pset_dxpl_mpio(dxpl, H5FD_MPIO_COLLECTIVE/H5FD_MPIO_INDEPENDENT)` from `vinfo->parallel_access`. DXPL creation failure is `NC_EHDFERR`, setup failure `NC_EPARINIT`. Pass it to both H5D calls; close it at `done` on every exit. Serial paths retain their existing transfer behavior and must not reference MPI symbols when compiled OFF.
- Replace collective zero-count early returns and entirely fill-only read skipping with none-selected file and memory dataspaces (`H5Sselect_none`). Supply an internal dummy byte for zero-element HDF5 calls; NULL user buffers are accepted only for zero-element requests. Scalars continue to represent one element and require a buffer. Independent empty calls retain the cheap no-op path.
- A zero in any count makes the entire request empty: validate strides/count arithmetic without manufacturing growth from another axis, contributing new extents, dereferencing buffers or running conversion. Preserve existing fixed-dimension bounds errors for nonempty requests.
- For clipped unlimited reads, preserve logical-memory placement and fill synthesis. Every collective rank enters `H5Dread` once, including ranks reading only fill; synthesize the missing logical values afterward. Preserve caller buffer guards and existing conversion/range rules.
- Reject parallel `NC_STRING`, `NC_STD_REF` and recursively variable-sized user-type variable transfers with `NC_ENOTBUILT` before automatic enddef, allocation, conversion or extent mutation. Use `type_info->varsized` for user types; do not reject fixed-size compounds just because their IDs are above `NC_FIRSTUSERTYPEID`. Serial data I/O is unaffected.
- Keep raw FP8/FP6/FP4 restrictions and NEP float16/bfloat16 conversion/quantization unchanged. A local `NC_ERANGE` flag must not bypass HDF5; return it only after successful data transfer. Ordinary errors retain precedence. Do not add a rank-wide error-consensus protocol.

### 3. Negotiate unlimited extents and dimension scales collectively

Files: `src/nextcdf4/nxt4io.c`, with dimension-length inquiry adjustments in `src/nextcdf4/nxt4meta.c` only where needed to report the agreed live extent.

- For parallel collective writes to a variable with unlimited dimensions, all ranks execute the same reduction sequence regardless of local emptiness or whether this rank needs growth. Build per-axis proposed extents from current dataset extents and nonempty selections, then use `MPI_Allreduce` with `MPI_MAX` on checked `unsigned long long` values over the owned `file->comm`. Check conversions between `size_t`, `hsize_t` and the reduction representation; never silently truncate. MPI failure returns `NC_EMPI`.
- Compute the global extent before any `H5Dset_extent`; all ranks use identical results. Grow the variable dataset and each affected unlimited dimension-scale dataset in deterministic dimension order. A coordinate dataset serving as its own scale is extended only once. Reacquire the file dataspace after extension before selection.
- Retain existing larger scale/logical lengths shared with other variables; never shrink a dimension or its scale when a shorter variable catches up. Keep `NC_DIM_INFO_T.len` consistent across ranks. Dimension-length inquiries after append and after reopen must report the agreed maximum; different variables sharing a dimension still supply fill beyond their own physical extent.
- Independent parallel writes needing physical dataset growth return `NC_ECANTEXTEND` before any dataset/scale change. Do not add an MPI collective to independent calls. Independent in-bounds transfers must work when only one rank calls I/O after collective metadata setup.
- Empty collective writes do not extend datasets when every rank is empty, but still participate in the reductions and HDF5 transfer. Cover multiple unlimited axes, nonuniform starts/counts, repeated append rounds, coordinate scales and shared dimensions.

### 4. Integrate filters with the access contract

Files: `src/nextcdf4/nxt4filter.c`, `src/nextcdf4/nxt4io.c`.

- After successful addition/replacement of any filter in `NEXTCDF4_def_var_filter`, `NEXTCDF4_def_var_deflate` or `NEXTCDF4_def_var_fletcher32`, set that variable's access preference to `NC_COLLECTIVE` when `file->parallel`. No-op setters that add no filter do not change the preference. Preserve level-zero behavior, validation, filter ordering and committed-variable `NC_ELATEDEF`.
- Reject a parallel data transfer with a nonempty pipeline and independent preference with `NC_EINVAL` before data or extent mutation. This also covers reopened filtered variables; document and test explicit `nc_var_par_access(..., NC_COLLECTIVE)` after reopen. Keep missing-plugin `NC_ENOFILTER` precedence.
- Generic filters follow the same rule; do not introduce a whitelist or new plugin path. Built-in filter tests are mandatory. External-plugin certification remains 1V3 coverage, not an implied guarantee for arbitrary codecs/types.

## Out of scope

- Upstream `tst_parallel*` ports, bidirectional upstream parallel NetCDF interchange, MPICH coverage, external-plugin matrix and disk-bound parallel benchmarks/reference artifacts: Sprint 1V3.
- Parallel dynamic/string/reference data support and parallel reference-helper certification: future work beyond this sprint, not silently promised by serial enhanced-model support. Existing serial support stays intact.
- General rank-local error consensus/recovery, mismatched collective order diagnosis, cross-rank `NC_ERANGE` aggregation and guaranteed physical MPI collective algorithms: outside this sprint's upstream-compatible caller contract.
- New MPI sanitizer CI, Fortran parallel wrappers, PnetCDF, mapped `varm` I/O and a chunk-cache behavior redesign: future work, not 1V3 requirements by implication.
- SWMR writer/reader behavior: Sprints 1V4–1V5. VDS, image/diskless/mmap and direct chunk APIs: v4.4.0.
- Release notes, tag/publication, Spack release/upstream version bump and conda release work: Sprint 2. This sprint does not implement, commit or publish anything during refinement.
