# V4.3.0 Sprint 1H: Continued Conversion Changes

Source: docs/roadmap.md, "V4.3.0 / Sprint 1H".

## Goal

NEXTCDF-4 reports conversion range errors without abandoning otherwise valid I/O, and has reproducible correctness and performance evidence for both conversion engines. Ed reviews that evidence and selects the permanent engine before the temporary build switch is removed. The final backend retains range regression coverage, accurate conversion documentation and dedicated correctness CI, while historical benchmark artifacts remain intact. IEEE float16 continues to use HDF5 until Sprint 1I.

## Decisions

| Topic | Decision |
| --- | --- |
| Permanent path | Required Ed review checkpoint after corrected OFF/ON correctness and performance results. No automatic speed threshold and no advance choice of engine. Do not remove the switch until Ed selects the path. (Ed accepted recommendation 1a.) |
| Measurements | Both existing GDAS benchmarks, plus representative integer narrowing, float/double conversion and quantized writes. Not an exhaustive performance matrix. (Ed: 2b.) |
| Range completion | Complete all values and the requested I/O, then return `NC_ERANGE`. Writes may replace attributes and extend unlimited dimensions. Range warnings are not transactional rejection. (Ed: 3a.) |
| Range classification | Finite floating overflow, integer range violations and NaN/infinity to integer are range errors. Ordinary precision loss, fractional truncation and floating underflow are not. NaN/infinity to floating destinations are not range errors. (Ed: 4a.) |
| Result values | Preserve each engine's existing conversion results, except where necessary to avoid undefined conversion or enforce the classification above. ON retains Sprint 1G's fill policy for invalid real-to-integer conversion and nearest/even bfloat16 narrowing; OFF retains HDF5 saturation/rounding. Output equality between engines is not required for range-error cases. |
| Exceptions | IEEE float16 conversion remains HDF5-owned in both modes. Preserve its existing output bits, including 65505 becoming infinity, while adding range reporting. Internal IEEE float16 and corrected boundary rounding remain Sprint 1I. |
| Independent API | `libnep`'s eight `nc_*_bfloat16` functions keep their existing signatures, backend independence, rounding and range contract. No new public conversion API. |
| Artifacts | Separate OFF/ON CSVs, stdout logs, machine records and comparison charts; never overwrite `reference_results.csv`, `reference_io_results.csv`, `reference_machine.txt` or their existing charts. |
| Build and packaging | CMake only; no dependency/minimum-version or install-layout change planned. No temporary Spack variant. Reassess actual recipe impacts at the permanent-path checkpoint. Conda is unchanged. |
| Acceptance | Full enabled CTest passes, docs build warning-free, no newly disabled tests. Performance is measured locally, not gated by runner timing. |

- Reproduce #381: double `{300000, -2}` read as short returns `NC_ERANGE`; read as uint also returns `NC_ERANGE`. Assert all output elements, with independent engine-appropriate expected exceptional results and equal in-range results.
- Cover get/put var, var1, vara and vars; scalars, arrays, positive strides, native and compatibility-mode standard types, chunked+shuffle/deflate and contiguous layouts, same-handle and reopen verification.
- Include signed/unsigned integer limits, negative-to-unsigned, exact 64-bit boundaries, float/double narrowing, values just around integer boundaries, fractional values within range, signed zero, NaN/infinity, finite overflow, and underflow to floating zero. Mixed arrays must show that values after an error are processed. An in-range fractional value must not set range.
- Pin the chosen classification: real-to-integer range is evaluated after truncation toward zero; nonfinite real-to-integer is a range error with defined engine-specific output; finite real-to-floating conversion is a range error when that engine overflows/saturates beyond its finite representable range. Same-type raw NaNs/infinities never cause range errors.
- Small floats: retain exhaustive widening/raw tests; update existing expected statuses for overflow-containing pinned writes without changing float16 bits or mode-specific bfloat16 rounding. Include positive/negative float16 65505 and bfloat16 FLT_MAX, double overflow, NaN/infinity and tiny finite inputs.
- Global/group/variable attributes: get, put, empty attributes, create and replacement, persistence after reopen, mixed valid/out-of-range values. A range-warning replacement installs the new converted value. Unsupported conversion leaves the old value intact.
- Quantized writes: all three modes, float/double destinations, scalar and array, same-type and converting inputs, overflow propagation, fill preservation and unchanged source buffers. Check conversion errors before quantization cannot be lost when quantization is performed.
- Verify error precedence: structural/type/permission/define-mode/allocation/HDF5 failures override range warnings. Rejected calls do not touch output/data/extents. Zero-count calls succeed without conversion/range warnings. Successful range-warning writes do extend unlimited dimensions and persist all values.

Run the new test in both existing configurations and record expected failures before changing production code. Do not weaken disabled-test policy or the independent wrapper contract.

### 2. Implement range observation in retained HDF5 conversion

Files: `src/nextcdf4/nxt4convert.c`, `src/nextcdf4/nxt4internal.h`, `src/nextcdf4/nxt4io.c`.

Keep `nx4_convert_type()`'s existing signature. Add this private callback, with per-call boolean context and no global state:

```c
static H5T_conv_ret_t
nx4_conversion_exception(H5T_conv_except_t exception, hid_t src_id,
                         hid_t dst_id, void *src_buf, void *dst_buf,
                         void *user_data);
```

- Set the context flag for `H5T_CONV_EXCEPT_RANGE_HI`/`RANGE_LOW`; also classify nonfinite-to-integer exceptions according to Decisions. Ignore precision/truncation and floating underflow. Return `H5T_CONV_UNHANDLED` so HDF5 retains conversion results; never abort merely for a range warning.
- Expose a private factory `int nx4_conversion_dxpl(hid_t *dxplp, int *range_error)` in `nxt4internal.h`, implemented beside the callback. It initializes the flag, creates `H5P_DATASET_XFER`, installs the callback and returns an owned DXPL through `dxplp`; close on setup failure and initialize the output to -1. Callers close it on every exit.
- In OFF, pass that DXPL to every converting `H5Dread`/`H5Dwrite`, scalar and hyperslab. Identity/raw I/O keeps the default fast path and must not scan every value. For the ON float16 exception, pass the DXPL to `H5Tconvert()` instead of `H5P_DEFAULT` and merge its flag into the helper's output.
- Before treating the callback as sufficient, run boundary tests for every retained conversion category, especially native float16, nonfinite-to-integer and double/float hardware paths. If HDF5 does not emit the required exception, add a narrow source-value classification pass for that uncovered type pair in `nxt4convert.c`; do not replace HDF5's conversion or change its output bits. Share integer-boundary classification with the existing guarded code, not rounded float representations of LLONG_MAX/ULLONG_MAX. This is a required coverage fix, not permission to weaken the contract.
- Keep range booleans separate from return codes. Successful HDF5 conversion plus a range flag is completed conversion; HDF5 failure remains `NC_EHDFERR`. Ensure callback context outlives the operation, multiplication is checked and all datatypes/DXPLs/scratch buffers are released.
- Complete Doxygen on new/changed private interfaces with author `Edward Hartnett, Intelligent Data Design, Inc.`. No installed public declaration is added.

### 3. Propagate completed-conversion warnings through variables and attributes
