# v4.3.0 Sprint 1N4: Upstream User-Type Tests

Source: docs/roadmap.md, "V4.3.0 / Sprint 1N4".

## Goal

A selected, reproducible set of upstream enum, opaque, compound and vlen regression programs runs against NEXTCDF-4 in both native and NetCDF-4-model modes, including sanitizer CI. This validates the completed 1N1–1N3 behavior without expanding the sprint into the full mixed-feature `nc_test4` suite.

## Decisions

| Topic | Decision |
|-------|----------|
| Ownership | Fourth sub-sprint owns the upstream ports Ed selected (Ed, 3b); 1N1–1N3 supply focused tests first. |
| Modes | Each selected port runs in native and `NC_NETCDF4_MODEL` modes (Ed, 1a). |
| Dynamic coverage | Exercise non-string nesting delivered in 1N3; string/reference graphs remain excluded (Ed, 2a). |
| CI | Run ports in existing normal CI and the dedicated sanitizer job from 1N3 (Ed, 4b). |
| Exact set | Six ports: `tst_enums`, `tst_opaques`, `tst_compounds`, `tst_compounds2`, `tst_vl`, `tst_vlen_unlim`, from netcdf-c `5baa62e6966d3e505b895574dafbd531a4aed360`. |
| Failure policy | Fix in-scope user-type regressions with focused reproductions; do not weaken assertions or disable a failing port. An unrelated feature/runtime defect is an explicit blocker reported to Ed, not an invitation to broaden scope silently. |
| Style | Preserve UCAR notices, keep adaptations small and use the existing shared test shims. |

## Work items

### 1. Import six programs and one fixture

Files: new `test/nextcdf4/nc_test4/tst_enums.c`, `tst_opaques.c`, `tst_compounds.c`, `tst_compounds2.c`, `tst_vl.c`, `tst_vlen_unlim.c`, `ref_tst_compounds.nc`; existing `nc_tests.h`, and `.gitignore` only if the fixture needs an explicit exception.

Copy from the exact pinned upstream revision. Preserve copyright/license notices and existing comments. Add plain provenance and `Author: Edward Hartnett, Intelligent Data Design, Inc.` adaptation comments, never Doxygen. Remove upstream `config.h` includes so NEP-generated feature macros cannot accidentally turn on unrelated upstream sections. Use existing shims and add only constants/includes actually required by the six sources. Do not define parallel-test macros. Commit `ref_tst_compounds.nc` byte-for-byte from the same revision; do not recreate it with NEXTCDF-4, since its upstream provenance tests interoperability. Record its source SHA and content checksum in a plain comment alongside the `srcdir` registration rather than creating a new documentation file.

Add a test-only mode selector in `nc_tests.h`:

```c
static int nep_nc_test4_create_mode(void);
```

It returns `NC_NEXTCDF4` when environment variable `NEP_NC_TEST4_MODEL` is unset, empty or `native`, and `NC_NEXTCDF4 | NC_NETCDF4_MODEL` when it equals `netcdf4`. Any other value fails the test rather than silently selecting a mode. Keep this helper local to test infrastructure, not an installed API. Replace the selected ports' create-time `NC_NETCDF4` flag with this helper, preserving `NC_CLOBBER`/other flags; add `NC_NEXTCDF4` to every open including the upstream reference fixture. Never mechanically rewrite `NC_FORMAT_NETCDF4` inquiry constants or expected type semantics. Existing ports do not adopt the new mode selector in this sprint.

### 2. Register independent mode runs

File: `test/nextcdf4/CMakeLists.txt`.

Create one executable per upstream filename with its upstream target name, linked to `ncnextcdf4 ${NETCDF_LIBRARIES} ${NEP_HDF5_LIBRARIES}` and existing shim/NetCDF/HDF5 include directories. Register two CTest names per target: `<target>_native` and `<target>_netcdf4_model`. Set `NEP_NC_TEST4_MODEL=native` or `netcdf4` respectively, alongside existing `NCRCENV_RC`, `NETCDF_RC`, and `LD_LIBRARY_PATH` values. The selector explicitly accepts `native` as the ordinary mode.

Use separate working directories `${CMAKE_CURRENT_BINARY_DIR}/nc_test4/<target>/<mode>` created by `file(MAKE_DIRECTORY ...)` at configure time. This prevents repeated upstream filenames from colliding under parallel CTest and keeps outputs away from the immutable fixture. Both `tst_compounds` registrations set `srcdir=${CMAKE_CURRENT_SOURCE_DIR}/nc_test4`; no test writes into that source directory. Label all twelve registrations `nextcdf4_user_types` so CI can select them without fragile regexes. They are always enabled when `HAVE_NEXTCDF4` is true, without runtime skips for the supported user types.

### 3. Run ports and fix user-type regressions without weakening coverage

Files: selected port sources and the affected `src/nextcdf4/nxt4type.c`, `nxt4meta.c`, `nxt4io.c`, `nxt4file.c`, `nxt4internal.h`; focused tests from 1N1–1N3.

Run each native/model pair and trace failures. For an in-scope backend defect, add a minimal focused regression, fix the shared path, rerun both port modes and all focused tests. Keep expected values/error codes and memory-ownership assertions intact. Port-only defects such as an upstream-owned buffer leak get a minimal explicit cleanup correction, with original semantics preserved and the adaptation recorded in a plain source comment. No blanket sanitizer suppression, `DISABLED TRUE`, weakened assertion, deleted test section or replacement of an upstream fixture with a generated NEP file.

If a new failure demonstrably depends on an out-of-scope feature, report the exact source line, reproducer and proposed owning sprint to Ed and leave this acceptance gate incomplete. This is an escalation boundary, not an unresolved interface choice.

## Verification

Use the existing configured `build`, not a second build-directory name. Fresh builds require specific permission before deleting an existing `build` directory.

```sh
cmake -S . -B build
cmake --build build --parallel 8
ctest --test-dir build -N -L nextcdf4_user_types
ctest --test-dir build -L nextcdf4_user_types --parallel 8 --output-on-failure
ctest --test-dir build -R '^tst_nextcdf4_(user_types|compound_arrays|vlen)$' --output-on-failure
ctest --test-dir build --output-on-failure
cmake --build build --target docs
```

The labeled inventory must show twelve enabled tests, six programs times two modes. Repeat with the sanitized `build` and instrumented dependencies configured exactly as 1N3 specifies:

```sh
ASAN_OPTIONS=detect_leaks=1:halt_on_error=1 UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1 ctest --test-dir build -L nextcdf4_user_types --output-on-failure
ASAN_OPTIONS=detect_leaks=1:halt_on_error=1 UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1 ctest --test-dir build --output-on-failure
```

Both CI jobs (`nextcdf4`, `nextcdf4-sanitizers`) must pass every selected case and the full suite, with zero sanitizer findings and zero documentation warnings. Compare source adaptations against the pinned checkout and verify the fixture checksum (`sha256sum` on upstream and copied fixture). Existing Spack `style`/`spack` jobs remain required and unchanged.
