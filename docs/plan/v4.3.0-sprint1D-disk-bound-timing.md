# V4.3.0 Sprint 1D: Disk-Bound Timing in the Compression Benchmarks

Source: docs/roadmap.md, "V4.3.0 / Sprint 1D".

## Goal

The compression-focused performance examples measure disk-bound I/O
the same way the Sprint 1C bfloat16 benchmarks do: write time ends
after `nep_perf_sync_file()`, and each read pass starts after
`nep_perf_drop_cache()`. The committed results CSVs, plot PNGs and
`_metadata.txt` captions for the buildable programs are regenerated
from an optimized (`RelWithDebInfo`) build, and the NEXTCDF-4
documentation now states plainly that the backend is experimental and
not all features are implemented. The remaining timing programs are
Sprint 1E.

## Decisions

| Topic | Decision |
| --- | --- |
| Scope | Compression benchmarks only: `deflate.c`, `zstandard.c`, `szip.c`, plus source-only edits to the disabled `lossless.c` and `quantize.c`. The other five programs go to Sprint 1E. |
| Repetitions | Keep the existing one-measurement-per-configuration structure. No `NREPS`/min-of-N; the disk-bound single runs on ~130 MB files are already dominated by real I/O. (Ed, 1D/1E split: 1a) |
| CSV columns | Unchanged. Only the numbers are refreshed. `docs/prd.md` documents each program's CSV schema and the `plot_*.py` scripts parse columns by name. (Ed: 2a) |
| Disabled programs | `lossless.c` and `quantize.c` get the same `perf_disk.h` source edits so the code stays consistent, but their CSVs, PNGs and metadata files are not regenerated (targets commented out since v4.2.0). (Ed: 3a) |
| Build for reference runs | `RelWithDebInfo` (`-O2 -g -DNDEBUG`), same as Sprint 1C. Project defaults stay unchanged. |
| CI | No workflow changes. These tests run only under `NEP_ENABLE_BENCHMARKS`, which CI does not enable. |
| Spack/conda | This sprint changes nothing either recipe depends on. |

### 2. `deflate.c`, `zstandard.c`, `szip.c`

For each program:

- Add `#include "perf_disk.h"` after the system/netcdf includes.
- **Write timer**: keep the start where it is. Move the end
  (`write_s = get_time() - t_write_start;`) to just after a new call:
  `if (nep_perf_sync_file(TMP_FILE)) { perror("nep_perf_sync_file"); return 1; }`
  placed immediately after `nc_close`. In `deflate.c` that is between
  lines 172 and 174; `stat()` stays between the two timed regions.
- **Read pass**: immediately before the read-timer start
  (`t_read_start = get_time();` at `deflate.c:186`), call
  `if (nep_perf_drop_cache(TMP_FILE)) { perror("nep_perf_drop_cache"); return 1; }`.
  The drop is outside the timed region; `nc_open` through `nc_close`
  stays the timed region.
- **Header docs**: in each `@file` block, update the timing
  description to "write time includes fsync; each read starts with the
  file dropped from the page cache" and the `@note` line to
  "Reference results are measured with `-DCMAKE_BUILD_TYPE=RelWithDebInfo` (-O2)."
