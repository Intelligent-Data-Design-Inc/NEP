# V4.3.0 Sprint 1V7: Remote References (OPeNDAP and NCZarr)

Source: docs/roadmap.md, "V4.3.0 - NEXTCDF4 Development / Sprint 1V7".

## Goal

A NEP application can store a remote-data reference — a `(URL, object
path)` pair of strings — in `NC_STRING` variables or attributes of a
NEXTCDF-4 file and later resolve it through a small `nc_ref_*`-shaped
API. `nc_ref_open_remote` opens any URL the installed NetCDF-C accepts
(DAP2, DAP4, NCZarr file/byte-range stores) via `nc_open`, resolves
the stored object path in the same call, and returns a caller-owned
session ncid plus the resolved object; `nc_ref_resolve` is also public
so one session can resolve many paths. Remote sessions are ordinary upstream NetCDF IDs — no HDF5
token, metadata mapping or NEXTCDF-4 machinery is involved on the
remote side. Remote access is read-only.

## Decisions

| Topic | Decision |
|---|---|
| Ed's answers | `2a 3c 4a 5a`; API shape revised after review to combined opener + public resolver (Ed chose option b). |
| API shape | Combined opener plus public resolver: `nc_ref_open_remote(int ncid, const char *url, const char *path, int *target_ncidp, int *kindp, int *objidp, char *att_name, size_t att_name_size)` does open + resolve in one call and returns the owned session (kept open for data reads and further resolutions); `nc_ref_resolve(int ncid, const char *path, int *kindp, int *objidp, char *att_name, size_t att_name_size)` stays public so one session can resolve many paths without paying a remote open per reference. |
| Storage convention (2a) | Convention only, no reserved names: an `NC_STRING` variable or attribute holds the URL, a parallel `NC_STRING` var/att of matching shape holds the object path. The API takes both strings as arguments; `docs/refs.md` documents the convention. |
| Remote sources (3c) | Any URL `nc_open` resolves: DAP2 and DAP4 (dispatch-chosen), and NCZarr `file://`/byte-range `https://...#mode=bytes` stores. `s3://` URLs are unsupported unless the underlying netcdf-c has `NC_HAS_S3`; failure propagates `nc_open`'s error. No constraint-expression/subsetting API. |
| Build gating/tests (4a) | New `NEP_ENABLE_REMOTE_REFS` option (default OFF, requires `NEP_ENABLE_NEXTCDF4`); compile-check `NC_HAS_DAP2 || NC_HAS_DAP4 || NC_HAS_BYTERANGE` in `netcdf_meta.h` → `FATAL_ERROR` if none. API returns `NC_ENOTBUILT` when the option is off. CI tests cover storage, argument errors and `NC_ENOTBUILT`; a live-URL test runs only when `NEP_REMOTE_TEST_URL` is set (local verification, never CI). |
| Spack (5a) | New `remoterefs` variant `when="@4.3.0:"` passing `NEP_ENABLE_REMOTE_REFS`, plus `depends_on("netcdf-c+dap", when="+remoterefs")` (comment noting `+nczarr` also satisfies the feature). Upstream copy ships with Sprint 2's version-bump PR. |
| Ownership/lifetime | Each successful `nc_ref_open_remote` returns an independent session the caller owns and must `nc_close`. IDs returned by `nc_ref_resolve` die with the session. No caching or shared handles. |
| Mode | Remote open is plain `nc_open(url, NC_NOWRITE, ...)` — read-only, upstream dispatch. If the open succeeds but resolution fails, `nc_ref_open_remote` closes the session, sets `*target_ncidp = -1` and returns the resolution error — callers needing the session despite a failed path call `nc_open` themselves. Write access and constraint expressions are out of scope. |
| Release | Sprint 2 owns release notes, tag and packaging publication. No implementation, commit or push during refinement. |

### 2. Public API in `include/nep.h`

Declare after the `nc_ref_*` block (near line 530), full Doxygen
blocks, `@author Edward Hartnett, Intelligent Data Design, Inc.`:

```c
int nc_ref_open_remote(int ncid, const char *url, const char *path,
                       int *target_ncidp, int *kindp, int *objidp,
                       char *att_name, size_t att_name_size);
int nc_ref_resolve(int ncid, const char *path, int *kindp,
                   int *objidp, char *att_name, size_t att_name_size);
```

- `nc_ref_open_remote`: `ncid` must be a NEXTCDF-4 file (context for
  the reference; validated via `ref_file`). `url` is opened with
  `nc_open(url, NC_NOWRITE, target_ncidp)` — no `NC_NEXTCDF4` flag, so
  any upstream dispatch (DAP2/DAP4/NCZarr) may answer — then `path`
  is resolved exactly as `nc_ref_resolve`. On success the caller owns
  `*target_ncidp` and `kindp`/`objidp`/`att_name` describe the remote
  object. On open failure `*target_ncidp` is -1; on resolution failure
  the session is closed, `*target_ncidp` is -1 and the resolution
  error is returned. `att_name` may be NULL when no `#` suffix is
  expected; `att_name_size` bounds the copied name. Document that the
  returned ncid is an ordinary NetCDF session, not NEXTCDF-4.
- `nc_ref_resolve`: `ncid` is a session from `nc_ref_open_remote` (or any
  read ncid — do not over-validate beyond a NULL check). `path` grammar:
  leading `/`, `/`-separated group path, final component the object
  name; an optional `#attname` suffix selects an attribute of the
  object. Resolution precedence: variable (`nc_inq_varid`), then group
  (`nc_inq_grp_ncid`), then committed type (`nc_inq_typeid`); `kindp`
  receives `NC_REF_OBJ_VAR`, `NC_REF_OBJ_GRP`, `NC_REF_OBJ_TYPE`, or
  `NC_STD_REF_ATTR` when `#` was used (then `att_name` receives the
  attribute name and `objidp` the owner's varid/grpid/typeid as a varid
  or `NC_GLOBAL`/`typeid` per documented mapping — attribute of a
  group returns the group ncid, of a variable the varid, of a type the
  typeid with kind `NC_STD_REF_ATTR` and the owner kind recoverable by
  the caller from the path).
- Errors: `NC_EINVAL` bad arguments/path grammar/`#` on a non-object
  path; `NC_ENOTBUILT` when built without `NEP_ENABLE_REMOTE_REFS` or
  the underlying netcdf-c lacks remote dispatch (surfaced as
  `nc_open`'s `NC_ENOTBUILT`/`NC_EDAP` error — document propagation);
  `NC_ENOTVAR`/`NC_ENOTGRP`/`NC_ENOTNC4`-family errors propagate from
  the inquiry calls.

### 3. Implementation in `src/nextcdf4/nxt4ref.c` (or new `nxt4remoteref.c`)

- Keep remote code in the reference compilation unit; if the file
  grows past ~1400 lines, split to `nxt4remoteref.c` and add to
  `src/nextcdf4/CMakeLists.txt`. Follow EBAIL/ELOG conventions.
- `nc_ref_open_remote`: validate `ncid` via `ref_file`; require
  non-NULL `url`, `path`, `target_ncidp`, `kindp`, `objidp`; set
  `*target_ncidp = -1`; call `nc_open(url, NC_NOWRITE, target_ncidp)`;
  on success call the internal resolve (same code as
  `nc_ref_resolve`) and on its failure `nc_close(*target_ncidp)`,
  reset to -1, return the resolution error.
- `nc_ref_resolve`: parse `path` — split off `#att` suffix, walk the
  group path with `nc_inq_grp_ncid` per component, then try
  `nc_inq_varid`, then `nc_inq_grp_ncid` (nested), then
  `nc_inq_typeid` on the leaf. `#att` requires a resolved owner
  (var/group/type); verify the attribute exists with `nc_inq_attid`.
- Compiled unconditionally; when `NEP_HAS_REMOTE_REFS` is 0 both
  functions return `NC_ENOTBUILT` immediately (stub path inside the
  same function, matching how other gated code handles absence — the
  symbols must always exist since `nep.h` declares them).

### 4. Tests: `test/nextcdf4/tst_nextcdf4_remote_ref.c`

New executable in `test/nextcdf4/CMakeLists.txt`, label
`nextcdf4_ref` (plain comments, `Author:` line, no Doxygen). All cases
must pass when the library is built **without** `NEP_ENABLE_REMOTE_REFS`
(the CI configuration) and exercise the real path when built with it:

- Storage convention: create native NEXTCDF-4 file, define an
  `NC_STRING` variable and a parallel `NC_STRING` variable (same
  dims), write `"<url>"`/`"<path>"` pairs, reopen and read back —
  always runs (pure NC_STRING I/O).
- Argument/negative cases — always runs when feature enabled, and
  under CI asserts `NC_ENOTBUILT` from both functions instead:
  NULL url/path/out-params → `NC_EINVAL`; malformed path (no leading
  `/`, empty components, `#` on root) → `NC_EINVAL`; missing object →
  inquiry error; unreachable/malformed URL → `nc_open` error
  propagated.
- Live resolution — skipped unless `NEP_REMOTE_TEST_URL` env var is
  set (getenv; print SKIP reason). `nc_ref_open_remote` on the env URL
  with a known path from `NEP_REMOTE_TEST_PATH` (default `/`), read a
  variable's data through the returned IDs, `nc_ref_resolve` a second
  path on the same session, `nc_close`. A second `nc_ref_open_remote`
  returns an independent session; a deliberately bad path on a good
  URL returns the resolution error with `target_ncid` -1.
- Local network-free case — when `NEP_REMOTE_TEST_URL` names a
  `file://` Zarr store path the same flow runs offline (local builds
  have `NC_HAS_NCZARR`); document that CI never sets the env vars.
- Register the test so it also runs when the option is OFF, asserting
  `NC_ENOTBUILT`; label membership keeps it in `nextcdf4_ref`.

## Out of scope

- OPeNDAP inside the HDF5 `NC_STD_REF` token format — impossible;
  tokens store filesystem filenames.
- `s3://` references (no local `NC_HAS_S3`), HDF5 ROS3, Azure/GCS
  stores; constraint-expression/subsetting APIs beyond the stored path.
- Write access to remote datasets, caching, prefetch, byte-range
  tuning.
- Fortran wrappers for remote references (beyond v4.3.0).
- CI dependency changes to enable DAP/NCZarr in the netcdf-c CI builds
  (revisit if real remote coverage is ever wanted in CI; network
  fragility makes it undesirable now).
- Release notes, tag, conda — Sprint 2.
