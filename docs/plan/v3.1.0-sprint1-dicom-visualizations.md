# v3.1.0 Sprint 1: DICOM Visualizations

## Sprint Goal

Add the first DICOM visualization examples to `examples/viz/`, generate two publication-ready grayscale PNG artifacts from the existing `MRBRAIN.DCM` and `0003.DCM` samples, and acquire 3–5 additional public-domain DICOM samples to broaden visual content and regression coverage.

## Scope

This sprint is limited to visualization and test-data expansion. It does not extend the DICOM UDF reader itself beyond what was delivered in v3.0.0 Sprints 1–3.

### In Scope

- Two new Python visualization scripts in `examples/viz/`.
- Build-system wiring under `HAVE_DICOM` / `ENABLE_VIZ_EXAMPLES`.
- Documentation updates for users and developers.
- Acquisition and provenance documentation for 3–5 new public-domain DICOM samples.
- CI updates so the DICOM workflow exercises the new visualization tests.

### Out of Scope

- New DICOM Transfer Syntax support.
- Changes to the DICOM dispatch or decompression code.
- New Fortran examples or C examples.
- New compression filters or format handlers.

## Background

The DICOM UDF handler is already implemented and tested in v3.0.0. The `examples/viz/` directory contains a shared framework (`plot_common.py`, `verify_viz_artifacts.py`) that produces black-and-white PNGs with external metadata files. The FITS, CDF, GeoTIFF, GRIB2, and PDS4 handlers already follow this pattern. DICOM visualization is currently missing and is the theme of v3.1.0.

## Major Tasks (Dependency Order)

1. **Prepare the visualization guard conditions**
   - Add `HAVE_DICOM` to the `NEP_ENABLE_VIZ_EXAMPLES` UDF-reader guard in `CMakeLists.txt` and `configure.ac` so DICOM can enable visualization builds.

2. **Add `plot_dicom_mrbrain.py`**
   - Open `test/data/DICOM/MRBRAIN.DCM` with `netCDF4.Dataset`.
   - Read `pixel_data[0, :, :]` (single-frame 512×512 16-bit MR).
   - Normalize signed/unsigned 16-bit samples to 8-bit grayscale.
   - Create a grayscale `imshow` figure.
   - Call `save_with_metadata(fig, "dicom_mrbrain_image", ...)` with title, caption, and alt_text under 75 words.

3. **Add `plot_dicom_xa_montage.py`**
   - Open `test/data/DICOM/0003.DCM` with `netCDF4.Dataset`.
   - Read all 17 frames of `pixel_data[:, :, :]` (512×512 encapsulated JPEG Baseline).
   - Convert any color frames to luminance.
   - Build a compact rectangular montage.
   - Call `save_with_metadata(fig, "dicom_xa_frame_montage", ...)`.

4. **Update build-system wiring**
   - `examples/viz/CMakeLists.txt`: copy the two scripts, add `if(HAVE_DICOM)` test blocks, copy `test/data/DICOM/0003.DCM` and `MRBRAIN.DCM` to the build tree if missing, and append the two basenames to `_viz_artifacts`.
   - `examples/viz/Makefile.am`: add the scripts to `TESTS`, `viz_artifacts`, `EXTRA_DIST`, environment variables, and file-copy rules under `if HAVE_DICOM`.

5. **Update `examples/viz/README.md`**
   - Add DICOM manual-run examples.
   - Describe `plot_dicom_mrbrain.py` and `plot_dicom_xa_montage.py` in the Scripts section.
   - Add the two new artifact basenames to the `verify_viz_artifacts.py` example invocation.

6. **Update `docs/dicom.md`**
   - Add a Visualization subsection describing the two plots and how to run them from a DICOM-enabled build.

7. **Acquire additional public-domain DICOM samples**
   - Identify 3–5 samples with varied modality (e.g., CT, CR, US) and clear visual content.
   - Prefer public-domain or CC0/CC-BY sources such as TCIA public collections, RSNA preview datasets, or the `pydicom`/`libdicom` test suites.
   - Place files under `test/data/DICOM/`.
   - Document provenance, license, and de-identification status in this plan file and in a `test/data/DICOM/README.md` update.

8. **Update `.github/workflows/ci-dicom.yml`**
   - Add Python virtual-environment creation and `requirements.txt` installation.
   - Pass `-DNEP_ENABLE_VIZ_EXAMPLES=ON` in the CMake configure step.
   - Pass `--enable-viz-examples` in the Autotools configure step.
   - Ensure `make check` / `ctest` runs the visualization tests.

9. **Run local verification**
   - Configure with DICOM and visualization enabled.
   - Run `ctest -R viz --output-on-failure` and `make check`.
   - Inspect the generated PNGs and metadata files.
   - Run `tst_dicom_udf` for regression.

## Acceptance Criteria

- `plot_dicom_mrbrain.py` and `plot_dicom_xa_montage.py` exist in `examples/viz/` and are copied to the build tree by both build systems.
- CMake and Autotools configure successfully with DICOM + visualization enabled.
- `ctest -R viz --output-on-failure` and `make check` generate both PNG/metadata pairs and `verify_viz_artifacts.py` passes.
- Both PNGs are grayscale, within the 8.0 by 6.1 inch / 150 DPI limits, and have valid `_metadata.txt` files.
- `docs/dicom.md` and `examples/viz/README.md` describe the new visualization scripts.
- At least 3 new public-domain DICOM samples are added under `test/data/DICOM/` with provenance documented.
- `.github/workflows/ci-dicom.yml` passes with visualization enabled.
- Existing DICOM tests continue to pass with DICOM enabled; the full suite remains regression-free with DICOM disabled.

## Testing Requirements

- `ctest -R viz --output-on-failure` (CMake) and `make check` (Autotools) in a build configured with `-DNEP_ENABLE_DICOM=ON -DNEP_ENABLE_VIZ_EXAMPLES=ON` / `--enable-dicom --enable-viz-examples`.
- Visual inspection of `dicom_mrbrain_image.png` and `dicom_xa_frame_montage.png`.
- Validation that the metadata files contain exactly `title`, `caption`, and `alt_text`, each non-empty, single-line, and caption ≤75 words.
- Regression run of `tst_dicom_udf`.
- CI verification of the updated `ci-dicom.yml` workflow.
