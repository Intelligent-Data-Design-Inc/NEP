# v4.3.0 Sprint 1V3: Parallel I/O Coverage and Interchange

Source: docs/roadmap.md, "V4.3.0 - NEXTCDF4 Development / Sprint 1V3".

## Goal

NEXTCDF-4 parallel I/O is exercised against the same upstream parallel
test programs netcdf-c runs against its own HDF5 backend, proven
bidirectionally interchangeable with upstream parallel netcdf-c,
certified on a second MPI implementation (MPICH) and against external
HDF5 filter plugins, and measured by a disk-bound collective I/O
benchmark with committed reference artifacts. The implementation code
changes only where the new coverage exposes real defects.

## Decisions

| Topic | Decision |
|---|---|
| Ed's answers | All recommendations accepted: 1a, 2a, 3a, 4a, 5a. |
| MPICH (1a) | New dedicated `ci-parallel-mpich` job building a second cached dependency stack (MPICH + parallel HDF5 2.1.1 + netcdf-c `main`) and running only the `nextcdf4_parallel` ctest label, not the full suite. Open MPI remains the full-suite stack. |
| Port selection (2a) | Port all eight upstream parallel tests: `tst_parallel`, `tst_parallel3`, `tst_parallel4`, `tst_parallel5`, `tst_parallel6`, `tst_parallel_zlib`, `tst_parallel_compress`, `tst_quantize_par`. The `hdf5internal.h` sections of `tst_parallel5` are adapted to the public `nc_get_var_chunk_cache`/`nc_set_var_chunk_cache` API; `tst_parallel3`'s big-file cases are kept. |
| Port mode matrix (3a) | Each port runs twice — native `NC_NEXTCDF4` and `NC_NEXTCDF4|NC_NETCDF4_MODEL` — via a parallel variant of `nep_nc_test4_create_mode()` in the `nc_tests.h` shim, matching the Sprint 1N4 two-mode pattern. `nc_open_par` always passes `NC_NEXTCDF4`; model is a create-time property recorded in the file marker. |
| Plugin matrix (4a) | zstd plus bzip2, loaded through `HDF5_PLUGIN_PATH` from the netcdf-c plugin directory already built into the parallel CI stack. Cases run-time-gate on the plugin `.so` being found so the suite still passes where a plugin is absent; zstd is required (fail, not skip, when the configured plugin dir lacks it). |
| Benchmark (5a) | New `examples/nextcdf4/parallel_perf.c` under `NEP_ENABLE_BENCHMARKS` (and `HAVE_NEXTCDF4_PARALLEL`): 4-rank collective write+read with `perf_disk.h` fsync/page-cache-drop timing, committed CSV, machine record via `record_machine.sh`, and a plot PNG. |
| Interchange | In-program, both directions in the same MPI test: NEXTCDF-4 writes (`NC_NEXTCDF4|NC_NETCDF4`, both model modes) → all ranks reopen through the upstream built-in backend (`nc_open_par`/`nc_open` with no UDF flag); upstream parallel netcdf-c writes (`NC_NETCDF4`) → all ranks reopen through NEXTCDF-4 (`nc_open_par` with `NC_NEXTCDF4`). Marker-less upstream files already open cleanly (`NEXTCDF4_read_markers`). |
| Packaging | No new CMake option, variant, dependency floor, installed file or plugin directory requirement. No Spack or conda recipe change. |

## Work items

### 1. Parallel port shims and CMake harness

Files: `test/nextcdf4/nc_test4/nc_tests.h`,
`test/nextcdf4/CMakeLists.txt`.

- Add `nep_nc_test4_par_create_mode()` next to
  `nep_nc_test4_create_mode()`: returns `NC_NEXTCDF4|NC_NETCDF4` for
  `NEP_NC_TEST4_MODEL` unset/empty/"native", and
  `NC_NEXTCDF4|NC_NETCDF4|NC_NETCDF4_MODEL` for "netcdf4"; any other
  value exits(2) like the serial helper. The `NC_NETCDF4` bit is
  mandatory because upstream `nc_create_par` rejects non-`NC_NETCDF4`
  creates without PnetCDF.
- Add `nep_nc_test4_par_open_mode()` returning `NC_NEXTCDF4` always
  (open-time model comes from the file marker, not a flag). Ports
  combine it with `NC_NOWRITE`/`NC_WRITE` as upstream does with bare
  mode flags.
- Register each port in a `foreach` loop mirroring the 1N4 block: one
  executable per port from `nc_test4/<name>.c`, include dir
  `nc_test4`, link `ncnextcdf4 ${NETCDF_LIBRARIES}
  ${NEP_HDF5_LIBRARIES} MPI::MPI_C`; two `add_test`s per port
  (`<name>_native`, `<name>_netcdf4_model`) via
  `${MPIEXEC_EXECUTABLE} -n 4` in per-port per-mode working
  directories, `PROCESSORS 4 TIMEOUT 180 LABELS nextcdf4_parallel`,
  `NEP_NC_TEST4_MODEL` in `ENVIRONMENT`, plus the standard
  `NCRCENV_RC`/`NETCDF_RC`/`LD_LIBRARY_PATH`. Gate the whole block on
  `NEP_ENABLE_PARALLEL_TESTS AND HAVE_NEXTCDF4_PARALLEL`, same as the
  existing parallel tests.
- Keep the existing serial `nc_test4` ports untouched; the new helpers
  are additive.

### 2. Port the eight upstream parallel tests

Files: new `test/nextcdf4/nc_test4/tst_parallel.c`,
`tst_parallel3.c`, `tst_parallel4.c`, `tst_parallel5.c`,
`tst_parallel6.c`, `tst_parallel_zlib.c`, `tst_parallel_compress.c`,
`tst_quantize_par.c` (copied from `/fast/ed/netcdf-c/nc_test4/` at the
pinned CI SHA, preserving UCAR notices).

- Near-verbatim edits only: `nc_create_par(..., NC_NETCDF4, ...)` →
  `nep_nc_test4_par_create_mode()`; `nc_open_par(..., 0/NC_NOWRITE/
  NC_WRITE, ...)` → `nep_nc_test4_par_open_mode()|…`; serial
  `nc_create/nc_open` sites → `nep_nc_test4_create_mode()` and
  `NC_NEXTCDF4` opens, as the serial ports already do. Keep
  `MPI_Init`/`MPI_Finalize`, rank logic, and `ERR` macros via the shim
  headers.
- `tst_parallel5`: drop `#include "hdf5internal.h"` and replace
  `nc4_hdf5_get_chunk_cache` calls with the public
  `nc_get_var_chunk_cache`; where upstream checks *file-level* cache
  defaults that have no public accessor, delete that specific
  assertion block with a comment noting the substitution. If
  `nc_get_var_chunk_cache` coverage duplicates existing
  `tst_nextcdf4_cache` behavior, keep it — this is upstream-parity
  coverage, not new assertions.
- `tst_parallel3`: keep the >2G/4G/8G big-file sections; they write no
  data (metadata only) per the upstream comment. If runtime proves
  excessive in CI, that is a defect to surface, not silently trim.
- `tst_quantize_par`: uses `nc_def_var_quantize` + parallel writes —
  supported since 1G/1H. Native mode additionally allows
  quantized small floats only if already supported; do not extend the
  port beyond upstream assertions.
- Where a port asserts upstream internals NEXTCDF-4 deliberately
  lacks (e.g. `NC_MPIIO` flags, pnetcdf), remove the section with a
  comment citing the NEXTCDF-4 contract — do not weaken assertions
  that map to supported features.
- Any port failure exposing a real backend gap is fixed in-sprint
  (1L2/1N4 precedent); fixes are scoped to correctness, not redesign.

### 3. Interchange test

File: new `test/nextcdf4/tst_nextcdf4_interchange.c`, registered in
the same parallel block (label `nextcdf4_parallel`, `-n 4`,
`TIMEOUT 180`).

- Round 1 (NEXTCDF-4 → upstream): all ranks `nc_create_par` with
  `nep_nc_test4_par_create_mode()`, define dims/dim-scale coord var,
  chunked vars with deflate+shuffle and an unlimited dim, collective
  writes of rank-coded data, `nc_close`, `MPI_Barrier`. Then all ranks
  reopen through the **upstream** dispatcher
  (`nc_open_par(path, NC_NETCDF4|NC_NOWRITE, comm, info)` — no UDF
  flag) in netcdf4-model mode, verify dims, atts, and full data; in
  native mode the file has NEXTCDF-4 markers but is still standard
  HDF5 — upstream open is attempted and either verifies the standard
  subset or is asserted to fail cleanly (record which behavior
  results; do not claim upstream reads native-only types).
- Round 2 (upstream → NEXTCDF-4): all ranks `nc_create_par` with bare
  `NC_NETCDF4` (upstream dispatcher), same shape minus NEXTCDF-4-only
  types, collective writes, close, barrier; reopen via
  `nc_open_par(path, NC_NEXTCDF4, …)` and verify — exercises the
  marker-less open path in `NEXTCDF4_read_markers`.
- Also verify serial cross-opens on rank 0 after a barrier
  (`nc_open` upstream ↔ `nc_open NC_NEXTCDF4`).
- Plain comments, `Author: Edward Hartnett, Intelligent Data Design,
  Inc.`, `MPI_Init`/`MPI_Finalize`, communicator abort on unexpected
  failure.

## Verification

```sh
export PKG_CONFIG_PATH=/home/ed/local/netcdf-c_mpi/lib/pkgconfig
export LD_LIBRARY_PATH=/home/ed/local/hdf5-2.1.1_mpi/lib:/home/ed/local/netcdf-c_mpi/lib:${LD_LIBRARY_PATH:-}

cmake -S . -B build \
  -DCMAKE_C_COMPILER=/usr/bin/mpicc \
  -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  -DHDF5_DIR=/home/ed/local/hdf5-2.1.1_mpi/cmake \
  -DCMAKE_PREFIX_PATH="/home/ed/local/hdf5-2.1.1_mpi;/home/ed/local/netcdf-c_mpi" \
  -DNEP_ENABLE_NEXTCDF4=ON -DNEP_ENABLE_NEXTCDF4_PARALLEL=ON \
  -DNEP_ENABLE_PARALLEL_TESTS=ON -DNEP_ENABLE_BENCHMARKS=ON \
  -DNEP_ZSTD_PLUGIN_DIR=<netcdf-c mpi plugin dir> \
  -DBUILD_TESTING=ON

ctest --test-dir build -L nextcdf4_parallel --output-on-failure
ctest --test-dir build --output-on-failure
cmake --build build --target docs
```

- `nextcdf4_parallel` label must include: the two existing tests, all

- Local MPICH run of `-L nextcdf4_parallel` against the locally built
  MPICH stack (work item 5 documents building it); where not built,
  MPICH verification is the CI job.
- Feature-OFF build (`-DNEP_ENABLE_NEXTCDF4_PARALLEL=OFF
  -DNEP_ENABLE_PARALLEL_TESTS=OFF`) still configures, builds, passes
  full ctest and docs — no MPI symbols outside the guards.
- CI: `ci-parallel.yml` (Open MPI, focused + full suite) and the new
  `ci-parallel-mpich.yml` (focused label) pass; `nextcdf4.yml` normal/
  sanitizer/coverage and all other workflows unaffected. No Spack/
  conda job changes expected — no recipe-affected change.

## Out of scope

- SWMR writer/reader: Sprints 1V4–1V5.
- VDS, `NC_DISKLESS`/`NC_INMEMORY`/`NC_MMAP`, direct chunk APIs:
  v4.4.0.
- Parallel dynamic/string/`NC_STD_REF` data I/O and parallel
  reference-helper certification: unsupported by design (1V2
  `NC_ENOTBUILT`), not this sprint.
- Upstream-file fixture additions, `nccopy`/`nextdump` parallel tools,
  Fortran parallel wrappers, PnetCDF, MPI-sanitizer CI, error
  consensus beyond the 1V2 caller contract.
- Any assertion that upstream can read native-only NEXTCDF-4 types;
  interchange coverage is limited to standard-type content.
- LZ4/nep-compress plugin in the matrix (not built into the CI stack),
  committed artifacts from the MPICH job, performance gates/trends.
- Release notes, tag, Spack/conda version bumps: Sprint 2. This sprint
  does not implement, commit or publish anything during refinement.
