# v4.3.0 Sprint 1O: Fill Mode, Cache Control, Renaming Groups

Source: docs/roadmap.md, "V4.3.0 - NEXTCDF4 Development / Sprint 1O".

## Goal

NEXTCDF-4 provides working file-level fill defaults, effective per-variable HDF5 chunk-cache control, and persistent group renaming in native and NetCDF-4-model files. Unsupported memory, sharing and parallel modes fail explicitly rather than silently producing ordinary serial disk files. Focused regressions establish these contracts without expanding this sprint into upstream suite porting or string support.

## Decisions

| Topic | Decision |
|---|---|
| Chunk cache | Real HDF5 access-property settings, including updating already-open datasets; no successful no-op (Ed accepted recommendation 1a). |
| Group compatibility | Group creation and rename work in native and `NC_NETCDF4_MODEL` modes; remove the existing model-mode creation ban. Classic-model groups remain unsupported (Ed accepted 2a). |
| Test scope | Focused regressions only; no new upstream `nc_test4` ports (Ed accepted 3a). |
| Fill semantics | Match upstream file-default semantics: affect subsequently defined eligible variables, not existing variables or persisted file defaults. Preserve per-variable overrides and dynamic-type safety. |
| Unsupported modes | Return `NC_EINVAL` in backend create/open for the unsupported mode bits before filesystem mutation. Preserve earlier libdispatch errors for combinations rejected before backend dispatch. |
| CI | New tests are enabled in the existing full normal and sanitizer CTest runs; no new job or dependency build. |
| Packaging | No new installed files, public API, CMake option, dependency, minimum version, plugin path or variant. Spack and conda recipes are unchanged. |
| Release | Sprint 2 owns release notes/publication; parallel I/O is deferred beyond v4.3.0. |

## Current state (2026-11-23)

- `src/nextcdf4/nxt4dispatch.c` uses `NC_RO_set_fill`, `NC_NOTNC4_rename_grp`, and `NC_NOTNC4_set/get_var_chunk_cache`; parallel variable access is also an unsupported stub. `docs/nextcdf4_status_v4_3_0.md` lists these gaps.
- `src/nextcdf4/nxt4create.c:valid_create_mode()` rejects NetCDF-3 variant bits and mutually exclusive compatibility modes only. `nxt4open.c:NEXTCDF4_open()` has no equivalent unsupported-mode check. Create can unlink an existing destination, so validation must precede that operation.
- `src/nextcdf4/nxt4meta.c` creates some variable datasets eagerly, defers user-type datasets, and rebuilds dirty datasets at `_enddef`. `nx4_dcpl_fill()` consumes `var->no_fill`; it preserves special handling for dynamic user types and `NC_STD_REF`. Dataset create/open sites currently use default access properties.
- `src/nextcdf4/nxt4file.c:NEXTCDF4_add_file()` allocates shared `NC_FILE_INFO_T` and private state. `nxt4internal.h` gives coordinate-variable and dimension-scale handles separate owners, which matters when reopening a variable's dataset for cache changes.
- `src/nextcdf4/nxt4group.c:NEXTCDF4_def_grp()` explicitly rejects both classic and NetCDF-4-model groups. Group inquiry walks the shared metadata tree; full-name inquiry has a fixed buffer and currently copies only `NC_MAX_NAME` bytes into the caller's full-path buffer. Renaming needs correct descendant path inquiries as well as link persistence.
- Existing dimension/variable rename paths in `nxt4meta.c` update metadata indices and flush with `H5Fflush(..., H5F_SCOPE_LOCAL)`.
- Upstream reference checkout `/fast/ed/netcdf-c`: `libhdf5/hdf5file.c:NC4_set_fill()` changes `NC_FILE_INFO_T.fill_mode`; `libhdf5/hdf5var.c` applies that default at variable definition only for classes below `NC_STRING`. Its cache setter updates `var->chunkcache` and reopens the dataset. `libsrc4/nc4internal.c:nc4_var_list_add()` initializes cache values from global NetCDF defaults.
- Installed `/usr/local/hdf5-2.1.1/include/H5Ppublic.h` declares `H5Pset_chunk_cache(dapl, nslots, nbytes, double_w0)` and corresponding getter. NetCDF's setter orders its arguments as bytes, slots, float preemption: these orders must not be confused. The netcdf skill and installed `/usr/local/netcdf-c/include/netcdf_filter.h` were checked; this sprint adds no filter ID or plugin requirement.
- Local tools: GCC 13.3.0, CMake 3.28.3, Doxygen 1.9.8, HDF5 2.1.1 and netcdf-c 4.10.2-development. Existing configured `build` uses these libraries, enables NEXTCDF-4/docs, and passes 45/45 CTest tests on this date. This is a baseline run, not proof of the proposed behavior.

Runner-provided system libraries are not relied on for NEXTCDF-4. Future runner image tool versions are not pinned or verified here.
- Earlier plans `v4.3.0-sprint1L2-port-nc-test4.md`, `v4.3.0-sprint1M-fix-nextcdf4-issues.md` and the four 1N plans defer file fill/cache/group rename here. Preserve 1M's deferred-setter safety and 1N's dynamic ownership. 1N4 explicitly leaves mixed-feature ports to later suite expansion.
- Sprint 1P owns strings, 1Q provenance, 1R Fortran, and Sprint 2 release work. The roadmap contains no newer version than v4.3.0 and Sprint 1O names no GitHub issue directly.

## Work items

### 1. File-level fill mode with definition-time inheritance

Files: `src/nextcdf4/nxt4file.c`, `nxt4meta.c`, `nxt4internal.h`, `nxt4dispatch.c`; new `test/nextcdf4/tst_nextcdf4_fill_mode.c`.

Add private dispatch entry `int NEXTCDF4_set_fill(int ncid, int fillmode, int *old_modep);` in `nxt4file.c` and wire it in place of `NC_RO_set_fill`. Resolve the file from root or subgroup IDs, reject read-only files with `NC_EPERM`, reject values other than `NC_FILL`/`NC_NOFILL` with `NC_EINVAL`, optionally return the previous mode, then update shared `h5->fill_mode`. Initialize it to `NC_FILL` for each new/open session. Do not enter define mode, flush, rebuild existing datasets, or persist a new hidden attribute merely to change this session default.

In `NEXTCDF4_def_var`, assign `var->no_fill` from the file default before any eager dataset creation. Apply upstream's class restriction for standard atomic numeric/character types; include NEP fixed-size numeric/complex/bitfield atomics explicitly rather than accidentally treating their numeric IDs as dynamic classes. Exclude `NC_STRING`, user-defined types and `NC_STD_REF` from file-default inheritance; preserve their existing per-variable fill handling. `nc_def_var_fill` remains the explicit variable override before commitment; setting it later still returns `NC_ELATEDEF`. A later file-default change does not retroactively alter already-defined variables, including pending user-type variables. Convert `NC_NOFILL` to a boolean for `var->no_fill` rather than assuming it is 1.

Test initial/old modes, repeated changes, NULL old-mode output, invalid modes/IDs, read-only rejection, root/subgroup calls, define/data-mode use, defaults captured before/after variable definition, explicit overrides, unlimited growth and reopen. Run native, model and classic cases where applicable. Never assert values of unwritten no-fill storage; use inquiry/DCPL fill-time properties and written-data integrity instead. Retain existing small-float and vlen fill tests unchanged and add default-inheritance exclusions to the focused test.

### 2. Real dataset access properties and cache updates

Files: `src/nextcdf4/nxt4meta.c`, `nxt4internal.h`, `nxt4dispatch.c`; new `test/nextcdf4/tst_nextcdf4_cache.c`.

Add private entries:

```c
int NEXTCDF4_set_var_chunk_cache(int ncid, int varid, size_t size,
                                size_t nelems, float preemption);
int NEXTCDF4_get_var_chunk_cache(int ncid, int varid, size_t *sizep,
                                size_t *nelemsp, float *preemptionp);
```

Use existing `var->chunkcache` as the requested settings. Add private helpers in `nxt4meta.c`, declared in `nxt4internal.h` only if needed outside that file:

```c
int nx4_var_dapl(const NC_VAR_INFO_T *var, hid_t *daplp);
int nx4_reopen_var_cache(NC_GRP_INFO_T *grp, NC_VAR_INFO_T *var);
```

`nx4_var_dapl` returns an owned `H5P_DATASET_ACCESS` list with `H5Pset_chunk_cache(dapl, nelems, size, preemption)`. Close it on every success/failure path. Apply it to variable dataset creation, coordinate-variable dataset creation/open, deferred creation, dirty rebuild and metadata-loader opens that become live variable handles. Discovery-only opens and standalone dimension scales need no per-variable override. At metadata load, initialize requested values from NetCDF global defaults before the live open; per-variable overrides are session-only, not on-disk metadata.

Setters validate IDs and finite preemption in [0,1], returning `NC_EBADID`, `NC_ENOTVAR` or `NC_EINVAL` as appropriate. Permit zero size/slots (cache disable/tuning), read-only sessions and data mode; allow all three compatibility modes and contiguous/scalar variables, for which raw chunk caching has no I/O effect. Do not mark DCPL dirty, require define mode, recreate a dataset, change filters, or touch values/attributes. For a pending dataset, store validated settings for eventual creation. For an existing dataset, save the prior settings, flush pending writes, close all NEXTCDF-4-owned aliases to that dataset, and reopen with the new DAPL; update both variable and coordinate-scale aliases with independently owned handles. Merely opening an additional handle while the old dataset remains open is not an effective cache update. On failure, restore old settings and attempt the old-DAPL reopen; if recovery fails, leave handles invalid and return `NC_EHDFERR`, never a stale closed handle or false success. Retain stable metadata IDs and object identity.

The getter accepts NULL outputs. For live chunked datasets, query `H5Dget_access_plist`/`H5Pget_chunk_cache` for effective settings, mapping slots/bytes order correctly; for pending or nonchunked variables report the stored request. Close temporary property lists. No performance threshold is an acceptance criterion.

Tests inspect the backend-owned live dataset DAPL through the private test include path, not a separately opened HDF5 handle. Cover global defaults at definition/open, per-variable isolation, before/after `_enddef` and writes, read-only tuning, zero settings, preemption boundaries/NaN/out-of-range, NULL getter outputs, invalid IDs, coordinate aliases, deferred user types, dirty rebuild, contiguous/scalar behavior and reopen resetting overrides. Verify values, filters, fills, attributes and dimension attachments remain intact. Exercise non-string vlen data with correct reclamation under sanitizers.

### 3. Group rename and NetCDF-4-model groups

Files: `src/nextcdf4/nxt4group.c`, `nxt4internal.h`, `nxt4dispatch.c`; existing `test/nextcdf4/tst_nextcdf4_group.c` and `tst_nextcdf4_rename.c`.

Add `int NEXTCDF4_rename_grp(int grpid, const char *name);` and wire it instead of `NC_NOTNC4_rename_grp`. Remove only the `file->netcdf4_model` creation rejection from `NEXTCDF4_def_grp`; classic-model creation remains `NC_ENOTNC4`. Rename also returns `NC_ENOTNC4` for classic-model files, `NC_EPERM` for read-only files and `NC_EBADGRPID` for the root of an enhanced-model file. Match upstream normalized-name validation using `nc4_check_name`, including `NC_EINVAL` for NULL, name-length and illegal-name errors; check the parent's variable/group/type namespace with `nc4_check_dup_name`. Same-name rename follows upstream's duplicate-name result, `NC_ENAMEINUSE`, rather than adding a new no-op exception.

Use `NEXTCDF4_check_write_define` for existing automatic enhanced-mode transitions, allocate the normalized replacement name before mutating HDF5, move the link with `H5Lmove` relative to the parent group, update the group's name and parent child index, and flush with `H5F_SCOPE_LOCAL`. Do not recreate groups, move them between parents, change ncids or close descendant datasets/types merely for rename. Maintain a coherent metadata/link pair on errors; preallocate before mutation and roll back the HDF5 link if the index update cannot be completed. A flush failure is reported, not disguised as a successful durable rename.

Correct `NEXTCDF4_inq_grpname_full` to copy the complete checked full path, not only `NC_MAX_NAME` characters. Retain its existing depth/path-capacity limits and report overflow rather than truncate. This bounded correction is part of making renamed descendant inquiries accurate, not a redesign of arbitrary-depth lookup.

Test nested populated groups, variables/attributes, inherited dimensions/types, same-session lookup by old/new relative and absolute paths, descendant full paths longer than `NC_MAX_NAME`, unchanged IDs, repeated rename, define/data modes, read-only/root/invalid/duplicate-name errors, and close/reopen persistence. Test native and `NC_NETCDF4_MODEL`; in model mode verify groups written by NEXTCDF-4 through upstream `nc_open` without `NC_NEXTCDF4`, and rename a group in an upstream-created file opened with NEXTCDF-4. Keep string values out. Confirm reference tokens still identify the same HDF5 objects; do not promise that a previously stored path string is rewritten.

### 4. Reject unsupported create/open modes before side effects

Files: `src/nextcdf4/nxt4file.c`, `nxt4internal.h`, `nxt4create.c`, `nxt4open.c`; existing `test/nextcdf4/tst_nextcdf4_file.c` and `tst_nextcdf4_open.c`.

Add shared private `int NEXTCDF4_check_mode(int mode);`, called by both backend entry points immediately after path validation. Return `NC_EINVAL` for any of `NC_DISKLESS | NC_INMEMORY | NC_MPIIO | NC_SHARE | NC_PERSIST | NC_MMAP`. `NC_MPIPOSIX` aliases `NC_MPIIO`; do not pretend it is an independent bit. Keep existing create-only format/compatibility-combination validation. Do not implement an unknown-bit allowlist that accidentally rejects the multi-bit 64-slot `NC_NEXTCDF4` encoding or legitimate supported mode flags.

Validate before `access`/unlink/create, state registration and HDF5 file open. Preserve upstream libdispatch's earlier errors for incompatible memory-flag combinations. Test each individual unsupported bit through public create/open, both read-only/read-write opens, and representative combinations. A create rejection must neither create a new file nor clobber an existing sentinel file. A rejected write-open must leave the existing valid dataset unchanged. Where libdispatch preempts backend execution, test `NEXTCDF4_check_mode` directly for the exact backend result rather than altering upstream dispatch. Supported mode controls must still create/open successfully. Keep `NC_NOTNC4_var_par_access` unchanged.

## Out of scope

- New upstream ports (`tst_grps`, `tst_coords`, `tst_chunks`, `tst_vars3`, and other mixed-feature cases): future suite-expansion work after feature prerequisites; no full upstream parity claim.
- String variable/attribute values, including strings nested in user types: Sprint 1P.
- Provenance attributes: Sprint 1Q. Fortran additions: Sprint 1R.
- Parallel create/open/access, MPI drivers, SWMR and in-memory image files (`nxt4image.c`): future release after v4.3.0; this sprint only rejects unsupported mode requests.
- Cache performance benchmarking, new plugins/filter APIs, global cache algorithm changes, unlimited group-depth/path redesign, nested reference types and unrelated backend defects: backlog.
- Release notes, tagging/publication, dependency release-floor bump, Spack version-bump/upstream PR and conda publication: Sprint 2. Sprint 2 must include the new controls, lifted model-group restriction, stricter mode rejection and parallel deferral in `docs/releases/v4.3.0.md`.
