# V3.4.0 Sprint 1: mmCIF Reader Infrastructure

**Objective**: Add the PDBx/mmCIF UDF slot definitions, a `NEP_ENABLE_MMCIF` CMake option (default `OFF`), a no-op dispatch layer (`libncmmcif`) that can open and close a real `.cif` file without parsing any records, C and Fortran smoke tests, and a dedicated `ci-mmcif.yml` CI workflow. No mmCIF record parsing happens in this sprint — that is Sprint 2.

---

## Background

PDBx/mmCIF files are dictionary-based plain-text files built on the STAR/CIF grammar (see the `mmcif` skill at `.devin/skills/mmcif/SKILL.md`). Unlike FITS, GRIB2, GeoTIFF, DICOM, or PDS4, a dedicated mmCIF reader does **not** require a new external parsing library; a small custom tokenizer will be written in Sprint 2. This sprint follows the same infrastructure-first pattern used for FITS and PDB: get the dispatch skeleton, build-system wiring, and CI green before writing any real reader logic.

**Clarified decisions** (from sprint planning):
- mmCIF is assigned **UDF8**, following the v3.3.0 assignment of legacy PDB to UDF7. The `pdb-legacy` and `mmcif` skill files already reflect this allocation.
- `NEP_ENABLE_MMCIF` defaults to **OFF** in this sprint; flip to `ON` in Sprint 2 once the dispatch layer is proven, mirroring the FITS and PDB precedent.
- A new dedicated `ci-mmcif.yml` workflow is created, matching `ci-fits.yml`/`ci-pdb.yml` conventions. No extra system packages are required for mmCIF itself.
- The smoke tests verify only `nc_open()`/`nc_close()` round-trips on real `.cif` files; no format-detection or parsing testing happens yet.
- `NC_MMCIF_initialize()` registers the handler with the literal magic string `"data_"`. A PDBx-specific category check to avoid matching generic (small-molecule) CIF files is deferred to Sprint 2.
- NEP is now **CMake-only** (Autotools was removed in v3.1.0), so this sprint makes no `configure.ac`/`Makefile.am` changes.

## Tasks

### 1. Add mmCIF to the UDF slot table in `include/nep.h`

```c
/** PDBx/mmCIF format uses UDF8 slot */
#define NEP_UDF_MMCIF NC_UDF8

/** PDBx/mmCIF magic: "data_" token at the start of the file */
#define NEP_MAGIC_MMCIF "data_"

/** PDBx/mmCIF format display name */
#define NEP_FORMAT_NAME_MMCIF "mmCIF"
```

Update the `@section udf_slots` Doxygen comment block and the `nep_udf_slots` table:
- List UDF8 as PDBx/mmCIF.
- Keep UDF9 as Reserved for future use.

### 2. Add `NEP_ENABLE_MMCIF` build option (default OFF)

**CMake (`CMakeLists.txt`)**:

```cmake
# PDBx/mmCIF reader support (v3.4.0) - default OFF; enable with -DNEP_ENABLE_MMCIF=ON
option(NEP_ENABLE_MMCIF "Enable PDBx/mmCIF reader support" OFF)
if(NEP_ENABLE_MMCIF)
    set(HAVE_MMCIF TRUE)
endif()
```

No `find_library`/`find_path` detection is needed — there is no external dependency.

Also update the following CMake locations:
- The `NEP_ENABLE_VIZ_EXAMPLES` guard that requires at least one enabled UDF reader: add `HAVE_MMCIF` to the list.
- The `.ncrc` fragment assembly block: add a `HAVE_MMCIF` branch that appends `.ncrc-mmcif.in`.

**`config.h.cmake.in`**:

```c
/* Define if the PDBx/mmCIF reader is enabled */
#cmakedefine HAVE_MMCIF
```

### 3. Create dispatch and file layers

New files, following the PDB Sprint 1 no-op pattern (`include/pdbdispatch.h`, `src/pdbdispatch.c`, `src/pdbfile.c`):

- `include/mmcifdispatch.h` — define `NC_FORMATX_NC_MMCIF` = `NC_FORMATX_UDF8`, `NC_MMCIF_FILE_INFO_T` struct (placeholder: `char *path`), and prototypes for `NC_MMCIF_open`, `NC_MMCIF_close`, `NC_MMCIF_abort`, `NC_MMCIF_inq_format`, `NC_MMCIF_inq_format_extended`, `NC_MMCIF_get_vara`, `NC_MMCIF_initialize`, `NC_MMCIF_finalize`.
- `src/mmcifdispatch.c` — `static const NC_Dispatch MMCIF_dispatcher` table; `NC_MMCIF_initialize()` calls `nc_def_user_format(NEP_UDF_MMCIF, MMCIF_dispatch_table, NEP_MAGIC_MMCIF)`; `NC_MMCIF_finalize()` returns `NC_NOERR`.
- `src/mmciffile.c`:
  - `NC_MMCIF_open()`: validate mode (read-only only), create a minimal `NC_FILE_INFO_T` via `nc4_file_list_add()`, set `h5->no_write = NC_TRUE`, allocate and store an empty `NC_MMCIF_FILE_INFO_T` with just the file path. **Does not read or parse the `.cif` file contents.**
  - `NC_MMCIF_close()`: free `NC_MMCIF_FILE_INFO_T` and `path`.
  - `NC_MMCIF_abort()`: return `NC_NOERR`.
  - `NC_MMCIF_inq_format()` / `NC_MMCIF_inq_format_extended()`: return `NC_FORMATX_NC_MMCIF` / `NC_NOWRITE`.
  - `NC_MMCIF_get_vara()`: return `NC_NOERR` (no-op; no variables exist yet).

### 4. Wire the mmCIF library into the build system

- `src/CMakeLists.txt`: add an `if(HAVE_MMCIF)` block building `ncmmcif` from `mmcifdispatch.c mmciffile.c`, linking HDF5/NetCDF-C, and installing `mmcifdispatch.h`.
- Add the `.ncrc` mmCIF fragment (`.ncrc-mmcif.in`):

```ini
# PDBx/mmCIF protein structure data (UDF slot 8)
NETCDF.UDF8.LIBRARY=@NEP_LIBDIR@/libncmmcif.so
NETCDF.UDF8.INIT=NC_MMCIF_initialize
NETCDF.UDF8.MAGIC=data_
```

### 5. Ensure `test/data/mmCIF/*.cif` test files are copied to the build tree

- `test/data/mmCIF/1J7W.cif`, `test/data/mmCIF/2W6V.cif`, and `test/data/mmCIF/4HHB.cif` already exist (sourced from https://www.rcsb.org).
- `test/CMakeLists.txt`: add an `if(HAVE_MMCIF)` block that creates `${CMAKE_CURRENT_BINARY_DIR}/data/mmCIF` and `configure_file()` copies the three `.cif` files, mirroring the `test/data/PDB/` directory-copy pattern.

### 6. Add C test `test/tst_mmcif_udf.c`

- Include `mmcifdispatch.h`.
- Call `NC_MMCIF_initialize()`.
- `nc_open("<builddir>/data/mmCIF/1J7W.cif", NC_NOWRITE, &ncid)`, expect `NC_NOERR`.
- `nc_close(ncid)`.
- Print `Done.` and return 0.
- Gated on `#ifdef HAVE_MMCIF`.

Wire into `test/CMakeLists.txt` (`if(HAVE_MMCIF)` block, `add_executable`, `target_link_libraries`, `add_test`, and the same `LD_LIBRARY_PATH`/`NETCDF_RC` environment used by other UDF tests).

### 7. Add Fortran smoke test `ftest/ftst_mmcif_udf.F90`

- `use netcdf` and `use iso_c_binding`.
- Bind to `NC_MMCIF_initialize()` via `iso_c_binding`.
- Open one real mmCIF file from `../test/data/mmCIF/1J7W.cif` read-only, forcing UDF slot 8 (`NC_UDF8` = `0x1000000` = `16777216`).
- Close the file.
- Gated on `HAVE_MMCIF`.

Wire into `ftest/CMakeLists.txt` (`if(HAVE_MMCIF)` block), linking `ncmmcif`, `nepf`, and `nep` plus NetCDF-Fortran libraries, with `add_dependencies(ftst_mmcif_udf ncmmcif)`.

### 8. Create `.github/workflows/ci-mmcif.yml`

New workflow file, modeled on `ci-pdb.yml` but with mmCIF enabled instead of PDB:

- **Trigger**: push and PR to `main`.
- **Matrix**: CMake only; Fortran ON; all other UDF readers and compression filters OFF.
- **Dependencies**: standard HDF5/NetCDF-C/NetCDF-Fortran build chain, no additional `apt-get` packages for mmCIF itself.
- **Configure**: `-DNEP_ENABLE_MMCIF=ON`, `-DNEP_ENABLE_PDB=OFF` (and all other format handlers OFF), `-DNEP_ENABLE_FORTRAN=ON`.
- **Build & test**: `cmake --build build -j$(nproc)` then `ctest --verbose`.
- **Summary step**: prints build system, `HAVE_MMCIF` status, and notes that no external parsing library is required.

Does not modify `ci.yml` — mmCIF stays OFF there by default (matching PDB Sprint 1 isolation).

## Acceptance Criteria

- `include/nep.h` defines `NEP_UDF_MMCIF` (`NC_UDF8`), `NEP_MAGIC_MMCIF` (`"data_"`), and `NEP_FORMAT_NAME_MMCIF`.
- `CMakeLists.txt` supports `NEP_ENABLE_MMCIF`, defaulting to `OFF`, and sets `HAVE_MMCIF` when enabled.
- `config.h.cmake.in` contains `#cmakedefine HAVE_MMCIF`.
- `include/mmcifdispatch.h`, `src/mmcifdispatch.c`, and `src/mmciffile.c` exist and build `libncmmcif.so` when enabled.
- `NC_MMCIF_initialize()` registers the handler on UDF8 with magic `"data_"`.
- `test/data/mmCIF/1J7W.cif`, `2W6V.cif`, and `4HHB.cif` are copied to the build tree under `data/mmCIF/`.
- `test/tst_mmcif_udf.c` opens and closes a real `.cif` file successfully.
- `ftest/ftst_mmcif_udf.F90` compiles and passes when `NEP_ENABLE_FORTRAN=ON`.
- `ci-mmcif.yml` is created and passes.
- `ci.yml` is unchanged and unaffected (mmCIF OFF by default).
- No mmCIF record parsing occurs yet.
