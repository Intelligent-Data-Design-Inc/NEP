# v4.3.0 Sprint 1N1: Fixed-Size User Types

Source: docs/roadmap.md, "V4.3.0 / Sprint 1N1".

## Goal

Compound types with scalar atomic fields, integer enums, and opaque types work as variables and attributes through definition, I/O, inquiry, close, and reopen. Both native NEXTCDF-4 and `NC_NETCDF4_MODEL` support these standard enhanced-model types, including interchange with upstream NetCDF-4. This is the foundation for 1N2 (fixed-size nesting/arrays), 1N3 (vlens), and 1N4 (upstream regression ports).

## Decisions

| Topic | Decision |

| Modes | Native and `NC_NETCDF4_MODEL` throughout (Ed, 1a); classic-model user types remain rejected. |
| Nesting | Non-string variable-length nesting belongs to 1N3 (Ed, 2a); fixed-size nesting belongs to 1N2. |

| Public surface | Existing netCDF C APIs and typeids only; no new installed API, CMake option, capability macro, or dependency. |
| Conversion | User types use matching-type/untyped I/O, not `nx4_convert_type`; no new numeric conversions. |
| Complex | Retain native HDF5 complex types; ordinary `{r,i}` compounds remain user compounds, never structurally reinterpreted. |

## Current state (2026-11-22)

- `src/nextcdf4/nxt4type.c` defines all four user-type classes, but `check_type_write` rejects `NC_NETCDF4_MODEL`. Compound fields and vlen bases use atomic-only mapping; array insertion and vlen element helpers return `NC_ENOTBUILT`.
- `src/nextcdf4/nxt4meta.c`: `NEXTCDF4_def_var`/`NEXTCDF4_put_att` call `NEXTCDF4_check_atomic_type`; `set_var_type` allocates private atomic records. Dataset creation, fill handling, attribute copying, writing and reading also assume atomic types. Merely removing validation is insufficient.
- `load_group_metadata` loads variables and attributes before `load_children` discovers committed types. `load_one_type` creates empty compound-field and enum-member lists. `load_one_var` uses atomic-only `map_nc_type`.
- `nx4_dcpl_fill` treats every id above `NC_STRING` as a NEP atomic. Installed `netcdf.h` reserves user ids from `NC_FIRSTUSERTYPEID` (=32); NEP atomic ids occupy the lower reserved range (`include/nep.h`).
- `src/nextcdf4/nxt4io.c` has atomic-only `NEXTCDF4_memory_type` and size resolution. `nxt4file.c` closes datasets but needs an explicit audit of type-handle lifetime before shared metadata deletion.
- `docs/nextcdf4.md` and `docs/plan/NEXTCDF4_plan.md` promise enhanced-model types but still describe complex as `{r,i}`. `docs/prd.md` also describes structural compound reinterpretation. The code uses native `H5T_COMPLEX_IEEE_F*`/`H5T_NATIVE_*_COMPLEX`.
- Earlier handoffs: 1L2 left user-type-dependent ports for later; 1M retained deferred DCPL rebuilds and committed-variable `NC_ELATEDEF`; 1H left user-type conversion out of scope. Preserve all three decisions.

## Work items

### 1. Context-aware type plumbing

Files: `src/nextcdf4/nxt4type.c`, `nxt4internal.h`, `nxt4meta.c`, `nxt4io.c`, `nxt4file.c`.

Add these private interfaces, with documented ownership:

```c
int nx4_find_type(NC_GRP_INFO_T *grp, nc_type xtype, NC_TYPE_INFO_T **typep);
int nx4_type_size(NC_GRP_INFO_T *grp, nc_type xtype, size_t *sizep);
int nx4_file_type(NC_GRP_INFO_T *grp, nc_type xtype, hid_t *typep);
int nx4_memory_type(NC_GRP_INFO_T *grp, nc_type xtype, hid_t *typep);
```

`nx4_find_type` returns a borrowed visible user-type record, checking the current group and ancestors, never a sibling/descendant merely because its id exists file-wide. The size/file/memory helpers retain current atomic behavior and resolve user records for ids ≥ `NC_FIRSTUSERTYPEID`. The latter two return owned HDF5 handles that callers close. Do not change the atomic-only helpers' signatures; migrate context-aware callers instead.

Use the shared `NC_TYPE_INFO_T` for user-typed variables with balanced reference counts; do not fabricate an atomic record or free the same record twice. Keep distinct file and memory layouts for non-native-endian types; compound memory fields use the offsets exposed by inquiry. Reject typed atomic buffers for user variables/attributes with `NC_EBADTYPE`; matching user types and `NC_NAT` bypass numeric conversion. Resolve user-defined fill sizes by class rather than `id > NC_STRING`; preserve atomic fill behavior and all Sprint 1M setter guards.

### 2. Definitions, persistence, and I/O

Files: `nxt4type.c`, `nxt4meta.c`, `nxt4io.c`, `nxt4file.c`, `nxt4internal.h`.

Remove only the erroneous `netcdf4_model` rejection in `check_type_write`. Permit standard user types in that mode; continue rejecting NEP-only atomic types recursively. Validate write permission, mode, names, enum integer bases, field bounds, and committed-type mutation before changing HDF5 or the metadata lists. Fix enum insertion/inquiry to preserve signed values and all unsigned 64-bit bits rather than widen every value through `long long`.

Defer creation of user-typed variable datasets until `_enddef` has committed their types. Preserve the existing eager atomic-variable path. Allow `var_io` to auto-enddef on writes before requiring a dataset handle; inquiries and setters must work while the user-typed dataset handle is negative. Queue attributes whose datatype is a user type or whose owning dataset is pending, retaining definition order, and materialize them after type commit and dataset creation. Existing atomic attributes on existing objects keep their path. A metadata write before enddef must not prematurely freeze a compound/enum that still accepts members.

Make `add_att`, `read_hdf5_att`, `nx4_write_att`, `nx4_rewrite_atts`, get/put/delete/rename attribute paths and fill restoration context-aware. For `NC_GLOBAL`, resolve the group identified by `ncid`, not always `h5->root_grp`, so subgroup attributes and their locally defined types use the right context. Support zero-length attributes, variable/global/subgroup attributes, replacement and same-type `nc_copy_att`. For fixed-size user data, copy exactly the resolved memory size per element with overflow guards. User-defined default/custom fills follow upstream class semantics; regression-test unwritten data rather than applying the NEP atomic zero-fill shortcut. No unrelated file-level `nc_set_fill` work.

Close owned type handles once, after dependent objects are finished and before netcdf metadata deletion, including partial-open and failed-definition paths. Preserve shared-record reference counts.

### 3. Load committed types before values

Files: `nxt4meta.c`, `nxt4type.c`, `nxt4internal.h`.

Split type discovery from child-group/value loading. Register the group tree and committed type identities before loading any variable or attribute that references them. Populate scalar compound fields and enum members, base types, sizes, and committed state before exposing inquiries. Resolve variable/attribute datatypes to registered committed objects by HDF5 object identity, not just matching type names or `H5Tequal` (distinct named types can have equal shapes). Preserve distinct types in different groups. Load native memory layouts consistently with the field offsets reported to callers. Reopened files must accept further writes without trying to recommit existing names. Return actual loader errors rather than silently dropping supported user-typed attributes.
