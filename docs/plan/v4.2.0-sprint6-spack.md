# v4.2.0 Sprint 6: Spack

Source: docs/roadmap.md, "V4.2.0 - Move Compression Filters to nep-compress / Sprint 6".

## Goal

Spack installs format-only NEP 4.2.0: there are no compression
variants, and every format reader whose dependencies Spack provides
is available. The in-repository recipe is an overlay repository that
is byte-identical to the copy in spack/spack-packages#5557.
`spack install --test=root` runs NEP's test suite in pinned,
non-masked CI on every push and pull request. Upstream PR #5557 is
updated in place so that 4.2.0 is the oldest version it offers.

## Decisions

| Topic | Decision |
| --- | --- |
| netcdf-c 4.10.1 not in spack-packages | Update #5557 now. Keep `depends_on("netcdf-c@4.10.1:")` and say in the PR body that it depends on spack/spack-packages#6569. Until #6569 merges, CI explicitly requests `^netcdf-c@main`. (Ed: 1a) |
| Old versions | The recipe offers only `main` and `4.2.0`. Upstream `1.3.0` is removed, and the PR explains why: every pre-4.2.0 release bundled the LZ4/BZIP2 filters, which now live in nep-compress. (Ed: 2a) |
| Format variants | Remove `dicom`, because GDCM has no Spack package. Leave `cdf` as a commented-out variant that points at spack/spack-packages#2797. Add `mmcif` and `nextcdf4`, both default off. Raise HDF5 to `@1.14:`. (Ed: 3a) |
| Spack CI | Rewrite `.github/workflows/spack.yml` on the nep-compress pattern: `spack/setup-spack@v3` pinned to Spack `v1.2.2` and spack-packages `v2026.10.0`, a committed `spack/ci/spack.yaml` environment, a dependency cache, and `install --test=root` on both pushes and PRs. Upstream's ruff/vermin checks replace `spack style \|\| true`. (Ed: 4a) |
| Release order | Tag v4.2.0 before this sprint starts, as the roadmap allows. The recipe changes land on `main` afterward; they do not affect the 4.2.0 tarball. |
| Recipe location | Move `spack/NEP/package.py` to `spack/repos/spack_repo/nep/packages/nep/package.py` with `repo.yaml` (namespace `nep`, `api: v2.2`), matching the nep-compress layout. `spack/cdf/` and `spack-cdf.yml` are not touched. |

### 2. Rewrite the recipe for 4.2.0

File: `spack/repos/spack_repo/nep/packages/nep/package.py`.

Header and docstring:

- Use the current upstream header, as in nep-compress:
  `# Copyright Spack Project Developers. See COPYRIGHT file for details.`
  followed by the SPDX line.
- Keep the docstring that says compression comes from nep-compress.

URLs:

- `url = "https://github.com/Intelligent-Data-Design-Inc/NEP/archive/refs/tags/v4.2.0.tar.gz"`
- Keep `homepage` and `git`.

Versions:

- `version("main", branch="main")`
- `version("4.2.0", sha256="<computed>")`, with no per-version
  `url=`. Compute the checksum after tagging:

  ```sh
  curl -sL https://github.com/Intelligent-Data-Design-Inc/NEP/archive/refs/tags/v4.2.0.tar.gz | sha256sum
  ```

  Then confirm it with `spack checksum nep 4.2.0`.
- Delete versions 2.4.0 through 3.0.0.

Variants, in this order:

- `docs` (default True), `fortran` (True), `fits` (False), `geotiff`
  (False), `grib2` (False), `pds4` (False), `pdb` (True), `mmcif`
  (False), `nextcdf4` (False), `parallel` (False), `examples`
  (False), `benchmarks` (False).
- Delete `dicom`.
- Add this commented block where `cdf` would sit:

  ```python
  # cdf: the NASA CDF reader needs the cdf package, which is not yet in
  # spack-packages (https://github.com/spack/spack-packages/pull/2797).
  # Enable once it merges:
  # variant("cdf", default=False, description="Enable NASA CDF reader support")
  # depends_on("cdf", when="+cdf")
  ```

- Add a comment that DICOM is omitted because NEP's DICOM reader
  requires GDCM's lossless JPEG libraries, which Spack does not
  package.
- `mmcif` description: "Enable PDBx/mmCIF reader support (no external
  library required)".
- `nextcdf4` description: "Enable the NEXTCDF-4 UDF backend".

Dependencies:

- Keep:
  - `c`
  - `fortran when +fortran`
  - `netcdf-c@4.10.1:`
  - `netcdf-c +mpi when +parallel`
  - `netcdf-fortran when +fortran`
  - `cfitsio`, `libgeotiff`, `libtiff` (with `+geotiff`), `g2c`,
    `libxml2` and `mpi`, each under its existing `when=`
  - `doxygen when +docs`
- Change HDF5 to `hdf5@1.14:+hl~mpi when ~parallel` and
  `hdf5@1.14:+hl+mpi when +parallel`.
- Add `depends_on("pkgconfig", type="build")`. CMake calls
  `pkg_check_modules` for netcdf and netcdf-fortran.
- Delete `libdicom` and `libjpeg-turbo`.
- The `mmcif`, `pdb` and `nextcdf4` variants add no dependencies.

`cmake_args`:

- `self.define("CMAKE_INSTALL_LIBDIR", "lib")`
- The existing `define_from_variant` list, minus `NEP_ENABLE_DICOM`,
  plus `NEP_ENABLE_MMCIF` and `NEP_ENABLE_NEXTCDF4`.
- `self.define("NEP_ENABLE_DICOM", False)` and
  `self.define("NEP_ENABLE_CDF", False)`, so a cache default can't
  turn them on.
- **Do not define `BUILD_TESTING`.** If it were OFF while `+docs` is
  on, CMake would do a docs-only build and install no libraries. Tests
  are always built and run only under `--test`.

Testing hooks:

- Delete the custom `check()`. `CMakeBuilder`'s default runs the
  `test` target when tests are requested.

`check_install`:

- Always assert `lib/libnep.so`.
- For each enabled reader, assert `lib/libnc<name>.so`: `geotiff`,
  `grib2`, `pds4`, `fits`, `pdb`, `mmcif`, and `nextcdf4` (as
  `libncnextcdf4.so`).
- When any reader is enabled, assert `share/.ncrc` (from
  `self.prefix.share`).
- Remove the `dicom` check.
- Use `self.spec.satisfies("+x")` instead of `"+x" in self.spec`.

### 3. CI environment and workflow

New file `spack/ci/spack.yaml`:

```yaml
spack:
  specs:
  - nep@main ~docs +fortran +fits +geotiff +grib2 +pds4 +pdb +mmcif +nextcdf4 ^netcdf-c@main~mpi
  repos:
    nep: ../repos/spack_repo/nep
  develop:
    nep:
      spec: nep@=main
      path: ../..
  view: false
  concretizer:
    unify: true
  config:
    install_tree:
      root: /opt/spack
      padded_length: 128
  packages:
    all:
      require: target=x86_64_v3
```

Add a comment above `specs` saying that `^netcdf-c@main` changes to
`^netcdf-c@4.10.1` once spack/spack-packages#6569 merges.

Rewrite `.github/workflows/spack.yml`:

- Triggers: `push`, `pull_request`, `workflow_dispatch`.
- Job `style`:
  - Install `ruff==0.15.11` and `vermin==1.8.0` with pip.
  - Run, without `|| true`:
    - `ruff format --diff`
    - `ruff check --no-fix`
    - `vermin --backport importlib --backport argparse --violations --backport typing --eval-annotations -t=3.6- -vvv`
  - All three run on the recipe, using the spack-packages
    `pyproject.toml` from the pinned `packages_ref` checkout (the same
    `setup-spack` step as the `spack` job).
- Job `spack`, copied from nep-compress's `spack.yml` with the same
  pins (`spack_ref: v1.2.2`, `packages_ref: v2026.10.0`,
  `spack_path: .ci-spack`, `packages_path: .ci-spack-packages`,
  `buildcache: true`):
  1. `spack -e spack/ci repo list`, then `spack audit packages nep`.
  2. `spack spec` for `nep@4.2.0 ^netcdf-c@main` and for
     `nep@main+docs+parallel ^netcdf-c@main+mpi ^mpich`, run with the
     overlay added (`spack repo add spack/repos/spack_repo/nep`).
  3. Concretize, restore the cache, install dependencies, and save
     the cache, exactly as nep-compress does.
  4. `spack -e spack/ci install --test=root --verbose nep`.
  5. Locate the prefix and decompress `spack-build-out.txt.gz`. Then:
     - `test -f` for `lib/libncmmcif.so`, `lib/libncnextcdf4.so` and
       `share/.ncrc`;
     - `grep -q` the build log for `tst_mmcif`, `tst_pdb_udf` and
       `ftst_pdb_udf`.

     Before writing the greps, the implementer checks the exact test
     names with `ctest -N` in a local `build`.
  6. On failure, upload the Spack logs.
- Delete the old `lint`, `spec` and `install` jobs and their
  `packages.yaml` externals.
