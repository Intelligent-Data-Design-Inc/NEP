# v4.2.0 Sprint 4: Make NEP Format-Only

## Goal and cutover gate

Remove NEP's bundled LZ4/BZIP2 compression implementation only after
nep-compress independently builds, tests and documents it. Interchange
between files written through old NEP and nep-compress is not a gate.
Preserve NEP's
UDF readers, NEXTCDF-4 backend, logging, and generic NetCDF/HDF5 filter
support. CMake is NEP's only supported build system.

[Sprint 1's ownership inventory](v4.2.0-sprint1-results.md) and
[Sprint 2's results](v4.2.0-sprint2-results.md) are the baseline.
[Sprint 3's hosted checks](v4.2.0-sprint3-results.md) establish the
standalone CI gate: PR #1 passed LZ4, BZIP2 and both-filter jobs.
The checks include new-project LZ4/BZIP2 round trips; old-NEP/new-project
file interchange is explicitly out of scope.

**Before editing/removing compression code:**

1. Confirm nep-compress C/Fortran/HDF5 round trips, including filter
   availability and missing-plugin errors, and its independent hosted
   CI pass. Old NEP writer fixtures are not required.
2. Verify a process can use NEP's format handlers and nep-compress
   together without a duplicate plugin ID, missing symbol or `nep.mod`
   collision. Confirm provenance and redistribution terms for the
   copied LZ4 plugin before declaring the new package release-ready.
   Stop before removal if these independent build/runtime checks fail.

File removals and deletion of the existing `build` tree require
confirmation naming the affected paths. The existing `build` tree
contains zero registered tests and an HDF5 1.14.6 cache; it must be
replaced before a clean format-only regression build per `AGENTS.md`.
No deletion is part of this plan document.

## NEP changes after the gate

1. **Source/API:** Extract only LZ4/BZIP2 code from `src/nep.c`,
   declarations and IDs from `include/nep.h`, leaving `nep_log`,
   `nep_set_log_level`, logging headers, UDF slot and NEXTCDF-4
   interfaces intact. Inactive JPEG/LZF stubs were never built and are
   removed rather than advertised as working compression APIs. Keep
   `libnep` for NEXTCDF-4 and other consumers.
2. **Build/metadata:** Remove `NEP_BUILD_LZ4/BZIP2`, `BUILD_LZ4/BZIP2`,
   generated `NEP_HAS_LZ4/BZIP2`, plugin build/install targets and the
   `test_h5` subdirectory from root `CMakeLists.txt`,
   `config.h.cmake.in`, `include/nep_meta.h.in`, `test/tst_meta.c`,
   `NEPConfig.cmake.in` and relevant test rules. Check formerly
   provided options produce a clear migration diagnostic rather than
   being silently accepted as unused CMake cache entries.
3. **Fortran and tests:** Remove compression-only `fsrc/nep.F90` /
   `fsrc/CMakeLists.txt`, `ftest/ftst_nep_{lz4,bzip2}.F90`,
   `test/tst_{lz4,bzip2}.c`, `test/tst_perf.c` and its sole helper
   `test/tst_utils.c`, and `test_h5/`. Update `test/` and `ftest/`
   CMake and run scripts. Keep `NEP_ENABLE_FORTRAN` for remaining
   reader tests and remove their now-obsolete `nepf` link dependency.
   Reassess what `NEP_HAS_FORTRAN` means after `nep.mod` is retired.
4. **Plugin and examples:** Remove NEP's `hdf5_plugins/LZ4/` only after
   verifying its required source/license notices are preserved in
   nep-compress. Remove LZ4/BZIP2-only examples under
   `examples/performance/` already copied to nep-compress; keep
   generic Deflate, Zstandard, chunking and other NetCDF examples.
   Keep `lossless.c` and `quantize.c` sources for a later release, but
   comment their targets and tests out until NEP explicitly depends on
   nep-compress. Continue building general Zstandard, zlib/DEFLATE and
   SZIP examples through NetCDF-C/HDF5.
5. **Packaging/CI:** Remove filter variants and invalid plugin
   install checks from `spack/NEP/package.py`, rewrite `conda/meta.yaml`
   and `conda/build.sh` so they no longer package a filter or check
   for `nep.mod`, and remove obsolete `-DNEP_BUILD_LZ4/BZIP2` switches
   from format-only workflows. Keep all format CI and optional reader
   dependencies. Ensure neither normal builds nor docs-only builds
   need liblz4/libbz2 development headers.
6. **Documentation:** Replace active bundled-compression claims and
   install instructions in `README.md`, `docs/mainpage.md`,
   `docs/design.md`, `docs/prd.md`, `docs/prfaq.md`, Doxygen inputs
   and package descriptions with a link to nep-compress and a
   source/build migration note. Remove or redirect
   `docs/compression.md` without breaking links; preserve historical
   release notes and historical images when still referenced.
   Add `docs/releases/v4.2.0.md` to document the package/API move.

## Acceptance and verification

- On a clean `build`, configure NEP without LZ4/BZIP2 packages and
  compile, install and run its registered format tests (including
  optional UDF readers when their dependencies exist). Test
  `NEP_ENABLE_NEXTCDF4=ON` and logging ON/OFF without relying on
  nep-compress. Verify a docs-only build and CMake package exports.
- Inspect installed NEP headers, libraries and modules: no bundled
  LZ4 plugin, compression wrapper symbols, `nepf`, or `nep.mod`;
  NEP's logging and format interfaces remain. Check no active docs,
  packaging, examples, or CI still claim bundled filters.
- Run nep-compress's own file round trips alongside NEP's installed
  format libraries. Document the package migration and retained filter
  IDs without promising old-NEP/new-project file interchange.
- Do not claim Sprint 4 complete if the independent nep-compress tests,
  LZ4 redistribution check, or format-only NEP regression build fails.
