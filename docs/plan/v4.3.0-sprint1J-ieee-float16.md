# V4.3.0 Sprint 1J: Support IEEE 754 Float16

Source: docs/roadmap.md, "V4.3.0 / Sprint 1J".

## Goal

IEEE 754 binary16 (`NC_FLOAT16`) gets the same treatment bfloat16
received in Sprints 1A-1C: NEP-owned conversion instead of the retained
HDF5 exception, a public `nc_*_float16` memory-type API in `libnep`,
a tutorial, disk-bound benchmarks on the GDAS sample with committed
reference CSVs and plots, and documentation. After this sprint every
supported small-float conversion in NEXTCDF-4 runs through NEP code
with round-to-nearest-even and `NC_ERANGE` reporting; HDF5 does no
application-level numeric conversion.

## Decisions

| Topic | Decision |
| --- | --- |
| Internal conversion | Replace the `half` HDF5 exception in `nx4_convert_type()` with NEP-owned IEEE-754 conversion: round-to-nearest-even, single rounding from double, quiet NaN preserved, signed zero preserved, finite overflow to ±inf setting `range_error`. The boundary is corrected to IEEE: finite magnitudes in (65504, 65520) round to 65504 (`0x7bff`); the tie at 65520 and all larger finite magnitudes give ±inf (HDF5 gave inf above 65504). Subnormal results round by RNE and are not range errors (Sprint 1H classification). (Ed: 1a) |
| Dead code | `nx4_conversion_exception()` and `nx4_conversion_dxpl()` exist only for that exception and are removed with it (declaration in `nxt4internal.h`). |
| Public API | Eight new `libnep` functions `nc_{get,put}_{var,var1,vara,vars}_float16` in `nep.h`, mirroring `nc_*_bfloat16`. Buffer type `nc_float16_t`: `_Float16` when the compiler defines `__FLT16_MAX__`, otherwise `uint16_t`; `NEP_HAVE_NATIVE_FLOAT16` is 1 or 0. `NC_FLOAT16` variables pass raw bits; `NC_FLOAT`/`NC_DOUBLE` variables convert in NEP (RNE, `NC_ERANGE` on finite get overflow); `NC_CHAR` gives `NC_ECHAR`, everything else `NC_EBADTYPE`. They work on any file the netCDF API can open. (Ed: 2a) |
| GDAS `prate_ave` subnormals | Keep all four fields. `prate_ave` values below 6.1e-5 land in binary16 subnormals (or 0), where relative error can exceed the 2^-11 RNE bound. Error gates use a combined tolerance — a point passes when `rel_err <= 2^-11` OR `abs_err` is under a per-field floor (`F16_ABS_ERR_MAX` = half the smallest subnormal, 2^-25); both metrics are reported in the CSV and docs. No sample point equals the declared fill 9.99e+20. (Ed: 3a) |
| Examples and benchmarks | Full bfloat16 mirror: `float16.c` tutorial, `float16_conv.h`, `float16_perf.c` (4 fields x {float32, float16 via `nc_*_float16`, float16 typed via `nc_put_vara_float`/`nc_get_vara_float`} x {contiguous, shuffle+deflate 1}), `plot_float16.py`, `make_float16_sample.c`/`.sh` producing committed `test/data/NEXTCDF4/gdas_sfc_sample_float16.nc`, `float16_io_perf.c`, `plot_float16_io.py`, committed reference CSVs, machine record and PNGs. (Ed: 4a) |
| Rounding consistency | The internal engine, the `nc_*_float16` functions and `float16_conv.h` all use the same RNE algorithms, so typed calls and wrapper calls produce identical bits — unlike bfloat16, where the historical HDF5 rows differed on ties. The `float16_typed` benchmark rows measure the engine path, not a different rounding. |
| Tests | New enabled `test/nextcdf4/tst_nep_float16.c` (mirrors `tst_nep_bfloat16.c`). Pinned float16 bits in `tst_nextcdf4_conv.c` are updated to NEP results (the only changes are at the overflow boundary: 65505 → `0x7bff` instead of `0x7c00`); `tst_nextcdf4_range.c` and `tst_nextcdf4_internal_convert.c` float16 expectations are updated where the boundary changed. `tst_nextcdf4_float16` stays disabled (#379). |
| Build and packaging | CMake only. New source file joins the existing `libnep`; new header declarations join `nep.h`. No option, dependency, minimum-version or install-layout change — nothing the Spack recipe depends on. Conda unchanged. |
| Acceptance | Full `ctest` passes, docs build warning-free, no newly disabled tests. Benchmarks are measured locally, not gated by CI. |

### 2. New `src/nep_float16.c`

Mirror `src/nep_bfloat16.c` structure (Doxygen `@file`/`@author`, no
libm calls, byte/`uint16_t` + `memcpy` access so the code is identical
for both `nc_float16_t` forms). Add it to `add_library(nep SHARED ...)`
in `src/CMakeLists.txt`.

Internal helpers (static, Doxygen comments):

```c
static float    f16_to_f32(uint16_t h);            /* exact decode */
static uint16_t f32_to_f16(float f, int *range);   /* RNE, sets range on finite overflow */
static uint16_t f64_to_f16(double d, int *range);  /* single rounding */
```

- `f16_to_f32`: decode sign/exponent/mantissa into the float bits via
  `uint32_t` assembly and `memcpy` — e == 0 → `ldexp`-free bit
  normalization loop or multiply by `0x1p-24f`; e == 31 → inf/NaN;
  otherwise rebias the exponent by +112. NaN payloads are preserved
  into the float NaN.
- `f32_to_f16`: work on `uint32_t u` from `memcpy`. NaN
  (`(u & 0x7fffffffu) > 0x7f800000u`) → `(uint16_t)(0x7c00u | top payload bits | 0x0200u)`
  (quiet NaN). Magnitude ≥ `0x477ff000u` (65520f) → ±`0x7c00` with
  `*range = 1` unless the input was already inf (inf → `0x7c00`, no
  range). Magnitude ≥ `0x38800000u` (2^-14) → normal path: rebias
  exponent −112, add the RNE rounding term `0x0fffu + ((u >> 13) & 1u)`
  before truncating to 10 mantissa bits. Smaller magnitudes → subnormal
  path: add the implicit leading bit and shift the significand right
  by `14 − e` extra positions with RNE sticky handling; result may be 0
  (underflow is not a range error). Sign bit copied in all paths.
- `f64_to_f16`: single rounding — narrow to float with round-to-odd
  (inexact results get an odd last bit, the `encode_bfloat_double`
  trick at `nxt4convert.c:176`), then `f32_to_f16`. Float's 24-bit
  significand has 13 spare bits over half's 11, so this equals
  rounding the double directly. Finite doubles that overflow float
  also overflow half → ±`0x7c00` with range.
- `f16_io(int ncid, int varid, const size_t *startp, const size_t *countp,
  const ptrdiff_t *stridep, void *buf, int put)`: identical structure
  to `bf16_io` — `nc_inq_vartype`/`nc_inq_varndims`, `NC_CHAR` →
  `NC_ECHAR`, only `NC_FLOAT16`/`NC_FLOAT`/`NC_DOUBLE` allowed else
  `NC_EBADTYPE`, `NC_FLOAT16` delegates to the untyped `nc_get_vars`/
  `nc_put_vars`, otherwise a temporary float/double buffer converts
  each value; gets return `NC_ERANGE` when any value overflowed.
- The eight public functions map `var`/`var1`/`vara`/`vars` onto
  `f16_io` exactly as the bfloat16 ones do.
