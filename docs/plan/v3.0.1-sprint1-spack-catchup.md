# V3.0.1 Sprint 1: Spack Catchup

## Sprint Goal

Bring the in-repository NEP Spack recipe, Spack CI, user documentation, and the existing upstream Spack pull request up to date through NEP v3.0.0. Resolve the outstanding package review feedback while retaining CDF support in NEP's local Spack repository.

---

## Scope

**In scope:**
- Add released NEP versions `2.6.0`, `2.6.1`, `2.7.0`, `2.7.1`, `2.8.0`, and `3.0.0` to `spack/NEP/package.py` with verified GitHub tag-tarball checksums.
- Keep version declarations in descending release order.
- Resolve review feedback in [spack/spack-packages#5557](https://github.com/spack/spack-packages/pull/5557): restore BZIP2 install verification, update the release list, and separate the local-only CDF capability from the upstream builtin recipe.
- Retain `+cdf` in NEP's in-repository recipe, add its `cdf` dependency, and preserve the documented local-repository setup that provides `spack/cdf/package.py`.
- Update the upstream pull request rather than opening a replacement.
- Pin Spack CI release checks to `nep@3.0.0`; test default, minimal, DICOM-enabled, and all-supported-reader concretization paths; perform minimal and all-supported-reader installs without masking failures.
- Update the README Spack installation guidance and applicable release/documentation references.

**Out of scope:**
- Changes to NEP runtime code, public APIs, CMake logic, or Autotools logic.
- Publishing the Conda recipe; that belongs to v3.0.1 Sprint 2.
- Adding NASA CDF as an upstream Spack builtin package.
- Changing default variant values.

## Clarified Decisions

- All published releases after `2.5.0` through `3.0.0` are added.
- The existing upstream PR [spack/spack-packages#5557](https://github.com/spack/spack-packages/pull/5557) is updated in place.
- The local NEP repository retains `+cdf`, declares `depends_on("cdf", when="+cdf")`, and supplies the dependency through `spack/cdf/package.py`.
- The upstream builtin recipe must not expose `+cdf` until the NASA CDF recipe is accepted upstream; this avoids a variant with no satisfiable builtin dependency.
- Spack CI uses `3.0.0` as the latest stable release, retains `main` coverage, and fails on install errors.
- Validation covers default, minimal, DICOM-enabled, and all-supported-reader specs; installs cover minimal and all-supported-reader configurations.

## Major Tasks

### 1. Update the Local Spack Recipe

- Add the six verified version stanzas in descending order.
- Retain all existing supported variants, including `dicom` and local-only `cdf`.
- Add the missing `cdf` dependency for `+cdf`.
- Restore `check_install()` validation of `libh5bzip2.so` when `+bzip2` is selected.
- Verify installed reader-library checks cover all locally supported reader variants.

### 2. Update the Upstream Spack Pull Request

- Rebase or otherwise synchronize the existing PR with the current `develop` branch as required.
- Add the available released versions and correct their order.
- Restore BZIP2 plugin install verification.
- Omit the `cdf` variant and its local-only documentation from the upstream builtin recipe until a CDF package exists upstream.
- Reply to each review thread with the implemented resolution and request a renewed review.

### 3. Modernize Spack CI

- Replace release-specific `2.5.0` checks with `3.0.0`.
- Add DICOM concretization coverage and include DICOM in the all-supported-reader local-repository configuration.
- Retain CDF coverage only where the CI creates and registers NEP's local CDF package repository.
- Replace masked `spack install ... || true` commands with failing installs.
- Reduce redundant historical release installs while preserving one minimal install and one all-supported-reader install.

### 4. Update Documentation

- Update the README latest-stable Spack example to `nep@3.0.0`.
- Keep the CDF local-repository prerequisite accurate and distinguish it from upstream builtin availability.
- Add v2.8.0 and v3.0.0 release-history entries where the product documentation tracks released versions.
- Update Spack-related release documentation as needed to state that DICOM is available through the local recipe and pending upstream synchronization.

## Testing Requirements

- Run `spack style` and `spack audit` on the local recipe.
- Run `spack spec -I nep@3.0.0`, `spack spec -I nep@3.0.0~docs~fortran`, and `spack spec -I nep@3.0.0+dicom`.
- With the local NEP/CDF repository registered, run `spack spec -I nep@3.0.0+geotiff+grib2+cdf+fits+pds4+dicom`.
- Run `spack install -v --fail-fast nep@3.0.0~docs~fortran`.
- With the local repository registered, run an all-supported-reader install and verify `check_install()` artifacts.
- Confirm that the corresponding Spack CI jobs complete on GitHub Actions.
