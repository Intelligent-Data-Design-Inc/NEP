# V3.0.1 Sprint 1: Spack Catchup

## Sprint Goal

Bring the in-repository NEP Spack recipe, Spack CI, user documentation, and the existing upstream Spack pull request up to date through NEP v3.0.0. Resolve the outstanding package review feedback while keeping the in-repository recipe directly submit-ready for spack-packages.

---

## Scope

**In scope:**
- Add released NEP versions `2.6.0`, `2.6.1`, `2.7.0`, `2.7.1`, `2.8.0`, and `3.0.0` to `spack/NEP/package.py` with verified GitHub tag-tarball checksums.
- Keep version declarations in descending release order.
- Resolve review feedback in [spack/spack-packages#5557](https://github.com/spack/spack-packages/pull/5557): restore BZIP2 install verification, update the release list, and separate the local-only CDF capability from the upstream builtin recipe.
- Omit `+cdf` because NASA CDF is not an upstream Spack package; the in-repository NEP recipe must match the submit-ready upstream-compatible variant set.
- Update the upstream pull request rather than opening a replacement.
- Pin Spack CI release checks to `nep@3.0.0`; test default, minimal, DICOM-enabled, and all-upstream-supported-reader concretization paths; perform minimal and all-upstream-supported-reader installs without masking failures.
- Update the README Spack installation guidance and applicable release/documentation references.

**Out of scope:**
- Changes to NEP runtime code, public APIs, CMake logic, or Autotools logic.
- Publishing the Conda recipe; that belongs to v3.0.1 Sprint 2.
- Adding NASA CDF as an upstream Spack builtin package.
- Changing default variant values.

## Clarified Decisions

- All published releases after `2.5.0` through `3.0.0` are added.
- The existing upstream PR [spack/spack-packages#5557](https://github.com/spack/spack-packages/pull/5557) is updated in place.
- The in-repository NEP recipe omits `+cdf` until the NASA CDF recipe is accepted upstream; this avoids a variant with no satisfiable builtin dependency and keeps the file directly submit-ready.
- Spack CI uses `3.0.0` as the latest stable release, retains `main` coverage, and fails on install errors.
- Validation covers default, minimal, DICOM-enabled, and all-upstream-supported-reader specs; installs cover minimal and all-upstream-supported-reader configurations.

## Major Tasks

### 1. Update the Local Spack Recipe

- Add the six verified version stanzas in descending order.
- Retain all upstream-supported variants, including `dicom`, and omit `cdf` until its dependency is accepted upstream.
- Restore `check_install()` validation of `libh5bzip2.so` when `+bzip2` is selected.
- Verify installed reader-library checks cover all upstream-supported reader variants.

### 2. Update the Upstream Spack Pull Request

- Rebase or otherwise synchronize the existing PR with the current `develop` branch as required.
- Add the available released versions and correct their order.
- Restore BZIP2 plugin install verification.
- Keep the in-repository and upstream builtin recipes aligned by omitting the `cdf` variant until a CDF package exists upstream.
- Reply to each review thread with the implemented resolution and request a renewed review.

### 3. Modernize Spack CI

- Replace release-specific `2.5.0` checks with `3.0.0`.
- Add DICOM concretization coverage and include DICOM in the all-upstream-supported-reader configuration.
- Exclude CDF from CI coverage until NASA CDF is available as an upstream Spack package.
- Replace masked `spack install ... || true` commands with failing installs.
- Reduce redundant historical release installs while preserving one minimal install and one all-upstream-supported-reader install.

### 4. Update Documentation

- Update the README latest-stable Spack example to `nep@3.0.0`.
- Document that the CDF reader is not available as a Spack variant until its dependency is accepted upstream.
- Add v2.8.0 and v3.0.0 release-history entries where the product documentation tracks released versions.
- Update Spack-related release documentation as needed to state that DICOM is included in the upstream-compatible recipe.

## Testing Requirements

- Run `spack style` and `spack audit` on the local recipe.
- Run `spack spec -I nep@3.0.0`, `spack spec -I nep@3.0.0~docs~fortran`, and `spack spec -I nep@3.0.0+dicom`.
- Run `spack spec -I nep@3.0.0+geotiff+grib2+fits+pds4+dicom`.
- Run `spack install -v --fail-fast nep@3.0.0~docs~fortran`.
- Run an all-upstream-supported-reader install and verify `check_install()` artifacts.
- Confirm that the corresponding Spack CI jobs complete on GitHub Actions.
