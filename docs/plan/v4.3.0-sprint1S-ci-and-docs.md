# v4.3.0 Sprint 1S: CI and Docs

Source: docs/roadmap.md, "V4.3.0 - NEXTCDF4 Development / Sprint 1S".

## Goal

CI measures and publishes line coverage for the full NEP test suite so untested code is visible, and the four project-framing documents (`README.md`, `docs/prd.md`, `docs/prfaq.md`, `docs/design.md`) describe the project as it stands at v4.3.0 — format readers plus the NEXTCDF-4 backend — rather than its historical compression-era evolution. `src/nextcdf4/nxt4meta.c` gains the deeper per-function walkthrough comments that explain what the metadata machinery does and why. No code behavior changes anywhere in the sprint.

## Decisions

| Topic | Decision |
|---|---|
| Coverage placement | New `nextcdf4-coverage` job in `.github/workflows/nextcdf4.yml` covering the full enabled build and the full ctest run (Ed accepted 1a). Reuses the `geotiff-coverage` pattern: `--coverage` flags, `lcov --capture/--remove`, `genhtml`, artifact upload. Not a new workflow file and not limited to NEXTCDF-4 labels. |
| Coverage gate | Report-only: `lcov --summary` printed to the log, HTML uploaded as an artifact, warning (not failure) below 50% — same as the geotiff job (Ed accepted 2a). No baseline gate this sprint. |
| Docs rewrite | Rewrite the framing of all four docs to a 4.3.0-forward summary; dated press-release framing goes away; compression appears only as a nep-compress pointer in `README.md` (Ed accepted 3a). Historical release notes and historical roadmap files are untouched. |
| `nxt4meta.c` depth | Comment-only: walkthrough paragraphs atop complex function bodies and deeper `/**` blocks where they remain thin — no restructuring, no file splits, no code changes (Ed accepted 4a). |
| Spack/conda | Coverage is a CI job, not a build option; no new CMake option, installed file, dependency, or variant. One line in Current state records that the recipe is unaffected. |

## Work items

### 1. Coverage job in `nextcdf4.yml`

File: `.github/workflows/nextcdf4.yml` — add a third job `nextcdf4-coverage`, modeled on `geotiff-test.yml`'s `geotiff-coverage` but covering the whole suite.

- `runs-on: ubuntu-latest`; same env block as `nextcdf4` (`NETCDF_SHA`, `DEPS`, `PKG_CONFIG_PATH`, `LD_LIBRARY_PATH`).
- Install `lcov` alongside the existing tool list (`cmake make gcc gfortran m4 pkg-config zlib1g-dev lcov`; gfortran kept so the Fortran tests run and contribute coverage; doxygen/graphviz not needed — docs target stays OFF).
- Reuse the dependency cache with a distinct key, e.g. `nextcdf4-coverage-${{ runner.os }}-${{ runner.arch }}-gcc-${{ steps.tools.outputs.compiler }}-hdf5-2.1.1-netcdf-${{ env.NETCDF_SHA }}-fortran-4.6.2-1`, and copy the "Build HDF5, NetCDF-C and NetCDF-Fortran" step verbatim (deps are NOT instrumented; only NEP is).
- Configure into a separate directory `build-cov` with the same flags as the `nextcdf4` job except `NEP_BUILD_DOCUMENTATION=OFF` and `NEP_ENABLE_FORTRAN=ON` retained, plus `-DCMAKE_C_FLAGS="--coverage -fprofile-arcs -ftest-coverage -O0"`, `-DCMAKE_Fortran_FLAGS="--coverage -O0"`, `-DCMAKE_EXE_LINKER_FLAGS="--coverage"`, `-DCMAKE_SHARED_LINKER_FLAGS="--coverage"`. `CMAKE_BUILD_TYPE` left default/RelWithDebInfo is acceptable but `-O0` in the flags keeps line attribution honest; do NOT pass `-Werror`-style additions — `--coverage` warnings must not fail the build.
- Build and run the full suite: `cmake --build build-cov --parallel 2` then `ctest --test-dir build-cov --output-on-failure` (all labels, same as the normal job's final step). Tests must still pass — a coverage build is a full test run, not a reduced one.
- Report: in `build-cov`, `lcov --capture --directory . --output-file coverage.info --ignore-errors unused,gcov`, then `lcov --remove coverage.info '/usr/*' '*/deps/*' '*/test/*' '*/test_*/*' '*/ftest/*' '*/examples/*' '*/nc_test4/*' --output-file coverage_filtered.info --ignore-errors unused` (verify actual test directory names against the build tree when implementing), `lcov --list coverage_filtered.info`, `lcov --summary coverage_filtered.info`, `genhtml coverage_filtered.info --output-directory coverage_html`.
- Warn-only threshold: same `<50%` shell check as the geotiff job (echo a warning, never `exit 1`).
- Upload `build-cov/coverage_html/` as artifact `nextcdf4-coverage` (retention 30, matching the geotiff job); on failure upload `build-cov/Testing/Temporary/` logs like the other jobs.
- Do not add a CMake `NEP_ENABLE_COVERAGE` option — flags are injected by CI only, keeping local builds unchanged. No Codecov/third-party service.
