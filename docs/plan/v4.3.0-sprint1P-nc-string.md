# v4.3.0 Sprint 1P: NC_STRING

Source: docs/roadmap.md, "V4.3.0 - NEXTCDF4 Development / Sprint 1P".

## Goal

NEXTCDF-4 preserves standalone and recursively nested `NC_STRING` values across variable and attribute I/O, close/reopen, and interchange with upstream netcdf-c. Native and NetCDF-4-model files have consistent string fill behavior and explicit ownership: writes borrow application buffers, successful reads return independently reclaimable payloads, and cached metadata never aliases caller-owned storage. Enabled focused regressions and three upstream string ports protect these contracts in normal and sanitizer CI.

## Decisions

| Topic | Decision |
|---|---|
| Nesting | Full string nesting, including compound scalar/array members, vlens of strings, and recursive combinations with existing supported user types (Ed accepted 1a). This completes the explicit 1N1–1N4/1O handoff. |
| Upstream ports | Port exactly `tst_strings`, `tst_strings2`, and `tst_atts_string_rewrite`, each in native and `NC_NETCDF4_MODEL` modes, alongside focused tests (Ed accepted 2a). Other ports remain future suite expansion. |
| Interoperability | Bidirectional interchange plus updating upstream-created string files through NEXTCDF-4 (Ed accepted 3a). Require upstream reads of NEXTCDF-4 model-mode output and upstream rechecks after updates. |
| Foreign fixed-length strings | Defer HDF5 fixed-length strings wider than one byte; preserve existing one-byte `NC_CHAR` behavior (Ed accepted 4a). Variable-length strings must be detected before byte-size checks. |
| Modes | Native and `NC_NETCDF4_MODEL` support standard strings and their nested forms; classic model continues rejecting `NC_STRING` and user-defined types. Reference nesting remains unsupported. |
| Ownership | Standalone strings use `char *` elements (`char **` arrays); nested values use the existing compound layouts and `nc_vlen_t` descriptors. Use existing `nc_free_string` and recursive `nc_reclaim_data` APIs, not a new allocator API. |
| Fill | Empty-string default, owned custom string fills, no per-variable `NC_NOFILL` for standalone `NC_STRING` (upstream `NC_EINVAL`). Preserve 1O's exclusion of strings/user types from file-default inheritance and 1M's committed-setter restrictions. |
| CI and packaging | Existing normal and sanitizer full-suite jobs run all additions. No new job, CMake option, public API, installed file, dependency minimum, plugin requirement, Spack variant or conda change. |
| Release | Sprint 2 owns release notes, tag and publication. NEXTCDF-4 remains experimental; this is not full upstream-suite parity. |

## Work items

### 1. Recover string datatypes and attributes without changing character arrays

Files: `src/nextcdf4/nxt4meta.c`, `nxt4io.c`, `nxt4type.c`; `nxt4internal.h` only for shared private declarations.

Keep the existing signatures of `map_nc_type(hid_t htype, nc_type *xtypep)`, `NEXTCDF4_map_hdf_type(nc_type xtype, hid_t *typep)`, `NEXTCDF4_memory_type(nc_type type, int *closep)` and the context-aware helpers:

```c
int nx4_type_size(NC_GRP_INFO_T *grp, nc_type xtype, size_t *sizep);
int nx4_file_type(NC_GRP_INFO_T *grp, nc_type xtype, hid_t *typep);
int nx4_memory_type(NC_GRP_INFO_T *grp, nc_type xtype, hid_t *typep);
```

In `map_nc_type`, inspect the class first and call `H5Tis_variable_str` only for strings: positive maps to `NC_STRING`, zero plus size one maps to `NC_CHAR`, zero plus larger size remains unsupported, negative is an HDF5 error. Do not call `H5Tget_sign` on noninteger types. Standalone variable-length strings remain atomic `NC_STRING`, not synthetic user-defined type IDs; nested resolution must apply the same mapping. Reconstruct `sizeof(char *)` memory sizes and dynamic-content metadata before values/fills are loaded.

Create new variable-length string datatypes with explicit `H5T_CSET_UTF8` and null termination, matching upstream. Accept legacy NEP ASCII-tagged strings as well: for existing datasets/attributes, derive string memory types from their stored datatypes, preserving each string leaf's character-set tag in recursive compound/vlen/array layouts. For compound reads retain the established foreign-anonymous-type packed-native-layout rule; do not replace it with a declared-layout assumption. No transcoding, normalization or UTF-8 validation is introduced; preserve bytes through the first NUL. Check datatype-construction failures and close every owned handle.

Load string attributes on root groups, subgroups and variables, including empty attributes and `_FillValue`. Preserve attribute lengths, types, definition order and reserved-name filtering. Keep unsupported foreign attribute types skippable, but distinguish that case from failure while loading a recognized string or string-containing type: propagate `NC_ENOMEM`/`NC_EHDFERR` instead of reporting a successful open with missing supported data. Carry callback failure through both group and variable attribute iteration, and clean partial-open metadata/handles.

### 2. Enable complete string-containing type graphs

Files: `src/nextcdf4/nxt4type.c`, `nxt4meta.c`, `nxt4internal.h`; `test/nextcdf4/tst_nextcdf4_vlen.c`, `tst_nextcdf4_compound_arrays.c`.

Retain the existing public-dispatch signatures:

```c
int NEXTCDF4_insert_compound(int ncid, nc_type typeid, const char *name,
                             size_t offset, nc_type xtype);
int NEXTCDF4_insert_array_compound(int ncid, nc_type typeid, const char *name,
                                   size_t offset, nc_type xtype, int ndims,
                                   const int *dim_sizesp);
int NEXTCDF4_def_vlen(int ncid, const char *name, nc_type base_typeid,
                      nc_type *typeidp);
```

Remove string-specific prohibitions from `member_type_ok`, `type_graph_has_forbidden`, `check_graph_clean` and vlen definition; retain recursive reference rejection, cycles, visibility/layout/overlap validation and compatibility checks. Strings occupy pointer-sized members; vlen-of-string payloads are arrays of `char *`, not character arrays. Support scalar and multidimensional array fields, vlens of string-containing compounds, compounds/arrays of vlens of strings, and further acyclic nesting. Do not enable reference-containing graphs or numeric conversion of user types.

Ensure recursive `varsized` propagation includes atomic string leaves at definition, dependency commit and reopen, without treating `NC_CHAR` as pointer-bearing merely because its synthetic type class is `NC_STRING`. Continue dependency-ordered type writes and scoped type identity on read. Structural `NEXTCDF4_inq_type_equal` and field/base/size inquiries must reflect strings consistently. Existing `NEXTCDF4_put_vlen_element` borrows payloads and `NEXTCDF4_get_vlen_element` copies descriptors/pointers using resolved base size; nested aliases are not independently reclaimable, exactly as for other dynamic bases.

Replace only the string rejection assertions in the existing focused tests with positive cases and move exhaustive string coverage to the new string test. Retain `NC_STD_REF`, cyclic graph, invalid layout and classic-mode rejection tests unchanged in meaning.

### 3. Unify ownership, fills and error cleanup

Files: `src/nextcdf4/nxt4meta.c`, `nxt4io.c`, `nxt4file.c`, `nxt4type.c`.

Use one invariant: cached string values, including `var->fill_value`, are element buffers whose elements are `char *`; even a single fill is an owned pointer-sized buffer holding an independently owned string, never a bare character buffer. Nested dynamic buffers follow the existing recursive layout. Normalize NULL standalone input elements to empty strings, preserving the current attribute policy; do not modify borrowed caller pointers. HDF5 null/default string results exposed by supported NetCDF string reads must become owned empty strings. Empty vlen descriptors stay `{0, NULL}`. Require non-NULL top-level buffers for nonempty transfers; zero-length attributes/selections must not dereference them.

Apply this invariant in `add_att`, `read_hdf5_att`, `NEXTCDF4_put_att`, `NEXTCDF4_get_att`, `NEXTCDF4_def_var_fill`, `nx4_dcpl_fill`, `load_one_var`, `nx4_fill_from_att`, fill inquiries in `NEXTCDF4_inq_var_all`, and teardown/replacement paths. Deep-copy both custom string fills and string-containing user-type fills; cached fills must not alias attributes, write inputs or inquiry outputs. `nc_inq_var_fill` returns a separately reclaimable string. Use the empty-string default for standalone strings; reject per-variable `NC_NOFILL` with `NC_EINVAL` before mutating state, while preserving session-default exclusions and late-setter errors. Keep dynamic user-type default fill as zeroed descriptors; do not silently redefine all nested default fills as nonempty strings.

Initialize temporary dynamic read buffers/descriptors before HDF5 can partially populate them. Use malloc/free-compatible read allocation, retain successful read payloads for the caller, and reclaim only HDF5 temporaries or failed partial results. Never reclaim successful caller results before return. On partial allocation/read/deep-copy failure, reclaim all values created by that operation exactly once and clear returned descriptors; do not free preexisting borrowed write buffers. HDF5 reclaim must receive an actual matching memory dataspace (including a scalar dataspace), not `H5S_ALL` as a reclaim dataspace. Cached values must be recursively released before type metadata disappears. Do not introduce blanket error suppression or sanitizer suppressions.

Audit `var_io`'s unlimited read fill path: place disk data and independently copied fills at the correct logical positions for multidimensional and strided selections, not merely a concatenated tail. Include a zero physical extent and mixed present/missing rows/columns; preserve non-string vlen and numeric behavior with regressions if shared indexing changes. String/numeric conversions remain unsupported; retain `NC_ECHAR` for character/noncharacter calls and `NC_EBADTYPE` for other unsupported string/numeric pairs, without entering HDF5 conversion or changing the numeric engine. Zero-count transfers must not extend datasets or allocate string payloads.

### 4. Focused string and interchange regressions

Files: new `test/nextcdf4/tst_nextcdf4_string.c`, existing `test/nextcdf4/CMakeLists.txt`, `tst_nextcdf4_group.c`, `tst_nextcdf4_vlen.c`, `tst_nextcdf4_compound_arrays.c`.

Add enabled target/test `tst_nextcdf4_string`, linked to `ncnextcdf4 ${NETCDF_LIBRARIES} ${NEP_HDF5_LIBRARIES}`, with the existing NetCDF/HDF5/private include paths and test environment. Give it `${CMAKE_CURRENT_BINARY_DIR}/string` as its own working directory and label `nextcdf4_strings`. It loops over native and `NC_NETCDF4_MODEL` modes internally. Extend the existing group test to check close/reopen rather than merely same-session strings. Write failing regressions before backend fixes.

Required focused cases:

- Scalar, fixed-rank and unlimited string variables; untyped and string-typed var/var1/vara/vars APIs; partial writes, overwrite, striding, append, zero counts and non-ASCII/empty/NULL input elements. Check legacy ASCII-tagged and upstream UTF-8-tagged storage without changing byte values.
- Root/subgroup/variable attributes, zero length, independent repeated gets, mutate/free input after put, replace/rename/delete, text-to-string and string-to-text replacement, `nc_copy_att`, enumeration order and reopen persistence. Preserve ordinary `NC_CHAR` arrays and reject wider fixed-length HDF5 datasets rather than reinterpreting them as pointer arrays.
- Default/custom `_FillValue`, `nc_def_var_fill`, fill inquiry ownership, unwritten elements and holes, multi-unlimited/strided clipped reads, default exclusion from `nc_set_fill`, and `NC_NOFILL` rejection without state change. Read-only and committed-variable errors must preserve existing values/fills.
- Scalar/array string members and recursive string/vlen/compound combinations as both variables and attributes. Verify complete type inquiries before/after reopen, multiple independent deep copies, empty vlens, pending attributes, dirty rebuild and correct reclamation. Use `nc_free_string` for standalone arrays and `nc_reclaim_data` for nested values while ncid/type context remains valid; free outer buffers separately when required.
- Invalid IDs/types, character/numeric mismatch, invalid stride/bounds, rejected reference nesting, classic-model rejection and deterministic failed-open/read cleanup. Avoid nondeterministic allocation-failure tests; still implement correct allocation-failure cleanup.
- Runtime upstream fixtures made with `nc_create(..., NC_NETCDF4, ...)`, deliberately without the NEXTCDF-4 flag. Open them with NEXTCDF-4 read-only and read-write, read/update string variables and attributes (including nested forms), close, then reopen with upstream to verify updates and untouched metadata/data. Independently write NEXTCDF-4 `NC_NETCDF4_MODEL` files and read them using upstream without `NC_NEXTCDF4`. Keep true upstream calls outside the port shims. Use simple declared/packed-compatible nested compound layouts for cross-backend payload assertions; separately retain the established packed foreign-layout regression instead of assuming upstream's known complex-layout defect is fixed.
- Repeated create/read/copy/replace/reclaim/close cycles exercise leaks and double frees. Newly allocated test resources are cleaned even on assertion failure; no performance threshold or optional runtime skip.

## Out of scope

- Foreign HDF5 fixed-length strings wider than one byte, string transcoding/validation and general HDF5 schema import: beyond v4.3.0 compatibility backlog. Existing `NC_CHAR` behavior remains supported.
- Other upstream ports, including `tst_fills`, `tst_fills2`, `tst_vlenstr` and mixed-feature programs: future suite expansion, not a claim that their features are unsupported.
- Reference nesting, user-type numeric conversion and unrelated defects: backlog; preserve current explicit rejections. No allocator/public API additions.
- Provenance attributes: Sprint 1Q. Fortran wrappers: Sprint 1R. Deprecated `varm`, image files, SWMR and all NEXTCDF-4 parallel I/O remain deferred beyond v4.3.0.
- Benchmarks, new CI jobs, packaging options/dependency bumps, conda work and upstream Spack recipe changes: not needed here. Release notes must describe standalone/nested strings, fill/ownership fixes and interoperability in Sprint 2; tag/version bump and publication also remain Sprint 2 work.
