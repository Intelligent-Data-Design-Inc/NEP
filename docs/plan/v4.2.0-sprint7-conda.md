# v4.2.0 Sprint 7: Conda

Source: docs/roadmap.md, "V4.2.0 - Move Compression Filters to nep-compress / Sprint 7".

## Goal

conda-forge carries a format-only `nep` 4.2.0 package for Linux. It
contains the PDB, mmCIF, FITS and PDS4 readers and the `share/.ncrc`
that registers them with conda-forge's `libnetcdf` 4.10.1. The
in-repository recipe follows the nep-compress pattern: a v1
`recipe.yaml` built with rattler-build from the checkout. A script
generates the staged-recipes copy, so the two recipes cannot drift. CI
builds the recipe, runs its tests and lints the staged copy on every
push and PR. staged-recipes PR #34309 is rewritten in place so that it
submits this package instead of the old LZ4 build of 3.0.0.

## Decisions

| Topic | Decision |
| --- | --- |
| GeoTIFF | Off for 4.2.0. NEP 4.2.0 cannot find conda-forge's flat `include/geotiff.h`; the fix is `4d920c5`, which came after the tag. Turn it on with the first release that contains `4d920c5`. No recipe patch. (Ed: 1a) |
| DICOM | Off. conda-forge's `gdcm` is built per Python version, so NEP would need one build per Python version and would pull Python into a C library. (Ed: 2a) |
| staged-recipes PR | Update #34309 in place: replace `recipes/nep/meta.yaml` with the generated v1 `recipe.yaml` and `build.sh`, retitle it `Add nep`, and rewrite the body. (Ed: 3a) |
| Maintainers | `captainkirk99` only. Replace `edhartnett`. (Ed: 4b) |
| Reader registration | No activation script. In netcdf-c, setting `NCRCENV_RC` replaces `~/.ncrc` and `./.ncrc` entirely (`libdispatch/drc.c`, lines 226-235). The docs tell users to append `$CONDA_PREFIX/share/.ncrc` to `~/.ncrc`, or to set `NCRCENV_RC` themselves. (Ed: 5a) |
| GRIB2, CDF, NEXTCDF-4 | Off. conda-forge has no `g2c` and no NASA `cdf` package. NEXTCDF-4 needs HDF5 2.1.1 or newer, and conda-forge pins `hdf5` 1.14.6. |
| Recipe format and tool | v1 `recipe.yaml` built with rattler-build, as in nep-compress. staged-recipes labels the `meta.yaml` example `example-v0-deprecated`. conda-build and `conda/meta.yaml` are removed. |
| MPI | `nompi` builds of `libnetcdf` and `hdf5` only, as in nep-compress. |
| Fortran | `NEP_ENABLE_FORTRAN=ON`, so `ftst_*` run during the build. NEP installs no Fortran library, so `netcdf-fortran` is a host requirement only. |
| Platforms | Linux only (`skip: not linux`). The `.ncrc-*.in` templates hard-code `.so` library names. |
| Version | The checkout recipe carries `4.2.1.dev0`. The staged copy is generated for `4.2.0`. |

### 1. Replace the recipe with a v1 recipe

- `git rm conda/meta.yaml`. Then `git mv conda/build.sh conda/recipe/build.sh`
  and rewrite it.
- New `conda/recipe/recipe.yaml`:

  ```yaml
  schema_version: 1

  context:
    name: nep
    version: "4.2.1.dev0"

  package:
    name: ${{ name }}
    version: ${{ version }}

  # BEGIN source
  source:
    path: ../..
  # END source

  build:
    number: 0
    skip:
      - not linux

  requirements:
    build:
      - ${{ compiler('c') }}
      - ${{ stdlib('c') }}
      - ${{ compiler('fortran') }}
      - cmake
      - ninja
      - pkg-config
    host:
      - libnetcdf >=4.10.1
      - libnetcdf * nompi_*
      - hdf5
      - hdf5 * nompi_*
      - netcdf-fortran
      - netcdf-fortran * nompi_*
      - cfitsio
      - libxml2

  tests:
    - script:
        - test -f $PREFIX/include/nep.h
        - test -f $PREFIX/lib/libnep${SHLIB_EXT}
        - test -f $PREFIX/lib/libncpdb${SHLIB_EXT}
        - test -f $PREFIX/lib/libncmmcif${SHLIB_EXT}
        - test -f $PREFIX/lib/libncfits${SHLIB_EXT}
        - test -f $PREFIX/lib/libncpds4${SHLIB_EXT}
        - test -f $PREFIX/lib/cmake/NEP/NEPConfig.cmake
        - test -f $PREFIX/share/.ncrc
        - test ! -e $PREFIX/lib/libncgeotiff${SHLIB_EXT}
        - test ! -e $PREFIX/lib/libncdicom${SHLIB_EXT}
        - test ! -e $PREFIX/lib/libncnextcdf4${SHLIB_EXT}
        - test ! -e $PREFIX/lib/libnep.a
        - NCRCENV_RC=$PREFIX/share/.ncrc ncdump -h test/data/PDB/1GAB.pdb
        - NCRCENV_RC=$PREFIX/share/.ncrc ncdump -h test/data/mmCIF/4HHB.cif
        - NCRCENV_RC=$PREFIX/share/.ncrc ncdump -h test/data/WFPC2u5780205r_c0fx.fits
      files:
        source:
          - test/data/PDB/1GAB.pdb
          - test/data/mmCIF/4HHB.cif
          - test/data/WFPC2u5780205r_c0fx.fits
      requirements:
        run:
          - libnetcdf

  about:
    homepage: https://github.com/Intelligent-Data-Design-Inc/NEP
    repository: https://github.com/Intelligent-Data-Design-Inc/NEP
    license: Apache-2.0
    license_file: LICENSE.txt
    summary: Scientific format readers (PDB, mmCIF, FITS, PDS4) for NetCDF-C
    description: |
      NEP (NetCDF Expansion Pack) adds read-only format readers to
      NetCDF-C through its User Defined Format API, so nc_open() and
      ncdump read PDB, PDBx/mmCIF, FITS and PDS4 files. Register the
      readers by appending $CONDA_PREFIX/share/.ncrc to ~/.ncrc. LZ4
      and BZIP2 compression is in the separate nep-compress package.

  extra:
    recipe-maintainers:
      - captainkirk99
  ```

  Tricky cases:
  - Run requirements come from the host packages' `run_exports`
    (`libnetcdf`, `hdf5`, `cfitsio`, `libxml2`). Do not list them by
    hand. `netcdf-fortran` is used only by `ftst_*`. If rattler-build
    reports it as an overdepending host requirement, accept the
    warning; it must not become a run requirement.
  - Drop the old `run_exports: pin_subpackage`. No package links
    against NEP, and nep-compress has no such entry.
  - The `ncdump` lines are the end-to-end check: they prove that
    conda-forge's `libnetcdf` loads each reader through `.ncrc`. If
    PDS4 needs a label file plus its data file, PDS4 is covered by
    ctest only. Do not add a PDS4 `ncdump` line unless a single
    in-repository `.xml` label opens with it, as checked locally.
  - `ncdump -h` exits non-zero when it fails to open a file, so a
    reader that does not load fails the test.

- New `conda/recipe/build.sh`:

  ```bash
  #!/bin/bash
  set -euxo pipefail

  cmake -S . -B build -G Ninja ${CMAKE_ARGS} \
    -DCMAKE_INSTALL_LIBDIR=lib \
    -DHDF5_ROOT="${PREFIX}" \
    -DBUILD_TESTING=ON \
    -DNEP_BUILD_DOCUMENTATION=OFF \
    -DNEP_BUILD_EXAMPLES=OFF \
    -DNEP_ENABLE_BENCHMARKS=OFF \
    -DNEP_ENABLE_PARALLEL_TESTS=OFF \
    -DNEP_ENABLE_FORTRAN=ON \
    -DNEP_ENABLE_PDB=ON \
    -DNEP_ENABLE_MMCIF=ON \
    -DNEP_ENABLE_FITS=ON \
    -DNEP_ENABLE_PDS4=ON \
    -DNEP_ENABLE_GEOTIFF=OFF \
    -DNEP_ENABLE_GRIB2=OFF \
    -DNEP_ENABLE_CDF=OFF \
    -DNEP_ENABLE_DICOM=OFF \
    -DNEP_ENABLE_NEXTCDF4=OFF
  cmake --build build --parallel "${CPU_COUNT}"
  ctest --test-dir build --output-on-failure --no-tests=error --parallel "${CPU_COUNT}"
  cmake --install build
  ```

  - `BUILD_TESTING=ON` must stay. Without it, the documentation
    default would make this a docs-only build.
  - Put a comment above `-DNEP_ENABLE_GEOTIFF=OFF`: "4.2.0 cannot find
    conda-forge's flat geotiff.h; enable with the first release
    containing 4d920c5 and add geotiff/libtiff to host."
  - If ctest fails only because of `--parallel`, for example tests
    sharing an output file, drop `--parallel` from the ctest line and
    record why in a comment. Do not skip tests.
