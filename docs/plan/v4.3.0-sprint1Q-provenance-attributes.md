# v4.3.0 Sprint 1Q: Provenance Attributes

Source: docs/roadmap.md, "V4.3.0 - NEXTCDF4 Development / Sprint 1Q".

## Goal

NEXTCDF-4 files carry the same provenance surface as upstream netCDF-4 files: a stored `_NCProperties` root attribute (with a `nextcdf4=` self-identifying key), a stored `_nc3_strict` marker on `NC_CLASSIC_MODEL` files, and virtual `_IsNetcdf4`/`_SuperblockVersion` attributes synthesized on name inquiry exactly as upstream's `nc4_get_att_special` does. `h5dump`, `ncdump -s`, and third-party tools see no difference between a NEXTCDF-4 file and an upstream NetCDF-4 file.

## Decisions

| Topic | Decision |
|---|---|
| `_nc3_strict` | Written on the root group as a scalar `H5T_NATIVE_INT` = 1 for `NC_CLASSIC_MODEL` files only, matching upstream's `write_nc3_strict_att` (Ed accepted 1a). |
| Write timing | Deferred: `_NCProperties`/`_nc3_strict` are written at `_enddef`, `nc_sync`, and `nc_close` when writable, and only when the attribute does not already exist — mirroring `NC4_write_provenance` in `sync_netcdf4_file` (Ed accepted 2a). |
| `_NCProperties` value | `version=2,netcdf=<linked netcdf-c version>,hdf5=<HDF5 version>,nextcdf4=<NEP_VERSION>` — upstream shape plus a `nextcdf4=` key, which the version-2 property format tolerates (Ed chose 3b). |
| Virtual attributes | `_IsNetcdf4` and `_SuperblockVersion` are never stored; they are synthesized in `NEXTCDF4_inq_att`/`NEXTCDF4_inq_attid`/`NEXTCDF4_get_att` for `NC_GLOBAL` name lookups, mirroring `nc4_get_att_special` (Ed accepted 4a). `_NCProperties` answers name lookups from in-memory state. |
| Foreign files | An opened-for-write file that lacks `_NCProperties` is left unstamped, matching upstream (Ed accepted 5a). Only files created under NEXTCDF-4 get a fresh stamp; existing stamps are never overwritten. |
| Test scope | Focused regressions only, in the existing enabled normal and sanitizer CTest jobs; no new upstream ports, no new CI job. |
| Packaging | No new installed files, public API, CMake option, dependency, minimum version, plugin path or variant. Spack and conda recipes are unchanged. |
| Release | Sprint 2 owns release notes, tag and publication. |

## Current state (2026-11-23)

- Upstream reference checkout `/fast/ed/netcdf-c`: `libhdf5/nc4info.c` writes `_NCProperties` as a scalar, fixed-size (`strlen`, not `strlen+1`), `H5T_STR_NULLTERM`, `H5T_CSET_ASCII` root attribute from `sync_netcdf4_file` (`hdf5file.c:168`); it returns `NC_EPERM` on read-only files and skips the write when the attribute already exists. `NC4_new_provenance` (`hdf5create.c:264`) records the string and the FCPL superblock version at create; `NC4_read_provenance` reads the existing string at open.
- `_IsNetcdf4`/`_SuperblockVersion` are virtual: `nc4_get_att_special` (`hdf5attr.c:86`) is called from `NC4_HDF5_inq_att`, `NC4_HDF5_inq_attid` and `NC4_HDF5_get_att` whenever a name lookup targets a `NAMEONLYFLAG` reserved attribute on a `NC_GLOBAL` (non-variable) attribute list — on any group's ncid, not just root. It returns `NC_EATTMETA` for attnum inquiries, `NC_INT`/len 1 for both names, converts to integer memtypes and returns `NC_ERANGE` for other memtypes; `_NCProperties` returns `NC_CHAR`/strlen and `NC_ENOTATT` when unset, `NC_ECHAR` for non-character memtypes.
- `NC4_isnetcdf4` (`nc4hdf.c:2512`) returns 1 when `_nc3_strict` or `_NCProperties` exists on the root group, else walks the file counting objects carrying `CLASS`/`NAME`/`REFERENCE_LIST`/`DIMENSION_LIST`/`_Netcdf4Coordinates`/`_Netcdf4Dimid` and returns 1 at ≥2 hits. `NC4_hdf5get_superblock` (`nc4hdf.c:2463`) reports the FCPL `super` field via `H5Pget_version`. Both functions plus `NC_findreserved` are exported from `/usr/local/netcdf-c/lib/libnetcdf.so`, but `NC4_isnetcdf4` walks upstream `NC_HDF5_GRP_INFO_T` layouts and cannot be reused — NEXTCDF-4 implements its own HDF5-level walk against `file->rootid`.
- `_nc3_strict` (`NC_ATT_NC3_STRICT_NAME`, `nc4internal.h:522`) is written by upstream's `write_nc3_strict_att` (`nc4hdf.c:1319`) during root-group metadata write only when `cmode & NC_CLASSIC_MODEL`; it is also skipped when already present. `_Format` needs no backend work: ncdump synthesizes it from `nc_inq_format`, which NEXTCDF-4 already reports as `NC_FORMAT_NETCDF4` (`docs/netcdf_ncdump_problem.md`).
- NEXTCDF-4 today: `is_reserved_att` (`src/nextcdf4/nxt4meta.c:284`) already lists `_Format`, `_nc3_strict`, `_NCProperties`, `_SuperblockVersion`, `_IsNetcdf4` — they are filtered from loaded attribute lists and rejected by `nc_put_att`/`nc_rename_att`, so `nc_get_att(...,"_IsNetcdf4")` returns `NC_ENOTATT` and nothing is written. Status doc gap 11 records this (`docs/nextcdf4_status_v4_3_0.md:164`); the plan source layout already names `nxt4provenance.c` (`docs/plan/NEXTCDF4_plan.md`).
- Markers are written eagerly by `NEXTCDF4_write_markers`/`NEXTCDF4_read_markers` (`src/nextcdf4/nxt4file.c:336`,`:380`). `NEXTCDF4__enddef` (`nxt4file.c:643`), `NEXTCDF4_sync` (`nxt4file.c:438`) and `NEXTCDF4_close` are the deferred-write call sites; `NEXTCDF4_FILE_INFO_T` carries `mode`, `netcdf4_model`, `no_write`, `hdfid`, `rootid` (`nxt4internal.h`). Superblock bounds are `H5F_LIBVER_LATEST` for native/classic and `H5F_LIBVER_V110` for `NC_NETCDF4_MODEL` (`nxt4create.c:125`); `H5get_libversion` is already used (`nxt4create.c:101`).
- NEP version: `NEP_VERSION` in generated `nep_meta.h` (`include/nep_meta.h.in:33`, `version.txt` = 4.3.0). netcdf-c runtime version: first whitespace-delimited token of `nc_inq_libvers()` (exported). HDF5 runtime version: `H5get_libversion`.
- Earlier sprints hand nothing else here: 1M fixed reserved-name handling, 1L2 ordered-attribute rewriting (`nx4_rewrite_atts` rewrites only indexed atts, so a stored `_NCProperties` is preserved untouched), 1O/1P defer provenance to this sprint. Sprint 1R owns Fortran, Sprint 2 owns release/tag/Spack/conda publication.
- Local tools: GCC 13.3.0, CMake 3.28.3, Doxygen 1.9.8, HDF5 2.1.1 (`/usr/local/hdf5-2.1.1`), netcdf-c 4.10.2-development (`/usr/local/netcdf-c`). `.github/workflows/nextcdf4.yml` runs the full suite in normal and `nextcdf4-sanitizers` jobs; ubuntu-latest runners provide the needed toolchain (dependencies are built in the workflow).
- Spack review (`spack/repos/spack_repo/nep/packages/nep/package.py`, `spack/ci/spack.yaml`, `.github/workflows/spack.yml`, `docs/spack.md`): this sprint changes nothing the recipe depends on — no CMake options/cache paths, dependencies/minima, installed files/layout or plugin directories. ## Work items

### 1. New `src/nextcdf4/nxt4provenance.c`

Files: new `src/nextcdf4/nxt4provenance.c`; `src/nextcdf4/CMakeLists.txt` (source list); `nxt4internal.h` (private declarations and one new field); `docs/Doxyfile.in` (add the file to `INPUT` next to the other `src/nextcdf4` entries).

Private interface (declare in `nxt4internal.h`, all with Doxygen blocks, `@author Edward Hartnett, Intelligent Data Design, Inc.`):

```c
int nx4_write_provenance(NEXTCDF4_FILE_INFO_T *file);
int nx4_get_att_special(NEXTCDF4_FILE_INFO_T *file, const char *name,
                        nc_type *xtypep, nc_type mem_type, size_t *lenp,
                        int *attnump, void *data);
```

File-local helpers: `nx4_build_ncproperties(char **out)`, `nx4_isnetcdf4(NEXTCDF4_FILE_INFO_T *)`, `nx4_superblock_version(NEXTCDF4_FILE_INFO_T *, int *)`, `nx4_walk_isnetcdf4` (H5Literate/H5Ovisit callback). Add `char *ncproperties` to `NEXTCDF4_FILE_INFO_T` (NULL when absent); freed in `NEXTCDF4_close`/`nc_abort` teardown.

`nx4_build_ncproperties` produces `version=2,netcdf=<t>,hdf5=<M.m.r>,nextcdf4=<NEP_VERSION>` where `<t>` is the first token of `nc_inq_libvers()` (stop at first space) and the HDF5 triple comes from `H5get_libversion`. Build once per file at create/first-write; no global cached state (upstream's `globalprovenance` exists for `--with-ncproperties` extras NEP does not support).

`nx4_write_provenance` mirrors `NC4_write_provenance` + `write_nc3_strict_att`:

- Return `NC_NOERR` immediately when `file->no_write` or the file was not created by NEXTCDF-4 and lacks a stamp decision (see below).
- If `H5Aexists(file->rootid, "_NCProperties") == 0` and `file->ncproperties` is set, create the attribute exactly like upstream: `H5Screate(H5S_SCALAR)`, `H5Tcopy(H5T_C_S1)` + `H5Tset_strpad(H5T_STR_NULLTERM)` + `H5Tset_cset(H5T_CSET_ASCII)` + `H5Tset_size(strlen(file->ncproperties))` — note upstream stores `strlen`, not `strlen+1`; keep byte parity. Never overwrite an existing attribute.
- If `file->mode & NC_CLASSIC_MODEL` and `_nc3_strict` is absent, create a scalar `H5T_NATIVE_INT` attribute with value 1.
- On a file opened for write that already carried `_NCProperties` (loaded at open), do nothing — the existing stamp is preserved verbatim. On a file that lacks it (foreign HDF5, upstream file without the attribute), do nothing: no fresh stamp for files NEXTCDF-4 did not create (decision 5a). The simplest correct gate: `nx4_write_provenance` writes `_NCProperties` only when `file->ncproperties` was populated at create time (a `stamp_new` flag or `backend_marked` distinction won't suffice — use an explicit `int created_by_us` set in `NEXTCDF4_create`), while `_nc3_strict` is written for classic-model files we created.
- Close every HDF5 handle on all paths; map failures to `NC_EHDFERR`/`NC_EFILEMETA` like the surrounding code.

`nx4_get_att_special` mirrors `nc4_get_att_special`:

- `attnump` non-NULL → `NC_EATTMETA`.
- `"_NCProperties"`: `file->ncproperties == NULL` → `NC_ENOTATT`; else `NC_CHAR`, len `strlen`, memtype must be `NC_NAT`/`NC_CHAR` (else `NC_ECHAR`), copy with NUL.
- `"_IsNetcdf4"`/`"_SuperblockVersion"`: `NC_INT`, len 1, values from `nx4_isnetcdf4` and `nx4_superblock_version`; integer memtype switch identical to upstream (`NC_BYTE`/`NC_SHORT`/`NC_INT`/`NC_UBYTE`/`NC_USHORT`/`NC_UINT`/`NC_INT64`/`NC_UINT64`, `NC_NAT`→`NC_INT`), `NC_ERANGE` otherwise.
- Any other name → `NC_ENOTATT` (callers only invoke it for the three names).

`nx4_isnetcdf4`: 1 when `H5Aexists(rootid, "_nc3_strict")` or `H5Aexists(rootid, "_NCProperties")` is positive; otherwise visit all objects under `rootid` (`H5Ovisit`/`H5Literate`) and return 1 when at least two carry any of `CLASS`, `NAME`, `REFERENCE_LIST`, `DIMENSION_LIST`, `_Netcdf4Coordinates`, `_Netcdf4Dimid`; HDF5 walk errors → 0.

`nx4_superblock_version`: `H5Fget_create_plist(file->hdfid)` + `H5Pget_version(&super,...)`; close the plist; error → `NC_EHDFERR`.

### 2. Wire create, open, and deferred write sites

Files: `src/nextcdf4/nxt4create.c`, `nxt4open.c`, `nxt4file.c`.

- `NEXTCDF4_create` (nxt4create.c): after `NEXTCDF4_write_markers`, build `file->ncproperties` via `nx4_build_ncproperties` and set `file->created_by_us = 1`. A build failure (`NC_ENOMEM`) propagates through the existing create-failure cleanup.
- Open path (nxt4open.c, after `NEXTCDF4_read_markers`): read `_NCProperties` from `file->rootid` when present — `H5Aopen`, verify `H5T_STRING` class, read into a NUL-terminated buffer with the attribute's own type (upstream uses `H5Tget_native_type`; either is fine since ASCII is preserved), store in `file->ncproperties`. A malformed (non-string) attribute is ignored with an `ELOG` line, matching upstream's "Invalid _NCProperties attribute: ignored" leniency — open does not fail.
- `NEXTCDF4__enddef`: after `commit_group_vars`, call `nx4_write_provenance` before `H5Fflush` (upstream writes provenance inside the same deferred-metadata pass).
- `NEXTCDF4_sync`: for writable files, call `nx4_write_provenance` before `H5Fflush`.
- `NEXTCDF4_close`: on the writable path (the `!file->no_write` branch before the final `H5Fflush`), call `nx4_write_provenance`; a failure there surfaces as the close's return code. Abort paths never stamp.
- Free `file->ncproperties` wherever `NEXTCDF4_FILE_INFO_T` is released (close and abort).

### 3. Virtual-attribute interception

Files: `src/nextcdf4/nxt4meta.c` (`NEXTCDF4_inq_att`, `NEXTCDF4_get_att`, and `NEXTCDF4_inq_attid` — the dispatch entry resolved by name).

In each of the three functions, after resolving `grp`/`var` and before the `find_att`/`get_att_context` miss, when `varid == NC_GLOBAL` (upstream's `!var` condition — apply it on any group's ncid, not just root, for exact parity) and `name` is one of `_NCProperties`, `_IsNetcdf4`, `_SuperblockVersion`, call `nx4_get_att_special(file, name, ...)` with that entry's outputs instead of returning `NC_ENOTATT`. `NEXTCDF4_inq_att` passes `xtypep`/`lenp` with NULL data; `inq_attid` passes `attnump` (yielding `NC_EATTMETA`); `get_att` passes `value`/`memtype`. Do not intercept on variable attribute lists, do not synthesize `_Format`, and do not add the names to `inq_natts`/`inq_attname` results — upstream's `NAMEONLYFLAG` semantics mean they answer only to name lookups.

### 4. Tests

Files: new `test/nextcdf4/tst_nextcdf4_provenance.c`; `test/nextcdf4/CMakeLists.txt`.

Register an enabled `tst_nextcdf4_provenance` (plain `Author:` comment, no Doxygen) linked like the other `tst_nextcdf4_*` tests, with its own `${CMAKE_CURRENT_BINARY_DIR}/provenance` working directory and label `nextcdf4_controls`. Loop over native, `NC_NETCDF4_MODEL`, and `NC_CLASSIC_MODEL` creates internally. Required cases:

- After create+close, open the raw file with HDF5 (`H5Fopen`): assert `_NCProperties` exists, is a scalar fixed-length ASCII string starting `version=2,netcdf=` and containing `,hdf5=` and `,nextcdf4=4.3.0` (compare the suffix key, not an exact full string); assert `_nc3_strict` == 1 exists iff `NC_CLASSIC_MODEL`; assert `_IsNetcdf4`/`_SuperblockVersion` do **not** exist as stored attributes.
- Same-session and post-reopen API checks: `nc_inq_att(NC_GLOBAL, "_IsNetcdf4")` → `NC_INT`, len 1; `nc_get_att_int` → 1. `nc_inq_att(NC_GLOBAL, "_SuperblockVersion")` → value matching `H5Pget_version` on the FCPL (expected 0 for `V110` model files, 3 for latest-bound files — assert whatever the FCPL reports via HDF5 in-test rather than hardcoding). `nc_get_att` for `_IsNetcdf4` with `NC_SHORT`/`NC_INT64`/`NC_DOUBLE` memtypes → OK/OK/`NC_ERANGE`. `nc_inq_attid` on these names → `NC_EATTMETA`.
- `_NCProperties` readable via `nc_get_att_text`; `nc_inq_att` → `NC_CHAR`, len `strlen`; `nc_get_att` with a numeric memtype → `NC_ECHAR`.
- `nc_inq_natts`/`nc_inq_attname` never enumerate the three names; `nc_put_att`/`nc_rename_att`/`nc_del_att` on them still return `NC_EBADNAME` (existing reserved-name coverage stays green).
- Preservation: create an upstream file via `nc_create(..., NC_NETCDF4)` (no NEXTCDF-4 flag) in-test, capture its `_NCProperties` bytes; open for write under NEXTCDF-4, add an attribute/variable, close; verify via HDF5 that the stamp is byte-identical (no overwrite) and readable through NEXTCDF-4 `nc_get_att`. Create a bare HDF5 file with `H5Fcreate` (no markers): opened for write under NEXTCDF-4 and closed → still no `_NCProperties` on disk; `_NCProperties` name lookup → `NC_ENOTATT`; `_IsNetcdf4` → 0.
- `nc_sync` and `nc_close` on a created file that never left define mode via explicit `nc_enddef` still produce the stamp (covers the close→`_enddef` path).
