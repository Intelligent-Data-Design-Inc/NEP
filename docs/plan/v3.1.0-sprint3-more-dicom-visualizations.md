# v3.1.0 Sprint 3: More DICOM Visualizations

## Sprint Goal

Expand the NEP DICOM visualization gallery in `examples/viz/` by adding a
publication-ready grayscale PNG for an additional currently-readable DICOM
sample, and wire the new example into the CMake/CTest workflow and
documentation.

## Scope

### In Scope

- Add `examples/viz/plot_dicom_ct_brain.py` to open
  `test/data/DICOM/CT-MONO2-16-brain.dcm` through the NetCDF UDF interface,
  read `pixel_data[0, :, :]`, apply a 1st–99.5th-percentile contrast window,
  and write `dicom_ct_brain_image.png` +
  `dicom_ct_brain_image_metadata.txt`.
- Update `examples/viz/CMakeLists.txt` to copy the new script, run it under
  `HAVE_DICOM`, and append `dicom_ct_brain_image` to the visualization
  artifact verification list.
- Update `examples/viz/README.md` and `docs/dicom.md` to describe the new
  DICOM visualization.
- Confirm the generated artifacts pass `verify_viz_artifacts.py` and that
  `ctest -R viz` succeeds in a DICOM-enabled build.
- Fix the `test/tst_dicom_udf` CMake link line to include `${HDF5_LIBRARIES}`
  so the DICOM UDF test links in a CMake-only configuration.

### Out of Scope

- Adding visualizations for DICOM samples that the current reader cannot open.
  Specifically:
  - `CT-MONO2-16-chest.dcm` uses JPEG Lossless transfer syntax
    `1.2.840.10008.1.2.4.70`.
  - `MR-MONO2-12-shoulder.dcm` uses JPEG Extended transfer syntax
    `1.2.840.10008.1.2.4.57`.
  - `MR-MONO2-16-head.dcm` is Implicit VR Little Enden and causes
    `dcm_filehandle_read_frame()` to fail with `DcmError set twice` under the
    installed libdicom.
  - `CR-MONO1-10-chest.dcm` has no DICOM preamble.
- Extending the DICOM UDF reader to support additional transfer syntaxes
  (that belongs to a future DICOM reader sprint).
- Autotools build-system changes (v3.1.0 is CMake-only per Sprint 2).

## Background

Sprint 1 added the first two DICOM visualizations (`plot_dicom_mrbrain.py` and
`plot_dicom_xa_montage.py`) and the public-domain OME sample set. Several
additional samples remain, but only `CT-MONO2-16-brain.dcm` is an uncompressed
Explicit VR Little Endian file that the current `libdicom`-based reader can
read end-to-end.

## Major Tasks (Dependency Order)

1. **Select visualization candidates**
   - Confirm transfer syntax and pixel encoding for each extra DICOM sample.
   - Restrict the sprint to `CT-MONO2-16-brain.dcm` (512×512, 16-bit signed,
     MONOCHROME2, Explicit VR LE).

2. **Add the CT brain visualization script**
   - Reuse `_dicom_udf.read_pixel_data()` and `plot_common.save_with_metadata()`.
   - Apply the same percentile contrast window used by
     `plot_dicom_mrbrain.py`.
   - Use a 6.0 by 5.0 inch grayscale figure.

3. **Wire the script into the build system**
   - Add the script to `_viz_python_files` in `examples/viz/CMakeLists.txt`.
   - Add a `viz_dicom_ct_brain` CTest entry.
   - Append `dicom_ct_brain_image` to `_viz_artifacts`.

4. **Update user-facing documentation**
   - Add the new script to `examples/viz/README.md`.
   - Add the new script to the Visualization section of `docs/dicom.md`.

5. **Validate the local DICOM-enabled CMake build**
   - Configure with DICOM and visualization enabled.
   - Run `ctest -R viz --output-on-failure`.
   - Confirm PNG/metadata pairs and `verify_viz_artifacts.py` pass.

6. **Update planning artifacts**
   - Expand `docs/roadmap.md` Sprint 3 with clarified decisions and issue link.
   - Create the GitHub issue for the sprint and reference this plan.

## Acceptance Criteria

- `plot_dicom_ct_brain.py` is present in `examples/viz/` and copied to the
  build tree by CMake.
- `cmake -S . -B build -DNEP_BUILD_EXAMPLES=ON -DNEP_ENABLE_VIZ_EXAMPLES=ON -DNEP_ENABLE_DICOM=ON`
  configures and builds successfully.
- `ctest --test-dir build -R viz --output-on-failure` passes, including
  `viz_dicom_ct_brain` and `viz_artifacts`.
- `dicom_ct_brain_image.png` and `dicom_ct_brain_image_metadata.txt` are
  generated and conform to diagram rules (grayscale, 8.0×6.1 in max, 150 DPI,
  external metadata with `title`, `caption`, `alt_text`, caption ≤ 75 words).
- `docs/dicom.md` and `examples/viz/README.md` describe the new plot.
- `test/tst_dicom_udf` links and passes in the CMake build.

## Testing Requirements

- `ctest --test-dir build -R viz`
- `ctest --test-dir build -R dicom_udf`
- Visual inspection of `dicom_ct_brain_image.png`
- `verify_viz_artifacts.py` passes for all generated artifact basenames.

## Build System and CI Integration

- `examples/viz/CMakeLists.txt`
- `examples/viz/README.md`
- `docs/dicom.md`
- `test/CMakeLists.txt` (DICOM test link fix)

## Dependencies and Risks

- **Dependency:** v3.1.0 Sprint 2 CMake-only migration must be in place so
  Autotools paths are not required.
- **Risk:** Additional public-domain DICOM samples use transfer syntaxes not
  supported by the current reader. This is accepted and documented; only
  `CT-MONO2-16-brain.dcm` is targeted.
- **Risk:** The `MR-MONO2-16-head.dcm` sample exposes a `libdicom`
  `dcm_filehandle_read_frame` failure for Implicit VR files. It is excluded
  until the DICOM reader can handle it.

## Definition of Done

- One new DICOM visualization script generates a validated,
  publication-ready artifact under CMake.
- CMake wiring, user documentation, and artifact verification are updated.
- Existing DICOM tests remain green.
- The roadmap and sprint issue link to this plan.
