# V4.3.0 Sprint 1G: Convert Data Types in One Function

Source: docs/roadmap.md, "V4.3.0 / Sprint 1G".

## Goal

NEXTCDF-4 has an experimental, NEP-owned conversion path for variable and attribute I/O, selected by the temporary CMake option `NEP_INTERNAL_CONVERT`. The default OFF build behaves as before. With ON, `nx4_convert_type()` handles supported numeric conversions, including round-to-nearest-even bfloat16 conversion, rather than asking HDF5 to convert application values. IEEE float16 conversion remains an explicit HDF5 exception until Sprint 1I. Both builds run in dedicated NEXTCDF-4 CI. This sprint establishes correctness and the comparison mechanism; Sprint 1H handles range-error reporting, measures performance, chooses the permanent path, and removes the temporary option.

## Decisions

| Topic | Decision |
| --- | --- |
| Switch | `option(NEP_INTERNAL_CONVERT "Use experimental internal NEXTCDF-4 type conversion" OFF)`. Build-time only, not a file-format or runtime setting. OFF preserves current behavior. (Ed's roadmap update.) |
| Implementation | NEP-owned conversion code modeled on `/fast/ed/netcdf-c/libsrc4/nc4var.c:nc4_convert_type()`, not a wrapper delegating standard numeric conversion to that function. (Ed: 1a.) |
| Callers | NEXTCDF-4 variable I/O, attributes, and quantized writes. `src/nep_bfloat16.c` and its format-independent public API remain independent of the optional backend. |
| bfloat16 | ON uses NEP round-to-nearest-even, single rounding from double, quiet NaN preservation and signed infinity on finite overflow. OFF retains HDF5's existing results. Raw matching-type I/O preserves bits. |
| IEEE float16 | Temporary exception in ON: `NC_FLOAT16` to/from `NC_FLOAT` or `NC_DOUBLE` still uses HDF5 conversion and retains current results. Internal IEEE float16 work belongs to Sprint 1I, not 1H. (Ed: 2a.) |
| Other new types | No new converting API for FP8/FP6/FP4, complex, bitfield, reference or user-defined types. Preserve supported matching-type I/O and string ownership. |
| Range reporting | Do not fix #381 or introduce `NC_ERANGE` returns from NEXTCDF-4 in this sprint. Keep range information internally for Sprint 1H. Existing `nc_*_bfloat16` range reporting is unchanged. |
| Performance | No benchmark runs, regenerated samples, CSVs, charts or machine records in 1G. Sprint 1H produces separate comparison artifacts, not replacements for the existing reference results. |
| CI | Dedicated `ubuntu-latest` NEXTCDF-4 job with OFF/ON matrix, in addition to existing CI. Do not enable benchmarks or disable failing tests to make it pass. |
| Packaging | Defer Spack changes until performance is measured and the permanent path chosen; no temporary variant or recipe arguments. The option will go away. (Ed's final answer.) Conda is not changed. |
| Build and docs | CMake only; Autotools was removed in v3.1.0. Full CTest remains passing and Doxygen remains warning-free. No public conversion function is added. |

## Current state (2026-11-17)

- `docs/roadmap.md` now names 1G for internal conversion, 1H for continued conversion changes, and 1I for IEEE float16. There is no later version heading beyond V4.3.0. Sprint 2 owns release notes and publication.
- `src/nextcdf4/nxt4io.c:var_io()` serves `NEXTCDF4_{get,put}_{vara,vars}`. Untyped calls passing `NC_NAT` are resolved to the variable type. Ordinary scalar and array I/O passes the requested HDF5 memory type to `H5Dread`/`H5Dwrite`, allowing HDF5 to convert. Scalars return before the quantization branch.
- `nxt4io.c:check_memtype()` permits float/double conversion on `NC_FLOAT16`/`NC_BFLOAT16`, rejects other typed small-float calls, and preserves matching-type raw I/O. `memory_type()` owns copied HDF5 datatypes through a `closep` output.
- Quantized array writes call upstream `nc4_convert_type()` and ignore `range_error`. `src/nextcdf4/nxt4meta.c:NEXTCDF4_put_att()` and `NEXTCDF4_get_att()` also call it for differing types and ignore range information. Attribute replacement currently deletes the old attribute before conversion succeeds. `native_hdf_type()` maps only standard numeric/char types; small-float attribute persistence cannot simply reuse it.
- `/fast/ed/netcdf-c/libsrc4/nc4var.c:nc4_convert_type()` has the signature used below, supports standard numeric types and quantization, and reports range information separately from its return status. It has no `NC_FLOAT16` or `NC_BFLOAT16` cases. The local source checkout is at `5baa62e6966d3e505b895574dafbd531a4aed360`.

### 2. Implement the private conversion entry point

Files: new `src/nextcdf4/nxt4convert.c`, `src/nextcdf4/nxt4internal.h`, `src/nextcdf4/CMakeLists.txt`.

Declare this private function in `nxt4internal.h` and compile its definition into `ncnextcdf4`:

```c
int nx4_convert_type(const void *src, void *dest, nc_type src_type,
                     nc_type dest_type, size_t len, int *range_error,
                     const void *fill_value, int strict_nc3,
                     int quantize_mode, int nsd);
```

- Implement standard numeric conversion in NEP, using upstream's source/destination switch organization as the reference. Standard numeric types are `NC_BYTE`, `NC_UBYTE`, `NC_SHORT`, `NC_USHORT`, `NC_INT`, `NC_UINT`, `NC_INT64`, `NC_UINT64`, `NC_FLOAT`, `NC_DOUBLE`. Do not route them through HDF5 or delegate their conversion to `nc4_convert_type()` in ON builds. Preserve relevant upstream attribution/license notices if adapting source.
- The helper takes already resolved types; callers resolve `NC_NAT`. Caller-owned, non-overlapping source/destination buffers; no ownership transfer. `range_error` is required and reset to zero. Zero length succeeds without accessing buffers after validating the type pair. For nonzero length, null buffers return `NC_EINVAL`. Validate the entire type pair before touching the destination.
- Standard in-range conversion follows C numeric conversion, including truncation toward zero for real-to-integer and exact same-type copying. Guard real-to-integer casts against NaN, infinity and out-of-range inputs rather than copying undefined floating-to-integer casts. For those exceptional real-to-integer cases use the destination's default NetCDF fill; use the supplied destination fill when present. For integer narrowing use the reference routine's cast behavior on the supported compiler, with range flags. Detect range boundaries without first rounding 64-bit integer limits to float/double. Overflow reporting to users remains deferred; output buffers must still be fully initialized and the loop must finish.
- `range_error` is a boolean (set, never counted into an overflowing int). The helper returns `NC_NOERR` for completed conversion even when it sets this flag; structural/unsupported-type errors return their normal error code. Public NEXTCDF-4 callers do not translate the flag to `NC_ERANGE` yet. Preserve the reference routine's `strict_nc3` handling of unsigned-byte to signed-byte range flags; existing attribute and quantization call sites continue passing 0, and the new ordinary-variable conversion path also passes 0. Do not change existing wrapper `NC_ERANGE` behavior in `src/nep_bfloat16.c`.
- `NC_CHAR` only copies to itself; char/non-char conversion returns `NC_ECHAR`. Numeric/string conversion returns `NC_EBADTYPE`. String duplication/freeing stays with existing attribute/string code, not this numeric helper. No reinterpretation of references/bitfields as numeric values.
- Add bfloat16 to/from float/double, using byte-wise `memcpy` access and the algorithms in `src/nep_bfloat16.c` as the reference. Narrowing uses nearest/even, preserves sign and a quiet NaN, preserves signed zero, and produces signed infinity on finite overflow. Double narrows once, not through ordinary nearest/even float followed by another nearest/even conversion. No dependence on compiler `__bf16` arithmetic. Same-type bfloat16 copies all bits, including NaN payloads. Other cross-small-float or integer/bfloat16 pairs return `NC_EBADTYPE`.
- The only HDF5 numeric exception is float16 to/from float/double. Dispatch that pair here through `H5Tconvert()` with an appropriately sized scratch buffer (`len * max(source_size, destination_size)`, checked for overflow), then copy the converted result out. Preserve HDF5 2.1.1 results and clean up datatypes/property lists on every exit. No double rounding via bfloat16 or float for double/float16.
- Matching raw FP8/FP6/FP4, complex, bitfield and reference variable I/O bypasses numeric conversion. No new conversion pair for these types or user-defined types. Preserve existing supported string I/O separately.
- Apply the existing BitGroom/GranularBR/BitRound algorithms after numeric conversion, once, only for float/double destinations; preserve fill values. Bring the needed quantization logic into NEP rather than delegating a converting call upstream. Invalid quantization type/mode/nsd must return `NC_EINVAL` instead of reaching an assertion or invalid shift. Limits: decimal digits 1..6/15 and binary bits 1..23/52 for float/double. This validation prevents unsafe entry to the new helper; it is not small-float quantization support.
- Provide full Doxygen blocks for the file, helper and private supporting functions. Use `Edward Hartnett, Intelligent Data Design, Inc.` as author. Follow `nxt4err.h` cleanup/logging conventions. Do not add a public declaration to installed `nep.h`.

### 3. Route variable I/O through the helper when ON

Files: `src/nextcdf4/nxt4io.c`, `src/nextcdf4/nxt4internal.h`, `src/nextcdf4/nxt4convert.c`.

- Keep the OFF path, memtype rejection rules, and HDF5 rounding unchanged. Keep the existing ordering of file/variable, permission and define-mode checks. Resolve `NC_NAT` before selecting a conversion path.
- In ON numeric reads, use the variable's native memory representation for HDF5 I/O, then call `nx4_convert_type()` into the application buffer. In writes, convert into a temporary buffer of the variable's native type, then write with that matching HDF5 memory type. HDF5 may still perform byte-order/file representation work; it must not perform application numeric conversion outside the float16 exception.
- Implement the shared private mapper `hid_t NEXTCDF4_memory_type(nc_type type, int *closep)` by extracting the existing `memory_type()` ownership contract. Use native byte order for raw bfloat16 buffers (unsigned 16-bit host-order bit patterns), not a hard-coded LE memory layout on big-endian hosts. Retain existing file datatype/endian mapping.
- Use the same conversion flow for scalars (one value), contiguous hyperslabs and strided hyperslabs. Integrate quantization into that flow so ON scalar and array writes both quantize exactly once and never modify the caller's source. Preserve zero-count no-I/O behavior and unlimited-dimension growth.
- Check both element-count and byte-size multiplication before allocation. Do not divide by a zero accumulated count. Validate arguments/conversion support and allocate/convert write data before extending a dataset. A rejected conversion must not change the application read buffer, dataset contents or unlimited dimensions.
- Use one cleanup path for HDF5 spaces, owned datatypes and scratch memory; fix any early-return leaks introduced or encountered in the touched scalar/conversion paths. No broad lifecycle refactor.
- Same-type nonquantized numeric and supported raw I/O retain the no-conversion fast path. Do not add a temporary allocation/copy just to call the helper for an identity operation.

### 4. Route attribute conversions through the helper when ON

HDF5 receives matching native numeric types; application numeric conversion happens in the helper. Extend the existing load path to recover those supported numeric values without feeding a negative `native_hdf_type()` result into `H5Aread`.
- ON permits bfloat16 attributes to/from float/double through the same numeric rules; float16 float/double conversion uses the documented exception. Do not broaden FP8/FP6/FP4 conversion, string/numeric conversion or reference attributes. Matching supported raw small-float attributes may retain their existing copy representation.
- Convert/validate/allocate the new value before deleting an existing attribute in the ON replacement path. Unsupported conversions leave the previous attribute intact. Check `len * type_size` overflow and HDF5 mapper errors. Keep existing string deep-copy/free rules; do not turn a `char **` attribute into a byte-copy ownership bug.
- Do not fix `_FillValue` rejection, variable fill recovery or #377 here. Pass no quantization for attributes. Range flags are not yet translated into public `NC_ERANGE`.
