# V4.3.0 Sprint 1V5: SWMR Reader Support and Documentation

Source: docs/roadmap.md, "V4.3.0 - NEXTCDF4 Development / Sprint 1V5".

## Goal

A NEP application can open a live NEXTCDF-4 SWMR file read-only and see the
writer's published updates without reopening: a new `NC_SWMR_READ` open flag
selects HDF5 SWMR read access, and `nc_swmr_refresh` reloads dataset extents
and cached dimension lengths so appended records and the writer's last
attribute-free schema become visible through the ordinary `nc_inq_*`/`nc_get_*`
calls. Multiple simultaneous readers and writer/reader close ordering are
tested end to end, and the SWMR contract for both sides is documented.

## Current state (2026-11-25)

- Sprint 1V4 is implemented and its plan is the authoritative contract:
  `docs/plan/v4.3.0-sprint1V4-swmr-writer-support.md`. Roadmap line 331
  records its explicit handoff: use `H5Fopen(..., H5F_ACC_RDONLY |
  H5F_ACC_SWMR_READ, ...)` — there is no `H5Fstart_swmr_read` in HDF5 2.1.1.
- `include/nep.h` defines `NC_SWMR_WRITE` (`0x08000000`, bit 27) and declares
  `nc_start_swmr_write`/`nc_swmr_flush` with full Doxygen blocks. Mode bits
  25–30 are free for NEP use; bit 26 is `NC_NETCDF4_MODEL`, bit 27 is
  `NC_SWMR_WRITE`. Bit 28 (`0x10000000`) is the next allocation.
- `src/nextcdf4/nxt4internal.h:125-154` holds `NEXTCDF4_FILE_INFO_T` with
  `swmr_requested`/`swmr_active`; `nx4_swmr_validate`/`activate`/`flush` are
  declared at lines 156-158 and implemented in `src/nextcdf4/nxt4file.c`.
- `src/nextcdf4/nxt4open.c:68-71` already validates `NC_SWMR_WRITE` open
  combinations; lines 121-126 pick `H5F_ACC_RDWR`/`H5F_ACC_RDONLY`. A reader
  flag needs a third access-mode arm (`H5F_ACC_RDONLY | H5F_ACC_SWMR_READ`)
  and must bypass `nx4_swmr_activate` (line 140).
- `src/nextcdf4/nxt4create.c:106` accepts the flag; `nxt4file.c:450` sets
  `swmr_requested` from `mode & NC_SWMR_WRITE`. `NEXTCDF4_check_mode` decides
  which mode bits are legal — `NC_SWMR_READ` must be added there.
- Dimension lengths are cached: `nxt4meta.c:3989` sets `dim->len` from the
  scale dataset's extent at load; the writer-side grow path in
  `nxt4io.c:517-522` updates `dim->len` after `H5Dset_extent`. Scale dataset
  handles live in `NEXTCDF4_DIM_INFO_T.hdf_dataset` (`nxt4meta.c:3998`),
  variable handles in `NEXTCDF4_VAR_INFO_T.hdf_dataset`. Coordinate dataset
  aliases are reopened by `nx4_reopen_var_cache` conventions; a reader
  refresh must refresh both handles of a coord-var alias or use object-token
  dedup like `nx4_swmr_flush`.
- `test/nextcdf4/tst_nextcdf4_swmr.c` + `tst_nextcdf4_swmr_reader.c` (raw
  HDF5, links only `${NEP_HDF5_LIBRARIES}`) run under label

  `H5Dpublic.h` declares `H5Drefresh`/`H5Dflush`. There is no
  `H5Fstart_swmr_read` and no `H5Arefresh`-style group metadata refresh —

- SWMR requires superblock v3. Native NEXTCDF-4 creates use

## Work items

### 1. Public flag, function and session state

Files: `include/nep.h`, `src/nextcdf4/nxt4internal.h`, `src/nextcdf4/nxt4file.c`.

- Add `#define NC_SWMR_READ 0x10000000` next to `NC_SWMR_WRITE`, documented as
  a NEP-only open flag for `nc_open` with `NC_NEXTCDF4`; not an upstream
  NetCDF constant and not valid at create.
- Declare `int nc_swmr_refresh(int ncid);` in `nep.h` beside
  `nc_swmr_flush` with a full Doxygen block (`@author Edward Hartnett,
  Intelligent Data Design, Inc.`): argument, linkage to `libncnextcdf4`,
  read-only SWMR session requirement, what becomes visible (appended records,
  grown unlimited-dimension lengths), what never becomes visible (new
  variables/attributes — schema is frozen by the writer contract), and every
  return code. Availability follows `NEP_HAS_NEXTCDF4`; no new feature macro.
- Add `int swmr_read;` to `NEXTCDF4_FILE_INFO_T` (session-only, set from the
  mode bit). Keep `swmr_requested`/`swmr_active` writer-only; assert in
  `check_mode` that the two flags never combine.
- New private helper `int nx4_swmr_refresh(NC_FILE_INFO_T *h5,
  NEXTCDF4_FILE_INFO_T *file);` declared in `nxt4internal.h` and implemented
  next to the other `nx4_swmr_*` helpers in `nxt4file.c`.
- `nc_swmr_refresh(int ncid)` validates the ncid through
  `NEXTCDF4_get_file` (`NC_EBADID` invalid, `NC_ENOTNC4` non-NEXTCDF-4),
  requires `file->swmr_read` (`NC_EINVAL` otherwise — including on ordinary
  read-only, writer-active or writable sessions), then runs the helper.
  Subgroup ncids operate on their owning file. No new error constants.

### 2. Reader open path

Files: `src/nextcdf4/nxt4open.c`, `src/nextcdf4/nxt4file.c` (`check_mode`),
`src/nextcdf4/nxt4create.c`.

- Extend `NEXTCDF4_check_mode` so `NC_SWMR_READ` is a legal mode bit.
  Reject: `NC_SWMR_READ` at create (`nxt4create.c` — `NC_EINVAL`), combined
  with `NC_WRITE`, `NC_SWMR_WRITE`, `NC_CLASSIC_MODEL`, `NC_DISKLESS`,
  `NC_INMEMORY`, `NC_SHARE`, `NC_PERSIST`, `NC_MMAP` or MPI `parameters`
  (each `NC_EINVAL`; keep `NC_ENOPAR` for `parameters` without parallel).
- In `NEXTCDF4_open`: when `mode & NC_SWMR_READ`, open with
  `H5F_ACC_RDONLY | H5F_ACC_SWMR_READ` on the same FAPL (still
  `H5F_CLOSE_STRONG`, no MPI driver), set `file->swmr_read = 1`, load markers
  and metadata normally, and skip `nx4_swmr_activate`. `file->no_write = 1`.
- After the metadata load, query `H5Fget_info2` and require superblock
  version >= 3 (`NC_EINVAL` otherwise); a `NC_NETCDF4_MODEL` file is accepted
  only when this check passes. Do not call `H5Fstart_swmr_write` or set libver
  bounds — a reader never upgrades anything.
- Marker validation stays unchanged: `NC_SWMR_READ` requires the file to be a
  valid NEXTCDF-4/model file as today (`_Nextcdf4Backend` marker check in
  `NEXTCDF4_read_markers`); the flag changes HDF5 access, not format rules.
- Failed opens keep the existing `fail:` cleanup; nothing may be left in the
  open-file list or holding HDF5 handles.

### 3. Refresh semantics

Files: `src/nextcdf4/nxt4file.c`, `src/nextcdf4/nxt4meta.c` (if a dim-extent
reload helper is cleaner there), `src/nextcdf4/nxt4io.c` (read-path sanity
only — no changes expected).

- `nx4_swmr_refresh` walks the root and all subgroups deterministically and
  calls `H5Drefresh` on every open variable dataset, then on every
  dimension-scale dataset. Coordinate-var/scale alias pairs may be
  deduplicated by HDF5 object token as `nx4_swmr_flush` does; refreshing an
  alias twice is also safe, never close one.
- After refreshing a scale dataset, reacquire its dataspace
  (`H5Dget_space`/`H5Sget_simple_extent_dims`) and store the current extent
  into `dim->len`; keep `dim->unlimited` untouched. Do the same for
  variable datasets' cached extent wherever the code tracks it (check
  `var_io`'s per-read `H5Dget_space` calls — refreshed handles already return
  fresh extents, so no separate var-extent cache update beyond `dim->len`
  should be needed; verify, don't assume).
- Refresh never loads new metadata: new variables, attributes, groups or
  types written since the reader's last refresh are not expected to exist
  (the writer froze schema at activation) and are explicitly not discovered.
  Document that a refresh is not a re-open.
- Reads mid-append: `H5Drefresh` then ordinary `nc_get_vara` is the supported
  sequence; partial records are an application concern. Reads on a
  SWMR-reader session use the existing `var_io` path unchanged; in-bounds
  checks must consult the refreshed `dim->len`, not a stale one.
- Writer path untouched: `nc_swmr_refresh` on a `swmr_active` session returns
  `NC_EINVAL` (writer flushes, reader refreshes — never mix); `nc_swmr_flush`
  on a `swmr_read` session returns `NC_EINVAL`/`NC_EPERM` as today for
  read-only.
- `NEXTCDF4_sync`/`NEXTCDF4_close` on a SWMR-reader session stay no-ops for
  flushing; close releases all refreshed handles normally through
  `nx4_close_group_hdf` and `H5F_CLOSE_STRONG`.

- Sanitizer cleanliness: helper closes netCDF handles before exit; parent

## Out of scope

- MPI-IO SWMR (reader or writer), SWMR in compatibility modes beyond the
  superblock-v3 model-file read acceptance, dynamic/string/`NC_STD_REF`/user
  type SWMR data, schema evolution visible to readers (writer contract
  freezes schema), Fortran SWMR wrappers, crash-recovery or power-loss
  durability: future work beyond v4.3.0.
- Atomic-timestep/commit-marker protocol, transactional rollback, per-variable
  refresh API, implicit refresh inside `nc_inq_dimlen`/`nc_get_vara`,
  automatic SWMR fallback on ordinary `nc_open`: not planned; revisit only
  with user feedback.
- VDS, diskless/in-memory, mmap and direct-chunk access: v4.4.0.
- Release notes/tag, Spack version bump and upstream
  `spack/spack-packages` PR update, conda publication: Sprint 2.
- Open verification item: HDF5 2.1.1's actual `H5F_ACC_SWMR_READ`
  acceptance rules for never-written model files and for readers opening
  before writer activation are pinned by the new tests during
  implementation, not assumed. No unanswered product-scope decision remains.
