# V3.0.0 Sprint 4: Functional Groups and Enhanced Multi-frame Metadata

**Objective**: Expose per-frame and shared functional-group metadata from enhanced multi-frame DICOM objects as NetCDF variables or global attributes.

---

## Background

Sprints 1–3 provide native and encapsulated pixel-data access for single-frame and multi-frame DICOM images, plus a Fortran smoke test, a C example program, packaging/CI integration, and user documentation. Many clinical DICOM objects store 3D or 4D volumes as multi-frame instances where each frame's geometry, timing, and acquisition parameters live in **Functional Groups** rather than top-level tags. This sprint adds that metadata layer once a suitable enhanced multi-frame sample is available.

This sprint:

- Parses **Shared Functional Groups Sequence** `(5200,9229)` and **Per-frame Functional Groups Sequence** `(5200,9230)`.
- Exposes selected frame-level metadata as NetCDF variables over the `frame` dimension, or as scalar global attributes when the value is shared across all frames.

## Tasks

### 1. Parse Functional Group Sequences

For multi-frame enhanced objects, locate:

- **Shared Functional Groups Sequence** `(5200,9229)` — one item containing attributes shared by all frames.
- **Per-frame Functional Groups Sequence** `(5200,9230)` — one item per frame.

Each item is a `DcmDataSet` (or `DcmSequence` in `libdicom` terms) nested inside the parent data set. Recursively retrieve elements from:

```
(5200,9229) SQ
  Item 1
    (0020,9113) Plane Position Sequence
      (0020,0032) ImagePositionPatient
    (0020,9116) Plane Orientation Sequence
      (0020,0037) ImageOrientationPatient
    (0028,9110) Pixel Measures Sequence
      (0018,0050) SliceThickness
      (0028,0030) PixelSpacing
(5200,9230) SQ
  Item 1..N
    ...
```

For this sprint, expose at minimum:

| Tag / nested path | Variable or attribute | Shape |
|-------------------|-----------------------|-------|
| `ImagePositionPatient` (0020,0032) | `image_position_patient` | `[frame][3]` or global if in Shared FG |
| `ImageOrientationPatient` (0020,0037) | `image_orientation_patient` | `[frame][6]` or global if in Shared FG |
| `PixelSpacing` (0028,0030) | `pixel_spacing` | `[frame][2]` or global |
| `SliceThickness` (0018,0050) | `slice_thickness` | `[frame]` or scalar attribute |

If a value is in the Shared Functional Groups Sequence, create a scalar global attribute or a constant variable. If it varies per frame, create a `[frame]` variable.

### 2. Expose functional-group variables

When `NumberOfFrames > 1` and functional groups are present:

- Add a `frame` dimension.
- Add `position` dimension of length 3 for `image_position_patient`.
- Add `orientation` dimension of length 6 for `image_orientation_patient`.
- Add `spacing` dimension of length 2 for `pixel_spacing`.
- Create variables of type `NC_DOUBLE` for pixel spacing, slice thickness, image position, and image orientation.

These variables are read-only. `NC_DICOM_get_vara()` returns the corresponding slice of the parsed arrays stored in `NC_DICOM_FILE_INFO_T`.

### 3. Robustness and edge cases

- Handle missing `NumberOfFrames` as `1`.
- Handle missing `SamplesPerPixel` as `1`.
- Handle missing `PlanarConfiguration` as `0` for RGB images.
- Ensure graceful failure when `libdicom` returns `NULL` metadata or frame data.
- If a functional group is missing, omit the corresponding variable rather than failing.

## Implementation Details

### Functional-group data structures

Extend `NC_DICOM_FILE_INFO_T`:

```c
typedef struct NC_DICOM_FILE_INFO {
    DcmFilehandle *filehandle;
    char *path;
    int transfer_syntax;
    int nframes;
    size_t rows;
    size_t columns;
    int samples_per_pixel;
    int bits_allocated;
    int pixel_representation;
    int planar_configuration;
    int encapsulated;

    /* Functional group arrays, allocated when present */
    double *image_position;     /* [nframes][3] */
    double *image_orientation;  /* [nframes][6] */
    double *pixel_spacing;      /* [nframes][2] */
    double *slice_thickness;    /* [nframes] */
} NC_DICOM_FILE_INFO_T;
```

Populate these arrays during `NC_DICOM_open()` by walking the Shared and Per-frame Functional Group Sequences. Free in `NC_DICOM_close()`.

### Variable dispatch in `NC_DICOM_get_vara()`

- `pixel_data` → pixel read path.
- `image_position_patient`, `image_orientation_patient`, `pixel_spacing`, `slice_thickness` → copy from the pre-parsed arrays.
- Any other variable name → `NC_ENOTVAR`.

## Acceptance Criteria

- Functional-group metadata variables are created for multi-frame enhanced DICOM files when present.
- Shared values are exposed as scalar global attributes or constant variables.
- Per-frame values are exposed as variables over the `frame` dimension.
- All DICOM tests pass with DICOM enabled, and existing tests continue to pass with DICOM disabled.
- Unsupported Transfer Syntaxes and malformed files fail cleanly.

---

## Testing

- Run `ctest -R dicom --output-on-failure` and the Autotools `make check` DICOM subset.
- Test a multi-frame enhanced DICOM sample that contains Shared and/or Per-frame Functional Groups. This sample is not currently in the repository; acquiring one is a prerequisite for this sprint.
- Run a full test suite with DICOM disabled to confirm no regressions.

---

## Build System Integration

No new build-system files are required. Existing `HAVE_DICOM` conditionals in `src/CMakeLists.txt`, `src/Makefile.am`, `include/Makefile.am`, and the top-level CMake/Autotools logic already include the DICOM handler.

## Definition of Done

The DICOM reader exposes shared and per-frame functional-group metadata for enhanced multi-frame objects, and the full test suite passes with DICOM enabled while remaining regression-free with DICOM disabled.
