# V4.3.0 Sprint 1C: Refine Performance Graphs

Source: docs/roadmap.md, "V4.3.0 / Sprint 1C".

## Goal

The bfloat16 benchmark results in the docs come from an optimized
(`-O2`) build, and the build type is recorded with them. The main size
and speed charts compare only float32 with bfloat16 converted by NEP.
A separate chart shows how much slower HDF5's conversion is. NEP ships
a bfloat16 copy of the GDAS sample,
`test/data/NEXTCDF4/gdas_sfc_sample_bfloat16.nc`, which is generated once
and committed. A new benchmark uses it to compare writing and reading
float32 data with writing and reading the same data already held as
bfloat16, with no conversion timed. Its chart is in `docs/float16.md`.

### 3. `examples/nextcdf4/make_bfloat16_sample.c`

Full Doxygen header (`@file`, `@brief`, a description, **Usage**,
`@author`), and a Doxygen block for every static function. It uses the
`ERR(e)` pattern (print `nc_strerror`, exit 2) and calls
`nep_set_log_level(-1)` first.

`make_bfloat16_sample <input.nc> <output.nc>`. With the wrong number of
arguments it prints usage and returns 2.

1. Open the input with `nc_open(in, NC_NOWRITE, …)` (the built-in
   backend). Create the output with `nc_create(out, NC_NEXTCDF4 | NC_CLOBBER, …)`.
2. Copy the global attributes in order, with
   `nc_inq_attname`/`nc_inq_att`/`nc_get_att`/`nc_put_att` and the same
   type and length. Then add the text global attribute `history` =
   `"Data fields converted from gdas_sfc_sample.nc to NC_BFLOAT16 with nc_get_var_bfloat16 (round to nearest, ties to even) by make_bfloat16_sample"`.
3. Define dims `grid_xt` = 1536, `grid_yt` = 768 and `time` = 1 (fixed),
   in that order, with lengths taken from the input.
4. For every input variable, in input order: if its type is
   `NC_DOUBLE`, define it as `NC_DOUBLE` (coordinates). If it is
   `NC_FLOAT`, define it as `NC_BFLOAT16` and call
   `nc_def_var_fill(…, NC_NOFILL, NULL)`. Any other type is an error
   (print it and return 1). Map dims by name. Copy every variable
   attribute as in step 2, except `_FillValue` and `missing_value`.
   Leave storage contiguous.
5. `nc_enddef`. For `NC_DOUBLE` variables, `nc_get_var_double` then
   `nc_put_var_double`. For the bfloat16 variables, read with
   `nc_get_var_bfloat16(in, …)` into a `uint16_t` buffer passed as
   `(nc_bfloat16_t *)(void *)`, then write with
   `nc_put_var_bfloat16(out, …)`. `NC_ERANGE` from the get is an error:
   print it and return 1, because GDAS has no out-of-range values.
6. Close both files and print `Wrote <out>`.

### 5. `examples/nextcdf4/bfloat16_io_perf.c`

Header in the style of `bfloat16_perf.c`: `@file`, `@brief`, the
description, CSV columns, timing definitions, the typical workflow, the
Learning Objectives, Key Concepts ("data already in bfloat16, no
conversion"), Related Examples (`bfloat16_perf.c`, `bfloat16.c`), the
`@note` from item 1, and `@author`. It includes `bfloat16_conv.h`.

`bfloat16_io_perf <gdas_sfc_sample.nc> <gdas_sfc_sample_bfloat16.nc> <results.csv>`.
With the wrong number of arguments it prints usage and returns 2. It
calls `nep_set_log_level(-1)`, then the item 1 warning.

Constants are the same as `bfloat16_perf.c` (`NFIELDS`, `FIELDS`
order `tmp2m, prate_ave, soilw1, land`, `NY`, `NX`, `NVALS`,
`NREPS 3`), with `TMP_FILE "bfloat16_io_perf_tmp.nc"`.

For each field:
1. Read `fdata` with `nc_get_var_float` from the float sample (built-in
   backend). Read `bdata` (`uint16_t`) with `nc_open(NC_NEXTCDF4 | NC_NOWRITE)`
   and `nc_get_var_bfloat16` from the bfloat16 sample.
2. Gate: for every i, `bdata[i] == float_to_bfloat16(fdata[i])`, fill
   points included. On a mismatch, print
   `<field>: bfloat16 sample does not match float_to_bfloat16 of the float sample at <i>`
   and return 1.
3. Run four configurations in this order: (float, contiguous),
   (bfloat16, contiguous), (float, deflate1), (bfloat16, deflate1). Use
   `static int run_config(const char *field, const void *data, int is_bf16, int deflate, row_t *row, void *rbuf)`.
   The file layout is the same as `bfloat16_perf.c`: fixed dims `time`
   = 1, `grid_yt`, `grid_xt`, one variable, and for deflate1
   `nc_def_var_chunking` 1x768x1536 with
   `nc_def_var_deflate(…, 1, 1, 1)`. bfloat16 variables also get
   `nc_def_var_fill(…, NC_NOFILL, NULL)`; float variables keep the
   default.
   - **Write time**: from `nc_create(NC_NEXTCDF4 | NC_CLOBBER)` through
     `nc_close`, with `nc_put_vara_float(fdata)` or
     `nc_put_vara_bfloat16(bdata)`.
   - **Read time**: from `nc_open(NC_NEXTCDF4 | NC_NOWRITE)` through
     `nc_close`, with `nc_get_vara_float` or `nc_get_vara_bfloat16` into
     `rbuf`.
   - No conversion in either timed region. Use
     `clock_gettime(CLOCK_MONOTONIC)`. Keep the minimum of `NREPS` runs.
     File bytes come from the last repetition.
   - Every repetition checks `memcmp(data, rbuf, NVALS * (is_bf16 ? 2 : 4))`.
     On a mismatch it prints an error and returns 1.
4. CSV header (exact):
   `field,type,storage,uncompressed_bytes,file_bytes,ratio_vs_float,write_s,read_s,write_speedup,read_speedup`.
   - `type` is `float` or `bfloat16`, and `storage` is `contiguous` or
     `deflate1`.
   - `uncompressed_bytes` is `NVALS * 4` or `NVALS * 2`.
   - `ratio_vs_float` is the (float, same storage) `file_bytes` divided
     by this row's.
   - `write_speedup` and `read_speedup` are the (float, same storage)
     time divided by this row's time. They are `1.000` for float rows.
   - Format: `%s,%s,%s,%zu,%lld,%.3f,%.6f,%.6f,%.3f,%.3f`.
   - Each row is also printed to stdout.
5. Gate: return 1 if any (bfloat16, contiguous) `file_bytes` is not
   smaller than the (float, contiguous) one. Speed is not gated.
   `remove(TMP_FILE)` at the end, and free all buffers.

### 11. Fix #382: contiguous variables made chunked with deflate 0

Added 2026-11-08, after the first benchmark run. Evidence (`/tmp/bf16exp`):
`h5dump -p` of a "contiguous" bfloat16 variable defined with
`nc_def_var_fill(NC_NOFILL)` shows `CHUNKED (1, 768, 1536)`,
`DEFLATE { LEVEL 0 }` and `H5D_ALLOC_TIME_INCR`. Without the call it is
`CONTIGUOUS` with no filters. Contiguous bfloat16 I/O measured 3.7 ms
to write and 2.0 ms to read with the bug, against 1.6 ms and 0.7 ms
without it.

- `src/nextcdf4/nxt4meta.c`:
  - In `NEXTCDF4_def_var`, right after `vinfo` is allocated with
    `calloc` (around line 956), add `vinfo->deflate_level = -1;`.

    `var->format_var_info = vinfo;` around line 2601), add
    `vinfo->deflate_level = -1;` before the filter scan (lines
    2670-2690) runs. A deflate filter found on open still sets the
    level.

    applied". All the readers (lines 1162, 1202, 1506, 1580, 1613)
    already test `>= 0`.

    alone is not enough. `var->storage` is calloc'd to 0, which is
    `NC_CHUNKED`, so `create_var_dataset` still chunked every variable
