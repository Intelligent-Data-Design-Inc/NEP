# v3.5.0 Sprint 4: ABI Example

## Sprint Goal and Scope

Add a standalone Python example under `examples/abi/` that opens a GOES-R
Advanced Baseline Imager (ABI) Level 2 Cloud and Moisture Imagery (CMIP)
NetCDF and plots a single-channel image on its native geostationary
projection. The sprint mirrors the `examples/nisar/` and `examples/swot/`
structures and produces a companion paper, `docs/netCDF_with_ABI_CMIP.md`, that
explains how ABI CMIP products map to netCDF-4. The example does not touch
NEP's C library, `include/nep.h`, or the UDF dispatch framework, and is
not wired into CMake, CTest, or CI.

**In scope:**

- `examples/abi/abi_example/` Python package with:
  - `reader.py` — open an ABI CMIP NetCDF, load `CMI`, apply any `DQF`
    mask, and attach 1-D `x` and `y` radian-angle coordinates plus the
    `goes_imager_projection` grid-mapping metadata.
  - `plots.py` — `cartopy`/`matplotlib` helpers for plotting `CMI` on a
    geostationary projection with coastlines and a colorbar, plus a
    full-disk or regional overview map.
  - `fetch.py` — optional download of a GOES-R ABI CMIP granule from the
    NOAA AWS Open Data registry (`s3://noaa-goes16/ABI-L2-CMIPM1/...`) for
    a user-specified date, satellite, channel, and region.
  - `cli.py` — command-line entry point (`python -m abi_example`).
- `examples/abi/requirements.txt` listing `xarray`, `netCDF4`,
  `matplotlib`, `cartopy`, `boto3` (or `s3fs`), and optionally
  `earthaccess` if a uniform credential path is desired.
- `examples/abi/README.md` documenting setup, usage, the plotted
  variable, and AWS/no-credential access; it embeds the committed example
  PNG(s).
- Committed example output PNG(s) under `examples/abi/figures/` (e.g.
  `cmi_map.png` and `full_disk_preview.png`).
- `docs/netCDF_with_ABI_CMIP.md` companion paper mirroring
  `docs/netCDF_with_NISAR.md` and `docs/netCDF_with_SWOT.md`: explain the
  ABI instrument, the GOES-R spacecraft and orbit, the CMIP product
  layout, the netCDF-4 view (`ncdump -h -s`), the geostationary
  projection metadata, and reference the example code.
- Top-level `README.md` and `examples/README.md` updates pointing to the
  new example.

**Out of scope:**

- Any change to `src/`, `include/`, NEP's UDF dispatch/format-reader code,
  or NEP's public API.
- CMake/CTest/CI integration (the example is pure Python, run directly
  from a virtual environment).
- Coverage of non-GOES ABI platforms (EUMETSAT/MTG FCI, KMA GEO-KOMPSAT
  AMI, JAXA Himawari AHI). The example targets the NOAA GOES-R series,
  but `docs/netCDF_with_ABI_CMIP.md` should note that ABI-like imagers fly on
  those platforms.

## Major Tasks (dependency order)

1. Create the `examples/abi/` directory structure.
2. Implement `abi_example/reader.py`:
   - Open an ABI CMIP NetCDF with `xarray`/`netCDF4`.
   - Load the `CMI` variable (channel reflectance/brightness temperature).
   - Mask invalid/fill pixels and `DQF > 0` pixels when `DQF` is present.
   - Attach the 1-D `x` and `y` coordinate variables (radians from the
     geostationary sub-satellite point) and the `goes_imager_projection`
     `grid_mapping` variable attributes.
3. Implement `abi_example/fetch.py`:
   - Build an ABI-L2-CMIP object key from user inputs: satellite
     (`GOES-16`, `GOES-17`, `GOES-18`, `GOES-19` or `east`/`west`
     aliases), region (`M1` full disk, `C` CONUS, `F` mesoscale), ABI
     channel (`01`–`16`), and date/time.
   - Download the matching granule from the public NOAA AWS S3 bucket
     (`s3://noaa-goes16/ABI-L2-CMIPM1/` etc.) using `boto3` or `s3fs`.
   - Fall back to direct HTTPS from `https://noaa-goes16.s3.amazonaws.com/`
     for simplicity if `boto3`/AWS credentials are not configured.
   - Cache the downloaded file in `data/` (untracked) and skip re-download
     if the file is already present.
4. Implement `abi_example/plots.py`:
   - `plot_cmi_map()` — pcolormesh or imshow of `CMI` on the native
     geostationary projection (`ccrs.Geostationary`), with coastlines,
     grid lines, and a colorbar. Use a channel-appropriate colormap and
     units from the file attributes.
   - `plot_overview()` — full-disk/regional overview showing the chosen
     sector on a global or regional map with coastlines.
5. Implement `abi_example/cli.py`:
   - Mutually exclusive positional `FILE` path or fetch mode flags
     (`--date`, `--satellite`, `--channel`, `--region`).
   - `--output-dir` flag (default `output/`, untracked).
   - `--show` flag for interactive display.
6. Generate the example output PNG(s) from a local sample file or from a
   fetched granule, and commit them under `examples/abi/figures/`.
7. Write `examples/abi/README.md` with setup instructions, usage examples,
   AWS/no-credential notes, and embedded output figure(s).
8. Write `docs/netCDF_with_ABI_CMIP.md`:
   - Introduce the GOES-R ABI mission, spacecraft, and orbit.
   - Introduce the CMIP product family (`ABI-L2-CMIPM1`, `ABI-L2-CMIPC`,
     `ABI-L2-CMIPF`).
   - Show the netCDF-4 view (`ncdump -h -s`) of a sample CMIP file.
   - Explain how `CMI`, `DQF`, `x`, `y`, and
     `goes_imager_projection` map to the NetCDF data model and how to
     convert `x`/`y` radians to geodetic latitude/longitude using the
     projection metadata.
   - Include Python and C code snippets that read the same data.
9. Update `examples/README.md` and the top-level `README.md` to reference
   `examples/abi/README.md`.
10. Manually verify the example end-to-end from the command line.

## Acceptance Criteria

- `examples/abi/` exists with a working, standalone Python CLI that:
  - Opens a user-provided ABI CMIP `.nc` file and produces a `CMI` map
    PNG.
  - Supports `--output-dir`, `--show`, and fetch-mode flags that download
    a granule from the NOAA GOES AWS Open Data registry.
- `examples/abi/requirements.txt` lists all needed dependencies and
  `pip install -r examples/abi/requirements.txt` succeeds.
- `examples/abi/README.md` documents setup/usage and embeds a committed
  example output image.
- `docs/netCDF_with_ABI_CMIP.md` is present, mirrors the depth and style of
  `docs/netCDF_with_NISAR.md` and `docs/netCDF_with_SWOT.md`, and
  accurately describes the chosen ABI CMIP product's netCDF-4 mapping.
- Top-level `README.md` and `examples/README.md` reference the new ABI
  example.
- No files under `src/`, `include/`, `test/`, `.github/workflows/`, or
  CMake files are modified.

## Testing Requirements

- Manual verification only (no CTest/CI integration this sprint):
  - Run `python examples/abi/<entry_point>.py /path/to/sample.nc` and
    confirm PNG output is produced.
  - Run with `--show` to confirm interactive display works.
  - Run with `--date ... --satellite ... --channel ... --region ...` to
    confirm the fetch path reaches AWS and downloads a granule; document
    the result or mark it as network-dependent.
- No new automated regression tests are added; this is an example, not a
  library feature.

## Build System Integration

None. The example is pure Python, run directly with a virtual
environment; it is intentionally **not** added to
`examples/CMakeLists.txt` or any CTest registration, matching the NISAR
and SWOT examples.

## Dependencies and Blockers

- A local ABI CMIP sample NetCDF, or network access to fetch one from the
  NOAA GOES AWS Open Data registry, is required for generating the
  committed example PNG(s) and for manual verification.
- The fetch path does not require Earthdata credentials, but it does
  require outbound HTTPS access to AWS S3 (`noaa-goes16.s3.amazonaws.com`
  etc.). `boto3` or `s3fs` must be available for the S3 path.
- Python dependencies: `xarray`, `netCDF4`, `matplotlib`, `cartopy`, and
  `boto3`/`s3fs`.

## Documentation Updates Required
