# v3.2.0 Sprint 1: Organize Visualization Examples

## Goal

Reorganize `examples/viz/` by scientific format while preserving the existing visualization behavior, artifact names, test names, UDF runtime environment, and CMake-only build support.

## Scope

Move format-specific visualization scripts into source directories named `CDF`, `DICOM`, `FITS`, `GeoTIFF`, `GRIB2`, and `PDS4`. The CMake build tree mirrors this layout. Shared infrastructure remains in `examples/viz/`, including `plot_common.py`, `test_plot_common.py`, `test_udf_open.py`, `verify_viz_artifacts.py`, the root `CMakeLists.txt`, and the root README.

DICOM's private `_dicom_udf.py` moves with the DICOM plotting scripts. Each relocated script must import root-level shared utilities reliably when run from its matching build-tree format directory.

Generated PNG and metadata artifacts remain in the existing flat visualization build directory. Artifact basenames, validation rules, CTest names, fixture behavior, and the `verify_viz_artifacts.py` command-line interface remain unchanged.

## Implementation Plan

1. Create the six format subdirectories and relocate every format-specific plotting script into its corresponding directory.
2. Update `examples/viz/CMakeLists.txt` to copy each source file to its matching build-tree directory, invoke each script from that location, and retain the current CTest names, UDF guards, artifact list, test working directory, fixtures, environment, and data-copy behavior.
3. Update imports and any path handling so scripts in format subdirectories can access root-level `plot_common.py`; DICOM scripts must also access their colocated `_dicom_udf.py`.
4. Retain the flat visualization artifact directory and validate the unchanged artifact basename list with the existing verifier.
5. Update the root visualization README with the new source/build directory layout, revised manual invocation paths, and a grouped script inventory. Do not add per-format README files.
6. Add or update regression coverage as needed to verify that CMake copies the scripts into the mirrored directories and that the existing visualization tests continue to execute successfully.

## Acceptance Criteria

- `examples/viz/` contains `CDF`, `DICOM`, `FITS`, `GeoTIFF`, `GRIB2`, and `PDS4` directories containing their respective format-specific scripts.
- Root `examples/viz/` retains only shared visualization utilities, tests, the verifier, root CMake configuration, and root README.
- The CMake build tree mirrors each format directory, and all CTest commands use the matching copied script paths.
- Each enabled format's visualization tests retain their existing names, UDF prerequisites, runtime environment, copied test-data behavior, fixtures, and expected artifact basenames.
- All PNG and `_metadata.txt` outputs continue to be generated in the existing flat visualization build directory and pass `verify_viz_artifacts.py` without interface changes.
- DICOM scripts can import both `_dicom_udf.py` from `DICOM/` and root-level `plot_common.py`; all other scripts can import root-level shared utilities.
- The root visualization README describes the organized layout and working manual commands.
- No visualization artifact content, file basenames, reader behavior, public CMake options, or test data changes solely because of the reorganization.

## Testing

- Configure with `NEP_BUILD_EXAMPLES=ON`, `NEP_ENABLE_VIZ_EXAMPLES=ON`, and every available UDF reader enabled.
- Run `ctest --test-dir build -R viz --output-on-failure`.
- Run each enabled format visualization test individually to confirm imports and mirrored build-tree paths.
- Run `verify_viz_artifacts.py` using the existing flat build-tree artifact directory and complete expected artifact basename list.
- Inspect the build tree to verify that all format-specific scripts reside under matching format directories and shared utilities remain at its visualization root.
- Run a normal non-visualization CTest configuration to confirm that disabled visualization support remains unaffected.

## Build System Integration

- `examples/viz/CMakeLists.txt`
- `examples/viz/README.md`
- Python imports and path handling in relocated visualization scripts

CMake is the sole supported build system. No new dependency, CMake option, UDF registration behavior, or install rule is required.

## Dependencies and Blockers

- Requires existing CMake visualization support and the source-root Python virtual environment with source-built `netCDF4`, Matplotlib, and NumPy.
- Full all-format validation requires the optional reader dependencies and test data already used by the existing visualization suite.
- No dependency on v3.2.0 Sprint 2 DICOM reader expansion; this sprint preserves current reader capabilities.

## Documentation Updates

Update only `examples/viz/README.md` to document the reorganized source/build layout and manual invocation paths. Existing generated-artifact requirements remain unchanged.

## Definition of Done

All format-specific visualization scripts are organized in mirrored source and build-tree directories, shared infrastructure remains at the visualization root, existing artifacts and CTest behavior are preserved, the root README is accurate, and the visualization suite passes for each enabled reader without regressions.
