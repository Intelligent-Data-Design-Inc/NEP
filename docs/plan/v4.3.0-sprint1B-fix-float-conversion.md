# V4.3.0 Sprint 1B: Fix Issue of Float Conversion

Source: docs/roadmap.md, "V4.3.0 / Sprint 1B".

## Goal

Typed I/O calls on NEXTCDF-4 small floating-point variables have a
defined, tested and documented behavior. On `NC_FLOAT16` and
`NC_BFLOAT16` variables the `float` and `double` typed calls
(`nc_put_vara_float`, `nc_get_var_double`, and so on) convert through
HDF5: reads are exact, and writes follow HDF5's measured rounding.
Every other typed call on a small-float variable fails with
`NC_EBADTYPE` (or `NC_ECHAR` for text) instead of silently producing
wrong data, and that includes all typed calls on the FP8/FP6/FP4 types,
whose HDF5 2.1.1 conversions are wrong. The Sprint 1A docs, which say
typed calls are a no-op, are corrected. The bfloat16 tutorial
cross-checks a typed read, the benchmark adds an HDF5-conversion
configuration with regenerated reference results, and issue #376 is
closed with an explanation. `libnep` gains a NetCDF-style family of
bfloat16 I/O functions (`nc_get_vara_bfloat16`, `nc_put_vara_bfloat16`
and the `var`, `var1` and `vars` forms) that exchange bfloat16 data in
memory. They pass raw bits through for `NC_BFLOAT16` variables and
convert to and from `NC_FLOAT` and `NC_DOUBLE` variables in NEP, with
round-to-nearest-even and `NC_ERANGE` on overflow. The bfloat16 examples
use these functions, and the benchmarks and plots are regenerated.

### 2. Memtype check in `src/nextcdf4/nxt4io.c`

Add, above `var_io()`:

```c
/*
 * Return non-zero if xtype is one of the NEXTCDF-4 small floating-point types.
 */
static int
is_small_float(nc_type xtype)
{
    switch (xtype) {
    case NC_FLOAT16: case NC_BFLOAT16:
    case NC_FLOAT8_E4M3: case NC_FLOAT8_E5M2:
    case NC_FLOAT6_E2M3: case NC_FLOAT6_E3M2: case NC_FLOAT4_E2M1:
        return 1;
    default:
        return 0;
    }
}

/*
 * Check that memtype may be used for I/O on a variable of type xtype.
 * NC_FLOAT16 and NC_BFLOAT16 convert to and from NC_FLOAT and NC_DOUBLE
 * through HDF5; the FP8/FP6/FP4 types allow only their own type, because
 * HDF5 2.1.1 converts them incorrectly. Other variable types are unchanged.
 */
static int
check_memtype(nc_type xtype, nc_type memtype)
{
    if (memtype == xtype || memtype == NC_NAT)
        return NC_NOERR;
    if (!is_small_float(xtype) && !is_small_float(memtype))
        return NC_NOERR;
    if (memtype == NC_CHAR)
        return NC_ECHAR;
    if ((xtype == NC_FLOAT16 || xtype == NC_BFLOAT16) &&
        (memtype == NC_FLOAT || memtype == NC_DOUBLE))
        return NC_NOERR;
    return NC_EBADTYPE;
}
```

In `var_io()`, right after `if (!data) return NC_EINVAL;` (line 124) and
before `memory_type()`, add:

```c
    if ((ret = check_memtype((nc_type)var->type_info->hdr.id, memtype))) return ret;
```

Tricky cases:

- The check runs before any HDF5 call, so a rejected read leaves the
  buffer untouched and a rejected write leaves the dataset untouched.
- It runs after the define-mode and permission checks, so a typed call in
  define mode still returns `NC_EINDEFINE` and a typed write on a
  read-only file still returns `NC_EPERM`. The test checks one of these.
- `memtype == NC_NAT` is resolved to the variable's type before
  `check_memtype`:
  `if (memtype == NC_NAT) memtype = (nc_type)var->type_info->hdr.id;`.
  (Correction found during implementation: NetCDF-C does pass `NC_NAT`
  from the untyped `nc_put_var`/`nc_get_var`, `nc_*_var1` and
  `nc_*_vars` calls (`dvarget.c:896`, `1040`, `1178`). Before this
  change, `memory_type(NC_NAT)` returned -1, so those calls failed with
  `NC_EBADTYPE` on every NEXTCDF-4 variable.)
- A `NC_CHAR` variable read with a small-float memtype is not reachable
  from the public API. It falls under the `NC_ECHAR` line, which is
  correct.
- Do not change `memory_type()` or the quantize path. Quantization on
  small-float variables is not covered by this sprint (see Out of

Reference decoders, for the test only:

- `static uint32_t bf16_to_f32_bits(uint16_t b) { return (uint32_t)b << 16; }`
- `static double f16_decode(uint16_t h)`. Let s = bit 15, e = bits 10-14
  and m = bits 0-9. If e == 0, the value is `ldexp(m, -24)`. If e == 31,
  it is `m ? NAN : INFINITY`. Otherwise it is `ldexp(1024 + m, e - 25)`.
  The sign is applied with `s ? -v : v`, so `-0.0` comes out for
  `0x8000`.
- `static int f16_is_nan(uint16_t h)` is
  `(h & 0x7c00) == 0x7c00 && (h & 0x03ff)`, and
  `static int bf16_is_nan(uint16_t b)` is
  `(b & 0x7f80) == 0x7f80 && (b & 0x007f)`.

### 10. bfloat16 I/O functions: `src/nep_bfloat16.c`

New file, `@file` and `@author` as in `src/nep.c`. Add it to
`add_library(nep SHARED nep.c nep_bfloat16.c)` in `src/CMakeLists.txt`.
Use no libm functions (`libnep` doesn't link `m`).

Internal helpers (`static`, with Doxygen comments):

```c
/* float -> bfloat16 bits, ties to even. Sets *range when a finite
 * input becomes +-inf. NaN stays a quiet NaN, as bfloat16_conv.h. */
static uint16_t
f32_to_bf16(float f, int *range)
{
    uint32_t u, mag;
    uint16_t b;

    memcpy(&u, &f, sizeof(u));
    mag = u & 0x7fffffffu;
    if (mag > 0x7f800000u)
        return (uint16_t)((u >> 16) | 0x0040u);
    b = (uint16_t)((u + 0x7fffu + ((u >> 16) & 1u)) >> 16);
    if ((b & 0x7fffu) == 0x7f80u && mag != 0x7f800000u)
        *range = 1;
    return b;
}

/* double -> bfloat16 bits with one rounding: round to float with
 * round-to-odd (inexact results get an odd last bit), then
 * f32_to_bf16. float has 16 more significand bits than bfloat16, so
 * this equals rounding the double directly. */
static uint16_t
f64_to_bf16(double d, int *range)
{
    float f = (float)d;
    uint32_t u;

    if (d == d && f - f != 0.0f && d - d == 0.0) {   /* finite d, inf f */
        *range = 1;
        return d < 0 ? 0xff80u : 0x7f80u;
    }
    if (d == d && (double)f != d) {
        double ad = d < 0 ? -d : d, af = f < 0 ? -f : f;
        memcpy(&u, &f, sizeof(u));
        if (!(u & 1u))
            u = af < ad ? u + 1u : u - 1u;
        memcpy(&f, &u, sizeof(f));
    }
    return f32_to_bf16(f, range);
}
```

bfloat16 to float is `(uint32_t)b << 16` through `memcpy`; to double,
widen that float. Buffers are always accessed as bytes or `uint16_t`
through `memcpy`, never as `__bf16` values, so the code is the same for
both `nc_bfloat16_t` forms.

One worker does all eight:

```c
static int
bf16_io(int ncid, int varid, const size_t *startp, const size_t *countp,
        const ptrdiff_t *stridep, void *buf, int put);
```

1. `nc_inq_vartype`, then `nc_inq_varndims`; return their errors.
2. `NC_CHAR` returns `NC_ECHAR`. Anything other than `NC_BFLOAT16`,
   `NC_FLOAT` or `NC_DOUBLE` returns `NC_EBADTYPE`. These checks come
   first, so a rejected call touches neither the buffer nor the file.
3. `NC_BFLOAT16`: return `put ? nc_put_vars(...) : nc_get_vars(...)`
   with the same arguments. (On NEXTCDF-4 this relies on the `NC_NAT`
   fix in item 2.)
4. If `ndims > 0` and `startp` or `countp` is NULL, return `NC_EINVAL`.
   `n` is the product of `countp[0..ndims-1]` (1 for a scalar). If
   `n > 0` and `buf` is NULL, return `NC_EINVAL`.
5. `malloc(max(n, 1) * (xtype == NC_FLOAT ? 4 : 8))`, or `NC_ENOMEM`.
6. Get: `nc_get_vars_float`/`nc_get_vars_double` into the temporary;
   on error free and return it. Convert every value; return
   `NC_ERANGE` if any set `range`, else `NC_NOERR`.
   Put: widen every value into the temporary, then
   `nc_put_vars_float`/`nc_put_vars_double` and return its result.
7. Free the temporary on every path.

The public functions:

- `vars`: `bf16_io` as is. `vara`: `stridep = NULL`.
- `var1`: `count` is all ones for `ndims` (`NC_MAX_VAR_DIMS` array);
  `indexp == NULL` means all zeros.
- `var`: `start` all zeros, `count` from `nc_inq_vardimid` and
  `nc_inq_dimlen` (current length for unlimited dims).
- Arrays sized `NC_MAX_VAR_DIMS`; return `NC_EINVAL` if `ndims` exceeds
  it.

Tricky cases:

- NaN inputs: not a range error; float NaN keeps its sign and top
  payload bits. NaN bfloat16 written to a float variable keeps its
  payload (`b << 16`).
- `-0.0` stays `0x8000`; float `1e-30` becomes `0x0da2`; subnormal ties
  round to even (`0x00008000` becomes `0x0000`).
- Double rounding: `1 + 2^-8 + 2^-30` must give `0x3f81` (a plain
  `(float)` cast would give the tie `1 + 2^-8` and then `0x3f80`), and
  `1 + 2^-8 - 2^-30` must give `0x3f80`.
- `FLT_MAX` and any finite double ≥ the bfloat16 overflow threshold
  give ±inf with `NC_ERANGE`; `±INFINITY` gives ±inf with `NC_NOERR`.
- `n == 0` (a zero count) still calls the netCDF function, so its
  argument checks run.
