# v4.2.0 Sprint 2: Local Implementation Status

The separate `/fast/ed/nep-compress/` repository now has standalone CMake
targets for `libnepcompress`, `libnepcompressf`, and `libh5lz4.so`; a
`nep_compress.mod` module; an external BZIP2 filter 307 preflight; and
individual CTest registration for the migrated C, HDF5 and Fortran tests.
NEP's source and build definitions were not changed in this sprint.

## Verified locally (2026-10-17)

- Both filters with Fortran ON: 13/13 CTest tests passed using NetCDF-C
  4.10.2-development, NetCDF-Fortran 4.6.2, and HDF5 2.1.1. These include
  LZ4 read/write using the new and installed reference plugins in separate
  processes, BZIP2 read/write with the external plugin, and missing-plugin
  API errors. Tests set `NCRCENV_RC` to an absent file to prevent the user's
  unrelated NEP UDF autoload configuration from masking failures.
- LZ4 only with Fortran OFF: 7/7 tests passed. BZIP2 only with Fortran ON:
  5/5 tests passed. These reconfigured the same local build; a clean
  per-matrix CI build is still due in Sprint 3.
- BZIP2 enabled with an existing but empty plugin directory fails CMake's
  encode/decode preflight. The private staged install contains the header,
  libraries, plugin, Fortran module, and CMake package exports. A C and
  Fortran consumer compile against the staged artifacts; `ldd` on the new
  library resolves the pinned NetCDF-C and HDF5 2.1.1 libraries.

## Open gates

- The old NEP `build` tree was incomplete (zero CTest tests and a stale
  HDF5 1.14.6 configuration); it was not deleted without approval.
  Old-NEP/new-project interchange tests were not run and are no longer
  required. nep-compress's independent LZ4/BZIP2 round trips passed.
- The copied `H5Zlz4.c` came from NEP's `hdf5_plugins/LZ4/src/` without
  alteration. The corresponding upstream plugin CMake notice references a
  `COPYING` file not in NEP; source provenance and redistribution terms
  require confirmation before distribution. The installed external BZIP2
  binary also lacks established provenance for a reproducible CI source;
  no binary was copied into nep-compress.
- Standalone GitHub CI and complete migrated user documentation were
  Sprint 3 tasks; NEP cleanup remains Sprint 4. Old-NEP file interchange
  is not a prerequisite for removal.
