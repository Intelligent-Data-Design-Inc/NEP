# v2.7.0 Sprint 5: Visualization Documentation, CI, and Polish

## Sprint Goal

Complete the Python visualization examples by documenting their supported workflows, adding end-to-end CI coverage for every enabled NEP UDF reader, and enforcing the publication-output contract for all generated PNG and metadata artifacts.

This is Sprint 5 in the v2.7.0 release. It implements the documentation, CI, and polish work identified as Sprint 6 in `docs/viz_plan.md`.

## Scope

The existing `examples/viz/` scripts open FITS, CDF, GeoTIFF, GRIB2, and PDS4 files through `netCDF4.Dataset`, use the NEP build-tree `.ncrc` configuration to autoload UDFs, and generate black-and-white PNGs with companion metadata files in the build tree. This sprint does not introduce new plots, new format-reader behavior, CSV intermediates, C extractors, or installed visualization artifacts.

The sprint includes:

- A `Visualization Examples` section in `docs/examples.md` covering capabilities, prerequisite virtual environment, source-built Python `netCDF4` requirement, build options, runtime `.ncrc` environment, supported input formats, generated output locations, and publication-output restrictions.
- A complete refresh of `examples/viz/README.md` so its CMake and Autotools instructions cover all currently supported visualization scripts and all enabled UDF readers.
- A concise visualization capability/configuration update in `docs/prd.md`, `docs/design.md`, and `docs/prfaq.md`, preserving the project requirement that existing NetCDF applications retain compatibility.
- A dedicated `.github/workflows/ci-viz.yml` workflow that builds Python `netCDF4` from source against the same NetCDF-C installation used by NEP, enables visualization examples and all supported UDF readers, runs the CMake and Autotools visualization test subsets, verifies output artifacts, and uploads them for inspection.
- One reusable Python artifact verifier that examines every expected visualization PNG and companion metadata file generated by the CI build. It must reject missing pairs, missing or reordered `title`, `caption`, and `alt_text` fields, empty values, captions over 75 words, oversized images, and non-grayscale RGB pixels.
- Module-level docstrings for every Python module in `examples/viz/`, including plotting helpers and test utilities.

## Implementation Plan

1. Inventory all Python modules and expected output basenames under `examples/viz/`. Define the complete expected artifact set conditionally by enabled reader: helper, FITS, CDF, GeoTIFF, GRIB2, and the four PDS4 mission examples.
2. Add `verify_viz_artifacts.py` to `examples/viz/`. It must accept the visualization output directory and the expected basenames, verify PNG/metadata pairs and the metadata contract, inspect PNG dimensions at 150 DPI limits (8.0 by 6.1 inches), and confirm RGB channels are equal within an explicit tolerance. It must report the failing basename and invariant clearly.
3. Register the verifier after the existing visualization scripts in both `examples/viz/CMakeLists.txt` and `examples/viz/Makefile.am`. Reuse the existing build-tree output directory and runtime environment, and ensure the expected-basename list matches only the readers enabled in each configuration.
4. Add module-level docstrings to `plot_common.py`, all plotting scripts, `test_plot_common.py`, `test_udf_open.py`, and the artifact verifier. Preserve existing runtime behavior and the companion-book attribution style.
5. Update `docs/examples.md` with an accurate `Visualization Examples` section. Document that the feature is optional, disabled by default, needs the source-root `.venv`, requires source-built `netCDF4` linked to NEP's NetCDF-C, uses build-tree `.ncrc` autoload, emits build-tree-only PNG/metadata artifacts, and enforces grayscale/no-in-figure-caption rules.
6. Update `examples/viz/README.md` with equivalent CMake and Autotools configuration, test, and manual invocation instructions for every supported format. Document `NCRCENV_RC`, `NETCDF_RC`, `LD_LIBRARY_PATH`, and the artifact verifier.
7. Update `docs/prd.md`, `docs/design.md`, and `docs/prfaq.md` with concise visualization capability, dependency, configuration, CI, and compatibility descriptions. Do not change the UDF API or reader semantics.
8. Create `.github/workflows/ci-viz.yml` as a dedicated two-entry CMake/Autotools matrix. It must provision all format-library prerequisites, build HDF5 and NetCDF-C, create a project-local `.venv`, install `requirements.txt` with `netCDF4` forced from source and linked against the workflow's NetCDF-C/HDF5 prefixes, configure NEP with `NEP_ENABLE_VIZ_EXAMPLES` / `--enable-viz-examples` and all reader options enabled, run only the visualization test subset, run the artifact verifier, and upload generated PNG and metadata files regardless of pass/fail.
9. Retain the visualization options as disabled by default. Confirm a build without visualization remains unaffected, and do not write generated artifacts to the source tree or install them.

## Acceptance Criteria

- `docs/examples.md` and `examples/viz/README.md` document all supported visualization formats, setup requirements, both build systems, runtime environment, output artifacts, and publication constraints.
- `docs/prd.md`, `docs/design.md`, and `docs/prfaq.md` accurately describe the optional visualization capability without changing existing API compatibility statements.
- Every Python module in `examples/viz/` has a module-level docstring.
- The artifact verifier validates every generated PNG/metadata pair and fails for missing files, invalid field order/content, captions over 75 words, oversized PNGs, and non-grayscale images.
- CMake and Autotools both invoke artifact verification after their conditional visualization test sets.
- `ci-viz.yml` builds `netCDF4` from source against the workflow's NetCDF-C; it does not use a bundled-libnetcdf wheel.
- The CI workflow runs the visualization test subset for both CMake and Autotools with all supported UDF readers enabled, then uploads PNG and metadata artifacts.
- All generated plots remain black and white, captions remain solely in `_metadata.txt`, artifacts remain in the build tree, and no CSV intermediates or extractor programs are added.
- Existing builds and tests with visualization disabled remain unchanged.

## Testing

- Run CMake and Autotools out-of-tree visualization configurations with all available format readers enabled and execute their visualization test subsets.
- Run the artifact verifier against successful output from both build systems.
- Add negative verifier coverage for a missing metadata file, malformed metadata order, a caption exceeding 75 words, an oversized image, and a non-grayscale image.
- Confirm every expected visualization basename has exactly one PNG and one `_metadata.txt` file.
- Confirm the CI virtual environment's `netCDF4` extension links against the NetCDF-C installation built by the workflow.
- Run normal CMake and Autotools configurations with visualization disabled to confirm no regression in default behavior.

## Build System Integration

- `examples/viz/CMakeLists.txt`: register conditional artifact verification after visualization scripts and pass the CMake build-tree output directory plus enabled expected basenames.
- `examples/viz/Makefile.am`: add the verifier to the Automake test sequence and construct the expected-basename arguments under the same `HAVE_*` conditionals used for the plotting scripts.
- `.github/workflows/ci-viz.yml`: create a dedicated CMake/Autotools visualization CI matrix; configure all enabled readers and provision the project-local virtual environment before configuring NEP.
- No new user-facing CMake or Autotools option is added; `NEP_ENABLE_VIZ_EXAMPLES` and `--enable-viz-examples` remain the entry points.
