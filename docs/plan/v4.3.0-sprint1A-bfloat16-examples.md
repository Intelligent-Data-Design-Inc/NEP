# V4.3.0 Sprint 1A: Add NEXTCDF4 float16 Examples and Documentation

Source: docs/roadmap.md, "V4.3.0 / Sprint 1A".

## Goal

NEP ships a C example that shows how to store real meteorological
data as `NC_BFLOAT16` in a NEXTCDF-4 file. It also ships a benchmark
that compares `NC_FLOAT` with `NC_BFLOAT16` on four GDAS surface
fields, writes file size, read/write speed and conversion error to a
CSV file, and confirms that every contiguous bfloat16 file is smaller
than its float file. A Python script plots that CSV. The GDAS sample is
committed under `test/data/netCDF-4/`. Reference results, plots and a
documentation section in `docs/nextcdf4.md` explain how to use bfloat16
and what its limits are.

### 3. `examples/nextcdf4/bfloat16_conv.h`

A header with Doxygen `@file`, `@brief` and
`@author Edward Hartnett, Intelligent Data Design, Inc.` and include
guard `BFLOAT16_CONV_H`. It includes `<stdint.h>` and `<string.h>`.
Both functions get full Doxygen blocks (`@param`, `@return`).

```c
/* Round-to-nearest-even float32 -> bfloat16 bit pattern. */
static inline uint16_t float_to_bfloat16(float f);
/* bfloat16 bit pattern -> float32 (exact). */
static inline float bfloat16_to_float(uint16_t b);
```

`float_to_bfloat16`: `memcpy` the float into a `uint32_t u`. If
`(u & 0x7fffffffu) > 0x7f800000u` (NaN), return
`(uint16_t)((u >> 16) | 0x0040u)`. Otherwise return
`(uint16_t)((u + 0x7fffu + ((u >> 16) & 1u)) >> 16)`. This overflows to
±Inf for values that round past the maximum, which is correct.
`bfloat16_to_float`: `uint32_t u = (uint32_t)b << 16;`, then `memcpy`
into a float.

Also in this header:
- `#define BF16_FILL_IN 9.99e+20f`, the GDAS input fill value;
- `#define BF16_REL_ERR_MAX 0.00390625`, which is 2^-8, the
  round-to-nearest bound for an 8-bit significand.

### 4. `examples/nextcdf4/bfloat16.c` (tutorial)

The file's Doxygen header follows `examples/performance/deflate.c`.
It has `@file` and `@brief`, a paragraph on bfloat16 (1 sign, 8
exponent and 7 mantissa bits; the same range as float32; about 2-3
significant decimal digits; half the storage), and these sections:
**Usage** (`./bfloat16 gdas_sfc_sample.nc`, with the `HDF5_PLUGIN_PATH`
and `NCRCENV_RC` needs), **Learning Objectives**, **Key Concepts**
(raw bit patterns, conversion in user code, native-mode only, no fill
value), **Key API functions** (`nc_create` with `NC_NEXTCDF4`,
`nc_def_var` with `NC_BFLOAT16`, `nc_put_vara`, `nc_get_vara`),
**Related Examples** (`bfloat16_perf.c`, `compression.c`), and
`@author Edward Hartnett, Intelligent Data Design, Inc.` Each static
function has a Doxygen block.

Behavior: `main(int argc, char **argv)`. It takes one argument, the
input path; anything else prints `usage: bfloat16 <gdas_sfc_sample.nc>`
and returns 2. Errors use the `deflate.c` `ERR(e)` pattern, which
prints `nc_strerror` and exits 2.

1. `nep_set_log_level(-1)`.
2. Open the input with `nc_open(path, NC_NOWRITE, &ncid)` (the built-in
   NetCDF-4 backend). Read `grid_yt` (768 doubles), `grid_xt` (1536
   doubles) and `tmp2m` (1x768x1536, `nc_get_var_float`). Read the
   `long_name` and `units` text attributes of `tmp2m` with
   `nc_inq_attlen` and `nc_get_att_text`. Close the file.
3. Call `write_file(const char *path, nc_type xtype, const void *data, …)`
   twice, writing `float_tmp2m.nc` (`NC_FLOAT`) and
   `bfloat16_tmp2m.nc` (`NC_BFLOAT16`) with
   `nc_create(path, NC_NEXTCDF4 | NC_CLOBBER, &ncid)`. Each file gets:
   - dims `time` = 1 (fixed, not unlimited, so storage stays
     contiguous), `grid_yt` = 768 and `grid_xt` = 1536;
   - the `NC_DOUBLE` coordinate variables `grid_yt` and `grid_xt`;
   - variable `tmp2m(time, grid_yt, grid_xt)` of type `xtype`, with
     `long_name` and `units` copied;
   - no fill value;
   - data written with `nc_put_vara(ncid, varid, start, count, data)`.

   The bfloat16 data is the input converted point by point with
   `float_to_bfloat16`. Write the float file with `nc_put_vara` as well,
   so the two calls are identical. Add a comment at the
   `nc_put_vara`/`nc_get_vara` calls saying that typed calls such as
   `nc_get_vara_float` must not be used on `NC_BFLOAT16` variables.
4. Reopen `bfloat16_tmp2m.nc` with `NC_NEXTCDF4 | NC_NOWRITE`.
   - Check that `nc_inq_vartype` gives `NC_BFLOAT16`.
   - Read it with `nc_get_vara` into a `uint16_t` buffer and check that
     it matches the written bits exactly.
   - Convert back to float. Over the points where the input is not
     `BF16_FILL_IN`, compute the maximum absolute error and the
     maximum relative error (relative only where the input is not 0).
5. `stat()` both files.
6. Print:

   ```
   tmp2m: 1179648 values
   float32  file: <n> bytes
   bfloat16 file: <n> bytes (<pct>% of float32)
   max abs error: <g> K
   max rel error: <g>
   ```

   (The unit comes from the `units` attribute.)
7. Return 1, with a message on stderr, if any of these hold: the bits
   do not match, the bfloat16 file is not smaller than the float
   file, or the maximum relative error is above `BF16_REL_ERR_MAX`.
   Otherwise return 0. Leave both output files in place for `ncdump`
   and `h5dump`.

### 5. `examples/nextcdf4/bfloat16_perf.c` (benchmark)

The header follows `deflate.c`. It lists the CSV columns, the timing
definitions and the typical workflow:

```sh
./bfloat16_perf gdas_sfc_sample.nc bfloat16_results.csv
python3 plot_bfloat16.py bfloat16_results.csv bfloat16
```

`main(int argc, char **argv)`. It takes exactly two arguments, the
input path and the output CSV path; otherwise it prints usage and
returns 2. It calls `nep_set_log_level(-1)` first.

Constants: `NFIELDS 4`, `FIELDS[] = {"tmp2m", "prate_ave", "soilw1", "land"}`,
`NY 768`, `NX 1536`, `NREPS 3`, `TMP_FILE "bfloat16_perf_tmp.nc"`,
chunk shape {1, 768, 1536} and deflate level 1.

For each field, in that order:

1. Read the field from the input (`nc_get_var_float`, built-in
   backend).
2. Run 4 configurations in this order: (float, contiguous),
   (bfloat16, contiguous), (float, deflate1), (bfloat16, deflate1).
   Each repeats `NREPS` times and keeps the minimum write and read
   times. File bytes come from the last repetition.
   - **Write time**: from just before conversion (bfloat16 only)
     through `nc_close`. It covers `nc_create(NC_NEXTCDF4|NC_CLOBBER)`,
     dims, var, `nc_def_var_chunking` + `nc_def_var_deflate(…, 1, 1, 1)`
     for deflate1, `nc_enddef`, `nc_put_vara` and `nc_close`. The file
     has only dims and the one variable, with no coordinate variables
     and no attributes.
   - **Read time**: from `nc_open(NC_NEXTCDF4|NC_NOWRITE)` through
     `nc_close`, plus the conversion back to float for bfloat16. Timing
     uses `clock_gettime(CLOCK_MONOTONIC)`.
   - Each repetition checks the bits read against the bits written
     (bit-exact for both types). A mismatch prints an error and makes
     the program return 1.
3. Append one CSV row per configuration.

CSV header (exact):

```
field,type,storage,uncompressed_bytes,file_bytes,ratio_vs_float,write_s,read_s,write_MBps,read_MBps,max_abs_err,max_rel_err
```

- `type` is `float` or `bfloat16`. `storage` is `contiguous` or
  `deflate1`.
- `uncompressed_bytes` is `NY*NX*sizeof(element)` (4718592 or
  2359296).
- `ratio_vs_float` is the field's (float, same storage) `file_bytes`
  divided by this row's `file_bytes` (1.000 for float rows).
- `write_MBps` and `read_MBps` are `NY*NX*4 / 1e6 / seconds`, using the
  float32 data volume for every row, so the speeds compare the same
  user data.
- `max_abs_err` and `max_rel_err` cover non-fill points only, as in
  the tutorial. They are 0 for float rows.
- Formats: `%s,%s,%s,%zu,%lld,%.3f,%.6f,%.6f,%.3f,%.3f,%.6g,%.6g`.

Gates:
- Return 1 if any (bfloat16, contiguous) `file_bytes` is not smaller
  than the matching (float, contiguous) `file_bytes`, or if any
  bfloat16 `max_rel_err` is above `BF16_REL_ERR_MAX`.
- Deflate rows are only reported, not checked for size.
- Remove `TMP_FILE` at the end.
- Also print each row to stdout, so ctest `--output-on-failure` shows
  it.
