# V4.3.0 Sprint 1: Fix Issues 372 and 374

Source: docs/roadmap.md, "V4.3.0 / Sprint 1".

## Goal

NEP's CMake build finds HDF5 1.x and 2.x correctly. It does not
silently pick up an unrelated HDF5 config package, and configure
fails if the HDF5 it found is not the one NetCDF-C links against
(#372). Every NEP target links HDF5 through the `hdf5::hdf5_hl` and
`HDF5::HDF5` imported targets that CMake's FindHDF5 creates, so
CMake config mode and FindHDF5 module mode produce the same link
lines. The Spack recipe keeps the `h5cc` workaround only for 4.2.0.
The in-repo conda recipe builds and tests the GeoTIFF reader (#374
part 1). Shipping 4.3.0 (tag, Spack version, conda-forge) happens in
Sprint 2.

## Decisions

| Topic | Decision |
| --- | --- |
| Release scope | Sprint 1 changes code, recipes and docs only. The v4.3.0 tag, release notes, Spack `4.3.0` version, the #5557 update and the conda-forge submission (#374 part 2) move to Sprint 2. (Ed: 1b) |
| HDF5 linking | Find HDF5 without a version in a new `cmake/NEPFindHDF5.cmake`. Every target links `${NEP_HDF5_LIBRARIES}` = `hdf5::hdf5_hl;HDF5::HDF5`. `cmake_minimum_required` goes up to 3.19, the first CMake whose FindHDF5 creates these targets. (Ed: 2b) |
| NetCDF-C/HDF5 consistency | Compare the `libhdf5.so.N` that `libnetcdf.so` needs (`readelf -d` NEEDED) with the SONAME of the HDF5 NEP found. Configure stops with `FATAL_ERROR` if they differ, and prints a STATUS line and skips the check if either can't be read. (Ed: 3a) |
| #372 regression test | Manual local verification with the commands in Verification. No new CTest test or CI job. (Ed: 4b) |
| Spack workaround | `HDF5_NO_FIND_PACKAGE_CONFIG_FILE` and `HDF5_C_COMPILER_EXECUTABLE` are only set for `@:4.2.0`. `main` is an infinity version in Spack, so it is outside `@:4.2.0` and CI's `nep@main` tests the fix. |
| Conda in Sprint 1 | Enable GeoTIFF in `conda/recipe/` now (the checkout already has the flat-header fix from `4d920c5`) and set `context.version` to `4.3.0.dev0`. `conda.yml`'s staged-copy lint step keeps the 4.2.0 tarball until Sprint 2. User-facing conda wording (README, `prd.md`, `prfaq.md`) changes in Sprint 2, when 4.3.0 is submitted. |
| Build system | CMake only. NEP has no Autotools build since v3.1.0. |

## Work items

### 1. New module `cmake/NEPFindHDF5.cmake`

Create the directory `cmake/` and the file `cmake/NEPFindHDF5.cmake`.
The header comment is `# Find HDF5 for NEP and check that NetCDF-C
uses the same HDF5.` followed by
`# Author: Edward Hartnett, Intelligent Data Design, Inc.`

At include time:

1. `find_package(HDF5 REQUIRED COMPONENTS C HL)`, with no version.
2. ```cmake
   if(NOT HDF5_VERSION OR HDF5_VERSION VERSION_LESS "1.14.0")
       message(FATAL_ERROR "NEP requires HDF5 1.14.0 or newer (found ${HDF5_VERSION})")
   endif()
   ```
3. If any of `hdf5::hdf5`, `hdf5::hdf5_hl` or `HDF5::HDF5` is not a
   target, stop with `FATAL_ERROR "FindHDF5 did not create the hdf5::hdf5, hdf5::hdf5_hl and HDF5::HDF5 targets; NEP requires CMake 3.19 or newer"`.
4. Set `NEP_HDF5_LIBRARY` to the first non-empty value among the
   `IMPORTED_LOCATION`, `IMPORTED_LOCATION_RELEASE` and
   `IMPORTED_LOCATION_DEBUG` properties of `hdf5::hdf5`. If all are
   empty, stop with `FATAL_ERROR`.
5. `get_filename_component(NEP_HDF5_LIBRARY_DIR "${NEP_HDF5_LIBRARY}" DIRECTORY)`.
6. `set(NEP_HDF5_LIBRARIES hdf5::hdf5_hl HDF5::HDF5)`. HL comes first
   for static link order. `HDF5::HDF5` carries libhdf5 and its own
   dependencies in both modes.
7. Print where HDF5 came from:
   - if `HDF5_DIR` is set and not `*-NOTFOUND`:
     `message(STATUS "NEP HDF5 ${HDF5_VERSION}: ${NEP_HDF5_LIBRARY} (CMake config ${HDF5_DIR})")`;
   - otherwise the same message ending in `(FindHDF5 module mode)`.

Define `function(nep_check_netcdf_hdf5)`. It takes no arguments and
reads `NETCDF_LIBRARY_DIRS`, `NETCDF_PREFIX`, `NEP_HDF5_LIBRARY` and
`HDF5_VERSION`:

1. `find_library(NEP_NETCDF_SHARED_LIBRARY NAMES netcdf HINTS ${NETCDF_LIBRARY_DIRS} "${NETCDF_PREFIX}/lib")`.
2. Use `CMAKE_READELF`. If it is empty, use
   `find_program(NEP_READELF readelf)`.
3. Skip the check with
   `message(STATUS "NEP: skipping NetCDF-C/HDF5 SONAME check (<reason>)")`
   in each of these cases:
   - no readelf;
   - no libnetcdf found;
   - `readelf -d` on `libnetcdf` shows no NEEDED entry matching
     `libhdf5(_debug)?\.so\.[0-9]+` (static or HDF5-less netcdf);
   - the HDF5 library has no SONAME (static HDF5).
4. Run `readelf -d` with `execute_process` on:
   - `NEP_NETCDF_SHARED_LIBRARY`;
   - `NEP_HDF5_LIBRARY`, after
     `get_filename_component(... REALPATH)`.

   From `libnetcdf`, extract the NEEDED name with the regex
   `\[(libhdf5(_debug)?\.so\.[0-9]+)\]` applied to lines containing
   `(NEEDED)`. From HDF5, extract the SONAME with the same regex on
   the `(SONAME)` line.
5. If they differ, stop with:

   ```
   NetCDF-C (${NEP_NETCDF_SHARED_LIBRARY}) links ${_needed}, but NEP found HDF5 ${HDF5_VERSION} (${_soname}) at ${NEP_HDF5_LIBRARY}. Set HDF5_ROOT to the HDF5 installation NetCDF-C was built with.
   ```
6. If they match, print
   `message(STATUS "NEP: NetCDF-C and NEP both use ${_soname}")`.

Only the SONAME (the ABI version) is compared, so 2.1.0 and 2.1.1,
which share `.so.320`, pass. That is intended.
