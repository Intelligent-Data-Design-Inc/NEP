# v3.5.0 Sprint 3: SWOT Example

## Sprint Goal and Scope

Add a standalone Python example under `examples/swot/` that opens a SWOT
gridded sea-surface-height product (NASA PO.DAAC `SWOT_L2_LR_SSH_*` or
AVISO+ `SWOT_L3_LR_SSH` NetCDF) and plots sea surface height anomaly
(`ssha`). The sprint mirrors the `examples/nisar/` structure and produces
a companion paper, `docs/netCDF_with_SWOT.md`, that explains how SWOT
products map to netCDF-4. The example does not touch NEP's C library,
`include/nep.h`, or the UDF dispatch framework, and is not wired into
CMake, CTest, or CI.

**In scope:**

- `examples/swot/swot_example/` Python package with:
  - `l3_ssh.py` — open the SWOT SSH NetCDF, load `ssha`, apply any
    `quality_flag` mask, and attach 2D `latitude`/`longitude` coordinates.
  - `plots.py` — cartopy/matplotlib helpers for the SSH map and a swath
    footprint overview.
  - `fetch.py` — optional `--bbox` search/download via `earthaccess`
    against the chosen PO.DAAC or AVISO+ collection.
  - `cli.py` — command-line entry point (`python -m swot_example`).
- `examples/swot/requirements.txt` listing `xarray`, `netCDF4`,
  `matplotlib`, `cartopy`, and `earthaccess`.
- `examples/swot/README.md` documenting setup, usage, the plotted
  variable, and Earthdata/AVISO+ credential setup; it embeds the
  committed example PNG(s).
- Committed example output PNG(s) under `examples/swot/figures/` (e.g.
  `ssha_map.png` and a `swath_footprint.png` overview).
- `docs/netCDF_with_SWOT.md` companion paper mirroring
  `docs/netCDF_with_NISAR.md`: explain the SWOT gridded product layout,
  show equivalent `ncdump` and `h5dump` views, and reference the example
  code.
- Top-level `README.md` and `examples/README.md` updates pointing to the
  new example.

**Out of scope:**

- Any change to `src/`, `include/`, NEP's UDF dispatch/format-reader code,
  or NEP's public API.
- CMake/CTest/CI integration (the example is pure Python, run directly
  from a virtual environment).

## Major Tasks (dependency order)

1. Create the `examples/swot/` directory structure.
2. Implement `swot_example/l3_ssh.py`:
   - Open a SWOT L2/L3 SSH NetCDF with `xarray`/`netCDF4`.
   - Load the `ssha` variable and mask invalid/fill pixels using the
     product `quality_flag` when present.
   - Return a `xarray.DataArray` with 2D `latitude` and `longitude`
     coordinate variables attached.
3. Implement `swot_example/fetch.py`:
   - Search and download a SWOT SSH granule that intersects a user-supplied
     lat/lon bounding box using `earthaccess`.
   - Support the NASA PO.DAAC `SWOT_L2_LR_SSH_*` collections by default;
     document how to switch to the AVISO+ `SWOT_L3_LR_SSH` collection if
     that is the chosen target.
   - Read credentials from `~/.netrc` or the `EARTHDATA_USERNAME` /
     `EARTHDATA_PASSWORD` environment variables, with the same fallbacks
     used by `examples/nisar/nisar_example/fetch.py`.
4. Implement `swot_example/plots.py`:
   - `plot_ssha_map()` — pcolormesh of `ssha` on a cartopy map, with
     coastlines, grid lines, and a colorbar.
   - `plot_footprint()` — overview map showing the granule's lat/lon
     bounding box.
5. Implement `swot_example/cli.py`:
   - Mutually exclusive positional `FILE` path or `--bbox W S E N`.
   - `--output-dir` flag (default `output/`, untracked).
   - `--show` flag for interactive display.
6. Generate the example output PNG(s) from a local sample file or from a
   granule fetched via `--bbox`, and commit them under
   `examples/swot/figures/`.
7. Write `examples/swot/README.md` with setup instructions, usage
   examples, credential setup, and embedded output figure(s).
8. Write `docs/netCDF_with_SWOT.md`:
   - Introduce the SWOT mission and the chosen gridded SSH product.
   - Show the netCDF-4 view (`ncdump -h -s`) and the HDF5 view
     (`h5dump -n` / `h5dump -H -A -d`) of the same file.
   - Explain how the `ssha`, `latitude`, `longitude`, and `quality_flag`
     variables map to the NetCDF data model.
   - Include C, HDF5, and Python code snippets that read the same data.
9. Update `examples/README.md` and the top-level `README.md` to reference
   `examples/swot/README.md`.
10. Manually verify the example end-to-end from the command line.

## Acceptance Criteria

- `examples/swot/` exists with a working, standalone Python CLI that:
  - Opens a user-provided SWOT SSH `.nc` file and produces an
    `ssha` map PNG.
  - Supports `--output-dir`, `--show`, and `--bbox` Earthdata/AVISO+
    fetch.
- `examples/swot/requirements.txt` lists all needed dependencies and
  `pip install -r examples/swot/requirements.txt` succeeds.
- `examples/swot/README.md` documents setup/usage and embeds a committed
  example output image.
- `docs/netCDF_with_SWOT.md` is present, mirrors the depth and style of
  `docs/netCDF_with_NISAR.md`, and accurately describes the chosen SWOT
  product's netCDF-4 mapping.
- Top-level `README.md` and `examples/README.md` reference the new SWOT
  example.
- No files under `src/`, `include/`, `test/`, `.github/workflows/`, or
  CMake files are modified.

## Testing Requirements

- Manual verification only (no CTest/CI integration this sprint):
  - Run `python examples/swot/<entry_point>.py /path/to/sample.nc` and
    confirm PNG output is produced.
  - Run with `--show` to confirm interactive display works.
  - Run with `--bbox` (requires Earthdata/AVISO+ credentials) to confirm
    the fetch path reaches search/download; document the result or mark
    it as credential-dependent.
- No new automated regression tests are added; this is an example, not a
  library feature.

## Build System Integration

None. The example is pure Python, run directly with a virtual
environment; it is intentionally **not** added to
`examples/CMakeLists.txt` or any CTest registration, matching the NISAR
example.

## Dependencies and Blockers

- A local SWOT L2/L3 SSH sample NetCDF, or Earthdata/AVISO+ credentials
  to fetch one via `--bbox`, is required for generating the committed
  example PNG(s) and for manual verification.
- The `--bbox` fetch path requires a NASA Earthdata Login account for
  PO.DAAC products, or an AVISO+ account for AVISO+ `L3_LR_SSH`
  products. Credential setup is documented as a user-provided
  requirement, not a blocker for merging the example.
- Python dependencies: `xarray`, `netCDF4`, `matplotlib`, `cartopy`, and
  `earthaccess`.
