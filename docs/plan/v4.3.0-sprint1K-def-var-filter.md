# V4.3.0 Sprint 1K: Do Filters Work with NEXTCDF-4

Source: docs/roadmap.md, "V4.3.0 / Sprint 1K".

## Goal

`nc_def_var_filter()` works on NEXTCDF-4 files with the same semantics
as upstream netcdf-c's HDF5 backend: any HDF5 filter (deflate, shuffle,
fletcher32, szip, bzip2, zstd, or a third-party plugin filter) can be
defined on a variable, is applied to the dataset-creation property
list, is reported by `nc_inq_var_filter_ids()`/
`nc_inq_var_filter_info()`/`nc_inq_var_filter()`, and survives
reopen. Variables whose mandatory filter plugin is missing at open
remain metadata-readable but fail I/O with `NC_ENOFILTER`, matching
upstream. The answer to the sprint's question becomes "yes" instead of
the current `NC_ENOTBUILT`.

## Decisions

| Topic | Decision |
| --- | --- |
| Filter state model | Adopt upstream's model: `NC_VAR_INFO_T::filters` (an `NClist` of `struct NC_HDF5_Filter`) is the single source of truth, manipulated through netcdf-c's exported `NC4_hdf5_addfilter()`, `NC4_hdf5_filter_lookup()`, `NC4_hdf5_filter_freelist()` and `NC4_hdf5_find_missing_filter()` (verified exported from `/usr/local/netcdf-c/lib/libnetcdf.so` and declared in NEP's vendored `include/hdf5internal.h`). `NEXTCDF4_VAR_INFO_T`'s `deflate_level`/`shuffle`/`fletcher32` fields retire; it gains `int flags` (bit `NC_HDF5_VAR_FILTER_MISSING`). Filter code moves to a new `src/nextcdf4/nxt4filter.c`, as `docs/plan/NEXTCDF4_plan.md` sketched. (Ed: 1a) |
| Setter semantics | Full upstream parity: filters cannot be removed once defined (re-defining an id replaces its params); `nc_def_var_deflate` with `deflate_level = 0` adds shuffle only; `nc_inq_var_filter_ids` returns `NC_NOERR` with `nfilters = 0` when empty; a variable recovered from disk (`var->created`) rejects filter changes with `NC_ELATEDEF`; pipeline order follows `NC4_hdf5_addfilter` insertion rules — fletcher32 first, shuffle first-or-second, everything else in definition order. (Ed: 2a) |
| `NC_CLASSIC_MODEL` | `nc_def_var_filter`, `nc_def_var_deflate`, `nc_def_var_fletcher32` and `nc_def_var_chunking` all return `NC_EINVAL` under `NC_CLASSIC_MODEL`, enforcing the contract `docs/nextcdf4.md` already documents. (Ed: 3a) |
| Plugin tests | Runtime-gated on `nc_inq_filter_avail`/`H5Zfilter_avail` for zstd (32015), bzip2 (307) and szip (4); they run in CI (the workflows export `HDF5_PLUGIN_PATH`) and skip cleanly elsewhere. The missing-plugin case is simulated in-process with `H5Zunregister()`. (Ed: 4a) |
| Define-mode error code | NEXTCDF-4 keeps its existing `NC_ENOTINDEFINE` (from `NEXTCDF4_check_write_define`) when the file is not in define mode; upstream's `NC_EINDEFINE` is not adopted. `NC_ELATEDEF` is added for `var->created`, matching upstream. |
| `inq_var_all` filter outputs | `shufflep`/`deflatep`/`deflate_levelp`/`fletcher32p` are derived from `var->filters` via `NC4_hdf5_filter_lookup`. `idp`/`nparamsp`/`params` stay unpopulated — upstream does not populate them either (its shared `NC4_inq_var_all` returns `NC_EFILTER` if asked). |
| Chunk defaults | When a filter forces `NC_CHUNKED`, NEXTCDF-4 keeps its existing convention (dimension length, or 1 for unlimited) computed in `nx4_create_var_dataset`; upstream's `nc4_find_default_chunksizes2` is not adopted. |
| Coordinate variables | Filters are allowed on coordinate variables (upstream parity — compressed axes are legitimate netCDF-4). Caveat: a def-var setter on a coord var recreates its dataset/scale, leaving dangling `DIMENSION_LIST` references on vars that already attached the dim — the documented fix is to set filters before defining dependent vars. This hazard already exists for all setters and is owned by #382, not this sprint. |
| Packaging | No Spack/conda changes: no new CMake option, dependency, minimum version or installed file. |

## Current state (2026-11-20)

- `nc_def_var_filter()` does **not** work: `NEXTCDF4_def_var_filter()`
  at `src/nextcdf4/nxt4meta.c:1750` is a stub returning `NC_ENOTBUILT`.
- `NEXTCDF4_inq_var_filter_ids()`/`_info()` (nxt4meta.c:1900, 1944)
  reconstruct only deflate/shuffle/fletcher32 from
  `NEXTCDF4_VAR_INFO_T` flags (nxt4internal.h:81-87); unknown filters
  cannot be represented. `inq_var_filter_ids` returns `NC_ENOFILTER`
  for an empty pipeline (upstream returns `NC_NOERR` + 0) and writes
  `ids[]` even when `ids == NULL` — a count-only call segfaults.
- `NC_NOOP_inq_filter_avail` in the dispatch table
  (nxt4dispatch.c:110) makes `nc_inq_filter_avail()` report every
  filter available, so `nc_def_var_bzip2`/`nc_def_var_zstandard`
  would proceed to failure rather than reporting `NC_ENOFILTER`.
- `create_var_dataset()` (nxt4meta.c:1296) builds the pipeline as
  shuffle → deflate → fletcher32; upstream produces fletcher32 →
  shuffle → deflate → others, so NEXTCDF-4 files with fletcher32 have
  a different (still valid) pipeline than equivalent upstream files.
- `load_one_var()` (nxt4meta.c:3199-3218) reads only
  deflate/shuffle/fletcher32 from the DCPL with a fixed 4-element
  `cd_values` buffer (blosc stores 7 params — truncation), silently
  drops unknown filters, and never marks missing filters.
- `var_io()` (nxt4io.c:236) has no missing-filter check; reading a
  var whose mandatory filter is absent fails as `NC_EHDFERR` inside
  `H5Dread` rather than `NC_ENOFILTER`.
- `NEXTCDF4_def_var_deflate` stores `deflate_level = 0` as a real
  zlib-0 filter; upstream treats level 0 as "no compression".
- `close_group_hdf()` (nxt4file.c:45-54) closes `vinfo->hdf_dataset`
  but never frees `vinfo` (pre-existing per-var leak) — the same site
  is where `NC4_hdf5_filter_freelist(var)` must run; netcdf-c's
  generic `nc4_var_list_del`/`var_free` do not touch `var->filters`.
- `var->created` is set only by `load_one_var` (nxt4meta.c:3146);
  vars defined in the current session are never marked, so an
  `NC_ELATEDEF` check must also mark them at `_enddef`.
- No setter checks `file->mode & NC_CLASSIC_MODEL`; the docs already
  promise classic model forbids chunking/compression/filters
  (`docs/nextcdf4.md:64`), and upstream applies no classic check in
  its filter path either.
- Wrappers that come free once the dispatch entries work:
  `nc_def_var_szip`/`nc_inq_var_szip`, `nc_def_var_bzip2`,
  `nc_def_var_zstandard`, `nc_def_var_blosc`,
  `nc_inq_var_filter` — all libdispatch code built on
  `def_var_filter`/`inq_var_filter_info`/`inq_filter_avail`
  (`/fast/ed/ab cd/libdispatch/dvar.c:868`, `dfilter.c`).
- Plugins available here: `/usr/local/netcdf-c/hdf5/lib/plugin`
  (`lib__nch5bzip2.so`, `lib__nch5szip.so`, `lib__nch5zstd.so`, ...);
  CI exports `HDF5_PLUGIN_PATH` at `.github/workflows/ci.yml:169,345,369`.
- Reference implementation: `NC4_hdf5_def_var_filter`
  (`/fast/ed/ab cd/libhdf5/hdf5filter.c:270`), `NC4_hdf5_addfilter`
  (ordering rules, line 136), `get_filter_info` open path
  (`libhdf5/hdf5open.c:1064`), DCPL application
  (`libhdf5/nc4hdf.c:884-915`), missing-filter I/O gate
  (`libhdf5/hdf5var.c:1587,1928`).
- Spack recipe impact: none — no CMake option, dependency, version
  floor, install-layout or plugin-directory change.

### 2. `src/nextcdf4/nxt4filter.c` — new file

Doxygen header per project style (`@file`, `@brief`, `@author Edward
Hartnett`, `@date`, `@copyright Intelligent Data Design, Inc.`).
Includes `nxt4internal.h`, `hdf5internal.h` (for `struct
NC_HDF5_Filter` + `NC_HDF5_*_MISSING`), `netcdf_filter.h`.

- `NEXTCDF4_def_var_filter(ncid, varid, id, nparams, params)` —
  port of `NC4_hdf5_def_var_filter`:
  1. `find_var_for_write()` prologue → `NC_EPERM`/`NC_ENOTINDEFINE`.
  2. `file->mode & NC_CLASSIC_MODEL` → `NC_EINVAL`.
  3. `var->ndims == 0` → `NC_EINVAL`; `var->created` → `NC_ELATEDEF`.
  4. `nparams > 0 && params == NULL` → `NC_EINVAL`.
  5. `H5Zfilter_avail(id) < 0` → `NC_EHDFERR`; `== 0` → `NC_ENOFILTER`.
  6. For a not-yet-defined id: deflate requires `nparams == 1` else
     `NC_EFILTER`, `params[0]` in 0-9 else `NC_EINVAL`, and fails
     `NC_EINVAL` if szip is already defined; szip requires
     `nparams == 2` else `NC_EFILTER`, `params[1]` even and `<= 32`
     else `NC_EINVAL`, fails `NC_EINVAL` if deflate is defined, and
     `params[1] >` product of `var->dim[d]->len` → `NC_EINVAL`
     (upstream compares against total elements, port verbatim).
  7. `NC4_hdf5_addfilter(var, id, nparams, params, 0)` — handles
     duplicates by replacing params, and inserts fletcher32 at index
     0, shuffle at index 0-or-1, others at the end.
  8. `var->storage = NC_CHUNKED`, then `nx4_create_var_dataset()`.
- `NEXTCDF4_def_var_deflate()` — moved here and rewritten to upstream
  `NC4_def_var_deflate` semantics: classic/scalar checks, then
  `NC4_hdf5_addfilter(var, H5Z_FILTER_SHUFFLE, 0, NULL, 0)` when
  `shuffle`, and `NC4_hdf5_addfilter(var, H5Z_FILTER_DEFLATE, 1,
  &level, 0)` only when `deflate && deflate_level` (level 0 → no
  deflate filter); then `nx4_create_var_dataset()`. Existing
  `deflate_level < 0 || > 9` → `NC_EINVAL` validation retained.
- `NEXTCDF4_def_var_fletcher32()` — moved here; classic/scalar
  checks; `NC4_hdf5_addfilter(var, H5Z_FILTER_FLETCHER32, 0, NULL, 0)`
  when `fletcher32` is nonzero (zero is a no-op, matching upstream —
  no removal); `nx4_create_var_dataset()`.
- `NEXTCDF4_inq_var_filter_ids()` — moved here, rewritten to iterate
  `var->filters`; writes `ids[]` only when `ids != NULL` (fixes the
  count-only segfault); always returns `NC_NOERR` with the count.
- `NEXTCDF4_inq_var_filter_info()` — moved here, rewritten as
  `NC4_hdf5_filter_lookup` + copy of `nparams`/`params`;
  `NC_ENOFILTER` when the id is not on the variable.
- `NEXTCDF4_inq_filter_avail()` — `H5Zfilter_avail(id) < 0` →
  `NC_EHDFERR`; `== 0` → `NC_ENOFILTER`; else `NC_NOERR`.
- `nx4_apply_filters(dcpl, var)` — iterate `var->filters` in order:
  fletcher32 → `H5Pset_fletcher32`, shuffle → `H5Pset_shuffle`,
  deflate → `H5Pset_deflate(params[0])` (`nparams != 1` →
  `NC_EFILTER`), szip → `H5Pset_szip(params[0], params[1])`
  (`nparams != 2` → `NC_EFILTER`), all others → `H5Pset_filter(dcpl,
  id, H5Z_FLAG_OPTIONAL, nparams, params)` (optional flag = upstream
  behavior so filters on vlen vars are ignored rather than fatal);
  HDF5 failure → `NC_EHDFERR`/`NC_EFILTER` per upstream.
- `nx4_load_filters(dcpl, var, vinfo)` — port of upstream
  `get_filter_info()`: for each of `H5Pget_nfilters`, call
  `H5Pget_filter2` twice (first for flags + `cd_nelems`, then into a
  `calloc`'d `cd_nelems`-sized buffer — no fixed-size truncation);
  `H5Zfilter_avail == 0` sets `NC_HDF5_FILTER_MISSING` on the spec
  and `vinfo->flags |= NC_HDF5_VAR_FILTER_MISSING`; a varsized type
  (`NC_STRING` or vlen class) with `H5Z_FLAG_MANDATORY` also marks
  missing; deflate requires `cd_nelems == 1` and level ≤ 9 else
  `NC_EHDFERR`; szip applies the 4→2 param fixup (`cd_values[0] &=
  H5_SZIP_ALL_MASKS`); each spec is stored with
  `NC4_hdf5_addfilter(var, id, n, vals, flags)` in DCPL order.

### 3. `src/nextcdf4/nxt4meta.c` — removals and rewiring

- Remove `NEXTCDF4_def_var_filter`, `NEXTCDF4_inq_var_filter_ids`,

- `NEXTCDF4_def_var_chunking`: add `file->mode & NC_CLASSIC_MODEL` →

- All callers of the renamed `create_var_dataset` updated

### 5. `src/nextcdf4/nxt4io.c` — missing-filter I/O gate

`if (vinfo->flags & NC_HDF5_VAR_FILTER_MISSING) return NC_ENOFILTER;`
with an `ELOG((0, ...))` naming the variable and the missing filter id
via `NC4_hdf5_find_missing_filter` — matching upstream's "Verify that
all the variable's filters are available" check, applied to both read
and write paths.

### 6. `src/nextcdf4/nxt4file.c` — cleanup and `_enddef` marking

- `close_group_hdf()` var loop: after closing `vinfo->hdf_dataset`,
  call `NC4_hdf5_filter_freelist(var)` when `var->filters != NULL`,
  then `free(vinfo)` and NULL `var->format_var_info` (fixes the
  existing per-var leak at the same site).
- `NEXTCDF4__enddef`: walk the group tree's vars and set
  `var->created = 1` (small recursive helper, or piggyback on an

### 8. `test/nextcdf4/tst_nextcdf4_filter.c` — new enabled test

Plain comments (no Doxygen markup), `Author: Edward Hartnett,
Intelligent Data Design, Inc.` Standard test env block in
`test/nextcdf4/CMakeLists.txt` (same as siblings; always registered,
not gated). `unlink(FILE_NAME)`, `NC_NEXTCDF4_initialize()`,
`nc_create(FILE_NAME, NC_NEXTCDF4 | NC_CLOBBER, ...)`. Cases:

- deflate via `nc_def_var_filter(H5Z_FILTER_DEFLATE, 1, &level)`:
  `nparams != 1` → `NC_EFILTER`; level 10 → `NC_EINVAL`; valid level →
  write/read round-trip; `nc_inq_var_deflate` reports it.
- Ordering: deflate then shuffle then fletcher32 →
  `nc_inq_var_filter_ids` yields `[FLETCHER32, SHUFFLE, DEFLATE]`.
- szip (gated on `nc_inq_filter_avail(H5Z_FILTER_SZIP)`):
  `nc_def_var_szip` + `nc_inq_var_szip` round-trip mask/ppb;
  deflate-then-szip and szip-then-deflate → `NC_EINVAL`;
  `nparams != 2` → `NC_EFILTER`; odd or >32 ppb → `NC_EINVAL`.
- zstd (`H5Z_FILTER_ZSTD`, gated): define with `{level}`, round-trip,
  close + reopen: ids report 32015, `nc_inq_var_filter_info` returns
  stored params, data round-trips. Multi-filter: shuffle + zstd.
- bzip2 (`H5Z_FILTER_BZIP2`, gated): same lighter check.
- Missing plugin (runs last): after creating/validating the zstd file,
  `H5Zunregister(H5Z_FILTER_ZSTD)`, reopen: open succeeds,
  `nc_inq_var_filter_ids` still reports 32015, `nc_get_var` →
  `NC_ENOFILTER`.
- Coordinate var: `nc_def_var_filter` (deflate + fletcher32) on a 1-D
  coordinate var defined before dependent vars — chunked coord data
  round-trips and the dependent var's dimids resolve on reopen.
- Errors: scalar var → `NC_EINVAL`; never-registered id →
  `NC_ENOFILTER`; re-defining deflate replaces params (still one
  filter); no-filter var → `nc_inq_var_filter_ids` `NC_NOERR` + 0
  with `ids == NULL` safe; `nc_inq_var_filter` → `idp = 0`;
  `nc_inq_var_szip` on plain var → zeros;
  `nc_inq_filter_avail(DEFLATE)` → `NC_NOERR`, bogus id →
  `NC_ENOFILTER`; `nc_def_var_filter` after `nc_enddef` →
  `NC_ENOTINDEFINE`; on a reopened var → `NC_ELATEDEF`;
  `nc_def_var_chunking(NC_CONTIGUOUS)` after a filter → `NC_EINVAL`;
  `nc_inq_var_chunking` on a filtered var reports `NC_CHUNKED`;
  every filter/storage setter in an `NC_CLASSIC_MODEL` file →
  `NC_EINVAL`.
