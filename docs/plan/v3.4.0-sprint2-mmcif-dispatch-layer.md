# v3.4.0 Sprint 2: PDBx/mmCIF Read-Only Dispatch Layer

## Sprint Goal and Scope

Replace the Sprint 1 no-op mmCIF dispatch layer (`src/mmciffile.c`) with a
real read-only STAR/CIF tokenizer and parser, exposing atomic coordinates
and key structural metadata as netCDF-4 dimensions, variables, and global
attributes through the existing UDF8 dispatch table (`src/mmcifdispatch.c`,
unchanged from Sprint 1). This mirrors the v3.3.0 Sprint 2 PDB dispatch
layer, adapted for the STAR/CIF `loop_`/key-value grammar instead of
fixed-column records.

In scope:
- A custom STAR/CIF tokenizer (no external library) that classifies
  key-value pairs (`_category.item value`) and `loop_` blocks.
- Parsing `_atom_site` (looped) into per-atom coordinate and identity
  variables.
- Parsing `_cell`/`_symmetry` (single-row) into unit-cell global
  attributes.
- Parsing `_entry`/`_struct`/`_entity`/`_pdbx_database_status` (single-row)
  into descriptive global attributes.
- A PDBx-vs-generic-CIF discriminator: reject files with no `_atom_site`
  category after the `"data_"` magic match.
- A `model` x `atom` netCDF schema, with `model` derived from
  `_atom_site.pdbx_PDB_model_num` (untested for >1 model this sprint,
  since all three test files are single-model).

Out of scope (deferred to a later sprint, matching the PDB precedent):
- `_entity_poly_seq`-derived sequence data (`sequence` group / `mon_id`
  variable).
- `_atom_site_anisotrop` (ANISOU-equivalent) data.
- `_struct_conn`/`_struct_conf`/`_struct_sheet_range` (bonds/secondary
  structure).
- Multi-model (NMR ensemble) mmCIF test coverage — no such file exists
  yet in `test/data/mmCIF/`.
- Flipping `NEP_ENABLE_MMCIF` to default ON (reserved for a "more
  testing" sprint, as with PDB Sprint 3).
- A companion mask/flag variable distinguishing `?` (unknown) from `.`
  (not applicable) — both map to the type's NetCDF fill value.

## NetCDF Schema

**Dimensions:**
- `model`: number of distinct `_atom_site.pdbx_PDB_model_num` values, or
  `1` if the item is absent. All three current test files
  (`1J7W.cif`, `2W6V.cif`, `4HHB.cif`) are single-model X-ray structures.
- `atom`: number of `_atom_site` rows per model, in file order (assumed
  constant across models within a file).

**Coordinate variables** (mirrors PDB's `atom_site_Cartn_x/y/z`, but
`NC_DOUBLE` since mmCIF values carry more decimal precision than PDB's
fixed `Real(8.3)` columns):
- `atom_site_Cartn_x`, `atom_site_Cartn_y`, `atom_site_Cartn_z`:
  `NC_DOUBLE`, shape `[model][atom]`, from `_atom_site.Cartn_x/y/z`.

**Per-atom variables** (dimension `[atom]`, constant across models):
- `atom_site_id` (`NC_INT`, from `_atom_site.id`)
- `atom_site_label_atom_id` (`NC_STRING`/`NC_CHAR`, from
  `_atom_site.label_atom_id`)
- `atom_site_label_comp_id` (`NC_STRING`/`NC_CHAR`, from
  `_atom_site.label_comp_id`)
- `atom_site_auth_asym_id` (`NC_STRING`/`NC_CHAR`, from
  `_atom_site.auth_asym_id`)
- `atom_site_auth_seq_id` (`NC_INT`, from `_atom_site.auth_seq_id`)
- `atom_site_occupancy` (`NC_DOUBLE`, from `_atom_site.occupancy`)
- `atom_site_B_iso_or_equiv` (`NC_DOUBLE`, from
  `_atom_site.B_iso_or_equiv`)
- `atom_site_type_symbol` (`NC_STRING`/`NC_CHAR`, from
  `_atom_site.type_symbol`)
- `atom_site_group_PDB` (`NC_STRING`/`NC_CHAR`, `"ATOM"`/`"HETATM"`, from
  `_atom_site.group_PDB`)

**Global attributes** (`NC_CHAR`/`NC_STRING`, only defined when the
source category/item is present in the file):
- `entry_id` (`_entry.id`)
- `struct_title` (`_struct.title`)
- `cell_length_a`/`b`/`c`, `cell_angle_alpha`/`beta`/`gamma`
  (`_cell.length_*`/`_cell.angle_*`)
- `symmetry_space_group_name_H-M` (`_symmetry.space_group_name_H-M`)
- `symmetry_Int_Tables_number` (`_symmetry.Int_Tables_number`)
- `pdbx_database_status_recvd_initial_deposition_date`
  (`_pdbx_database_status.recvd_initial_deposition_date`)

## Value Handling

- `?` (unknown) and `.` (not applicable) both map to the destination
  variable's NetCDF fill value (`NC_FILL_DOUBLE`, `NC_FILL_INT`, or an
  empty string, depending on type). No separate presence/mask variable is
  added this sprint.
- Quoted values (`'...'`, `"..."`) have their surrounding quote
  characters stripped during tokenization; multi-line semicolon text
  fields are not required for the categories in scope and can be skipped
  if encountered (documented limitation).

## Major Tasks (dependency order)

1. Add a STAR/CIF tokenizer to `src/mmciffile.c` (or a new
   `src/mmcifparse.c` helper) that reads the whole file into memory
   (mmCIF files here are a few MB at most; no streaming needed), strips
   `#` comments, and classifies lines into: `data_` block headers,
   `loop_` declarations, `_category.item` declarations (loop header or
   single key-value), and data rows.
2. Implement loop-row tokenization that is whitespace-aware but respects
   single/double-quoted values (values containing spaces are quoted in
   the `_atom_site` loop, e.g. residue names are not, but defensive
   quote-handling is required for robustness against future files).
3. First pass over `_atom_site`: count rows to size the `atom` dimension,
   collect distinct `pdbx_PDB_model_num` values to size `model`, and
   reject with `NC_EINVAL` if the row count is zero (no `_atom_site`
   category — this doubles as the PDBx-vs-generic-CIF discriminator
   described in Sprint 1's deferred decision).
4. Second pass: allocate per-atom arrays, populate identity fields from
   the first model's rows, and populate `[model][atom]` coordinate
   arrays across all models (loop implementation should work correctly
   for `model` > 1 even though it is untested against real data this
   sprint).
5. Parse `_cell`, `_symmetry`, `_entry`, `_struct`, `_pdbx_database_status`
   single-row (non-looped) key-value pairs into global attribute values;
   only define attributes for categories/items that are actually present.
6. Replace `NC_MMCIF_open()`'s no-op body: after building the netCDF-4
   skeleton (unchanged from Sprint 1) and running the tokenizer/parser,
   call `nc4_def_dim`/`nc4_def_var`-equivalent internal helpers
   (following the `pdbfile.c`/`fitsfile.c` pattern of populating
   `NC_GRP_INFO_T`/`NC_VAR_INFO_T` directly) to create the dimensions,
   variables, and attributes above. Return `NC_EINVAL` if no `_atom_site`
   rows were found.
7. Implement `NC_MMCIF_get_vara()` to serve reads from the in-memory
   arrays built at open time (mirrors `NC_PDB_get_vara()`'s
   in-memory-buffer pattern; no re-parsing on every read).
8. Expand `test/tst_mmcif_udf.c` with the assertions in Testing
   Requirements below, replacing the Sprint 1 open/close-only checks.
9. Update `ci-mmcif.yml` if needed so the expanded test still passes
   (workflow already builds with `NEP_ENABLE_MMCIF=ON`; no default-value
   change required in `CMakeLists.txt`).

## Acceptance Criteria

- `nc_open()` on `test/data/mmCIF/1J7W.cif`, `2W6V.cif`, and `4HHB.cif`
  succeeds and exposes the schema above.
- `atom` dimension length matches each file's `_atom_site` loop row
  count.
- `model` dimension is `1` for all three test files.
- `nc_get_vara()` on `atom_site_Cartn_x/y/z` for a known atom index
  matches the `_atom_site.Cartn_x/y/z` values read directly from the
  file (e.g. atom id 1 in `1J7W.cif`: x=10.834, y=19.914, z=6.870).
- `atom_site_group_PDB` correctly distinguishes an `ATOM` row from a
  `HETATM` row in at least one file.
- `_cell`/`_symmetry`-derived global attributes match the file's values
  for files that contain those categories.
- A synthetic file with `"data_"` but no `_atom_site` category is
  rejected with `NC_EINVAL`.
- Full test suite remains green with `NEP_ENABLE_MMCIF` both ON and OFF.

## Testing Requirements

- Extend `test/tst_mmcif_udf.c`:
  - Verify `atom` and `model` dimension lengths for all three test files.
  - Verify `atom_site_Cartn_x/y/z` for at least one specific atom in each
    file against hand-computed expected values from the raw file.
  - Verify `atom_site_group_PDB` correctly distinguishes an `ATOM` row
    from a `HETATM` row (at least one test file has `HETATM` rows).
  - Verify `_cell`/`_symmetry`-derived global attributes.
  - Verify `entry_id` and `struct_title` global attributes.
  - Add a small malformed-input fixture (e.g. a `data_` file with only
    `_entry.id` and no `_atom_site` loop) and assert `NC_EINVAL`.
- Run via `ctest -R tst_mmcif_udf --output-on-failure` with
  `-DNEP_ENABLE_MMCIF=ON`.
- Confirm `ci-mmcif.yml` passes with the expanded test.

## Definition of Done

custom STAR/CIF tokenizer, files without an `_atom_site` category are
