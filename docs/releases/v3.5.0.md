# NEP v3.5.0 - Build Metadata Header and NISAR/SWOT/ABI Examples

> Adds a generated `nep_meta.h` build-info header and three standalone Python examples for NISAR, SWOT, and GOES-R ABI CMIP data.

This release is example- and infrastructure-focused: it introduces a CMake-generated build metadata header and expands the example suite with three new standalone Python packages for earth-observation data. No new UDF readers or C API changes are included.

---

## Highlights

- **`nep_meta.h` build metadata header** (#353) — `include/nep_meta.h.in` is configured at build time to produce `nep_meta.h`, exposing version, build date, compiler, and `0`/`1` feature flags for every enabled reader and filter.
- **NISAR soil-moisture example** (#355) — `examples/nisar/` plots NISAR L3 PR SME2 soil moisture from a user-supplied `.h5` file.
- **SWOT sea-surface-height example** (#357) — `examples/swot/` plots `ssha` from SWOT L2/L3 gridded NetCDF products.
- **GOES-R ABI CMIP example** (#359) — `examples/abi/` plots `CMI` reflectance/brightness temperature from ABI Level 2 CMIP NetCDF granules.

---

## Features

### Build Metadata Header (`nep_meta.h`) (#353)

- `include/nep_meta.h.in` is the committed source of truth; `nep_meta.h` is generated at CMake configure time into the build tree and added to `.gitignore`.
- Macros include NEP version (`NEP_VERSION_MAJOR/MINOR/PATCH`), build date, compiler name, and `NEP_ENABLE_*` feature flags as `0`/`1` values.
- The generated header is installed alongside `nep.h` so downstream projects can inspect build capabilities.
- `test/tst_meta.c` is a compile-only test that includes `nep_meta.h` and validates the version macros.
- No runtime build-info query API is added in this release.

### NISAR Example (#355)

- New `examples/nisar/` directory with a Python-only, standalone package.
- CLI mirrors `nisar_play`'s `plot-sme2` command: a required positional NISAR SME2 `.h5` path plus `--output-dir` and `--show` flags.
- `fetch.py` ports the `nisar_play` bbox-search/download path, including `~/.netrc` / `EARTHDATA_USERNAME` / `EARTHDATA_PASSWORD` credential handling.
- `sme2.py` and `plots.py` read soil moisture and produce output PNGs.
- A pre-generated soil-moisture PNG is committed under `examples/nisar/` and shown in `examples/nisar/README.md`.
- `examples/nisar/requirements.txt` declares `xarray`, `netCDF4`, `matplotlib`, `cartopy`, and `earthaccess`.

### SWOT Example (#357)

- New `examples/swot/` directory with the `swot_example` package.
- CLI takes a local `.nc` file or a `--bbox W S E N` fetch path; the fetch path uses `earthaccess` against the chosen collection.
- `examples/swot/swot_example/l3_ssh.py`, `plots.py`, `fetch.py`, and `cli.py` read SWOT gridded SSH and plot `ssha` masked with the product `quality_flag` when present.
- Output PNGs (e.g., `ssha_map.png` and a swath overview) are committed under `examples/swot/figures/` and embedded in `examples/swot/README.md`.
- `docs/netCDF_with_SWOT.md` is a companion paper explaining how SWOT gridded SSH products map to NetCDF-4.
- Credentials come from `~/.netrc` or `EARTHDATA_USERNAME` / `EARTHDATA_PASSWORD`; AVISO+ fetch is documented separately.

### ABI Example (#359)

- New `examples/abi/` directory with the `abi_example` package.
- CLI takes a local `.nc` file or fetches a granule from the NOAA GOES AWS Open Data registry by date, satellite, channel, and region.
- `examples/abi/abi_example/reader.py`, `plots.py`, `fetch.py`, and `cli.py` plot `CMI` on its native geostationary projection.
- Output PNGs (e.g., `cmi_map.png` and a full-disk preview) are committed under `examples/abi/figures/` and embedded in `examples/abi/README.md`.
- `docs/netCDF_with_ABI_CMIP.md` is a companion paper explaining ABI CMIP product mapping and the geostationary projection metadata.
- `examples/abi/requirements.txt` declares `xarray`, `netCDF4`, `matplotlib`, `cartopy`, `boto3`/`s3fs` (or direct HTTPS) for NOAA GOES access; no Earthdata credentials are required.

## Build System

- `CMakeLists.txt` adds `configure_file()` logic to generate `nep_meta.h` from `include/nep_meta.h.in` at configure time.
- `include/nep_meta.h` is added to `.gitignore` and an install rule is added alongside `nep.h`.
- CMake captures `version.txt`, compiler information, and `NEP_ENABLE_*` option state to populate the header placeholders.

---

## Testing

- `test/tst_meta.c` validates that `nep_meta.h` is generated correctly and that version macros match `version.txt`.
- The NISAR, SWOT, and ABI examples are standalone Python packages and are not registered in CMake/CTest or run in CI; each is exercised manually from the command line.

NEP's example programs are companion code for *The NetCDF Developer's Handbook: The Authoritative Guide to Writing High-Performance Programs for Scientific Data Management, Second Edition* — available on [Amazon](https://www.amazon.com/dp/B0H7Q1Z75L).

## Dependencies

- The `nep_meta.h` feature requires only CMake and the existing NEP build configuration.
- New Python example dependencies: `xarray`, `netCDF4`, `matplotlib`, `cartopy`, `earthaccess` (NISAR/SWOT), and `boto3`/`s3fs` (ABI fetch path). These are optional and are declared in per-example `requirements.txt` files.

---

## Known Limitations

- The NISAR, SWOT, and ABI examples are not built or run by CMake/CTest; they are intended as standalone scripts.
- NISAR sample files are not committed to the repository; users must supply their own SME2 `.h5` file path.
- Fetch paths for NISAR and SWOT require valid NASA Earthdata/PO.DAAC (or AVISO+) credentials.
- The ABI fetch path requires network access to the NOAA GOES AWS Open Data registry or a user-supplied local `.nc` file.
