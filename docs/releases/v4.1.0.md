# NEP v4.1.0 - NEXTCDF4 Tools and Examples

> Continues the NEXTCDF-4 work from v4.0.0 by adding user-facing tooling, language bindings, and the documentation and logging infrastructure needed to support them.

This release focuses on making the NEXTCDF-4 backend accessible to users and downstream developers through documentation, logging, tools (`nextcopy` / `nextdump`), and language bindings. The full NEXTCDF-4 backend implementation was completed in v4.0.0.

---

## Highlights

- **Complete NEXTCDF-4 user and developer documentation**: dedicated reference page, Doxygen integration, and updates to design, PRD, FAQ, and release notes.
- **NEP logging framework**: unified `LOG(())` macro for the NEXTCDF-4 backend and NEP handlers, activated when netcdf-c logging is enabled.
- **`nextcopy` and `nextdump` tools**: copy and inspect NEXTCDF-4 files with support for all NEXTCDF-4 types and compatibility modes.
- **Fortran and language bindings**: expose new C APIs and datatypes through maintained language bindings.
- **Compatibility and release validation**: broad NetCDF-C compatibility testing, interoperability checks, regression tests, and performance/resource-leak validation across supported HDF5 versions.

---

## Sprint 1: NEXTCDF-4 Documentation

### Documentation

- **`docs/nextcdf4.md`** — dedicated user reference page for the NEXTCDF-4 backend:
  - Overview and relationship to the built-in NetCDF-4/HDF5 backend.
  - Build configuration, `NEP_ENABLE_NEXTCDF4`, and HDF5 version requirements.
  - Creating and opening files with `NC_NEXTCDF4` and `.ncrc` UDF9 autoload.
  - Compatibility modes: native, `NC_CLASSIC_MODEL`, and `NC_NETCDF4_MODEL`.
  - Supported atomic types table, including new small floats, complex, bitfield, and reference types.
  - Hidden markers (`_Nextcdf4Backend`, `_Nextcdf4Model`, `_Netcdf4Coordinates`, `_Netcdf4Dimid`).
  - Reference API overview (`nc_ref_object`, `nc_deref_object`, `nc_ref_region`, `nc_deref_region`).
  - Known limitations and code examples.
- **`docs/mainpage.md`** — added NEXTCDF-4 section to the Doxygen landing page with a link to `nextcdf4.md`.
- **`docs/formats.md`** — added NEXTCDF-4 UDF9 entry to the UDF slot assignment and reference tables, plus an autoload example using `NC_NEXTCDF4`.
- **`docs/design.md`** — updated project structure and architecture sections to reflect the completed NEXTCDF-4 implementation.
- **`docs/prd.md`** — added a NEXTCDF-4 product-requirements section covering goals, build options, type support, compatibility contract, public API additions, and limitations.
- **`docs/prfaq.md`** — added NEXTCDF-4 FAQ entries and updated version, format, stability, and use-case summaries.
- **`docs/releases/v4.1.0.md`** — this release notes file.

### Verification

- Doxygen build (`cmake --build build --target docs`) completes with zero warnings.
- All new and updated cross-references resolve.
- Documentation is consistent with `docs/plan/NEXTCDF4_plan.md`, the v4.0.0 sprint descriptions, and the `src/nextcdf4/` implementation.

## Sprint 2: Logging in NEP

- Adds a `LOG(())` macro for the NEXTCDF-4 backend and NEP handlers, modeled on netcdf-c `libsrc4` and `libhdf5` logging.
- NEP logging is turned on automatically when netcdf-c logging is enabled.

---

## Sprint 3: Tools and Language Bindings

- Creates `nextcopy` and `nextdump` utilities with support for all NEXTCDF-4 types and compatibility modes.
- Exposes new C APIs and datatypes through Fortran and other maintained language bindings.

---

## Sprint 4: Validate Compatibility and Prepare the Release

- Broad NetCDF-C compatibility, interoperability, regression, and representative-file testing across supported HDF5 versions.
- Performance and resource-leak checks.
- Final user documentation, examples, release notes, and v4.1.0 release readiness work.

---

## Dependencies

- netcdf-c built with UDF plugin and `NC_Dispatch` support.
- HDF5 1.14.0 or newer (required for NEXTCDF-4).
- HDF5 2.1.1 or newer (recommended for small floating-point and complex types).
