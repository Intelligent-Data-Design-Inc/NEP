# NEP v4.1.0 - NEXTCDF4 Documentation and Logging

> Continues the NEXTCDF-4 work from v4.0.0 with user and developer documentation, independent NEP logging, and a tighter focus for the NEP repository.

This release documents the NEXTCDF-4 backend, adds independently configurable NEP diagnostics, and moves standalone Earth-observation mission examples to their dedicated repository. The full NEXTCDF-4 backend implementation was completed in v4.0.0.

---

## Highlights

- **Complete NEXTCDF-4 user and developer documentation**: dedicated reference page, Doxygen integration, and updates to design, PRD, FAQ, and release notes.
- **Independent NEP logging framework**: `ELOG(())` and related E-prefixed macros for the NEXTCDF-4 backend and future NEP handlers, enabled by default and controlled with `nep_set_log_level()`.
- **Focused example collection**: standalone NISAR, SWOT, GOES-R ABI, and Sentinel-3 OLCI applications moved to the dedicated *Earth Observation in Practice* repository.

## Sprint 2: Logging in NEP

### Implementation

- NEP logging is now independent of NetCDF-C logging. Added the CMake option `NEP_ENABLE_LOGGING` (default ON). When ON, the build-time `NEP_LOGGING` macro is defined; when OFF, `ELOG(...)` expands to nothing. The feature is exported through `nep_meta.h` as `NEP_HAS_LOGGING`.
- Added `include/nep_logging.h` with the `ELOG(())`, `EBAILLOG`, `EBAIL`, and `EBAIL_QUIET` macros, all modeled on the NetCDF-C logging convention.
- Added a public `nep_set_log_level(int new_level)` API in `include/nep.h` and implemented it, along with `nep_log()` and the `nep_log_level` global, in `src/nep.c`.
- Linked the NEXTCDF-4 backend (`ncnextcdf4`) against the core `nep` library so it shares the same logging state.
- Added `src/nextcdf4/nxt4err.h` with NEXTCDF-4-specific `EBAIL` and HDF5-aware `EBAIL2` macros adapted to the local `ret`/`fail:` style. `EBAIL2` dumps the HDF5 error stack directly with `H5Eprint2()` and does not rely on NetCDF-C's `nc_log_hdf5()`.
- Wired logging into the NEXTCDF-4 backend:
  - `NC_NEXTCDF4_initialize()` reads the `NEP_LOG_LEVEL` environment variable and applies it with `nep_set_log_level()`.
  - Lifecycle functions (`create`, `open`, `close`, `abort`, `sync`, `enddef`, `redef`, `inq_format*`) emit entry/exit diagnostics.
  - Metadata functions (`def_dim`, `def_var`, `load_metadata`) log their calls and key parameters.
  - Replaced temporary `fprintf(stderr, ...)` debug statements in `nxt4create.c`, `nxt4open.c`, and `nxt4file.c`.
- Added `test/nextcdf4/tst_nextcdf4_logging.c` which verifies:
  - Log output appears at level 3 and contains expected lifecycle messages.
  - Output disappears after `nep_set_log_level(-1)`.
  - An HDF5 open failure emits a severity-0 error line.
  - The test skips cleanly when `NEP_LOGGING` is not defined.

### Documentation

- Added a "Diagnostics and Logging" section to `docs/nextcdf4.md` explaining the independent `nep_set_log_level()` API, the `NEP_LOG_LEVEL` environment variable, severity levels, and which NEXTCDF-4 operations are instrumented.

## Sprint 3: Remove Space Mission Examples

- Removed the standalone NISAR, SWOT, GOES-R ABI, and Sentinel-3 OLCI Python applications and their committed figures and dependency files.
- Removed the four mission-specific companion articles and detailed implementation plans.
- Retired project skills dedicated solely to creating or maintaining the migrated standalone mission examples.
- Updated the top-level README to direct users to the [Earth Observation in Practice](https://github.com/captainkirk99/Earth_Observation_in_Practice) repository and the companion [book](https://www.amazon.com/Earth-Observation-Practice-Mission-Mission/dp/B0HJRZ9F7L/).
- Retained NEP examples that directly exercise UDF readers, compression filters, NetCDF, NcZarr, OPeNDAP, parallel I/O, and NEXTCDF-4 functionality.
- The migration does not change the NEP API, ABI, UDF dispatch behavior, or supported file formats.

---

## Dependencies

- netcdf-c built with UDF plugin and `NC_Dispatch` support.
- HDF5 1.14.0 or newer (required for NEXTCDF-4).
- HDF5 2.1.1 or newer (recommended for small floating-point and complex types).
