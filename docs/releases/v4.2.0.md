# NEP v4.2.0 — Compression Moves to nep-compress

NEP 4.2.0 makes NEP a format-only package. It builds and installs the
scientific format UDF readers and the optional NEXTCDF-4 backend. The
LZ4/BZIP2 C and Fortran wrapper APIs, the LZ4 HDF5 filter plugin, and
the filter tests and benchmarks have moved to the separate
[nep-compress](https://github.com/captainkirk99/nep-compress) project
(currently v1.2.0). The goal is to make both packages easier to install:
users of the format readers no longer need LZ4/BZIP2 development
packages or HDF5 plugin setup, and compression users no longer need
NEP's format-reader dependencies.

This release does not change UDF slot assignments, format-reader
behavior, NEP logging, or the NEXTCDF-4 on-disk format. It removes the
compression APIs from NEP's public interface, so applications that use
them must switch to nep-compress (see
[Migrating applications](#migrating-applications)).

## Highlights

- **Format-only NEP.** NEP no longer builds, installs or tests
  compression filters, and no longer needs `liblz4` or `libbz2`
  development headers.
- **nep-compress.** The same LZ4/BZIP2 functionality is now a separate
  package with its own C header, Fortran module, CMake options, CI,
  documentation, Spack recipe and conda recipe.
- **Unchanged filter IDs.** nep-compress uses the same registered HDF5
  filter IDs (LZ4 `32004`, BZIP2 `307`), so files written with either
  filter remain readable whenever a compatible plugin is on
  `HDF5_PLUGIN_PATH`.
- **Simpler CI and packaging.** The compression build matrix, the
  `hdf5_plugins` CI build step, and filter variants and checks in the
  in-repository Spack and conda recipes have been removed.

## Migrating applications

| Before v4.2.0 | With nep-compress |
| --- | --- |
| `<nep.h>` for compression wrappers | `<nep_compress.h>` |
| `-lnep` for `nc_def_var_lz4` / `nc_def_var_bzip2` | `-lnepcompress` |
| `use nep`, `-lnepf`, `nep.mod` | `use nep_compress`, `-lnepcompressf`, `nep_compress.mod` |
| `NEP_BUILD_LZ4` / `NEP_BUILD_BZIP2` | `NEPCOMPRESS_BUILD_LZ4` / `NEPCOMPRESS_BUILD_BZIP2` in the separate project |
| NEP's bundled LZ4 plugin directory | nep-compress's installed `lib/plugin`, plus an external BZIP2 plugin directory when needed |

Applications that only read formats through NEP's UDF handlers need no
changes. Install both projects only if your application needs both the
format readers and compression. The BZIP2 filter still requires a
separate, compatible HDF5 BZIP2 plugin; neither NEP nor nep-compress
builds one.

NEP makes no guarantee that files can be exchanged between old NEP
and nep-compress. nep-compress checks its own write, reopen and read
round trips for both filters.

## Public API Changes

Removed from `include/nep.h`:

- `nc_def_var_lz4()`, `nc_inq_var_lz4()`, `nc_def_var_bzip2()` and
  `nc_inq_var_bzip2()` (now in nep-compress).
- `nc_def_var_lzf()` and `nc_inq_var_lzf()`. These were declared but
  never compiled (`BUILD_LZF` was never defined), so they could not be
  linked. The never-compiled JPEG wrappers in `src/nep.c` were also
  removed.
- `LZ4_ID`, `BZIP2_ID` and `LZF_ID`.

Removed from the installation:

- The Fortran `nep` module (`nep.mod`) and the `nepf` library.
- The `lib/plugin/libh5lz4.so` HDF5 plugin.

Retained:

- `libnep`, `nep_set_log_level()`, the NEP logging headers, the UDF
  slot definitions, and the NEXTCDF-4 types and reference APIs.

## Build-System Changes

- `NEP_BUILD_LZ4` and `NEP_BUILD_BZIP2` have been removed. If either is
  still passed, CMake prints a warning that points to nep-compress and
  builds no filter.
- The `BUILD_LZ4`/`BUILD_BZIP2` definitions are gone from `config.h`.
- `NEP_HAS_LZ4` and `NEP_HAS_BZIP2` are gone from the generated
  `nep_meta.h`. `NEP_HAS_FORTRAN` now means Fortran format-reader test
  support.
- The `fsrc/` Fortran wrapper library, the `hdf5_plugins/` LZ4 plugin
  build, and the `test_h5/` HDF5 filter tests have been removed.
- Fortran format-reader tests no longer link against `nepf`.
- `NEPConfig.cmake` describes NEP as providing format handler support.
- NEP still uses CMake only.

## Tests

- The compression tests (`tst_lz4`, `tst_bzip2`, `tst_perf`,
  `ftst_nep_lz4`, `ftst_nep_bzip2` and the `test_h5/` HDF5 plugin
  tests) have been removed; nep-compress now runs equivalent tests.
- `tst_meta` now checks `NEP_HAS_FORTRAN` in place of `NEP_HAS_LZ4`.
- The format-reader, NEXTCDF-4 and logging tests are unchanged.

### Known test limitation

- **Five NEXTCDF-4 reopen tests are disabled.** They are still
  registered but marked disabled: `tst_nextcdf4_float16`, `complex`,
  `bitfield`, `ref` and `tst_explore`.
  - They abort in the installed netcdf-c `NC_reclaim_data`
    `USEFILEINFO` assertion.
  - The same failures were present before the compression split.
  - The assertion was not removed or bypassed in NEP or netcdf-c.
  - Re-enable these tests when the underlying issue is resolved.
- `tst_rename` was already disabled before v4.2.0.

## Examples

- **Moved to nep-compress:** the LZ4/BZIP2 performance examples
  (`lz4.c`, `bzip2.c`), their results CSV files, metadata and plot
  scripts.
- **Not built or tested:** the mixed-filter `lossless.c` and
  `quantize.c` benchmark sources remain in NEP. A later release can
  reactivate them with an explicit nep-compress dependency.
- **Still available:** NetCDF-C/HDF5 examples using Zstandard,
  zlib/DEFLATE and SZIP, plus the chunking, cache-tuning, NcZarr,
  OPeNDAP, parallel I/O, format-reader and NEXTCDF-4 examples.
- **Fixed:** `cache_tuning.c` had integer overflow in its cache-size
  table, and its thrashing test had a missing loop.

## Packaging and CI

- **Spack:** `spack/NEP/package.py` no longer has the `lz4`/`bzip2`
  variants or plugin install checks. Updating the upstream Spack
  package (spack/spack-packages#5557) to 4.2.0 will follow this
  release.
- **Conda:** `conda/meta.yaml` and `conda/build.sh` package format-only
  NEP. They no longer depend on `lz4-c` or check for `nep.mod` or the
  LZ4 plugin, and they require HDF5 1.14 or newer.
- **CI:** the compression matrix and the external `hdf5_plugins` build
  were removed from `ci.yml`, and the obsolete
  `-DNEP_BUILD_LZ4/BZIP2` switches were removed from all format
  workflows.

## Compatibility and Upgrade Notes

- Format-reader applications, UDF slot assignments and `.ncrc`
  autoload configuration are unchanged.
- Existing NEXTCDF-4 files remain compatible.
- Applications that call the LZ4/BZIP2 wrappers or `use nep` from
  Fortran must move to nep-compress; see the migration table above.
- Files compressed with LZ4 or BZIP2 stay readable as long as a
  compatible plugin is on `HDF5_PLUGIN_PATH`. Set it to nep-compress's
  `lib/plugin`, plus your BZIP2 plugin directory if needed.
- NEP itself no longer needs `HDF5_PLUGIN_PATH`.

## Dependencies

- NetCDF-C 4.10.1 or newer with UDF plugin and `NC_Dispatch` support.
- HDF5 1.14.0 or newer.
- HDF5 2.1.1 or newer is recommended for the complete NEXTCDF-4
  small floating-point type set.
- LZ4 and BZIP2 are no longer NEP dependencies.

## Documentation

- `docs/compression.md` has been removed. Compression documentation
  now lives in nep-compress's `docs/compression.md` and README.
- `README.md`, `docs/mainpage.md`, `docs/design.md`, `docs/prd.md`,
  `docs/prfaq.md`, `docs/formats.md`, `docs/examples.md`,
  `docs/spack.md` and the Doxygen inputs now point compression users to
  nep-compress.
- The v2.2.0 press release and earlier release notes still describe
  the features that were bundled at the time; they are kept as history.
- `docs/plan/v4.2.0-sprint1-*` through `sprint4-*` record the
  inventory, migration decisions and verification for this release.
