# NEP v4.2.0: Compression Package Split

NEP now builds and installs scientific format UDF handlers and the
optional NEXTCDF-4 backend, not bundled LZ4/BZIP2 HDF5 plugins.
The LZ4/BZIP2 C and Fortran wrapper APIs, the LZ4 plugin, filter tests
and dedicated benchmarks are maintained in
[nep-compress](https://github.com/captainkirk99/nep-compress).
The BZIP2 filter still requires a separate compatible HDF5 plugin.

## Migrating applications

| Before v4.2.0 | With nep-compress |
| --- | --- |
| `<nep.h>` for compression wrappers | `<nep_compress.h>` |
| `-lnep` for `nc_def_var_lz4` / `nc_def_var_bzip2` | `-lnepcompress` |
| `use nep`, `-lnepf`, `nep.mod` | `use nep_compress`, `-lnepcompressf`, `nep_compress.mod` |
| `NEP_BUILD_LZ4` / `NEP_BUILD_BZIP2` | `NEPCOMPRESS_BUILD_LZ4` / `NEPCOMPRESS_BUILD_BZIP2` in the separate project |
| NEP's bundled LZ4 plugin directory | nep-compress's installed `lib/plugin`, plus an external BZIP2 plugin directory when needed |

Old NEP build switches generate a migration warning and no longer build
filters. Install both projects only if your application needs both
format readers and compression. NEP retains its logging API and generic
filter support in NEXTCDF-4. No old-NEP/new-project file interchange
guarantee is made; nep-compress verifies its own write/reopen/read
round trips for both filters.

The v2.2.0 press release and earlier release notes describe the
features that were bundled at the time; they are retained as history.
The mixed-filter `lossless.c` and `quantize.c` benchmark sources remain
in NEP but are not built or tested; a later release can reactivate them
with an explicit nep-compress dependency. NetCDF-C/HDF5 examples using
Zstandard, zlib/DEFLATE, or SZIP remain available.

## Known test limitation

Five NEXTCDF-4 reopen tests (`tst_nextcdf4_float16`, `complex`,
`bitfield`, `ref`, and `tst_explore`) are temporarily registered but
disabled. They abort in the installed netcdf-c `NC_reclaim_data`
`USEFILEINFO` assertion; the same failures were present before the
compression split. The assertion was not removed or bypassed in
NEP or netcdf-c. Re-enable these tests when the underlying issue is
resolved. `tst_rename` was already disabled before v4.2.0.
