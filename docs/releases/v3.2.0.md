# NEP v3.2.0 - JPEG Lossless DICOM Decode and Organized Visualization Examples

> Adds JPEG Lossless (Process 14) decode support to the DICOM reader and reorganizes visualization examples into per-format directories.

This release closes a real capability gap discovered while auditing DICOM sample coverage: two of the five OME public-domain samples added in v3.1.0 use JPEG Lossless transfer syntaxes and were being rejected. It also reorganizes `examples/viz/` into per-format subdirectories ahead of future format additions.

---

## Highlights

- **JPEG Lossless (Process 14) decode support** (#338, #339) — the DICOM UDF reader now decodes `1.2.840.10008.1.2.4.57` and `1.2.840.10008.1.2.4.70` encapsulated transfer syntaxes via GDCM's bundled IJG lossless codec, fixing two previously-rejected OME sample files.
- **Precision-aware codec dispatch** (#339) — `dicom_jpeg_lossless_precision()` inspects the JPEG stream's own SOF3 marker to select the matching 8/12/16-bit `gdcmjpeg` variant, independent of the DICOM `BitsAllocated` tag.
- **Visualization examples reorganized by format** (#334, #336) — 15 plot scripts and the DICOM UDF helper moved from a flat `examples/viz/` into `CDF/`, `DICOM/`, `FITS/`, `GeoTIFF/`, `GRIB2/`, and `PDS4/` subdirectories, with the CMake build tree mirroring the layout.
- **Expanded DICOM regression coverage** (#339) — `test/tst_dicom_udf.c` now validates all five OME samples added in v3.1.0, including pixel-data reads through the new lossless decode path and a clean-rejection assertion for the one file that remains out of scope.
- **Corrected DICOM sample documentation** (#339) — `test/data/DICOM/README.md`'s transfer-syntax labels, several of which were wrong since v3.1.0, now match each file's actual embedded Transfer Syntax UID.

## Features

### JPEG Lossless DICOM Decode (#338, #339)

- **`src/dicomjpeglossless{8,12,16}.c`** — per-precision decode wrappers around GDCM's `gdcmjpeg8`/`gdcmjpeg12`/`gdcmjpeg16` libraries (IJG libjpeg 6b plus the classic lossless/Process 14 patch, mangled symbol namespace so all three link into one binary).
- **`src/dicomjpeglosslessimpl.inc.c`** — shared memory-based `jpeg_source_mgr` and decode logic, included once per precision variant since each variant's headers define incompatible `JSAMPLE` types.
- **`src/dicomjpeglosslessprecision.c`** — `dicom_jpeg_lossless_precision()` scans the encapsulated JPEG stream's SOF3 marker to pick the correct codec at decode time.
- **`src/dicomfile.c`** — recognizes JPEG Lossless transfer syntaxes alongside existing JPEG Baseline support and dispatches `dicom_read_frame_buffer()` to the new decoder.
- New optional build dependency: `libgdcm-dev`. Without it, DICOM support still builds; JPEG Lossless files are rejected cleanly with `NC_EINVAL` instead of crashing or hanging.

### Visualization Examples Reorganization (#334, #336)

- 15 plot scripts relocated into `examples/viz/{CDF,DICOM,FITS,GeoTIFF,GRIB2,PDS4}/`; `examples/viz/DICOM/_dicom_udf.py` moves with its DICOM scripts.
- `examples/viz/CMakeLists.txt` mirrors the source layout in the build tree while artifact basenames, CTest names, fixtures, and the `verify_viz_artifacts.py` interface are unchanged.
- `examples/viz/README.md` documents the new grouped layout and manual run paths.

## Bug Fixes

- **`CT-MONO2-16-chest.dcm` and `MR-MONO2-12-shoulder.dcm` incorrectly rejected** (#338, #339) — both use JPEG Lossless transfer syntaxes, not "Explicit VR Little Endian" as originally documented in v3.1.0; both now decode correctly.
- **Incorrect transfer-syntax labels in `test/data/DICOM/README.md`** (#339) — corrected against each file's actual embedded Transfer Syntax UID, verified directly via libdicom.

---

## API Changes

None. All changes are additive to the DICOM reader's internal decode path; the public NetCDF UDF interface, dimensions, and attribute mapping are unchanged.

---

## Build System

- **CMake**: `CMakeLists.txt` and `src/CMakeLists.txt` detect `gdcmjpeg8`/`gdcmjpeg12`/`gdcmjpeg16` headers/libraries under `NEP_ENABLE_DICOM` and set `HAVE_DICOM_LOSSLESS` in `config.h` when found.
- **CI**: `.github/workflows/ci-dicom.yml` installs `libgdcm-dev`, builds NetCDF-Fortran, and enables `NEP_ENABLE_FORTRAN` so `ftst_dicom_udf` runs alongside `tst_dicom_udf`. `.github/workflows/ci.yml`'s DICOM-enabled matrix job (`fortran=on`, `compression=all`) also installs `libgdcm-dev`.

## Testing

- `test/tst_dicom_udf.c` — added test blocks for `CT-MONO2-16-brain.dcm` and `MR-MONO2-16-head.dcm` (native), `CT-MONO2-16-chest.dcm` and `MR-MONO2-12-shoulder.dcm` (JPEG Lossless, including decoded pixel reads), and a clean `NC_EINVAL` rejection assertion for `CR-MONO1-10-chest.dcm`.
- `ftest/ftst_dicom_udf.F90` — added an open/close smoke check for `CT-MONO2-16-brain.dcm`.
- `ctest --test-dir build -R dicom --output-on-failure` passes with `NEP_ENABLE_DICOM=ON` and `libgdcm-dev` installed; the full suite remains regression-free with DICOM disabled.

NEP's example programs are companion code for *The NetCDF Developer's Handbook: The Authoritative Guide to Writing High-Performance Programs for Scientific Data Management, Second Edition* — available on [Amazon](https://www.amazon.com/dp/B0H7Q1Z75L).

## Dependencies

- **`libgdcm-dev`** (new, optional) — provides `gdcmjpeg8`/`gdcmjpeg12`/`gdcmjpeg16` for JPEG Lossless decode. DICOM support builds without it.
- `libdicom` and `libjpeg`/`libjpeg-turbo` remain required DICOM reader dependencies (unchanged from v3.0.0).

---

## Known Limitations

- **`CR-MONO1-10-chest.dcm`** has no 128-byte preamble/`DICM` magic; libdicom cannot parse it. Rejected cleanly with `NC_EINVAL`; out of scope for this release.
- **`MR-MONO2-16-head.dcm`** opens and reports correct metadata, but pixel-data reads fail due to a libdicom-internal limitation with this file's missing `NumberOfFrames` tag, unrelated to JPEG decoding. Metadata coverage is tested; pixel-data reads are not asserted for this file. See `docs/plan/v3.2.0-sprint2-dicom-sample-coverage.md` for detail.
