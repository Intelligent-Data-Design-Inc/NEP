# NEP v3.1.0 - DICOM Visualizations and CMake-Only Build

> First DICOM visualization examples and complete removal of the Autotools build system in favor of CMake-only builds.

This release adds three DICOM visualization scripts to the `examples/viz/` gallery, acquires five new public-domain DICOM test samples, and makes CMake the sole supported build system by removing all Autotools infrastructure from the repository.

---

## Highlights

- **DICOM visualization gallery** (#330, #333) — four new Python scripts produce publication-ready grayscale PNGs from DICOM medical images via the NetCDF UDF interface.
- **CMake-only build system** (#332) — removed 33 Autotools files including all `Makefile.am`, `configure.ac`, `m4/` macros, and generated artifacts; CMake 3.9+ is the sole build path.
- **Five new public-domain DICOM samples** (#331) — CT, MR, and CR modality images from the OME collection expand test data coverage under `test/data/DICOM/`.
- **Seven CI workflows converted** (#331) — `ci.yml`, `ci-dicom.yml`, `ci-fits.yml`, `ci-formats.yml`, `ci-parallel.yml`, `ci-viz.yml`, and `geotiff-test.yml` are now CMake-only.
- **DICOM UDF helper module** (#331) — `examples/viz/_dicom_udf.py` handles `libncdicom.so` loading and `NC_DICOM_initialize()` registration for Python visualization scripts.

---

## Features

### DICOM Visualization Scripts (#330, #331, #333)

- **`plot_dicom_mrbrain.py`** — opens `test/data/DICOM/MRBRAIN.DCM` through the NetCDF UDF interface, reads `pixel_data[0, :, :]`, normalizes 16-bit samples to 8-bit grayscale, and writes `dicom_mrbrain_image.png` + `_metadata.txt`.
- **`plot_dicom_xa_montage.py`** — opens `test/data/DICOM/0003.DCM`, reads all 17 encapsulated JPEG Baseline frames, builds a compact grayscale montage, and writes `dicom_xa_frame_montage.png` + `_metadata.txt`.
- **`plot_dicom_ct_brain.py`** — opens `test/data/DICOM/CT-MONO2-16-brain.dcm`, applies a 1st–99.5th-percentile contrast window, and writes `dicom_ct_brain_image.png` + `_metadata.txt`.
- **`plot_dicom_mr_head.py`** — opens `test/data/DICOM/MR-MONO2-16-head.dcm` and writes `dicom_mr_head_image.png` + `_metadata.txt`.
- **`_dicom_udf.py`** — shared helper that loads `libncdicom.so` via ctypes and calls `NC_DICOM_initialize()` before opening DICOM files with `netCDF4.Dataset`.

### CMake-Only Build Migration (#332)

CMake 3.9+ is the sole supported build system. Use:

```bash
cmake -S . -B build -DCMAKE_INSTALL_PREFIX=/usr/local
cmake --build build
ctest --test-dir build
cmake --install build
```

All `NEP_*` CMake options retain their existing names and behavior. Public APIs, compression filters, UDF readers, and installation layout are unchanged.

## Build System

- **Autotools removed**: 33 files deleted — all `Makefile.am`/`Makefile.in`, `configure.ac`, `config.h.in`, `autogen.sh`, `m4/ax_lib_hdf5.m4`, `hdf5_plugins/configure.ac`, `hdf5_plugins/LZ4/configure.ac`, `hdf5_plugins/LZ4/lz4_config.h.in`, and all Autotools-only test runners.
- **CI converted**: Seven GitHub Actions workflows updated to CMake-only; no Autotools bootstrap, configure, build, or test steps remain.
- **CMake minimum**: 3.9 (unchanged).
- **DICOM visualization guard**: `HAVE_DICOM` added to the `NEP_ENABLE_VIZ_EXAMPLES` conditional in `examples/viz/CMakeLists.txt`.

---

## Testing

- `ctest --test-dir build -R viz_dicom` exercises four DICOM visualization scripts and validates PNG/metadata output through `verify_viz_artifacts.py`.
- `ctest --test-dir build -R dicom_udf` runs the DICOM reader regression suite against uncompressed and JPEG Baseline samples.
- All retained CI configurations pass under CMake-only builds.

NEP's example programs are companion code for *The NetCDF Developer's Handbook: The Authoritative Guide to Writing High-Performance Programs for Scientific Data Management, Second Edition* — available on [Amazon](https://www.amazon.com/dp/B0H7Q1Z75L).

- No new source dependencies added.

---

## Known Limitations

- Issue #330 remains open (Sprint 1 issue tracks additional DICOM visualization work beyond what shipped).
- `CT-MONO2-16-chest.dcm` uses JPEG Lossless transfer syntax — not yet supported by the reader.
- `MR-MONO2-12-shoulder.dcm` uses JPEG Extended transfer syntax — not yet supported.
- `CR-MONO1-10-chest.dcm` has no DICOM preamble — reader cannot detect it.

---

## Breaking Changes

- **Autotools build system removed.** Users who built with `./configure && make && make install` must migrate to the CMake commands above. All public CMake options, APIs, and runtime behavior are unchanged.
