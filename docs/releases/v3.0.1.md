# NEP v3.0.1 - Conda Packaging and Spack Catchup

> Package the v3.0.0 source release as a minimal Conda distribution and bring the upstream Spack recipe current through v3.0.0.

This release adds the first `conda-forge` NEP package, built with LZ4 compression and Fortran wrappers only, and updates the Spack recipe to include releases 2.6.0 through 3.0.0. No NEP runtime code, public API, or local build defaults changed.

---

## Highlights

- **Minimal Conda package (#328)** — packages NEP v3.0.0 from the immutable GitHub tag tarball; enables LZ4 and Fortran, disables BZIP2 and all UDF readers.
- **conda-forge staged-recipes submission (#327, #328)** — prepares the initial `nep` feedstock and documents the reader-free package boundary.
- **End-to-end Conda CI (#328)** — renders/lints `conda/meta.yaml`, builds with `--no-anaconda-upload`, and smoke-tests the installed LZ4 plugin and Fortran module in a clean environment.
- **Spack recipe catchup (#326)** — adds verified checksums for v2.6.0 through v3.0.0, restores BZIP2 install verification, and removes the unsatisfiable `+cdf` variant.
- **Source-build parity preserved (#326, #328)** — CMake, Autotools, runtime code, and local build behavior are unchanged; packaging choices apply only to Conda and Spack recipes.

---

## Features

### Conda Packaging Infrastructure (#328)

- `conda/meta.yaml` targets the v3.0.0 source tag with the verified SHA256 checksum and `pin_subpackage('nep', max_pin='x.x')`.
- `conda/build.sh` invokes CMake with `-DNEP_BUILD_LZ4=ON`, `-DNEP_ENABLE_FORTRAN=ON`, `-DNEP_BUILD_BZIP2=OFF`, and every reader disabled (`NEP_ENABLE_GEOTIFF/FITS/PDS4/CDF/GRIB2/DICOM=OFF`).
- The recipe depends only on core HDF5, NetCDF-C (>=4.10.1), NetCDF-Fortran, and LZ4; BZIP2, `libdicom`, `libjpeg-turbo`, and other reader-only dependencies are excluded.
- The `test` section verifies `libh5lz4.so` / `libh5lz4.dylib` and `nep.mod` are installed.

### Spack Recipe Maintenance (#326)

- Adds `version()` entries for 2.6.0, 2.6.1, 2.7.0, 2.7.1, 2.8.0, and 3.0.0 with immutable tarballs and SHA256 sums in `spack/NEP/package.py`.
- `check_install()` now asserts `libh5lz4.so` and `libh5bzip2.so` are present when the corresponding variant is enabled.
- Removes the `+cdf` variant until NASA CDF is available as an upstream Spack package.
- Updates `.github/workflows/spack.yml` to concretize and install v3.0.0 default, minimal, DICOM, and all-upstream-supported-reader specs without masking failures.

## Build System

- **Conda**: `conda/build.sh` and `conda/meta.yaml` now drive the Conda-only CMake invocation; existing NEP CMake defaults are untouched.
- **Spack**: `spack/NEP/package.py` requires `netcdf-c@4.10.1:` and `hdf5@1.12:+hl~mpi` (or `+mpi` with `+parallel`); variant-to-CMake mappings pass through existing `NEP_*` options.

---

## Testing

- `.github/workflows/ci-conda.yml` renders the recipe with `conda-build --output/--check`, builds with `--no-anaconda-upload`, resolves the produced artifact, and installs it into a clean prefix to verify the LZ4 plugin and Fortran module.
- The Spack workflow validates `spack style`, `spack audit`, and install-only checks for the current release matrix.

NEP's example programs are companion code for *The NetCDF Developer's Handbook: The Authoritative Guide to Writing High-Performance Programs for Scientific Data Management, Second Edition* — available on [Amazon](https://www.amazon.com/dp/B0H7Q1Z75L).

## Dependencies

- **Conda package**: HDF5, `libnetcdf >=4.10.1`, `netcdf-fortran`, `lz4-c`.
- **Spack recipe**: `netcdf-c@4.10.1:`, `hdf5@1.12:+hl`, `lz4`, `bzip2`, optional reader libraries when their variants are enabled.
- No new NEP source dependencies.

---

## Known Limitations

- Issue #327 remains open until the `conda-forge/staged-recipes` PR is accepted and the generated `nep-feedstock` produces installable packages.
- The Conda package intentionally excludes BZIP2 and all UDF readers (CDF, GeoTIFF, GRIB2, FITS, PDS4, DICOM); source builds and Spack still provide these options.
- The Spack `+cdf` variant is deferred until NASA CDF becomes an upstream Spack package.
