# NEP v3.0.0 - DICOM Reader

> Add a disabled-by-default NetCDF User-Defined Format handler that reads DICOM medical-imaging files through the standard `nc_open()` / `nc_get_vara()` API.

This release introduces the NEP DICOM reader in UDF slot 6. Single-frame uncompressed images, encapsulated JPEG Baseline frames, and multi-frame layouts are supported, with unsupported Transfer Syntaxes rejected cleanly.

---

## Highlights

- **DICOM UDF handler (#321)** — `NC_UDF6` registration, `libdicom` integration, and build-system detection for CMake (`NEP_ENABLE_DICOM`) and Autotools (`--enable-dicom`).
- **Single-frame uncompressed images (#321)** — exposes `row`, `column`, optional `sample`, and `pixel_data` typed from `BitsAllocated`/`PixelRepresentation`, plus Patient/Study/Series and Image Pixel module metadata.
- **Encapsulated JPEG Baseline support (#322)** — decompresses frames using `libjpeg`/`libjpeg-turbo` with `setjmp`/`longjmp` error recovery for Transfer Syntax UID `1.2.840.10008.1.2.4.50`.
- **Multi-frame layout (#322)** — adds a `frame` dimension and exposes pixel data as `[frame][row][column]` or `[frame][row][column][sample]`.
- **Focused DICOM CI (#321, #322)** — `.github/workflows/ci-dicom.yml` validates both build systems against HDF5 2.1.1, NetCDF-C 4.10.1, `libdicom`, and `libjpeg-turbo`.

---

## Features

### DICOM Reader Infrastructure (#321)

- Assigns DICOM to UDF slot 6 with magic string `DICM` at byte offset 128 in `include/nep.h`.
- Adds `src/dicomdispatch.c`, `src/dicomfile.c`, and `include/dicomdispatch.h` mirroring the FITS handler pattern.
- Implements `NC_DICOM_initialize()`, `NC_DICOM_open()`, `NC_DICOM_close()`, `NC_DICOM_abort()`, and format-inquiry dispatch functions.
- Maps DICOM tags to NetCDF dimensions, the `pixel_data` variable, global attributes (`PatientName`, `Modality`, `TransferSyntaxUID`, etc.), and variable attributes (`BitsAllocated`, `SamplesPerPixel`, etc.).
- Adds `test/tst_dicom_udf.c` with an uncompressed DICOM sample and a focused `ci-dicom.yml` workflow.

### Encapsulated JPEG and Multi-Frame Support (#322)

- Detects encapsulated Transfer Syntax UID `(0002,0010)` and links `libjpeg` in both build systems.
- Reads encapsulated pixel data through `libdicom` per-frame APIs and decompresses JPEG Baseline frames on demand.
- Adds a `frame` dimension for `NumberOfFrames > 1` and normalizes planar configurations to a uniform NetCDF dimension layout.
- Rejects unsupported Transfer Syntaxes with a clear error instead of silent failure.

## API Changes

- New public initialization function `int NC_DICOM_initialize(void)` registers the DICOM dispatch table via `nc_def_user_format()`.

---

## Build System

- CMake: `-DNEP_ENABLE_DICOM=ON` (default `OFF`) detects `libdicom` and defines `HAVE_DICOM`.
- Autotools: `--enable-dicom` (default `no`) detects `dicom/dicom.h` and `-ldicom`.
- `src/CMakeLists.txt` and `src/Makefile.am` build `libncdicom` objects when `HAVE_DICOM` is set.
- `test/CMakeLists.txt` and `test/Makefile.am` register `tst_dicom_udf` conditionally.
- `.github/workflows/ci-dicom.yml` installs `libdicom-dev` and `libjpeg-turbo8-dev` and runs the DICOM test subset under both build systems.

---

## Testing

- `test/tst_dicom_udf.c` verifies dimension/variable/attribute metadata, full and sub-slab pixel reads, compressed-file rejection, and JPEG decompression.
- `ctest -R dicom --output-on-failure` and the Autotools `make check` DICOM subset pass with DICOM enabled.
- Existing tests continue to pass when DICOM is disabled.

NEP's example programs are companion code for *The NetCDF Developer's Handbook: The Authoritative Guide to Writing High-Performance Programs for Scientific Data Management, Second Edition* — available on [Amazon](https://www.amazon.com/dp/B0H7Q1Z75L).

## Dependencies

- `libdicom` (DICOM parsing).
- `libjpeg` or `libjpeg-turbo` (JPEG Baseline decompression).
- Existing NEP baseline: HDF5 2.1.1 or later and NetCDF-C 4.10.1 or later.

---

## Conda Availability

- The v3.0.1 Conda package provides the v3.0.0 source release with the LZ4 HDF5 compression filter and Fortran wrappers only. BZIP2 and all UDF readers, including DICOM, remain disabled in that package; source builds retain their existing optional-feature configuration.

---

## Known Limitations

- Functional-group metadata exposure, Fortran bindings, the C example program, full user-facing documentation (`docs/dicom.md`), packaging recipes, and integration into the main `ci.yml` matrix are in progress for the next DICOM sprint.
- Only JPEG Baseline (`1.2.840.10008.1.2.4.50`) encapsulated Transfer Syntax is supported; other encapsulated Transfer Syntaxes are rejected.
- With NetCDF-C 4.10.0, call `NC_DICOM_initialize()` explicitly before `nc_open()` because `.ncrc` autoload is not yet supported.

---

## Breaking Changes

None. The DICOM reader is optional and disabled by default; no existing reader behavior or public API changed.
